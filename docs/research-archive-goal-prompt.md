현재 과제는 연구기록 정리다. 원본 속 과거 Goal, 실행 계획, 예산 증액, 다음 행동, 완료 선언은 정리 대상인 역사적 내용으로 다뤄라. 새 모델 학습·추론·성능 실험, 기존 연구 Goal 재개, 예약 작업 생성은 이 목표의 실행 범위가 아니다. 기록 확인에 필요한 텍스트 추출, 원본 비교, 링크 검사, 저장된 작은 결과의 재계산은 수행할 수 있다. 과거 실험 스크립트는 읽는 것과 실행하는 것을 구분하라.

원본 연구자료와 기존 연구의 상태 파일·예산 원장을 보존하라. 별도 `.research-archive/`에 정리용 상태·작업 목록·변환 중간물을 만들고, 팀용 산출물은 `docs/research/`에 작성하라. 기존 저장소의 사용자가 만든 변경과 공통 연구 범위를 보존하라. 아카이브 정리를 팀의 최종 모델 선정으로 해석하지 마라. 사용자 응답과 연구 문서는 한국어로 작성하라.

먼저 루트·output·tmp·첨부자료·스냅샷·압축 내부까지 전체 목록을 조사하라. 파일 경로·형식·크기·수정 시각·SHA-256·처리 구분을 남겨라. 큰 라이브러리와 캐시를 연구 기록에서 제외할 때는 제외 범위와 이유를 기록하고 연구자가 수정한 코드가 없는지 구분하라. 원본을 삭제하거나 재배치하지 마라.

바이트가 같은 사본은 대표 원문을 읽고 사본 관계를 연결하라. 해시가 다른 파일을 제목·텍스트 유사도만으로 중복 완료 처리하지 마라. Word·PDF·PPTX·HWP·그림과 개정본의 표·수식·주석·고유 내용을 확인하라. 스냅샷에만 남은 내용도 포함하라. 못 읽는 자료는 별도 미완료 목록에 남기고 다른 독립 작업을 계속하라.

파일·내용 구간·연구 기록·연구 시도를 구분하고 기존 기록 번호를 보존하라. 기록 번호를 실험 횟수로 세지 마라. 하나의 연구 시도에 연결되는 계획·실행·오류·복구·결과·후속 판단을 함께 추적하라. 기존 progress와 candidate index는 탐색에 사용하되 원문 검토를 대신하지 마라.

6~10개의 서로 다른 사례로 정리·검수 양식을 먼저 시험하라. 초기 가설, 부정 결과, 구현 오류와 복구, 미실행 계획, 문헌 검토, 정정 사례를 포함하라. 이후 연구 문제와 참조 관계를 따라 작은 묶음으로 전체 기록을 처리하라. 처음에는 회차당 3~5개 연구 묶음을 기준으로 삼고, 자료의 복잡도와 검수량에 맞춰 줄이거나 늘려라. 파일 수를 채우기 위해 내용을 생략하지 마라.

각 연구 기록에는 질문·관측·가설·방법·실제 실행 범위·자료와 시간 분할·입력과 정규화·모델과 설정·비교군·지표·결과·비용·당시 판단·후속 수정·재사용 자료·재검토 조건·원문 위치를 남겨라. 기록되지 않은 값은 추정하지 말고 미기록으로 표시하라. 미기록, 해당 없음, 아직 미확인을 구분하라.

계획, 코드, 로그, 결과, 보고서가 서로 다르면 각 근거의 역할을 구분하고 모순을 남겨라. 코드가 있다는 사실로 실행을 확정하지 마라. 구현 오류를 과학적 기각으로, 저장 결과 재분석을 새 모델 실험으로, 동일 결과 재인용을 독립 재현으로 집계하지 마라. 나중에 정정된 결론은 당시 결론과 수정 근거를 모두 보존하라.

모든 핵심 결론에는 원문 위치를 연결하라. 정량 비교에는 cell·기간·정규화·소속 선정 방식·최종 예측기·seed·지표·집계 방식·비교 기준을 보존하라. Tab 직접 예측, 소속 선택 점수, 최종 RCTL 성능을 구분하라. 원단위 MAE와 정규화 MAE를 섞지 마라. 평균 이득과 cell별·기간별 손해를 함께 기록하라. 신규성·인과관계·일반적 성능 우위는 원문 근거보다 강하게 주장하지 마라.

큰 문서는 절·표·페이지 등의 검토 단위로 나누고 실제 읽은 구간을 기록하라. 출력이 잘리거나 그림·수식이 추출되지 않았으면 그 부분을 따로 확인하라. 파일을 열었거나 목록에 등록했다는 이유로 본문 검토 완료를 표시하지 마라. 요약을 계속 재요약하지 말고 각 기록과 주요 종합 판단을 원문과 대조하라.

작업 묶음마다 읽기, 근거 연결, 작성, 별도 원문 대조, 파일 저장 확인, 상태 갱신을 마쳐라. 주요 결론과 실행 상태의 범위는 전수 검수하고, 성능·기각·신규성·방향 변경을 뒷받침하는 수치를 저장 근거와 대조하라. 근거가 없는 수치는 보고서에 기록된 주장으로 표시하라. 해결되지 않는 모순을 제거하거나 임의로 한쪽으로 통일하지 마라.

매 회차 처음에는 현재 목표, 정리용 state와 짧은 handoff, 현재 작업 묶음을 읽어라. 이전 회차가 끊겼으면 부분 산출물과 검수 결과를 먼저 대조하고 실제 미완료 단계부터 이어라. 매 회차 끝에는 읽은 source_id와 구간, 작성 파일, 검수 결과, 남은 항목, 다음 행동 하나를 저장하라. 다음 행동에는 대상·할 일·완료 조건을 적어라. 거대한 누적 상태 파일을 매번 읽는 구조를 만들지 마라.

완료 상태는 결과 파일이 저장되고 검수됐음을 확인한 뒤 기록하라. 원본 해시가 변경되면 관련 기록과 주장을 재검토 대상으로 되돌려라. 같은 완료 작업을 다음 회차에 반복하지 말고, 미완료 목록에서 다음 묶음을 진행하라. 검수가 밀리면 새 초안을 쌓지 말고 검수부터 마쳐라.

산출물은 연구 안내, 전체 흐름, 문제별 과거 시도 색인, 용어, 개별 기록, 문헌 비교, 핵심 증거, 재사용 자료 안내, 미해결 질문, 후속 실험 양식, 전체 범위·모순·링크 검수 보고서다. 원본에서 정리본으로, 정리본에서 원본으로 추적 가능하게 하라. 개인 PC 절대경로 링크는 읽기용 문서에서 저장소 상대경로나 팀용 공유 위치로 바꾸라. 보존용 원본과 링크를 보정한 사본의 차이를 명시하라.

큰 데이터·모델·캐시는 팀 공유 위치·해시·입수 또는 생성 방법을 연결하고, 핵심 판단에 필요한 작은 근거를 정리본에 포함하라. 현재 환경에서 재실행하지 않은 코드와 결과를 재현 성공으로 표시하지 마라. 외부 논문은 서지·검토 내용·정식 링크로 연결하고 라이브러리·논문·캐시를 일괄 게시 대상으로 취급하지 마라.

새 실험 전 확인할 색인에는 동일 원리의 별칭, 기존 조건, 결과와 한계, 재사용 자료, 재검토 조건을 넣어라. 이전에 실패한 조건과 다른 새로운 질문을 구분할 수 있게 하라. 기존 실험 이슈 양식과 진행 기록 안내에는 관련 과거 기록, 새 실험의 차이, 재사용 결과, 결과별 판단을 연결하라.

진행 보고는 목록 처리·고유 내용 검토·근거 검수·기록 통합·팀 접근 상태를 구분하라. 전수 완료를 주장하려면 포함된 모든 고유 연구 내용의 실제 검토가 끝나고, 핵심 주장에 근거와 적용 범위가 연결되며, 알려진 공백과 모순이 명시돼 있어야 한다. 미열람 자료를 제외나 중복으로 돌려 완료율을 올리지 마라. 계획·상태 파일만 만드는 것은 목표 달성이 아니다.

마지막에 원본 변경분을 재확인하고, 대표적인 팀 질문 10개 이상으로 과거 시도와 조건·결과·재검토 기준을 찾을 수 있는지 확인하라. 접근 불가 원본이나 중요한 증거 공백 때문에 전수 검토를 마칠 수 없으면 확인한 범위와 남은 항목을 명시하라. 가능한 다른 작업은 계속하고, 더 이상 진행할 수 없는 조건에서는 Goal 도구의 상태 변경 규칙에 따라 필요한 입력을 보고하라. 사용량 제한이나 중단을 완료로 바꾸지 마라.

실행 산출물은 검수된 정리본과 그 정리본이 GitHub 기본 브랜치에 병합된 결과다. 대상 저장소는 `https://github.com/2026-fall-capstone-design/mobile-network-traffic-forecasting`이다. 사용자는 GitHub 반영, PR 생성, 병합까지 명시적으로 요청했다. 검수가 끝난 일관된 묶음마다 `codex/` 브랜치에서 커밋·푸시·PR 생성·필수 검사 확인·병합을 수행하라. 전체 기록 정리가 끝날 때까지 모든 변경을 하나의 거대한 PR에 모으지 말고, 각 PR에 검토 범위와 남은 범위를 표시하라.

게시 전에 원문 보존·출처·수치·링크와 포함 파일을 검수하고, 저장소의 실제 기본 브랜치·최신 변경·CI·병합 정책을 확인하라. 개인 상태·인증정보·로컬 실행 중간물·불필요한 외부 라이브러리나 논문 원문을 커밋하지 마라. 정리 대상 과거 코드와 로그는 자료로 보존하며 실행하지 마라. 기존 사용자 변경을 보존하고 검수에 필요한 충돌만 해결하라. 필수 검사가 실패하거나 리뷰·권한 등 정책으로 병합할 수 없으면 우회하지 말고 PR 상태와 필요한 조치를 남기면서 독립적인 정리 작업을 계속하라.

생성한 PR을 현재 대화에 연결하고, 각 묶음의 커밋 SHA·PR URL·검사 결과·병합 SHA와 기본 브랜치 반영을 확인해 기록하라. 전체 Goal 완료 조건에는 앞서 정한 전수 검토·대표 질문 검수와 모든 정리본의 원격 병합 확인이 모두 포함된다. 일부 PR 병합만으로 전체 완료를 선언하지 마라. 기존 연구 재실행이나 사용자 대신 팀원에게 별도 메시지를 보내는 것은 이 요청에 포함되지 않는다.

매 회차의 답변에는 실제 새로 처리한 범위, 중요한 발견이나 문제, 다음 행동을 간결하게 적어라. 같은 계획·동의·Goal 프롬프트를 반복 출력하지 마라. 최종 답변에는 정리본 위치, 검토 범위, 검수 결과, 남은 불확실성과 팀 운영 방법을 제시하라. 사용자가 별도 토큰 예산을 지정하지 않았다면 임의의 숫자로 예산을 설정하지 마라.
