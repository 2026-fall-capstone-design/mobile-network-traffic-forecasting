# 역할 분담과 진행 기록

팀원이 현재 작업과 결과를 이어받을 수 있도록 기록합니다.
작업 상태는 [팀 보드](https://github.com/orgs/2026-fall-capstone-design/projects/1),
코드 변경은 PR, 실험 해석과 회의 결과는 이 폴더에 남길 수 있습니다.

새 실험을 설계하기 전에 [과거 시도 색인](../research/prior-attempts.md)에서 관련 조건·실패·정정을 확인합니다.
아카이브의 본문 검토는 진행 중이므로, 색인에 없다는 이유만으로 새로운 시도라고 판단하지 않습니다.

## 역할별 결과물

아래 네 영역을 기준으로 담당 범위를 나누고, 실제 담당자는 팀 보드나 작업 기록에 표시합니다.

| 영역 | 주요 작업 | 다음 작업자에게 전달할 결과 |
|---|---|---|
| 데이터·기준 모델 | 데이터 확보, 전처리, 기준 모델 실행 | 입력 형식, 전처리 설정, 기준 예측 결과 |
| 모델 연구 | 연구 모델 구현, 설정 비교, 실험 실행 | 모델 실행 방법, 예측값, 실험 설정 |
| 평가·연동 | 평가 표본 정렬, 지표 계산, JSON 생성·검증 | 비교 지표, 검증된 결과 파일 |
| 웹·배포 | 결과 탐색 화면, 차트·필터, Pages 확인 | 결과를 조회할 웹과 확인 기록 |

담당 영역이 맞닿는 작업은 입력 형식과 전달할 파일을 먼저 정합니다.
예를 들어 모델·평가 담당자는 `Prediction` 필드를,
평가·웹 담당자는 [웹 데이터 규약](../web-data-contract.md)을 함께 확인합니다.

## 단계별 완료 기준

| 단계 | 확인할 결과 |
|---|---|
| 환경과 합성 예제 | 새 환경에서 예제 실행·검증·웹 조회 가능 |
| 데이터와 기준 모델 | 데이터 범위와 전처리를 정하고 동일 테스트 구간의 기준 성능 확보 |
| 연구 비교 실험 | 같은 조건의 모델 비교, 지표와 사례 분석, 재현 방법 정리 |
| 최종 데모와 보고서 | 대표 결과를 웹에 반영하고 보고서·발표 자료와 수치 일치 확인 |

## 기록 위치와 이름

팀원이 다시 찾을 필요가 있는 설명을 남깁니다.
PR에 이미 실행 결과와 해석이 충분하다면 해당 PR을 링크해도 됩니다.

이 폴더에 문서를 추가할 때는 `YYYY-MM-DD-주제.md` 형식을 사용합니다.
예: `2026-10-07-baseline-comparison.md`.

### 작업·회의 기록

```markdown
# YYYY-MM-DD — 주제

## 목표
이번 작업이나 회의에서 해결할 내용

## 완료한 내용과 결정
- 변경하거나 합의한 내용:
- 관련 PR·파일:

## 확인한 결과
- 실행 또는 확인 방법:
- 결과와 남은 문제:

## 다음 작업
- 할 일:
- 담당자:
- 먼저 필요한 작업:
```

### 실험 기록

```markdown
# YYYY-MM-DD — 실험 이름

## 목적
- 확인할 가설 또는 비교할 조건:
- run_id:

## 실행 조건
- 관련 과거 기록 / 이번에 달라지는 질문과 조건:
- 재사용할 예측값·설정·로그:
- 코드 커밋 / 미커밋 변경:
- 데이터 버전 / 셀 / 기간:
- 학습·검증·테스트 구간:
- 모델 버전 / 변경 설정 / 시드:
- 실행 명령 / 설정 파일:
- 실행 환경 / 장치:

## 결과
- 예측값·지표·로그 위치:
- 기준 모델과의 비교:
- 실행 시간:
- 새 실행 / 저장 결과 재분석 / 동일 결과 재인용의 구분:

## 해석과 다음 실험
- 확인한 차이:
- 한계 또는 실패 사례:
- 평균 결과와 기간별·셀별 손해:
- 다음에 변경할 조건:
```

기록한 결과 경로가 다른 팀원의 환경에서도 의미가 있도록
저장소 내 경로나 팀 저장 공간의 위치를 사용합니다.
