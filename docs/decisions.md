# 주요 결정

프로젝트 구성의 이유와 변경 이력을 기록합니다.
작업 절차는 [협업 안내](../CONTRIBUTING.md),
실험 기준은 [공통 실험 규약](research-protocol.md)에 정리합니다.

## 현재 구성

아래 구성은 2026-10-07에 정했습니다.

| 결정 | 이유 | 관련 파일·문서 |
|---|---|---|
| Python에서 예측·평가하고 JSON으로 전달 | 실험 결과를 저장해 비교하고 웹에서 같은 결과를 조회 | [결과 내보내기](../src/traffic_forecasting/export/__init__.py) |
| HTML·CSS·JavaScript 정적 웹과 GitHub Pages 사용 | 저장된 결과를 팀원이 바로 열어 확인 | [웹 개발 안내](../web/README.md) |
| 모델 간 공통 평가·JSON 형식 사용 | 모델 구현을 바꾸어도 지표 계산과 화면을 함께 사용 | [웹 데이터 규약](web-data-contract.md) |
| Python 버전과 uv 의존성 고정 | 로컬·CI에서 같은 기본 환경으로 실행 | [.python-version](../.python-version), [uv.lock](../uv.lock) |
| PR과 Squash 병합으로 변경 반영 | 작업 단위로 변경 내용과 검사 결과를 남김 | [협업 안내](../CONTRIBUTING.md) |
| Python 검사와 데이터·웹 검증을 CI로 실행 | 코드 오류, 결과 파일 불일치, 예제 재현 실패를 병합 전에 확인 | [CI·배포 설정](../.github/workflows/ci.yml) |
| CodeRabbit 제목·요약 생성과 한국어 리뷰 사용 | PR 설명 작성과 변경 검토 보조 | [CodeRabbit 설정](../.coderabbit.yaml) |

## 다음에 정할 내용

| 항목 | 결정할 때 확인할 내용 |
|---|---|
| 주력 연구 방향 | TabICLv2 직접 예측과 군집화 후 RCTL 예측의 구현 범위·비교 방법 |
| 연구 데이터 | 대상 셀·기간, 관측 단위, 시간 간격, 데이터 확보 방법 |
| 모델 실행 환경 | 선택한 구현의 의존성, 장치 요구 사항, 작은 표본에서의 실행 결과 |
| 웹 결과 확장 | 연구에서 필요한 예측 구간과 군집 결과의 표시 방식 |

결정되면 실행 설정과 관련 문서를 갱신하고 아래 형식으로 이력을 남깁니다.
