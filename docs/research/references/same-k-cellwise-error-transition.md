# 같은 K의 저장 오차 진단을 새 후보에 재사용할 때

[원106](../records/0136-same-k-cellwise-error-transition.md) · [원105](../records/0135-blocked-audit-and-resume-conditions.md)

같은K·모델당sample 개수는 자료 구성·최적화 경로까지 통제한 비교가 아니다. 원106의 평균 손해, 네 전이 조합, 유리한cell·날짜와 실제epoch 차이를 함께 읽는다. saved scaled MAE를 직접Tab 성능·원단위 MAE·독립 RCTL 재현과 섞지 않는다.

새 후보는 실제 손해/범위 → 경쟁 원인과 식별 한계 → Tab이 추정할 정보와 달라질 결정 → 최소 판별 비교를 적는다. 지원차이의 근거가 없으면 retrieval·거리·겹침 보정을 원인 해결책으로 추천하지 않는다. 기존 달력·일/주lag와 입력지원/위험 결과를 재사용하고 같은 계산을 반복하지 않는다. 손해가 큰4/7cell만 새평가에 고르지 않는다.

20개 날짜와 두seed는 독립20실험·유의성 검정이 아니다. 오차차이 항등식을 인과 기여율로 쓰지 않고, globalK1과 K4의 비교도 동일K 비교와 구별한다. 조건별구성 진단·학습정책/자료량 통제·가까운 조건부전이 방법과의 결정 차이는 당시 후속 조건이며 실행완료나 신규성 증거가 아니다.

추가18fit·다음Tab32context/16384행·별도600초는 계획이며 기존잔여 포함은 context/query행에 적용된다. 당시nativeGoal/heartbeat 상태는 JSON보고로만 확인했다. 원code 실행/모델·자동화 재개는 이 정리에서 수행하지 않았다.
