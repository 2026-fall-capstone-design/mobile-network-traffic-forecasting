## 검산이 확인하는 것

역사적 스크립트를 import하지 않는다. NumPy의 object 역직렬화를 금지하고 필요한 배열만 읽어 scalar 평균을 계산한다. 각 배정 후보에서는 cluster 내부 목적값 전체를 다시 계산하여 동점 규칙·두 절반 감소·비공백·목적지 이웃 제약을 적용한다. 68개 사전 의존 파일의 실제 hash를 비교하고 설정·봉인 hash, 시간 순서, 정산과 사후 alias의 원장 식별값을 대조한다.

RCTL 단계는 저장 metrics JSON과 실제 예측 파일의 SHA만 검사한다. [639 검산](pilot-002.md)에서 이미 확인한 MAE를 반복 학습하거나 재계산하지 않는다. alias가 가리키는 동일 cohort/group/seed/protocol·예측 바이트인지 확인하는 검증이다. 638 edge에는 자체 query 시각이 없어 637 공통 시점과 앞선 검산의 행 순서 근거를 사용한다.

전체 90경로의 원본 ID·크기·hash를 inventory와 대조했다. 새 보존 파일은 19개·95,120바이트이며 나머지 71경로는 기존 보존본으로 연결한다. 원본 연구의 AGENTS·state·focus·progress·candidate index·예산 원장 6개가 정리 시작 기준에서 바뀌지 않았음을 확인했다. 당시 원장 hash가 후속 기록까지 반영된 현재 원장 hash와 같다는 주장은 하지 않는다.

저장소 검사는 전체 목록 연결, 보존 byte identity, 로컬 Markdown 파일 링크를 검사한다. CI에 이번 저장 산술 검사를 추가했다. 의미 대조는 같은 정리 에이전트가 수행했으며 독립 연구자 검토나 수학 정리의 증명으로 표시하지 않는다.

## 남은 범위

641 before 상태 사본, 두 helper 코드 전체, 상위 원자료 생성 과정은 아직 읽기·내용 검증이 남아 있다. 앞선 과제의 미해결 조건(평가 분포의 p, 잡음·입력 빈도 영향, 희소 graph 밖의 관계, 원척도 반례, 신규성·일반화)은 이번 대조로 해결되지 않는다. 642 추천안의 실제 상태는 다음 기록에서 판정한다. 이 묶음의 검수·병합은 전체 아카이브 Goal 완료가 아니다.
