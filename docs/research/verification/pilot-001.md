## 저장값의 별도 계산

[검수 스크립트](../../../scripts/research_archive/verify_relation_pilot.py)는 과거 연구 코드를 import하거나 실행하지 않는다. `allow_pickle=False`로 저장 배열을 읽고 다음을 확인한다.

- 원본 ID·query 시각·입력 shape, 저장 dtype·정렬된 분위수, 완료물 바이트 동일성.
- 79개 입력 지원 mask와 절반별 최소 입력·날짜 조건, 22개 retained edge.
- 44개 모델별 edge의 truth·p 연결, 공통 mask, score 식·범위, graph 비용.
- 5,632개 혼합 중앙값을 분위수 knot 합집합의 선형 구간으로 계산하여 저장 q와 대조.
- 초기·최종 목적값, 각 이동의 출발/도착 조건·두 목적 감소, 최종 labels와 K4.

원본 폴더로 확인한 뒤, [저장소 사본의 manifest](../evidence/0635-0638/manifest.json)만 사용하는 경로로 다시 확인했다. 둘 다 통과했다. 최대 root 차이는 `1.9984014443252818e-15`였으며, 회복 행 1,853개와 공통 관계 2→22개가 일치했다. [상세 결과](pilot-001-arithmetic.json)를 보존했다.

이는 저장값의 대조다. 모델 학습·추론, 과거 연구 Goal, 예산 원장은 실행하거나 갱신하지 않았다. 원본 제어 파일 여섯 개의 해시도 초기 보존값과 일치했다.

## 팀 접근과 보존

304개 원본 경로에 대응하는 220개 고유 파일을 1,872,029바이트의 [근거 묶음](../evidence/0635-0638/README.md)으로 저장했다. 원본 해시와 사본 해시를 대조했다. 정리본·색인의 링크는 저장소 상대경로다. 원문 안의 개인 경로·상태 갱신 명령은 `.txt` 보존 자료로 구분한다.

여기서 접근 확인은 저장소 안의 자료만으로 대조가 가능하다는 뜻이다. 원격 반영은 PR·병합 확인으로 별도 관리하며 [현재 정리 범위](../README.md)와 함께 확인한다.

## 남은 항목

616의 원자료 생성·정규화, 633의 초기 소속, 512·634의 문헌·독창성, 639의 RCTL 성능은 이번 검수 범위 밖이다. 638 설정에는 상속한 `at`·`limits`가 남아 있어, 실제 실행 시각은 run 로그, 이번 상한은 `seconds_cap=12`와 코드의 `CAP`로 구분한다.

636에서 재사용한 5개 cell의 정렬 전 HGB crossing 수는 확인한 완료 요약에 없다. 637의 `crossing_rows`를 전체 14cell 값으로 확대하지 않는다. 이번 검수와 무관한 616의 다른 예측 오차 필드도 미검토다.

후속 [639 검수](pilot-002.md)에서 평균 이득, 기간별 손해, 지표 척도와 재사용 범위를 확인했다. 초기 가설·부정 결과·문헌·미실행 제안까지 시범 양식을 계속 시험한다. 전체 연구기록 정리는 진행 중이다.
