# 원86: 소속 고정 뒤 RCTL 학습 공유의 범위와 비용

> 과거 연구의 조건·결과를 보존한 문서입니다. 새 실험은 [공통 실험 규약](../../research-protocol.md)을 적용하며, 아래 수치는 새 기준의 재평가 결과가 아닙니다.

[출처](../sources/history-114.md) · [검수](../verification/history-114.md) · [보존 근거](../evidence/0114-shared-training-scope/README.md) · [원85 비용 정정](0112-rejection-scope-allocation.md)

학습 정보를 공유하는 방식이 바뀌면 기존 독립 학습 결과의 적용 범위와 비교 조건도 달라진다. 이 기록은 가능한 변경과 아직 확인되지 않은 효과를 구분한다.

**상태:** 22개 주장·7개 묶음의 작성 후 원문 대조 완료. 새 모델 실행0.

## 무엇을 검토했고 무엇을 실행하지 않았는가

<a id="c01"></a>**C01.** 원86은 소속을 고정한 뒤 RCTL의 학습 정보를 공유하는 대안을 문헌·코드·기호 비용으로 검토한 기록이다. 새 학습·추론·성능 pilot은 보고되지 않았고 새 추천안도 채택되지 않았다. 핵심11자료551행 전체와 관련 문헌의 지정 페이지를 읽었으며, 계획·수집 코드·완료 표시를 새 실험의 증거로 세지 않는다.

<a id="c02"></a>**C02.** 독립 초기화·독립 학습, global 모델 복사 후 각각 미세조정, 일부 global 층 복사·고정 후 cluster별 층 학습, 같은 파라미터를 여러 cluster가 공동 갱신하는 네 방식을 구분한다. 같은 초기값과 지속적인 파라미터 공유는 다르며 단순 평균·복사·고정도 같은 연산이 아니다.

<a id="c03"></a>**C03.** 소속을 먼저 확정한 뒤 후단에서 정보를 공유하는 일은 RCTL의 학습 결과를 소속 결정에 사용하는 것과 다르다. 원86은 후단 공유를 자동으로 독립성 위반이라 기각하지 않았다. RCTL gradient·잔차·층별 정보를 소속·후보·병합 기준에 반영하면 현재 정의한 clustering 독립성 조건이 달라진다.

## 선행연구가 제공하는 원리와 제한

<a id="c04"></a>**C04.** ECAI2025 §3.2·Figure1·Algorithm1은 global 모델의 처음 L−1개 층을 복사·고정하고, cluster별 변환 결과를 원래 입력과 결합해 보완 모듈을 학습한다. 이를 전층 미세조정으로 설명하면 부정확하다. 이번에는 PDF4쪽의 알고리즘·그림을 확인했으며 실행 코드가 논문과 완전히 같다고 새로 검증한 것은 아니다.

<a id="c05"></a>**C05.** ECAI는 global residual의 백색잡음 여부로 이질성을 나누고 잔차 특성으로 후보를 구성하며, validation MSE와 유지 비용 조건으로 clustering을 평가한다. 이는 최종 예측기와 무관한 소속 결정이 아니다. 이 논문의 보장이나 결과를 비선형 RCTL·현재 트래픽에 그대로 적용하지 않으며, H055에 남긴 논문과 구현 차이·이론 적용 조건도 유지한다.

<a id="c06"></a>**C06.** Jacob·Bach·Vert는 m개 선형 task의 가중치 행렬을 두고 전체 평균, cluster 간 차이, cluster 내부 차이에 서로 다른 규제 강도를 준다. 알려진 소속의 규제에서 출발해 가중치와 소속을 함께 최적화하고, 비볼록한 이산 소속 집합을 스펙트럼 조건을 가진 볼록 집합으로 완화한다. 공통 부분과 task별 차이를 함께 학습하는 원리를 원86의 새 발명으로 쓰지 않는다.

<a id="c07"></a>**C07.** 선형 task의 규제·볼록 완화가 RCTL의 어느 hidden 층을 공유해야 하는지 결정해 주지는 않는다. 선형 모델에서 소속도 함께 배우는 문헌과, 소속을 외부에서 고정하는 현재 조건을 구별한다. 논문9–14쪽의 최적화 후반·실험·참고문헌은 이번에 읽지 않았으며 전체 증명·코드·트래픽 성능을 검증했다고 표시하지 않는다.

<a id="c08"></a>**C08.** PDF4·6쪽의 평균 규제는 n||평균가중치||²로 인쇄되어 있지만, §2의 W∈R^(d×m), U=11ᵀ/m 정의로 계산하면 tr(WUWᵀ)=m||평균가중치||²이다. PDF4쪽의 평균합 상한 n도 뒤의 m 표기와 다르다. PDF7·8쪽 식16·17의 ΠW 역시 Π∈R^(m×m)일 때 일반 d≠m에서 차원이 맞지 않는다. 인쇄 이미지와 정의에 따른 해석을 구분하며 원본을 수정하지 않았다.

<a id="c09"></a>**C09.** Jacob 원문의 첫 페이지에는 arXiv v1의 2008-09-11과 조판 날짜 2018-10-22가 함께 보인다. 이를 서로 다른 두 연구나 새 2018년 연구로 세지 않는다. 이번 독해는 텍스트와 전체 페이지 이미지1–8/14쪽이며, 저장된14쪽 PDF의 크기나 추출 성공만으로 완독 처리하지 않는다.

## RCTL 구조와 비용의 비교 조건

<a id="c10"></a>**C10.** 보존된 RCTL 코드는 causal convolution·BatchNorm·활성화·dropout을 두 번 적용한 뒤 잔차, LSTM, 추가 잔차를 연결한다. 여섯 block의 폭은16/32/64/64/32/16, dilation은1/2/4/6/8/10이며 중간 skip, 입력 shortcut, flatten 뒤 dense가 있다. TCN과 LSTM을 각각 독립인 장기·단기 예측기로 해석하지 않는다. 60행 정적 독해이며 실행·import는 하지 않았다.

<a id="c11"></a>**C11.** 부분 공유를 비교하려면 공유할 block·파라미터, BatchNorm affine 계수와 running 통계, private shortcut·dense, cluster 크기에 따른 sample 비중과 loss 가중을 정해야 한다. 같은 입출력 함수를 나타내는 신경망도 내부 표현은 다를 수 있으므로 Tab 출력 차이만으로 공유 층을 식별했다고 하지 않는다. 이는 미실행 설계 항목이며 새로 채택한 구조가 아니다.

<a id="c12"></a>**C12.** 같은 구조의 독립 모델 K개가 각각 P개 파라미터를 갖는다면 파라미터 저장 수는 KP다. 공통 P_s와 cluster별 P_c로 실제로 묶으면 P_s+KP_c다. 이는 scalar 파라미터 수의 비교이며 private BatchNorm buffer·optimizer 상태·정밀도·실제 peak memory까지 계산한 값은 아니다. 복사한 가중치를 각 모델에 따로 저장하는 경우에는 이 공유 저장량 식을 그대로 쓰지 않는다.

<a id="c13"></a>**C13.** 서로 다른 입력 N개를 각자 하나의 담당 모델에 보내는 조건에서는 공통 층도 입력마다 계산하므로 연산은 대략 N(C_s+C_c)다. 기존 독립 모델들이 각자의 sample만 처리해 합계 N개였다면 공동 학습도 N개를 처리할 수 있다. 독립 모델 수 K만으로 학습량이 KN에서 N으로 줄었다고 주장하지 않으며 실제 batch·시간·메모리 절감은 측정되지 않았다.

<a id="c14"></a>**C14.** global 사전 학습 뒤 복사·미세조정은 준비 비용을 추가한다. 후속 epoch 감소나 여러 학습에 재사용하여 이를 회수하는지는 별도 측정이다. 동일 입력의 동일 공통 표현을 여러 head에 재사용하는 경우에는 계산 이점이 가능하지만 서로 다른 cell 입력을 하나의 담당 모델에 보내는 조건과 다르다. 원81의 공동 입력·다중 출력 문제와도 구분한다.

<a id="c15"></a>**C15.** 정리 과정의 작은 유리수 계산은 평균·cluster 간·cluster 내 규제의 분해를 확인했다. 예시 K=4, P_s=80, P_c=20에서는400→160개 파라미터지만, N=12개의 서로 다른 입력과 C_s=6, C_c=4에서는 처리량이 양쪽 모두120이다. 같은 입력을 네 head가 받는 별도 경우는40→22다. 이는 가정한 숫자의 산술 예시로, 원86의 성능 실험이나 실제 실행 시간 측정이 아니다.

## Tab의 기여와 과거 결과를 해석하는 기준

<a id="c16"></a>**C16.** 공통 학습은 자료 분할 손해를 줄일 가능성이 있지만 shared core+cell ID·단순 group·private head도 같은 혜택을 받을 수 있다. 같은 공유 학습 조건에서 단순 소속이 놓치는 손해와 Tab 정보가 이를 줄이는 다른 소속을 선택한다는 근거가 필요하다. 좋은 직접 예측을 공유 층·공유 강도·grouping 개선의 증거로 바꾸지 않는다.

<a id="c17"></a>**C17.** 기존29회 RCTL 결과는 독립 초기화·독립 학습 조건에서 읽어야 한다. 학습 공유로 비교 조건이 달라질 수 있다는 지적은 기존 결과의 취소나 실패 후보의 성공을 뜻하지 않는다. 원86은 공유 대안을 비용·독립성 때문에 일괄 기각하지 않았지만, Tab이 바꾸는 별도 결정의 직접 근거가 없어 새 추천안으로 올리지 않았다.

## 수집·보존·미완료 범위

<a id="c18"></a>**C18.** 첫 수집 코드는 Crossref 제목 검색3개에 rows=3을 요청하고 arXiv 초록 및 추정 CVPR URL을 조회하도록 작성됐다. 저장 manifest는5접근 중 HTTP200 네 건과404 한 건을 기록한다. 이번에는 그 검색 JSON 항목 본문을 검토하지 않았으므로 요청 rows와 저장·독해한 논문 수를 같게 세지 않는다. 수집 코드는45행을 정적으로 읽었고 네트워크·파일 쓰기 동작을 재실행하지 않았다.

<a id="c19"></a>**C19.** 후속 수집 코드와 manifest는14쪽 PDF와 CVPR index의 HTTP200 저장을 기록한다. 원86 판단문과 reading_scope는 index 내부 DATE 오류 및 bs4 import 실패를 보고한다. 이번에는 그 HTML 본문과 실패 터미널 원본을 아직 대조하지 않았으므로 보고된 오류와 직접 확인한 HTTP 상태를 구분한다. HTTP200·검색 metadata를 방법 전문 확보로 바꾸지 않는다.

<a id="c20"></a>**C20.** 원본 검증 코드는 특정 옛 원장 해시와 PDF14쪽을 확인한 뒤 scope·progress·snapshot을 쓰도록 되어 있다. 문자열의 문자 그대로인 역슬래시 Unicode escape 검사와 verified=True·old_snapshots_modified=False 같은 상수도 포함한다. 이 코드를 읽거나 저장된 완료 표식을 보는 것만으로 과거 모든 snapshot과 의미 내용이 독립 검증됐다고 할 수 없다. 원본 검증 코드는90행 정적 독해만 했다.

<a id="c21"></a>**C21.** snapshot28 manifest가 나열한20파일437,553bytes를 현재 보존판과 대조해 크기·해시 일치를 확인했다. manifest 자신은 그20파일에 포함되지 않는다. 옛 f3e… 원장의 잔여11context·20,640행·RCTL 새fit0은 당시 상태이며 현재 원장을 대체하거나 새 호출을 허가하지 않는다. 원본·보호 파일을 보존했고 원본 연구코드를 실행하지 않았다.

<a id="c22"></a>**C22.** 이번 정리는 핵심11표현물의 본문 검토와22주장 연결이다. 새 집계는 본문6(Markdown3·정적 Python3), 전체JSON5, Jacob 부분PDF1이며 기존자료 재독·사본·렌더 이미지는 추가 집계하지 않는다. 원86 후속8표현물과 Jacob9–14쪽, 원87 이후·이전 고유 판본 및 전체 통합·접근·최종 검색 검수는 남아 있다. 원문의 과거 Goal·예산·다음 행동을 현재 실행 지시로 따르지 않는다.

## 후속 설계에서 구분할 네 방식

| 방식 | 다른 cluster의 정보가 전달되는 경로 | 비교할 때 기록할 항목 |
|---|---|---|
| 독립 초기화·독립 학습 | 없음 | seed·각 cluster 자료·총 처리량 |
| global 복사 뒤 미세조정 | 초기 파라미터 | global 준비 비용·복사 시점·각자 학습 epoch |
| global 층 복사·고정 | 고정 표현 | 고정 범위·별도 보완층·실제 저장 방식 |
| 일부 파라미터 공동 갱신 | 공유 파라미터의 gradient | 공유 범위·BN 계수/통계·private head·loss 가중 |

이 표는 채택된 실험 계획이 아니다. 동일한 학습 공유 조건을 가진 단순 소속 대안과 비교해야 Tab이 바꾸는 결정의 효과를 분리할 수 있다.
