# 23·25 조건부 공유 비용: 예측 정확도와 소속 선택의 차이

2026-09-25의 계획23과 결과25 §1을 정리한 기록이다. **주 설정(k=32)에서 TabICL 혼합 예측의 query MAE는 KNN보다 작았지만, 기존 다섯 분할의 RCTL 오차 순위를 설명하는 데 TabICL이 더 유용하다는 근거는 얻지 못했다.** 입력별 관계 충돌 비용을 계산한 제한된 재분석이며, 새로운 소속을 만들거나 RCTL을 학습한 실험이 아니다. 전체 기록25의 recursive 예측·문헌 검토는 후속 묶음으로 남긴다. (H016-C01)

[원계획23](../evidence/0023-0025-pooling/originals/SRC-0021137.md.txt), [원결과25](../evidence/0023-0025-pooling/originals/SRC-0021188.md.txt), [출처15개와 실제 읽은 범위](../sources/history-016.md), [검수와 재사용 방법](../verification/history-016.md).

## 질문과 이전 시도의 관계

[B1](0003-b1-anchor-projection.md)은 대표 입력으로 예측을 옮기는 단계에서 오차가 커졌고, [B2](0004-0007-b2-observed-risk.md)는 관측 query의 손실표로 만든 분할이 empirical 기준보다 RCTL에서 나빴다. 23은 실제 query 입력을 그대로 두고, 그 입력에서 여러 cell이 같은 예측값을 써야 할 때의 최소 MAE 증가를 계산했다. B1의 입력 축약이나 B2의 제한된 보정 규칙을 제거해도 TabICL 분포의 도입 이유가 남는지 묻는 진단이었다. 당시 계획부터 후보를 추천안이나 새 이론으로 확정하지 않았다. (H016-C02)

cell i의 추정 분포에 저장 atom이 B개 있을 때 `L_i(a|x) = mean_b |z_ib(x) − a|`로 놓는다. 입력 x에서 cell 비중을 `w_i(x)`로 추정하고, 고정 분할 G에 대해 다음 비용을 계산한다.

```text
Δ_G(x) = Σ_{g∈G} min_a Σ_{i∈g} w_i(x) L_i(a|x)
         − Σ_i w_i(x) min_a L_i(a|x)
```

첫 항의 최적값은 **가중 혼합 분포의 중앙값**에서 얻는다. cell별 중앙값을 평균한 값이 아니다. 각 group의 질량을 따로 1로 맞춘 손실을 단순 합산하지 않으며, 원 비중이 전체 비용에 남는다. 입력 지원이 분리되면 비용0, 같은 입력에서 동일 빈도로 target0/2이면 비용1, 같은 중앙값의 대칭 분포는 폭이 달라도 비용0이라는 저장 예가 있다. 모든 cell의 target과 예측에 같은 입력 함수를 더한 경우에도 비용은 같다. 저장된 세 toy 결과와 shift 오차0을 대조했으며 새로운 무작위 모의실험은 하지 않았다. (H016-C03)

이 식은 참 조건부 분포를 아는 충분히 유연한 예측기의 관계 충돌을 표현한다. 실제 계산은 추정 분포와 추정 비중을 쓴다. 유한 자료를 합칠 때의 추정 이득, 표본 중복·의존성, RCTL 용량과 최적화는 계산하지 않는다. [08·09의 독립 표본과 중복 표본 반례](0008-0009-finite-sample-pooling.md)는 비용0이어도 pooling 이득이 달라질 수 있음을 보여 주는 기존 근거다. 이 반례를 새 실행으로 세지 않는다. (H016-C04)

## 실제로 사용한 자료와 설정

Milan 가공 hourly internet 자료의 기존 16cell을 사용했다. cell ID는 `3737, 3745, 3753, 3765, 4537, 4545, 4553, 4565, 5337, 5345, 5353, 5365, 6137, 6145, 6153, 6165`다. 각 cell의 시점0–671 평균으로 나눈 target을 사용하므로 아래 MAE는 cell별 평균으로 정규화된 척도다. 입력16개는 최근8값, 24/168시간 lag, 직전24시간 평균·표준편차, 시간·요일의 sine/cosine이다. 저장 raw·scale·날짜 문자열로 선택16cell의 저장 입력을 대조한 최대 차이는0이었다. 원 H5는 이번 묶음에서 다시 열지 않았다. (H016-C05)

context target은168–671의504개/cell, query는672–839에서 `rint(linspace(672,839,64))`로 고른64개/cell, 총1,024행이다. [기존 B1 예측](../evidence/0003-0007/originals/SRC-0023605.npz)의 앞64개 anchor를 제외하고 실제 query 예측만 재사용했다. 비교한 추정기는 TabICL의129개 midpoint 분위수 atom, 저장 중앙값 하나, cell별32-NN context target의 경험 분포다. 129개 atom은 native 전체 분포와 구분한다.

pooled context의 표준화를 고정한 뒤 가까운 context의 cell 빈도로 비중을 추정했다. 주 설정은 density k=32, 민감도 설정은16/64이며 분포용 KNN의 이웃 수는32로 고정했다. 각 cell의 context 수가504개로 같아 이 범위의 source cell 사전 비중은 같다. 비중은 입력 지원의 추정치이며 참 지원을 보증하지 않는다. query 소유 cell의 비중0은 k16에서47/1,024, k32에서30/1,024(2.9296875%), k64에서13/1,024였다. 소유 group의 전체 비중이0이면 자기 cell 분포의 중앙값으로 돌아간다. 이는 진단 규칙이며 실제 공동 학습이 아니다. (H016-C06)

분할은 [기존 RCTL 설정](../evidence/0003-0007/originals/SRC-0030238.json)의 primary seed20260925, global K1과 다섯 K4를 고정했다. 과거 RCTL은 train168–839, validation840–1007, test1008–1487이었다. **이번 query는 Tab context 밖이지만 RCTL train 안에 있다.** RCTL 결과도 이미 관찰한 상태였다. 점수 파일을 저장하고 해시를 남긴 뒤 이전 RCTL 결과를 읽는 코드 순서는 확인했지만, 이것을 독립 holdout이나 사전 맹검으로 해석하지 않는다. (H016-C07)

## float32 실패, 재개와 비용

원문25는 첫 float32 축약 계산의 비음수 비용 검사 실패와 float64 통일 후 한 번의 재개를 보고한다. [재개 marker](../evidence/0023-0025-pooling/originals/SRC-0025174.json)의 코드 해시는 [보존된 수정 코드](../evidence/0023-0025-pooling/originals/SRC-0022693.py.txt)와 같다. 다만 실패 exit1과3.8575159초는 수정 코드가 기록한 상수이며 원 실행 콘솔을 별도로 확보한 증거가 아니다. 최초 float32 판본·콘솔을 확인했다고 쓰지 않는다.

|---|---:|---|

재개 타이머는 import·초기 준비와 marker 저장 뒤 시작하고 최종 배열·summary·finish 저장 전에 끝난다. 따라서6.433936600초는 전체 프로세스 시간으로 검증된 값이 아니다. 보고값은 계획의60초/2GiB 상한 안에 있지만 연속 최고 RSS나 모든 준비·저장을 포함한 예산 준수 검증은 아니다. [초기45회 Tab 호출·29회 RCTL fit 비용](0015-0021-cumulative-costs.md)은 재사용 근거이며 이번 재분석의 신규 비용으로 중복 합산하지 않는다. 모델 호출0회가 계산 비용0이라는 뜻은 아니다. (H016-C11)

## 재사용과 남은 확인

[검산 도구](../../../scripts/research_archive/verify_conditional_pooling_history.py)는 저장54행·9개 순위·114개 배열의 집계와 자료 연결을 대조한다. Tab 분포/중앙값의36조건은 원 코드의 중앙값 선택 후 절대손실 합산과 다른 CDF 적분식으로 비용을 계산하고, 저장 예측이 가중 중앙값의 최적성 조건을 만족하는지 확인했다. 최대 비용 차이는 약1.16×10⁻¹³이었다. density의 최근접 이웃을 원자료에서 다시 찾거나 KNN atom을 재구성한 검사는 아니다. 정규화·특징 대조도 저장 raw와의 비교이며 원 H5의 신규 검수로 세지 않는다. (H016-C12)

같은 실험을 다시 설계하기 전에 이 저장 분포·비중·소속·예측과 [08·09 반례](0008-0009-finite-sample-pooling.md)를 재사용한다. 새 질문이 있다면 입력·source와 target의 cell 비중·표본 의존성·독립 평가 기간·최종 learner 중 무엇이 달라지는지 먼저 적는다. 서로 다른 추정기의 cost 크기, 직접 예측 MAE, 최종 RCTL 성능을 하나의 성공 기준으로 섞지 않는다.

24의 frozen recursive 진단,25 §2·§3와 후속 판단의 전체 연결, density/KNN 생성 과정의 수치 재구성, 최초 실패 콘솔, 이후515/521/524 등의 관련 기록은 이번 검수 완료 범위 밖이다. 원문25를 전부 읽은 것과 이들 주장을 검증한 것은 다르다. 원문의 과거 Goal·예산·다음 행동은 당시 연구 상태이며 현재 실행 지시로 사용하지 않는다.
