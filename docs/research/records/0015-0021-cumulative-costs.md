# 15·21 — 초기 누적 호출과 시간 측정 범위

2026년 9월 25일 흐름의 비용 문장을 저장된 호출·종료 기록과 다시 연결했다. **기록21까지의 TabICL 완료 호출은 45회, 호출별 query 합계는 35,712행, 저장된 fit+predict 경과시간 합은 223.886886초**다. 이는 전체 연구시간이나 서로 다른 관측 수가 아니다. 같은 초기 RCTL 결과의 29fit·1,565epoch도 별도로 집계한다. 이 아카이브 작업에서는 모델을 실행하지 않았다.

원문 [15의58행](../evidence/0013-0015/originals/SRC-0020972.md.txt)의 개별 비용·누적 호출 수와 [21의70행](../evidence/0018-0021/originals/SRC-0021095.md.txt)의 누적 값에 대조했다. 원문의 세 자리 반올림 값도 일치한다. [출처28개와 실제 읽은 범위](../sources/history-015.md), [저장값 검산](../verification/history-015-cost-check.json), [주장 대조](../verification/history-015-primary-review.json)를 함께 본다. 후속 연구·실패 시도의 전수 비용과 기록15·21 전체 통합은 아직 끝나지 않았다.

## 호출 수와 query 행의 단위

여기서 1회는 원 로그의 한 context 준비(`fit`)와 이어지는 예측(`predict`) 쌍이다. 고유 cell 수, foundation model을 새로 학습한 횟수, 문서 번호와 다르다. B1/B2는 cell별 context이고, 14/19/20은 여러 cell의 행을 합친 context를 조건마다 다시 준비한다. 같은 cell·시각·자료가 여러 조건에서 반복될 수 있다. **H015-C01**

초기 [공식 구현 검토](0005-official-tabicl-audit.md)에서 확인한 고정 회귀 경로의 `fit`은 checkpoint·변환·ensemble 준비를 포함하며, cell 자료로 foundation-model 가중치를 최적화하는 학습이 아니다. 아래 시간은 당시 CPU 실행에서 `perf_counter`로 잰 경과시간이다. CPU 사용량을 코어별로 합산한 시간이 아니다. 같은 ensemble1이라도 context·query·출력 종류와 자료가 달라 이 표만으로 모델 간 속도 우위를 판단하지 않는다. **H015-C02**

표의 시간은 저장 원값을 먼저 합산한 뒤 소수점 여섯 자리로 반올림했다. 반올림한 fit·predict 열을 다시 더한 값과 마지막 자리가 다를 수 있다.

B1의 한 호출은 공통 anchor64개와 16cell×64개의 실제 query, 합계1,088행을 예측한다. 이를 16개 context에서 반복해17,408행으로 센다. 14의1,024행도 세 입력 조건에서 반복한다. 따라서 전체35,712행을 고유 관측·독립 표본으로 쓰면 안 된다. B1의 교차 예측 비용을 cell 자신의 query만 계산하는 B2와 같은 조건으로 비교하지 않는다. [B1 조건](0003-b1-anchor-projection.md), [14 조건](0013-0015-transfer-cell-identity.md). **H015-C03**

## 모델 호출 시간과 단계 시간의 차이

모든 TabICL 호출 타이머는 estimator 생성 뒤 시작하고, 호출 결과 저장·성능 집계·별도 비교 모델 적합 전에 끝난다. 19의 `np.asarray` 변환과20의 최근 관측값을 더해 원 target 척도로 복원하는 연산은 해당 `predict_seconds` 안에 들어간다. 01의 자료 구성·앞선32개 Ridge 진단과 각 smoke 뒤의 대응 Ridge 적합도 TabICL 시간 밖이다. 타이머 경계는 코드를 정적으로 확인했으며 당시 실행시간을 다시 재현하지 않았다. **H015-C06**

단순 모델 시간은 Ridge와 HGB의 생성·적합·예측 구간이며,14는각2조건,19는각3조건,20은각2조건이다. `stage_seconds`에는 해당 단계의 TabICL·단순 모델·중간 처리 시간이 함께 들어가므로 이 세 열을 더하면 중복 계산이다. B1/B2에 단순 모델 시간 필드가 없다는 것은 비용0이라는 뜻이 아니다. **H015-C07**

B1의 stage 타이머는 scaler/KMeans와 anchor 준비 뒤, B2는 scaler/KMeans·공통 Ridge 준비 뒤 시작한다. 14·19·20은 설정 기록 뒤에 시작하며 최종 summary·예측 묶음·종료 파일 저장 전에 끝난다. 따라서 stage 시간도 프로세스 시작부터 끝까지의 전체 wall time은 아니다. 13은 자료 로드 전에 시작하고 결과 JSON 저장 전에 끝난다. 이 서로 다른 측정 구간을 모두 합쳐 전체 연구시간으로 표시하지 않는다. **H015-C08**

## 초기 RCTL29fit의 별도 원장

같은 [B2 후속 RCTL](0004-0007-b2-observed-risk.md)의 완료 결과를 재사용한다. 한 fit은 특정 method·seed·cluster 조합의 최종 예측기 한 개다. 첫 seed에 global1+다섯 partition×4=21fit, 두 번째 seed에 Tab/empirical×4=8fit이다. 02의 초기 계획과 달리04에서 두 번째 seed의 비교군을 empirical로 사전에 바꿨으며, 계획과 실행을 혼합하지 않는다.

RCTL의 개별 `fit_seconds`는 그룹 자료·모델·옵티마이저를 만든 뒤 시작하고, 학습과 에폭별 validation, 최선 상태 복원, test 추론, 예측·checkpoint·history 저장 및 오차 계산을 포함한다. 이후 fit 결과 JSON 저장과 로그는 개별 타이머 밖이지만 전체 타이머 안이다. 전체 타이머는 설정 파일 저장 이후·H5 로드 이전에 시작하고 최종 종료 파일 저장 전에 끝난다. 따라서1,652.177200초를 순수 학습 시간으로 쓰지 않는다. [SRC-0023202](../evidence/0003-0007/originals/SRC-0023202.py.txt). **H015-C10**

## 상한·누락 비용·재사용 조건

02가 정한 TabICL80context/60,000query/40분, RCTL29fit/2,320epoch/50분과 전체 local modeling100분은 **당시 실행 상한**이다. 04는 이 상한을 유지하며 비교군을 수정했다. 상한을 실제 사용량으로 전사하거나 현재 정리 작업의 실행 허가로 사용하지 않는다. [SRC-0020823](../evidence/0001-0002/originals/SRC-0020823.md.txt), [SRC-0020825](../evidence/0003-0007/originals/SRC-0020825.md.txt). **H015-C11**

이 원장은 확인한 완료 로그의 합계다. 설치·다운로드·자료 준비·대기·문헌 검토·검수, 타이머 밖 저장, 초기 실패·재시도 전체를 포함한 총비용은 확인되지 않았다. 값이 없으면 미기록/미확인으로 남기며0으로 채우지 않는다. 전체 프로젝트에서 다른 호출이 없었다거나 이후에도 누적45회였다고 주장하지 않는다. 당시 상한 준수의 전수 감사나 다른 하드웨어에서의 속도 재현도 아니다.

같은 결과를 찾을 때는 단계·source_id·SHA256과 `method/seed/cluster` 또는 호출 조건을 함께 확인한다. 새 실험에는 실제로 바뀐 자료·context·출력·cache·장치·시간 측정 구간을 적고, 재사용 결과와 새 호출을 별도로 집계한다. [검수 범위](../verification/history-015.md), [과거 시도 색인](../prior-attempts.md).
