# 47 유용한 입력과 함께 학습할 cell은 같은가

2026-09-26의 47번은 **다른 cell의 과거를 입력에 추가하는 일**과 **다른 cell의 학습 표본을 합치는 일**을 구분했다. 예측 의존 graph를 곧바로 RCTL 소속으로 바꾸는 방향은 당시 추천하지 않았다. 입력 정보의 효용만으로 공동 학습 함수의 적합성이 보장되지 않고, 기존 문헌과의 차이 및 계산 비용도 설명해야 했기 때문이다. 이는 모든 공간 입력을 기각하거나 새 최종 연구 방향을 확정한 기록이 아니다.

[원문 47](../evidence/0045-0046-input-stability/originals/SRC-0021660.md.txt) 전체와 선택한 1차 근거를 대조했다. 46의 저장 예측 수치·당시 원장·실행 상태는 [45–46 기록](0045-0046-input-stability.md)에 있다. 이번 페이지는 47 §1·§3–6·§7 문헌 접근을 연결한다. 원 코드 실행·새 모델 학습·추론·forward·난수 실험은 0이다. [출처와 열람 범위](../sources/history-028.md), [주장별 검수](../verification/history-028.md)

## 입력 열과 학습 행을 먼저 구별한다

| 행동 | 바뀌는 것 | 소속 설계에서 답해야 할 질문 |
|---|---|---|
| sample pooling | 한 함수를 추정하는 학습 행의 공급원 | 두 cell이 같은 입력 의미와 조건부 예측 함수를 공유하는가 |
| input sharing | 예측할 때 관측하는 입력 열 | 어느 cell의 어느 시각 값을 어느 열에 놓고, 실제 예측 시점에 얻을 수 있는가 |
| 모든 군집 구성원의 이력 연결 | 군집 크기에 따라 입력 폭이 바뀜 | 입력 폭·첫 층 구조·매개변수 수를 어떻게 맞출 것인가 |
| 고정된 상대 위치 이웃 입력 | 각 target 주변의 정해진 역할을 사용 | 같은 군집의 서로 먼 target은 서로 다른 실제 이웃을 쓴다는 점을 어떻게 다룰 것인가 |

UPC 원논문 IV.A의 cell별 sliding sequence와 [고정 commit의 GECOS 코드](https://github.com/Superint-Lab/GECOS/blob/a7519dde9d6f5deb3006689df047d99ea0dac7b7/main.py)를 함께 확인했다. 공개 `main.py`는 `Input(shape=(self.steps, 1))`와 `Dense(1)`을 쓴다. 중간 Conv1D의 여러 filter는 학습한 내부 채널이며 원자료의 여러 cell 입력 채널이라는 뜻이 아니다. 같은 cluster에 속한다고 여러 cell 이력이 동시에 입력 열이 되는 것으로 해석하지 않는다.

공개 파일은 `x_train/y_train`을 외부에서 받고 전체 군집 데이터 로더를 제공하지 않는다. 따라서 코드의 입출력 모양과 cell별 시퀀스 설명을 확인한 범위이며, 논문의 전체 전처리·학습을 재현한 것은 아니다. 두 로컬 사본의 동일 해시와 [기존 공식 코드 대조](../verification/pilot-005-document-review.json)를 재사용했다. UPC PDF는 [원논문 DOI](https://doi.org/10.1109/TNSM.2025.3599168)의 보존본 6–7쪽을 다시 읽었으며 신규 전논문 독해로 세지 않는다.

## DIC-ST: 군집화의 대상과 graph의 역할

[DIC-ST 원논문](https://doi.org/10.3390/rs14061439)은 Remote Sensing 14(6), 1439, 2022-03-16 출판본이다. 저장 PDF의 선택 구간에서 확인한 자료는 **실제 기지국 22개·100일·시간별 downlink GB**다. 이 프로젝트의 Milan HDF5 실험과 다른 자료다.

각 기지국 시계열을 EMD로 분해하고 IMF의 entropy·스펙트럼 피크 수를 사용해 추세·주기·본질 성분으로 묶는다. 논문은 이 절차를 KNN, K=3으로 표기한다. 이때 군집화 대상은 **IMF이며 UPC의 cell partition이 아니다**. 성분별 transfer entropy(TE) 관계를 graph로 만들고 기지국을 node로 하는 2층 GCN으로 예측한 뒤 세 성분을 합친다. 본문은 `T×22` 자료와 입력 전치를 설명한다. squared loss로 학습하며, §4.3은 train:test 3:1·10일 예측·batch 128·300 iterations를 기록한다.

Table 2의 값을 그대로 옮겼다. RMSE/MAPE는 해당 논문의 척도이며 이 프로젝트의 정규화 MAE와 직접 비교하지 않는다. 원 예측 출력은 재현하지 않았다.

| 원논문 조건 | 기지국1 RMSE | 기지국1 MAPE | 기지국2 RMSE | 기지국2 MAPE | 기지국3 RMSE | 기지국3 MAPE |
|---|---:|---:|---:|---:|---:|---:|
| DIC-ST | 2.1952 | 43.5132 | 2.141 | 23.7567 | 1.9206 | 21.2691 |
| DIC-ST (no causality) | 3.5753 | 97.5417 | 2.3824 | 29.2335 | 2.4058 | 40.009 |
| ARIMA | 4.1138 | 104.2443 | 2.3028 | 46.5367 | 2.3538 | 25.2774 |

세 기지국에서 graph 조건의 RMSE가 더 작다는 선행 결과는 보존한다. 이 결과가 UPC식 cell 분할이나 동일 RCTL로의 표본 병합을 입증하지는 않는다. 관측 시계열의 TE를 개입 효과의 인과 증명으로 해석하지도 않는다.

재사용 전에 풀어야 할 원문 표기와 범위는 다음과 같다.

- 식 11은 `Ci(t)`를 예측하며 `Cj`의 과거를 추가하지만 화살표는 `Ci→Cj`다. 구현에서 edge 방향을 그대로 확정하기 어렵다.
- 식 13은 양방향 TE의 **비율 ≥1**, Algorithm 2는 **TE 값 자체 ≥1**로 적는다. Algorithm 2에는 절대값 기호가 없다. 47의 “절대값”은 비율 대신 값 자체의 문턱이라는 취지로만 읽으며 `abs(TE)` 연산으로 구현하지 않는다.
- §4.3 본문은 비교군을 `BIC-ST (no causality)`, Table 2는 `DIC-ST (no causality)`로 쓴다. 표의 이름을 보존하고 이 차이를 남겼다.
- EMD·graph 추정의 정확한 절단 시점이 예측 분할과 어떻게 연결되는지는 선택 구간에서 명료하지 않다. 미래 누출이 있었다고 확정하지 않는다. 현재 설계에 옮길 때는 예측 시점 이전 자료로 입력과 graph를 만들 수 있는지 따로 정해야 한다.
- Algorithm 2의 쌍 계산과 세 겹 순회 비용을 포함해야 한다. 대규모 자료에서 빠르다는 실측 근거는 이번 기록에 없다.

17쪽 Data Availability는 `Not applicable`로 적는다. 선택한 본문에서 공개 원자료·코드 링크를 확인하지 못했으며, 모든 사이트에 코드가 없다는 전수 조사 결론은 아니다. 시계열 분해와 예측 관계 graph의 결합 자체를 새 기여로 주장하거나, 표기 수정만을 신규성으로 제시하지 않는다는 것이 당시 반영점이다.

## Markov boundary: 입력 집합의 이론과 실제 회귀기를 구별한다

[The Good, the Bad, and the Ugly of Markov Boundary for Tabular Prediction](https://arxiv.org/abs/2605.29411v2)의 **2026-08-19 v2**를 확인했다. arXiv는 CIKM 2026 accepted로 표기한다. 3,450개 합성 SCM task, 6개 SCM 계열·6개 회귀기, task당 표본 1,000개인 연구다. 실제 통신 트래픽 실험이 아니며 고정된 평가 설정의 결과다. 원 task 결과를 다운로드하거나 코드를 실행하지 않았다.

Theorem 2.2는 Markov·faithfulness·product support의 양의 밀도·train/test 동일 DAG·각 boundary 좌표의 비퇴화 조건부 평균 영향 등의 가정 아래 **MSE의 Bayes 예측 충분성·최소성**을 다룬다. 모든 열을 쓰는 집합도 충분할 수 있다. 모집단에서 충분하다는 사실만으로 유한 자료의 모든 학습기가 같은 성능을 낸다는 결론은 나오지 않는다.

Proposition 3.2의 Gaussian 선형 OLS 예에서 초과 위험은 `σ²p/(n−p−1)`이다. 올바른 선형 모형·train/test의 같은 양의 정부호 공분산·`n>p+1` 등의 조건이 있다. 전체 F개와 boundary k개의 차이의 선도항은 `σ²(F−k)/n`이다. 이를 F=1,000·n=1,000인 비정규화 OLS나 신경망·RCTL·MAE에 그대로 적용하지 않는다. Proposition 5.1의 필요한 신호 누락과 불필요한 열 추가 비용, Proposition 5.2의 boundary 상위집합 충분성 역시 모집단 정보와 실제 추정 비용을 구별해서 읽는다.

다음은 Table 2의 **F=200** 두 행이다. Win은 전체 입력보다 예측이 좋아진 task 비율이며 오차 감소량이 아니다. 시간과 Completion은 논문이 보고한 추정기 결과다.

| 추정기 | F1 | Precision | Recall | Win/Ridge | Win/TabPFN | Win/XGB | 시간(s) | Completion |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Grow-Shrink | 0.633 | 0.570 | 0.752 | 98.9% | 37.4% | 77.9% | 8.1 | 100.0% |
| HITON-MB | 0.588 | 0.818 | 0.485 | 58.0% | 1.1% | 55.8% | 8.0 | 98.9% |

같은 추정 입력 집합도 회귀기에 따라 이득이 다르다. 이 표에는 추정 mask의 **TabICL Win 열이 없으며**, TabPFN 수치를 TabICLv2의 결과로 바꾸지 않는다. 참 SCM boundary를 이용한 분석과 실제 추정 boundary의 분석도 구별한다. 누락/추가 개수에 따른 gain 그림은 회귀기와 실험 조건에 따른 관측이지, 같은 오류 개수이면 같은 위험이라는 법칙이 아니다.

§7의 boundary head와 예측 손실을 함께 학습하는 구조는 **후속 학습 방향 제안**이다. 이 논문이 새 causal/tabular foundation model을 구현했다거나 공개 frozen TabICLv2가 이미 제공하는 API라는 뜻이 아니다. 정확한 TabICL checkpoint/API·세부 학습 예산까지 이번 선택 구간에서 확정하지 않았다. 당시 반영점은 TabICL이 유용하다고 고른 입력을 RCTL의 최적 입력으로 간주하지 않고, 필요한 신호의 누락과 열 추가의 비용을 나누어 보는 것이다.

## 입력 의존성이 공동 함수의 충분조건이 아닌 논리 반례

실제 트래픽이나 적합 결과가 아닌 조건부 예측 함수의 예다. 가장 최근 한 시점의 중심화 값만 사용하고 다음과 같이 둔다.

```text
a_next =  0.5 b + εa
b_next = −0.5 a + εb
```

여기서는 영평균 Gaussian innovation이 cell 간·시간 간 독립이고 과거와도 독립이며, 같은 양의 분산 `σ²`를 갖는다고 명시한다. 전이행렬 `A=[[0,1/2],[-1/2,0]]`는 `AᵀA=I/4`로 안정적이다. 정상 공분산 `Σ=(4/3)σ²I`는 `Σ=AΣAᵀ+σ²I`를 만족한다. 두 좌표는 정상 Gaussian 분포에서 독립이고 분산이 같다. [정확한 유리수 대수 확인](../verification/history-028-logic-check.json)

각 target에 대해 입력을 `[자기 값, 상대 값]`으로 놓으면 입력 분포는 같다. A의 조건부 중앙값은 `+0.5×상대 값`, B의 것은 `−0.5×상대 값`이다. 상대 값이 0일 확률은 0이므로 **cell 구분 없는 함수 하나**가 두 조건부 중앙값을 동시에 표현할 수 없다. 상대 cell이 양방향으로 유용하다는 사실은 같은 함수를 공유하기 좋은 cell이라는 충분조건이 아니다.

cell ID·입력 역할 구별 또는 다른 이력 구성을 넣으면 이 반례의 전제가 달라진다. 모든 multivariate RCTL의 실패나 유한 표본에서 pooling이 반드시 손해라는 주장이 아니다. 이 예에 seed·적합 횟수·실측 MAE는 해당하지 않는다. 난수 생성이나 시뮬레이션도 하지 않았다.

또한 정적 graph의 boundary에는 target의 자식이 포함될 수 있다. 미래 target 뒤에 생기는 관측을 현재 예측 입력으로 가져올 수는 없다. 먼저 예측 시점에 관측 가능한 열의 집합을 고정하고, 그 안에서 정보와 학습 단위를 논해야 한다.

## TabICLv2의 가능한 역할과 계산 규모

47이 검토한 역할은 동일 context 행·target·query 시간에서 **입력 열만 바꾸어** 다른 cell의 과거가 주는 추가 정보를 비교하는 것이다. 기존 sample 교체 점수와 다른 질문이며 당시 이 Tab 계산을 실행하거나 채택하지 않았다.

cell마다 자기 입력 1개와 후보 k개의 입력을 각각 비교하는 한 차례의 방식은 `N(k+1)` context를 만든다. k=8, context 256행, query 64행, ensemble 1이라는 가정의 산술은 다음과 같다.

| cell 수 N | context 구성 수 | query 예측 행 수 |
|---:|---:|---:|
| 128 | 1,152 | 73,728 |
| 1,024 | 9,216 | 589,824 |
| 10,000 | 90,000 | 5,760,000 |

특정 비교 방식의 작업량이며 **모든 알고리즘의 보편적 하한이나 실행시간 측정치가 아니다**. 시간 블록 반복·입력 조합·군집 갱신·후보 검색·전처리 비용은 포함하지 않았다. 입력 열과 전처리가 바뀐 context들이 하나의 cache를 그대로 공유할 수 있다고 가정하지 않는다. 자기/모든 이웃의 `2N` 비교는 가능하지만 그때의 질문은 개별 후보 선택 대신 이웃 묶음 전체의 효용이 된다.

## 당시 판단과 다음 연구를 구별하는 기준

47은 “TabICLv2로 예측 의존 graph를 구해 연결된 cell을 같은 RCTL로 묶기”를 현 상태에서 추천하지 않았다. 이유는 입력 열의 정보와 학습 행의 병합이 다른 문제라는 점, 성분별 예측 graph를 이미 사용한 통신 선행연구가 있다는 점, [46](0045-0046-input-stability.md)의 일부 긍정 결과에도 회귀기·주 사이의 유지가 제한적이었다는 점이다. HGB의 작은 다음 주 개선과 Ridge의 악화를 모두 보존한 판단이며 공간 신호의 전면 부정은 아니다. 새 전체 방향·최종 Word는 당시 미완성으로 기록됐다.

재검토할 때는 회복하려는 관측 정보, 실제 가용 시각과 열의 역할, 입력 구성이 RCTL의 공동 학습 단위와 맞는 이유, 다른 회귀기로의 전달 여부, 독립 기간과 규모 비용을 구체적으로 바꿔 설명해야 한다. 기존 결과를 같은 조건으로 다시 돌리거나 점수 이름만 바꾸는 것으로 차별점을 대신하지 않는다. 이는 기록에서 얻은 설계 제약이며 새 실험을 실행했다는 뜻이 아니다.

보존된 접근 로그는 MDPI 직접 요청 2개의 403, 출판사 정적 PDF의 200, Markov PDF/HTML/abs의 200을 확인해 준다. 47이 언급한 후속 웹 429·OpenReview/PMC challenge는 이 로그만으로 별도 검증하지 못했다. CLPREM·temporal causal PFN은 당시 검색 발견이며 여기서 본문 검토 완료로 세지 않았다. 47의 옛 Goal 유지·잔여 예산·다음 행동은 역사적 상태로 보존했다.

두 PDF의 선택 텍스트 20쪽·시각 확인 6쪽과 UPC 2쪽 재독을 연결했다. 전논문·별도 TXT/HTML의 고유 내용·모든 관련 보고서·후속 75번까지 완료한 것은 아니다. 소스 버전과 접근 경로는 [근거 묶음](../evidence/0047-input-sharing-roles/README.md)에 있고, 남은 범위는 [H028 출처](../sources/history-028.md)에 남겼다.

후속 [75의 입력 공유 재진입](0072-0075-output-compression.md)은 이 기록과의 중복을 확인하여 새 모델 실행 전에 중단됐다. 74의 공통28열에서 좋은 Tab 직접 예측을 얻었다는 사실만으로 자기 입력 대비 공간 입력의 이득을 확인했다고 볼 수 없다.
