# 원84 근거 종합: 직접 예측·소속 결정·최종 RCTL을 구별하기

[출처](../sources/history-110.md) · [검수](../verification/history-110.md) · [당시 보고서의 팀용 사본](../evidence/0110-evidence-synthesis/team-report.md) · [수치 대조](../evidence/0110-evidence-synthesis/evidence-comparison.json)

새 설계를 논의하기 전에 어떤 성과가 있었고 어떤 연결이 아직 확인되지 않았는지 찾는 중간검토다. 직접 예측의 이득을 유지하면서 소속 결정과 최종 예측기의 개선 여부를 각각 확인한다.

**상태:** 26개 주장·7개 묶음의 작성 후 원문 대조 완료. 원본 코드·모델 실행0.

## 읽은 범위

<a id="c01"></a>**C01.** 원84는 2026-09-26의 근거 종합·교수 검토용 중간 문서다. 이번에는 계획·findings·보고서3본문, 보조JSON4개, 생성·보관 코드2개의 총9고유 자료1109행을 읽었다. 16개의 동일 사본 경로를 연결하며 새 독립 실험9회를 뜻하지 않는다. DOCX·저장 PDF·PNG5장·고유 누적연혁8그룹은 후속 독해로 남겼다.

<a id="c02"></a>**C02.** 당시 계획과 findings는 새 TabICLv2/RCTL 실행·새 자료 진단0, 정수 작업량 산술·기존 JSON 대조·문서 생성·보관을 기록한다. 원본 코드는 이번에 텍스트로만 읽었다. 원문의 과거 Goal·예산·사용자 질문·다음 행동을 현재 연구 실행 지시로 사용하지 않는다.

## 세 가지 평가를 구별한다

<a id="c03"></a>**C03.** 원74의 값은 cell4개, 공통 입력28열, 고정 context256행으로 비교한 결과다. 전체 query336시간 가운데 뒤168시간의 정규화 MSE/MAE이며 1시간 ahead rolling 예측이다. 원래 설정의 seed는20260925다. 전처리·시간 분할의 상세 검수는 H070에 연결한다.

<a id="c04"></a>**C04.** 원74의 Ridge MSE/MAE는0.014360/0.089565, HGB는0.011925/0.078400, TabICL은0.009580/0.066828이다. 원84가 복사한 전체 teacher 객체는 기존 결과와 일치하며 표의 여섯 반올림 값도 맞다. 공통 입력에서의 국소 직접 예측 이득이고 공간 입력의 인과 효과나 clustering 개선을 검증한 결과는 아니다.

<a id="c05"></a>**C05.** 원80의 teacher 평가는16cell·시간672–839의 개발 구간이다. TabICL MSE/MAE0.0130434764/0.0774403728, Ridge0.0158390254/0.0900110079, HGB0.0158616659/0.0877404634이며 원74의 표와 합쳐 평균내지 않는다. Tab 출력은 저장129개 분위수의 평균 근사로 API의 정확한 mean과 다르며 새 Tab context/query는0이다.

<a id="c06"></a>**C06.** 원80에서 Tab의 cell MSE는 HGB보다16/16개에서 낮고 Ridge보다15/16개에서 낮다. 예외6153에서는 Tab0.0307530347, Ridge0.0246902515로 Ridge가 더 낫다. 평균 이득을 모든 cell 또는 MAE의 동일한 승패로 확장하지 않는다. 이는 저장된 cell MSE의 비교이며 모델을 다시 실행한 결과가 아니다.

<a id="c07"></a>**C07.** input_only·raw_joint·TabICL·Ridge·HGB 다섯 방법만 같은 K4 partition이며 저장 ARI는1이다. untrained_probe의 ARI는0.375, PCC와 random은0.0625, global은0이다. findings는 처음 검사가 PCC/random/untrained까지 포함해 실패한 뒤 범위를 고쳤다고 보고한다. 최종 코드·결과에서는 다섯 방법을 확인했지만 최초 실패 코드·로그는 이번에 확보하지 못했다.

<a id="c08"></a>**C08.** 원07의 RCTL 비교는16cell·평가480시간의 cell별 정규화 MAE 평균이다. K4에서 seed20260925의 empirical/Tab은0.081600/0.087328, seed20260926은0.083516/0.087760이다. 두 seed는 같은 평가자료를 쓴 것이며 독립 데이터셋 두 개가 아니다. 원84의 여덟 조건별 요약과 보고서 네 값은 저장 결과에 일치한다.

<a id="c09"></a>**C09.** Tab partition의 RCTL MAE는 empirical보다 각각7.02%,5.08% 높았다. 저장 paired 비교의 개선 cell 수는 각각6/16,7/16이므로 모든 cell이 악화됐다고 말하지 않는다. 저장 퍼센트와 평균값으로 다시 계산한 float64 비율에는 작은 반올림 차이가 있지만 두 자리 표기는 같다. 이번 작업은 저장 수치 비교이며 새로운 성능 측정이 아니다.

<a id="c10"></a>**C10.** global K1의0.071068은 당시 primary seed에서 모든 시험 K4 평균보다 작았지만 같은 K의 비교군은 아니다. balanced PCC도 UPC와 같지 않다. 이미 사용한 Milan 구간은 후속 설계의 개발 자료이며 독립 최종 test가 남았다고 표시하지 않는다. 원74·원80·RCTL의 기간·cell·출력·척도를 구별한다.

## 남은 연구 판단

<a id="c11"></a>**C11.** Tab 직접 예측이 좋다는 사실만으로 다른 모델의 공동 학습 이득을 보장할 수 없다. 보고서는 다른 함수도 유한한 학습 용량에서 같이 배울 수 있고 비슷한 함수라도 표본 중복으로 이득이 작을 수 있다는 가능성을 설명한다. 이를 새로운 실험이나 증명으로 읽지 않는다. 필요한 근거는 Tab 정보가 단순 대안과 다른 유용한 결정을 만들고 최종 RCTL에 이득을 주는지다.

<a id="c12"></a>**C12.** 보고서는 HCP의 분리·결합 학습 검증, RMB-CLE의 교차 예측 profile, ETAP의 gradient·실제 이득 차이, Traffic Matrix의 random/global 비교를 남은 판단과 연결한다. 기존 문헌 검수에 이어 읽으며 이번에 네 논문을 새로 전부 검증하거나 실험을 재현했다고 세지 않는다. RCTL 정보를 소속 판단에 쓰는 설계는 기존 독립 조건과도 대조해야 한다.

<a id="c13"></a>**C13.** 시각·요일·주기 lag는 이미 공통 입력에 반영할 수 있다. TabPFN-ST-AR의 도로 결과를 cell 통신량 성능으로 옮기지 않는다. 과거 관측 lag를 공유하는 rolling sample은 그 자체로 미래 target 누수가 아니며 표본 의존성과 누수도 다르다. 시간 간격을 늘리는 선택에는 실제로 줄일 의존성·비용 근거가 필요하다.

## 작업량은 실행 시간과 다르다

<a id="c14"></a>**C14.** M256·Q64·k16을 가정한 N128/1024/10000의 모든 교차 query 행 수는1,040,384/67,043,328/6,399,360,000이다. 방향 후보만 보면131,072/1,048,576/10,240,000, 선택한 관계의 양방향 상한은262,144/2,097,152/20,480,000이다. 표의 아홉 수치와 JSON의21개 작업량 수치를 정수 산술로 대조했다. 실행 시간이나 확정한 최적 설정이 아니다.

<a id="c15"></a>**C15.** 교차 query는 N(N−1)Q, 자기 평가 query는 별도 NQ, 방향 후보는 NkQ다. 중복 제거한 무방향 관계 수는 min(Nk,N(N−1)/2) 이하이고 양방향 query는 그 두 배에 Q를 곱한다. 상호 후보 선택을 가정해 Nk/2라고 둘 수 없다. 고정된 cell context의 준비 횟수N과 총 context행 NM도 query행과 따로 센다.

<a id="c16"></a>**C16.** 고정 context의 cache 재사용과 context를 교체·병합한 뒤의 재준비를 구별한다. 후보 탐색이 모든 쌍을 먼저 보면 전체 과정을 선형이라고 할 수 없다. k16은 예시이며 후보 축소로 중요한 관계를 놓치는지 별도 확인해야 한다. 원84는 이 원칙을 최종 신규 clustering 알고리즘으로 제안하지 않았다.

## 재검토 조건

<a id="c17"></a>**C17.** 당시 완료표는 실행 환경·checkpoint 확보와 국소 직접 예측 이득을 확인한 반면, 채택할 유용한 clustering 결정·Tab clustering의 RCTL 개선·최종 추천 방향·사용 기간의 독립 test는 미완료로 두었다. 보고서 완성과 연구 목표 달성을 구별한다.

<a id="c18"></a>**C18.** 실제 통신망의 운영 제약 답변은 기록되지 않았다. 이를 임의로 채우지 않는다. global·계절·lag·정규화 이후에도 남는 손해와 기존 실패 원인을 바꾸는 결정을 먼저 정의하고, 좋은 cell을 결과를 본 뒤 고르는 방식으로 새 검증을 만들지 않는다. 후속 실험에는 기존 기록과 바뀐 조건을 연결해야 한다.

<a id="c19"></a>**C19.** 실행 입력은 hourly 가공 자료이며 원10분 자료와 다르다. 활동 cell 선택과 PCC balanced의 비교를 UPC 전체 재현과 구별한다. 보고서가 고정한 TabICL checkpoint는 tabicl-regressor-v2-20260212.ckpt, 공식 코드 commit은0dbff3ec8fc68c123c87af77b0ea8b25cd2d23f3이다. 별도로 RCTL Torch port의 복사 가중치 forward 일치를 확인했다는 보고가 RCTL 학습 경로의 동일성까지 검증한 것은 아니다.

## 예산·문서·보관의 판본

<a id="c20"></a>**C20.** 원84는 당시 누적 원장 SHA-256 f3e370…을 인용하며 Tab 잔여11context·20,640query행, 새 RCTL fit0을 기록한다. 현재 같은 원장 경로의 해시는17a549…이며 정리 시작 때의 보호 기준과 같다. 이번 대조는 f3e370…과 같은 보존 원장을 사용했다. 당시 값과 현재 판본을 혼동하지 않으며 이 값은 추가 모델 실행 허가가 아니다.

<a id="c21"></a>**C21.** build_synthesis_84.py는 저장 결과·원장 검사를 거쳐 근거 JSON, Markdown, Word를 작성한다. --evidence-only도 근거 JSON을 쓰므로 읽기 전용 검사 명령이 아니다. 문서 저장은 이름이 같은 출력 파일을 덮어쓸 수 있다. A4·맑은 고딕·문서 격자 해제·쪽나눔 설정을 정적으로 읽었으며 이번에 원본 생성 코드를 실행하지 않았다.

<a id="c22"></a>**C22.** verify_and_archive_84.py의 자동 검사는 PDF5쪽·쪽당 글자 수·일부 용어·로컬 링크·DOCX zip·원장 해시 등을 확인한다. all_five_pages_visually_reviewed, source_statistics_checked_against_saved_JSON 등 일부 값은 저장 코드에 직접 적힌 보고값이다. 이 true만으로 현재의 시각·의미 검수가 완료됐다고 보지 않는다.

<a id="c23"></a>**C23.** findings와 검증 JSON은 첫 렌더가 쪽나눔·문서 격자의 영향으로9쪽·빈 페이지 문제를 보였고 수정 뒤5쪽을 모두 확인했다고 기록한다. 이것은 당시 검수 보고다. 이번 묶음에서는 DOCX와 PDF·PNG의 실제 본문·페이지를 아직 읽지 않았고, 최초9쪽의 저장 증거도 재검증하지 않았다.

<a id="c24"></a>**C24.** manifest에는20파일·총2,334,424바이트가 나열돼 있으며 manifest 자신은 이20개에 포함되지 않는다. 현재 보존된20파일의 크기·해시는 목록과 일치한다. 보관 코드는 snapshot이 이미 있으면 중단하고 복사 후 해시를 기록한다. previous_snapshots_modified=false라는 고정 보고값을 전체 이전 snapshot의 독립 불변 검증으로 확대하지 않는다.

## 팀 접근과 남은 범위

<a id="c25"></a>**C25.** 핵심9개 원문은 바이트 그대로 보존한다. 보고서의 개인 PC 링크7개는 별도의 팀용 사본에서 저장소 상대경로로만 바꿨고 변경 위치를 기록했다. HCP 원문 파일 링크는 기존 문헌 검수 페이지로 연결하므로 논문 전문의 새 배포본은 아니다. 근거JSON의11개 인용 해시는 기존 보존본 모두와 연결했고 현재 경로의 예산 원장 판본 차이는 따로 남겼다.

<a id="c26"></a>**C26.** DOCX1·저장PDF1·PNG5·고유progress1의8그룹은 해시 확인만 했으며 미독으로 남겼다. snapshot26 candidate index는 H109와 바이트가 같아 재집계하지 않는다. 최초 실패 검사·9쪽 렌더의 세부 증거, 이전 미완독 판본, 전체 실패·비용 통합과 최종 검색 검수도 남는다. 원84나 전체 Goal의 완료로 판정하지 않는다.
