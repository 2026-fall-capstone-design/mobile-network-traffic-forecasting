# 10–12 — 전체 grid의 범위와 UPC 소속 안정성

후속 [13–15의 교차 예측·cell 식별 정보 진단](0013-0015-transfer-cell-identity.md)은 저장된 소속과 실제 예측 관계를 연결한다. 13/14와 15의 수치·방법 부분까지 검수했으며, 15의 여섯 문헌과 이후 판단은 계속 확인 중이다.

2026-09-25의10·11 계획과12 판단은 중앙부16cell의 B2 기각을 도시 전체로 확대하지 않으려는 후속 진단이다. 저장 결과에서는 평균적인 하루 형태가 안정적이어도 peak mode와 특정 UPC 해석의 소속은 달라질 수 있었다. **소속 변화가 최종 예측 손해라는 증거는 확보하지 않았다.** [08·09의 출발 질문](0008-0009-finite-sample-pooling.md), [원문과 읽은 범위](../sources/history-007.md), [보존 근거](../evidence/0010-0012/README.md), [검수](../verification/history-007.md).

## 질문·실행 상태·자료

JSON의 계획 해시는 보존 계획과 일치한다. 해시 연결은 실행 전 봉인의 독립적인 시각 증명은 아니다. 기록 번호10·11·12를 세 번의 모델 실험으로 세지 않는다. [10 계획](../evidence/0010-0012/originals/SRC-0020863.md.txt), [11 계획](../evidence/0010-0012/originals/SRC-0020887.md.txt), [12 판단](../evidence/0010-0012/originals/SRC-0020908.md.txt).

## 10: pilot 범위와 평균 파형·peak mode

첫28일 cell별 평균 활동량의 중앙값은 전체 **204.86194122**, pilot **734.78829167**이었다. 고정16cell 중15개가 전체 중앙값보다 높았다. pilot ID는 이전 [B2 배열](../evidence/0003-0007/originals/SRC-0023589.npz)의 `cell_ids`와 일치한다. 이는 pilot이 상대적으로 활동량이 큰 cell을 많이 포함한다는 관측이며, 활동량이 성능 차이를 일으켰다는 인과 검증은 아니다.

다음168시간의 cell별 MAE를 그 cell의 첫672시간 평균으로 나눈 뒤 cell에 같은 가중치를 주어 평균했다. 즉 원단위 MAE나 min-max MAE가 아니다. `y[t-lag]`를 기준값으로 쓰며, 평가 주간 안에서 이미 관측한 과거값도 사용한다. 단일 시점에서 일주일 전체를 예측하는 설정과 다르다. 전체와 pilot은 같은 시각을 비교하되 cell 집합 크기가 다르다. [코드53–79행](../evidence/0010-0012/originals/SRC-0022978.py.txt), [전체 분포 JSON](../evidence/0010-0012/originals/SRC-0023595.json).

|---|---:|---:|
| 직전1시간 | 0.12939062 | 0.11858320 |

pilot에서는 전주값과 직전값의 오차가 가깝지만 전체에서는 차이가 더 컸다. 이 결과로 유리한 지역을 새 대상으로 고르거나 전체 도시에서 clustering이 불필요하다고 결론내리지 않았다. 평균 외 분위수와 cell별 값은 그대로 보존했다. 독립 도시·기간의 성능 검정은 아니다.

앞뒤14일의 각 cell weekday24시간 평균 profile 사이 PCC 중앙값은 **0.98408251**이었다. weekday의 일일 최대 시각에 대한 최빈값(mode)이 같은 cell은 **38.23%**, 원형24시간 거리로1시간 이내인 cell은 **62.72%**였다. 일일 최대나 mode가 동점이면 가장 이른 시각을 택한다. **한 기간 이상에서 mode가 동점인45.99%는 JSON 보고값이며, 동점 수가 NPZ에 없어 독립 재계산하지 않았다.** 평균 profile 상관과 가장 흔한 최대 시각의 일치는 서로 다른 통계다. 넓은 peak·두 봉우리는 원12의 가능한 설명이며 각 cell의 원인을 확인한 결과는 아니다. [코드31–52행](../evidence/0010-0012/originals/SRC-0022978.py.txt), [12의19–23행](../evidence/0010-0012/originals/SRC-0020908.md.txt).

## 11: 원 UPC와 이번 구현의 차이

원 UPC의 §III.A/Algorithm1은 weekday peak로 나눈 group의 평균 파형 PCC를 이용한다. θ=10일 때 `group size > 10`을 사용하며 작은 group에는 `None`을 둔다. 이번 기록은 작은 group 처리·남은 group 배정 순서·평균 파형 표현을 명시해서 제한된 부분을 계산했다. [원 논문](https://doi.org/10.1109/TNSM.2025.3599168), [지정 쪽·코드 검토](../verification/history-007-primary-review.json).

고정 공개 [GECOS main.py](https://github.com/Superint-Lab/GECOS/blob/a7519dde9d6f5deb3006689df047d99ea0dac7b7/main.py)는 미리 만든 correlation CSV를 읽어 `idx % n_groups`로 초기화하고 소속을 반복 재배정한다. 난수 초기화가 아니며 peak 생성부터 원 Algorithm1까지의 완성 구현으로 볼 수 없다. 공개 코드1–134행을 정적으로 재확인했으며 실행하지 않았다. 코드·논문 불일치를 이번 제한 구현의 완전한 재현 근거로 사용하지 않는다.

실제 과거 구현은 다음 조건을 고정했다. [11 계획13–18행](../evidence/0010-0012/originals/SRC-0020887.md.txt), [구현16–72행](../evidence/0010-0012/originals/SRC-0023208.py.txt).

1. 각14일 안에서 cell별 min-max를 계산하고 weekday10일을 사용한다. peak 동점은 이른 시간으로 정한다. 유한하지 않거나 기간 범위가0인 cell과 크기10이하 peak group을 미배정(-1)으로 남긴다.
2. 파형은 cell·weekday를 평균한24시간 profile을 주 분석으로, cell만 평균한10×24시간 연속 파형을 민감도 조건으로 둔다. 10의 원활동량 profile 비교와11의 min-max 후 group profile 비교를 구분한다.
3. PCC가 가장 작은 두 group을 seed로 고르고, 추가 seed는 선택된 seed들과 평균 PCC가 가장 작은 group이다. K3이 주 분석이고 K4·5도 저장했다.
4. 남은 group을 오름차순 또는 내림차순으로, 현재 cluster의 group들과 평균 PCC가 가장 높은 cluster에 붙인다. 초기 group PCC를 유지하고 기존 group들을 다시 배정하지 않는다. 배정 점수는 cluster 안의 peak group마다 같은 가중치를 주는 상관 평균이며 group의 cell 수로 가중하지 않는다. 동점은 낮은 시간·cluster 번호다.
5. 두 기간에 모두 배정된 cell에서 ARI와 최적 label 정렬 일치율을 계산한다. 정답 cluster에 대한 분류 정확도가 아니다. 같은 기간의 순서 차이도 함께 계산했다.

## 당시 판단·비용·남은 범위

12는 ‘소속을 안정적으로 만들자’만으로 새 목표를 세우지 않았다. 소속 변동이 서로 다른 예측 관계를 섞는지, 단순 profile·분포 비교로 설명되는지 먼저 확인한 뒤 TabICL의 추가 정보를 판단하자는 입장이다. 원 UPC 성능 결함, clustering 전반의 무용성, TabICL 필요성·신규성을 이 자료로 확정하지 않는다. [12의31–37행](../evidence/0010-0012/originals/SRC-0020908.md.txt).

10/11의 저장 경과시간은 각각 **0.2892933초 / 0.3006076초**다. 10은50ms 간격 RSS 표본의 최대199,385,088bytes, 11은 몇 시점에서 관측한 RSS 최대206,843,904bytes를 기록했다. 진짜 순간 peak·현재 환경의 속도로 보장하지 않는다. 측정은 import 이후의 start에서 시작한다. 10의 NPZ 쓰기는 elapsed에 포함되지만 최종 JSON 쓰기·출력은 이후다. 11의 최종 JSON·NPZ 쓰기·출력은 모두 elapsed 계산 이후다. 원 계획의60초/30초·1GiB와 코드를 비교했으나 현재 자원 예산으로 승계하지 않았다.

12의 마지막 문장에 나오는 ‘세 진단’ 중 **0.2492086초는 앞선08 진단**이다. 이번10/11의 두 결과와 더해 인용한 것으로 연결했으며 세 번의 새 모델 실행으로 집계하지 않았다. [08의 저장 경과시간](../evidence/0008-0009/originals/SRC-0023580.json), [08·09 기록](0008-0009-finite-sample-pooling.md). 10/11 코드는 모델을 호출하지 않으며 저장된 Tab context/query·RCTL fit도0이다. 과거 RCTL 잔여 예산0과 다음 행동 문구는 역사적 자료다.

새로운 동일 조건 계산 전에 보존 배열과 [검산 도구](../../../scripts/research_archive/verify_population_upc_history.py)를 확인한다. 재검토할 때는 기간·자료 해상도, peak/동점/작은 group 규칙, 파형과 배정 순서, 실제 공유 learner·예측 손실에서 달라지는 질문을 명시한다. 저장 집계·소속의 검산은 원신호에서 PCC·seed·greedy partition을 다시 생성한 독립 재현이 아니다. 동점 비율·raw 품질·비용의 독립 재계산과 원 UPC 전 과정/성능 검증은 미완료다. 이후13–15의 예측 관계·cell identity 진단, 후속 UPC/TabPFN 기록은 별도 묶음으로 이어간다.
