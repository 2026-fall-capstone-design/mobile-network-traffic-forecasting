# 51–55. 관측 비용·새 방법·TabICL의 기여를 따로 판단하기

2026-09-26의 55번 결론은 **관측 비용 문제는 존재하지만, 검토한 원리의 신규성과 작은 확인에서의 TabICLv2 추가 이득이 부족해 clustering으로 확대하지 않는다**였다. 모든 데이터에서 TabICL이 쓸모없다는 결론이나 전체 연구 중단 선언은 아니다. 이 문서는 51의 자료·예측 문제 조사, 52의 Beijing 스키마 확인, 53의 선행연구, 54의 부분 관측 복원, 55의 판단을 연결한다. 이후 아카이브에서 확인한 자료는 당시 판단과 구분한다. [55 원문](../evidence/0052-0054-partial-observation/originals/SRC-0021824.md.txt), H044-C07·34·36.

팀원이 같은 연구를 다시 설계하기 전에는 아래에서 **선택하는 대상, 실제 가용 입력, 평가할 출력, 줄일 비용**이 과거와 무엇이 다른지 확인하면 된다. [자료별 읽은 범위](../sources/history-044.md)와 [36개 주장 검수](../verification/history-044.md)를 함께 제공한다. 관련 저장 자료 103개 고유 바이트 묶음·207개 경로를 대조했으며, 연구 내용·파생본·metadata·미해결 접근을 구분했다. 이것이 전체 과거기록이나 외부 저장소의 전수 독해 완료를 뜻하지는 않는다. H044-C01·35.

비용의 예를 비교할 때도 분모를 유지한다. Moghadas의 EUMA K2 사례에서 약 17% 입력의 성능과 **clustering 10,415.90초·centroid training 92.39초·global 23.89초**는 별도 항목이다. Zoom2Net의 Transformer 단독은 표에서 1ms 미만이지만 CEM 포함 경로는 **0.145–0.532초**다. NETNOMOS의 약 **5배**는 규칙 강제를 포함한 추론 비용 설명이다. 장치·자료·작업이 다르므로 이 숫자로 방법 간 통일된 속도 순위를 만들지 않는다. H044-C16–19.

## 54에서 실제로 실행한 것과 실행하지 않은 것

54는 기존 Milan 개발 자료의 Internet activity를 이용한 **현재값 복원**이다. 중앙지역 16 grid cell 중 probe는 3737·3765·6137·6165, 대상은 3745·4545·5345·6145로 고정했다. 대상별 처음 672시간 평균으로 정규화하고 context 256행·query 64행, 총 query 256행을 썼다. query는 2013-12-14·18·22·26 각 00–15시의 서로 떨어진 네 블록이다. 실제 장애나 operator 보고 정책을 측정한 것이 아니다. H044-C22.

TabICLv2 ensemble=1·median·CPU·seed20260925, StandardScaler+Ridge(alpha=1), HGB는 같은 12열의 가용 정보를 받았다. 마지막 보고·전날·지난주·수준 보정 전날의 무학습 기준은 그중 필요한 일부를 사용한다. 55의 ‘모든 방법이 같은 입력’은 **같은 정보 가용성**으로 읽어야 한다. 모든 기준이 12열을 전부 소비하거나 TabICL의 MICE API를 실행한 실험은 아니다. 모델별 나머지 설정·입력 재구성과 한계는 [54 상세 기록](0052-0054-partial-observation.md)을 재사용한다. H044-C20·22.

|---|---:|---:|---:|---:|
| last_report | 0.278152 | 0.355694 | 0.200610 | 346.382762 |

정규화 MAE는 4×64 절대오차의 평균이다. Tab은 Ridge보다 네 cell 모두 나빴고, HGB보다 나은 한 cell에서도 Ridge가 더 좋았다. 앞 두 블록의 Tab 이득은 보존하지만 후반 손해와 전체 평균을 바꾸지 않는다. 정규화 전체에서는 Ridge, 원 activity MAE에서는 HGB가 가장 작다. 서로 다른 척도의 순위를 섞지 않는다. [저장 결과](../evidence/0052-0054-partial-observation/originals/SRC-0029391.json), H044-C23–26.

사전 확대 조건은 전체에서 모든 단순 대안보다 작음, 앞/뒤 각각 모두보다 작음, 네 cell 중 세 개 이상에서 더 좋은 Ridge/HGB보다 작음의 **동시 충족**이었다. 저장 판정은 `false / false / 0`, 확대 `false`다. 통계적 유의성 검정이나 업무 허용오차 기준은 아니다. 새로운 probe 선택, clustering, RCTL fit/forward, 독립 test를 수행한 결과로 집계하지 않는다. H044-C27·31.

## 구현 중단·완료 실행·비용을 함께 보존한다

처음에는 완전 관측된 과거 context까지 공동 결측으로 취급한 assert에서 모델 호출 전에 중단했다. 검사 대상을 query로 수정했고 데이터·seed·판정 규칙은 그대로였다. correction JSON은 첫 process wall **4.1631648초**, 새 모델 호출 0을 보고한다. 별도 stderr/프로세스 로그는 대조하지 못했으므로 실행 당시의 모든 행동을 독립 입증한 것은 아니다. 이후 완료된 모델 실행과 partial/final 저장 사본은 한 묶음이며 별도 재현 두 번으로 세지 않는다. H044-C28.

| 비용 | 저장값 | 포함 경계 |
|---|---:|---|
| Tab fit+predict | 2.543409199995949초 | 4 contexts·256 query행 |
| Ridge/HGB fit+predict | 0.4162254999973811초 | 8 fits, 아래 cheap 안에 포함 |
| 수정 후 cheap | 0.7142799000030209초 | stage에서 Tab 시간을 뺀 값 |
| 수정 후 stage | 3.25768909999897초 | 준비 전부와 최종 저장 뒤 처리까지의 총 시스템 지연은 아님 |
| RSS 관측 최대 | 480579584 bytes | 호출 사이 표본, 연속 peak 아님 |

`stage = Tab + cheap`이며 simple 시간을 다시 더하지 않는다. 첫 실패 wall도 당시 cheap 원장에 별도로 반영했다. H031의 원장 대조에서 누적 Tab **49 contexts·35,968행·226.4302954999971초**, 남은 count **31 contexts·24,032행**, RCTL **29 fits·추가 0**을 확인했다. 55의 인쇄값 226.430296초와 저장값의 마지막 자리 차이는 그대로 남긴다. 모델링 합계 **1955.243333100001초**, cheap 합계 **60.806025800002814초**도 초기 다운로드·전처리의 미계측 시간을 포함한 전 연구 총비용이 아니다. [원장 계보 검수](../verification/history-031-lineage-check.json), H044-C29–30.

per-cell 복원을 유지한다면 직접 관측 m개 외 N−m개의 context/cache·온라인 추론·갱신 비용을 고려해야 한다. 각 cell마다 k개 대안을 따로 검사하는 설계의 Nk 평가 규모는 조건부 구조 계산이며 모든 구현의 하한이 아니다. 4-cell 실측 시간을 10,000-cell 서비스 지연으로 단순 선형 확정하지 않는다. 가중치 학습 0과 운영비 0도 다르다. H044-C32.

## 같은 조건은 무엇을 재사용하고, 어떤 차이가 있어야 다시 검토하나

같은 네 cell·입력·기간·설정의 질문에는 [54의 plan·수정 전후 code·settings·calls·result·NPZ](../evidence/0052-0054-partial-observation/README.md)를 먼저 재사용한다. Beijing NPZ의 shape·통계 확인, 논문 비교와 인쇄표 검수도 기존 기록을 찾으면 된다. 코드 보존은 현재 환경에서의 재실행 성공이 아니다. H044-C33.

## 취득 이력과 남은 공백

자료 이름 검색만으로는 관련 코드 6종을 범위에서 놓쳤다. 기존에 읽은 2종은 재사용하고, 최초 발견된 telemetry 수집 코드와 합쳐 **신규 5개·209줄**을 정적으로 읽었다. 4개 취득 로그에는 **26항목 중 25개 성공·Ciena 1개 `Not PDF`**가 있으며 저장 크기·해시를 대조했다. 렌더 로그의 **16개 미리보기**는 기존 판독 자료와 연결한다. 네트워크 그림은 125dpi, telemetry/학위논문 그림은 120dpi 설정이다. 이 코드 버전만이 당시 출력의 유일한 생성자였다는 프로세스 trace까지 확보한 것은 아니다. H044-C02–06.

새 코드 5개만 원 바이트의 `.py.txt`로 보존하고 기존 사본 58개·metadata 40개를 연결했다. 원본 207개 경로와 보호 원장 6개는 변경하지 않았다. 자동 해시·산술 검사는 문장 해석을 대신하지 않으며, 이번 정리에서 새 모델·원 연구 코드 실행·난수 생성은 모두 0이다. H044-C01–06·36.

103개 자료의 범위를 대조하고 55의 판단을 통합했지만, **51·53·55의 관련 자료 전체 검증 완료로 표시하지 않는다.** Frontiers·Zindi·TabICL의 과거 연결 그림 동일성, STK의 원 논문/공간 자료와 단위, 대용량 beam 원자료, GIF 생성 설정·예측 배열, 일부 실행 로그와 전체 환경 재현은 남아 있다. 후속 PDF·현재 그림·저장 배열 검수로 각각의 공백을 대신 메우지 않는다. 외부 원문은 공식 링크·해시로 연결하며 모든 팀원의 접근까지 확인한 것은 아니다. 56 이후를 포함한 전체 기록, 실패·비용의 전역 통합, 최종 원본 변경분과 대표 질문 검색 검수도 계속 진행한다. H044-C35.
