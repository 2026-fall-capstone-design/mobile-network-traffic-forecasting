## 그림이 보여 주는 방법

`system_model.png`는 네트워크 관측에서 예측 엔진을 거쳐 에너지 절약·전력 할당으로 이어지는 개념도다. 예측 영역 안의 서로 다른 **target 값 범위**에 목적을 둔다. 그림만으로 실제 전력 절감, cell 소속 변경 또는 RCTL 성능을 측정했다고 판단할 수 없다.

`all_intervals_16.gif`의 검은 파선은 B-Policy, 붉은 점선은 `[0.75,1.0]`에 초점을 둔 C₀.₂-Policy, 여러 색과 선 모양은 D₁₆★의 구간별 예측이다. 분홍 영역은 과거, 초록 영역은 예측 구간, 오른쪽 회색 띠는 값 구간이다. 여러 곡선을 16개 cell이나 16개의 물리적 군집, 예측 신뢰구간으로 읽지 않는다. 가는 검은 기준 곡선에는 실제 무선 자료의 식별자가 없다.

`subset_intervals_wproba_16.gif`는 일부 보라색 구간별 곡선과 아래쪽 반투명 음영을 보여 준다. 첫 프레임의 축약 범례에는 I₁₂와 I₁₆이 양 끝에 표시되고 서로 다른 보라색 선 모양은 네 가지가 보인다. 이 표시만으로 정확한 구간 번호 대응이나 다섯 개 정책을 확정하지 않는다. README는 구간 분류를 이용해 신뢰할 예측을 선택한다고 설명한다. 그러나 그림에는 음영을 위한 별도 확률 축·보정 오차·명시된 신뢰수준이 없다. **음영을 예측 신뢰구간이나 보정된 확률의 증거로 재해석하지 않는다.**

`patching_inf_16.gif`의 보라색 D₁₆∞-Policy는 `[0.75,1.0]`을 범례에 명시하고, 해당 위쪽 값 범위를 격자 음영으로 표시한다. 일부 미래 시점에서는 보라색 선이 끊기고 뒤쪽 높은 값 구간에서 다시 나타난다. 따라서 보이는 선만으로 모든 미래 시점에 대한 완전한 예측 배열이나 전체 MAE를 복원할 수 없다. README는 관심 범위와 겹치는 구간 모델을 확률적 구간 분류로 결합하는 사례라고 설명한다.

## 좋은 장면과 한계를 함께 보존

프레임 번호는 각 GIF를 0부터 디코딩한 번호다. 다음은 시각 관찰이며 픽셀에서 수치 오차를 추정한 결과가 아니다.

| 확인 구간 | 실제 보이는 내용 | 가능한 해석의 범위 |
|---|---|---|
| 전체 구간·patching GIF, 0–3 | 상승 구간의 높은 값에서 B·C도 가는 기준선과 가깝다 | 모든 시점에서 D가 우월하다는 설명을 붙이지 않음 |
| patching GIF, 4–24 | 기준선이 높은 상태를 유지하는 동안 B가 낮아지고 보라색 선은 높은 부분을 따라간다 | 해당 시각 사례의 목적 범위 설명. 전체 자료 평균 이득은 별도 표/원자료가 필요 |
| patching GIF, 25–37 | 관심 범위에서 B와 보라색 선이 가깝고, 급락 뒤 보라색 선은 전체 미래를 이어 그리지 않는다 | 관심 범위 밖의 생략을 정확한 예측으로 세거나 B의 실패로 돌리지 않음 |
| patching GIF, 38–47 | 뒤의 재상승이 높은 값 범위에 도달하면 보라색 선이 다시 나타난다 | 한 프레임의 보이는 부분만 골라 전체 예측을 평가하지 않음 |

표시된 곡선 외에 학습 seed, backbone, checkpoint, train/test 파일, 원래 예측 배열, 구간별 표본 수, 평균/분산, 실행 로그가 GIF 안에 제공되지는 않는다. 이미 검수한 논문·shell의 설정을 근거 없이 이 GIF의 정확한 생성 설정이라고 연결하지 않는다. 논문의 zero-mask MAE 분모, 정책별 이득과 손해, 에너지 simulation의 조건은 [H032 기록](0051-0055-gotsf-audit.md)의 범위로 유지한다. 이번 그림 검토는 그 수치를 재계산하거나 독립 재현한 것이 아니다.

## 데이터 그림과 카드 설명을 함께 읽기

`dataset_split.png`에는 네 시계열, 앞쪽 주황 영역, 떨어진 두 초록 영역과 사이의 회색 영역이 보인다. 원본이 518×149인 작은 그림이므로 정확한 시각 수는 작은 눈금에서 추측하지 않고 카드 본문을 근거로 적는다. 카드의 설명은 앞 5주 840시간, week6와 week11 각 168시간이다. 이 두 시험 주를 연속 336시간의 실제 달력 기간으로 이어 붙이면 안 된다. 카드가 주는 test 파일 index `0–167`과 `168–335`는 그 시간적 간격을 지우지 않는다.

카드의 training `0–839` 옆에는 `(weeks 1–6)`라는 표기도 남아 있다. 이는 같은 카드의 first5 weeks 설명과 맞지 않는다. 그림을 읽었다는 이유로 그 모순을 임의로 수정하거나 원시 CSV를 검증했다고 표시하지 않는다. 이 연구에서 사용할 실제 timestamp와 분할은 원자료에서 별도로 확인해야 한다.

`network.png`는 기지국, 예시 사용자 세 명과 KPI 곡선을 그린 개념도다. 카드가 설명한 30 BS×3 cell×32 beam의 실제 식별자 대응표나 중복 없는 합산, 물리 단위를 입증하지 않는다. 2,880 beam을 2,880 cell로 바꾸어 부르거나 미래 PRB/MR 관측값을 사전에 알려진 입력으로 사용해도 된다는 근거가 아니다. 대용량 원시 CSV를 이 묶음에서 읽지 않았다.

## 재사용할 때 피해야 할 중복과 오해

- target 값 구간에 목적을 두고 구간 소속 가능성으로 예측을 결합하는 원리는 이 선행자료에 이미 있다. 요청 범위나 가중 loss를 추가했다는 차이만으로 새 clustering 기여를 주장하지 않는다.
- README 예시의 `nr_intervals` 주석에는 horizon을 나눈다는 문구가 있지만, 본문·그림·기존 논문 검수는 **target 값 범위**를 다룬다. 과거 주석은 보존하고 실험 정의를 시간 분할과 혼동하지 않는다.
- GIF를 다른 예측기의 성능 대리 점수에서 RCTL 공동 학습 이득으로 건너가는 근거로 쓰지 않는다. 재검토하려면 최종 목적 지표, 실제 사용 가능한 입력, 비교군, 데이터 분할과 비용이 연결되어야 한다. 이는 새 실험 실행 지시가 아니다.
- 같은 그림을 다시 인용하는 것은 새 독립 실험이 아니다. 향후 재현 시에는 고정 버전, 생성 코드·체크포인트·예측 배열과 지표 분모를 함께 연결해야 한다.

로고는 장식 자료로 읽었다. README badge URL의 표시 번호 `2402.03885`와 실제 arXiv 링크 `2504.17493`의 차이, 옛 데이터 badge 경로도 원문에 남아 있다. badge 문자열은 검토했지만 외부 badge 이미지 바이트는 확보하지 않았다. tree에만 있는 `figures/patching_1_16.gif`와 루트의 다른 로고도 metadata만 확인했다. 이들은 본문에서 연결된 연구 미디어 7개와 구별하며 읽지 않은 내용으로 명시한다.

코드 tree의 181개 항목과 root 필드는 이번에 전체를 읽었다. H032의 선택 필드 집계 1개를 whole JSON 1개로 승격하고 선택 필드 전용 집계에서 1개를 뺀다. 이는 동일 파일의 분류 변경이며 새로운 파일 181개나 모델 결과의 검토가 아니다. 기존 HF tree 20개 항목과 info는 재독으로만 기록한다. 신규 로컬 본문과 원문 사본은 0개다.

51·55의 다른 고유 저장 내용과 전체 종합, 실제 자료의 단위/합산 가능성, 생성 설정·원자료 접근 공백은 남아 있다. 원본·과거 실행 원장 보존 검사를 통과했고 모델 fit/forward, 원연구 script 실행, pickle load와 난수 생성은 모두 0회다.
