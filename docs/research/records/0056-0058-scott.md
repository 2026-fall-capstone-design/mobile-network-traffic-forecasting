# 56·58. SCott — 학습 표본 층화와 cell 소속 변경의 구별

SCott은 시간대·주기 등으로 **학습용 시계열 창을 층화하고 한 예측기의 gradient 분산을 줄이는 optimizer**다. 최종 RCTL을 여러 cell cluster로 나누거나 TabICL의 오차를 다른 학습기의 표본 가치로 사용하는 방법은 아니다. 58번의 이 구별은 원문과 일치한다. 실제 RCTL의 시간·오차 개선은 이번 문헌에서 검증되지 않았다. 현재 상태는 원문·공식 부록·인쇄 수치의 검수다. 저장 논문 11쪽 텍스트와 1–9쪽 시각 자료, 과거 p5 preview, 공식 부록 10쪽 텍스트·시각 자료를 읽었다. 표의 결과 168개 숫자와 튜닝 60개 값을 대조했다. 원 코드 실행·모델 학습·추론·난수 생성은 0이며, 저자 실험을 독립 재현한 것은 아니다. [출처 범위](../sources/history-048.md) · [주장 지도](../verification/history-048-claims.json)

## 어떤 대상을 묶고 무엇을 최적화하는가

본문 §3의 표본은 `(시계열 i, 예측 시점 t)`에 대응하는 context와 미래 target의 창이다. 식 1의 목적은 이 표본 집합 D 전체의 평균 손실이다. 따라서 strata는 같은 예측기를 학습할 **표본을 추출하는 구획**이다. §2는 여러 모델을 유지하거나 모델 구조를 바꾸는 접근과 이를 구별한다.

§5.1은 반복되는 시간 패턴의 timestamp를 이용한다. 그림 1의 AR(2) 예시는 `sin(t)+cos(2t)+0.2ε`를 만들고 `t mod 8`로 8개 strata를 구성한다. 일반화 예로 달·계절의 계층적 구획을 들며, density/spectrum 등의 feature와 K-means도 대안으로 언급한다. 가까운 입력·출력이 같은 현재 파라미터에서 비슷한 gradient를 만들 수 있다는 동기다. Tab 예측 오차가 RCTL gradient와 정렬된다는 검증을 제공하지 않는다.

시간 규칙의 조회 비용이 작다는 저자 설명과, 실제 전처리·튜닝·전체 학습 비용을 측정했다는 주장은 구별한다. 좋은 strata는 서로 다른 계절을 이름으로 나누는 것만으로 보장되지 않는다. 해당 학습기의 strata 내부 gradient 분산이 실제로 작아지는지가 관련 조건이다. 학습 자료의 target을 사용하는 것과 test 구간을 선택·튜닝에 사용하는 것도 별도로 관리해야 한다.

## 가중 snapshot과 control variate

서로 겹치지 않는 D₁,…,D_B로 D를 나누고 각 표본은 한 stratum에만 속한다. `w_i=|D_i|/|D|`로 두며 각 stratum에서 균등 추출한 mini-batch ξᵢ의 평균 gradient를 사용한다. 식 7은 다음 추정량이다.

`g(θ) = Σ_i w_i ∇f_{ξ_i}(θ)`

Lemma 1은 고정된 θ에서 `E[g(θ)]=∇f(θ)`, 독립적인 strata 추출에 대해 `Var(g)=Σ_i w_i² Var(∇f_{ξ_i})`를 제시한다. 크기가 다른 strata를 똑같이 평균 내면 일반적으로 원래 D의 평균 목적과 달라진다. 단일 표본의 역확률 가중이나 “큰 오차 표본”만 남기는 선택과 계산식이 같지 않다.

Algorithm 1은 매 outer loop의 snapshot θ₀에서 g₀를 만든 뒤, inner loop마다 **동일한 ξ**에 대해 현재점과 snapshot의 gradient 차이를 사용한다.

`v_k = ∇f_ξ(θ_k) − ∇f_ξ(θ₀) + g₀`, `θ_{k+1}=θ_k−α_t v_k`

두 항에 서로 다른 표본을 넣는 것은 이 알고리즘과 다르다. 또한 snapshot 추정량 g의 불편성을 모든 inner update의 조건부 불편성으로 바꾸면 안 된다. 부록 식 56은 snapshot 오차 `ζ_t=g₀−∇f(θ₀)` 때문에, snapshot을 고정한 inner 기대값에 ζ_t가 남음을 명시한다. [본문 p4–5](https://proceedings.mlr.press/v139/lu21d/lu21d.pdf#page=4) · [부록 p8](https://proceedings.mlr.press/v139/lu21d/lu21d-supp.pdf#page=8)

목적과 sampling의 표기에도 주의가 필요하다. 식 1은 모든 `(i,t)`를 같은 무게로 평균 내지만, 식 2 설명은 i를 균등하게 고른 뒤 그 시계열 안의 t를 균등 추출한다. Tᵢ가 서로 다르면 한 표본의 확률 `1/(N T_i)`는 `1/|D|`와 다를 수 있다. 실제 데이터의 길이·sampler·보정 가중을 확인해야 한다. 이것만으로 저자 구현에 편향이 있었다고 확정하지 않는다.

## 수렴 정리의 조건과 적용 경계

Theorem 1은 AR(p)+MSE와 zero-respecting optimizer에서 느린 학습을 유발하는 자료가 **존재한다**는 구성적 하한이다. 모든 시계열 자료나 현재 RCTL이 반드시 느리다는 결론은 아니다. 각주 2는 적절한 scaling으로 크기 δ를 제한할 수 있지만 p 의존성은 남는다고 설명한다.

Theorem 2와 Corollary 1의 범위를 아래처럼 보존한다.

| 항목 | 원문 조건·의미 | 현재 연구에 적용할 때의 경계 |
|---|---|---|
| 목적함수 | 각 표본 손실 fᵢ,ₜ가 모든 θ에서 L-smooth. 비볼록 허용 | MAE·ReLU의 비미분 지점까지 이 가정이 성립한다고 할 수 없음 |
| 분산 | 각 stratum에서 균등 추출한 gradient의 분산에 σᵢ² 상한. `S=Σ_i w_i²σ_i²=O(ε²)` 조건 | strata 명칭이나 원 loss의 작은 분산만으로 보장되지 않음 |
| 이론상 크기·반복 | M=1; `K_t∼Geo(B/(B+1))` | 각주 분포는 `P(K=k)=p^k(1−p)`, k≥0이므로 `E[K]=B`. 다른 geometric 관례와 혼동 금지 |
| 학습률·출력 | 부록은 `α_t L=cB^(−2/3)`을 사용. outer snapshot 중 `α_t B` 비례로 출력을 추출 | 임의의 lr·마지막 iterate·S-Adam에 같은 정리를 자동 부여하지 않음 |
| 보장 대상 | `E‖∇f(θ̂)‖≤ε`에 필요한 gradient 복잡도 | test 오차·전역 최적값·wall time 보장이 아님 |
| 같은 크기의 strata | 각 stratum의 표본 수가 같고 1보다 클 때 Corollary 1 | 크기 가정을 지우고 식 11만 적용하지 않음 |

본문의 gradient 복잡도는 `O(ΔL(BS)^(2/3)/ε^(10/3) + ΔL|D|^(2/3)·1{B=|D|}/ε²)`이며 `Δ=f(0)−inf f`다. 모든 표본을 singleton stratum으로 만들면 내부 분산은 0이지만 snapshot에서 전체 자료를 읽는 비용이 생긴다. Table 2는 random hashing과 SCSG, 가장 세밀한 층화와 SVRG의 연결을 설명한다. 이 점근식의 상수·가정까지 독립 인증하거나 RCTL 속도 향상률로 환산하지 않았다.

증명을 재사용할 때에는 부록 Lemma 5의 전개도 재검토해야 한다. 식 84의 교차항에는 앞서 곱한 `w_i w_j`가 표시되지 않으며, 각 항을 stratum 평균이 아닌 전체 gradient로 중심화했다. 독립 추출만으로 이 교차항들이 각각 0이 되는 것은 아니다. 독립 층화의 분산식을 전개하려면 `μ_i=E[∇f_{ξ_i}]`로 중심화하고 `Σ_i w_i μ_i=∇f`를 사용해야 한다. 이는 인쇄된 전개의 확인 항목이며, 그 자체로 식 79의 분산 상한이나 논문 실험 결과가 거짓이라고 결론 내리지 않는다.

실용 Algorithm 2는 고정한 K 상한 아래 `‖v_k‖²≤γ‖v_0‖²`이면 inner loop를 종료한다. 이 방식은 이론의 geometric 선택과 구별된다. 부록의 추가 그림은 같은 조기 종료를 SCSG·SVRG에도 적용해 비교한다. [부록 Algorithm 2·그림 5](https://proceedings.mlr.press/v139/lu21d/lu21d-supp.pdf#page=1)

58번이 언급한 RCTL의 training-mode BatchNorm·dropout도 남는 조건이다. batch 구성이 계산에 영향을 주며, 두 gradient에서 확률적 연산을 어떻게 짝지을지 확인해야 한다. eval-mode의 고정 표본 gradient 분산을 실제 training-mode 분산과 같다고 보고하지 않는다. 이 문서에서는 RCTL의 새 gradient·학습을 계산하지 않았다.

## 튜닝과 총비용을 비교할 때

부록 A.4의 grid는 학습률 10개, 기본 γ 4개이며 변형 optimizer에서 γ를 6개로 늘린다. weight decay는 1e−5, Adam 계열의 선택된 β₁/β₂는 0.9/0.999다. Table 4의 전체 42개 learning rate와 18개 γ를 [검산 JSON](../evidence/0056-0058-scott/stored-results-arithmetic.json)에 남겼다. 특히 N-BEATS–Traffic의 SCott lr=0.0025와 SGD/SCSG lr=0.0001은 다르다. 동일 시간 예산의 튜닝된 방법 비교이지 동일 lr 통제 실험은 아니다.

매 step에 모든 strata를 사용하면 §5.3의 계산량은 O(B·M)이다. SCott은 이를 주기적 snapshot과 inner gradient 차이로 분산한다. 구현 관점에서는 snapshot 계산, 현재점 gradient, 같은 표본의 snapshot점 gradient, 샘플링·메모리 관리가 필요하다. 캐시·벡터화 방식에 따라 실제 비용은 달라진다. 부록 식 72의 `B+E[K_t]=2B`는 점근 복잡도 계산에 사용된 셈이며, backward 두 항과 구현 상수까지 반영한 실측 비용표가 아니다.

팀의 비교에서는 strata 준비·튜닝·snapshot·본 학습·평가 시간을 구분하고 같은 품질 목표까지의 총비용 또는 같은 총예산에서의 품질을 기록해야 한다. 0.5/3시간의 표를 전체 프로젝트 준비 비용이나 RCTL 비용 절감률로 바꾸지 않는다. 이 항목은 후속 실험을 설계할 때의 확인 기준이며 이번에 새 실험을 실행했다는 뜻은 아니다.

## 기존 시도와 새 제안을 구별하는 기준

58번은 시간대 stratification에 Tab 이름만 붙이거나 TabICL의 큰 예측 오차를 RCTL 표본 중요도로 쓰는 안을 채택하지 않았다. 원문은 그 판단에 필요한 **층화 대상·목적함수·gradient 계산·가정·비용**을 구체화한다. “모든 표본 압축/층화가 실패한다”는 결론은 제공하지 않는다.
