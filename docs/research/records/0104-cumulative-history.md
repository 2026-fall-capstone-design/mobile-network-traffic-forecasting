# 원82까지의 누적 연구일지와 후보 결정 지도

[출처](../sources/history-104.md) · [검수](../verification/history-104.md) · [판본 차이](../evidence/0104-cumulative-history/unique-deltas.json) · [원82 상세](0099-intermittence-decision.md)

같은 연구를 반복하기 전에 **어떤 결정을 바꾸려 했는지 → 당시 무엇을 실제 수행했는지 → 무엇이 남았는지**를 찾는 문서다. 기록 번호는 실험 횟수가 아니다. 숫자·seed·분할·실행 비용의 세부 조건은 각 상세 기록을 따른다.

**상태:** 26개 주장·6개 묶음의 작성 후 원문 대조 완료. 새 연구 코드·모델 실행0.

## snapshot24의 고유 변경과 원82

<a id="c01"></a>**C01.** snapshot24 후보표 44행과 누적 연구일지 401행을 모두 읽었다. 2026-09-26 원82까지의 상태를 담은 서로 다른 두 고유 파일이다. 원본 번호·문서 수·후보 결정 수·실제 실행 횟수를 서로 바꾸어 세지 않는다. 직전 snapshot23 후보표는 재참조했고 연구일지는 1–22행만 다시 읽었다.

<a id="c02"></a>**C02.** 후보표는 43→44행이며 현재 16행의 간헐성 후보만 추가됐다. 연구일지는 389→401행으로, 7행의 최신 상태 제목이 원81에서 원82로 바뀌고 현재 9–20행이 삽입됐다. 기존 후보표 43행과 연구일지 388행이 동일하다는 기계 비교와, 새 누적 본문을 실제 읽은 범위를 구별한다.

<a id="c03"></a>**C03.** 현재 연구일지 20행은 snapshot23의 42파일·3,524,587바이트 보관 확인을 보관 후 추가했다고 명시한다. 새 원82 조사와 이전 원81의 보관 확인이 같은 삽입 구간에 들어갔어도 두 사건은 다르다. 과거 검사 완료라는 문구를 이번에 모든 검사를 재수행했다는 뜻으로 바꾸지 않는다.

<a id="c04"></a>**C04.** 원82의 새 판단은 99.94%·99.21%를 각각 10분·1시간 단위에서 gap을 포함한 IP 시계열의 비율로 읽는다. 전체 시점의 결측률이나 실제 무통신 비율이 아니다. H100은 CESNET Table6와 ISP의 서술을 대조해 이 정정을 확인했으며, 관측 비율 분포와 수집기 장애도 별도 근거로 구별했다.

<a id="c05"></a>**C05.** 기존 진단의 0.0001975는 0.01975%이며 최초 35일의 hourly Internet 840시점×10,000 grid에 관한 저장 값이다. 원82가 새로 계산한 통계도, 원시 10분 자료 전체에서 희소성이 없다는 증거도 아니다. H099에서 생성 코드의 분모와 백분율 변환을 확인했지만 traffic tensor의 0 개수를 독립 재계산하지 않았다는 한계를 함께 따른다.

<a id="c06"></a>**C06.** Citywide의 SMS·통화, Beam의 발생 분류·양 예측, Deep Renewal의 발생 간격·크기·공유 LSTM을 현재 cell 소속 수정 효과와 구별했다. 실제 무통신이 반복적 예측 손해를 만든다는 근거와 기존 방법을 넘어서는 유용한 공유 결정이 없다는 것이 당시 비채택 이유다. 모든 간헐 예측의 불가능성을 뜻하지 않는다.

<a id="c07"></a>**C07.** 연구일지는 PDF 2개 21쪽·HTML 5개 보존과 선택 PDF 시각 대조를 보고한다. 후속 정리 H100–H103의 본문·표·수식 검수는 별도 시점이다. 특히 H103에서 확인한 과거 source_manifest 4항목에는 Deep Renewal이 없으므로 그 옛 입수 시각은 미확인이다. 현재 확보한 출판사 보완자료로 과거 열람이나 입수 이력을 대신 증명하지 않는다.

<a id="c08"></a>**C08.** 원82는 새 외부 코드 실행·단순 모델 fit·모델 추론을 하지 않았다고 기록한다. 누적 원장의 Tab 69context·39,360행, 잔량 11context·20,640행과 RCTL 29fit·추가 0은 원80 종료 상태의 재인용이다. H099의 원장 검수에 연결하며 이 숫자를 원82의 추가 실행이나 현재 예산으로 사용하지 않는다.

## 시간이 지나며 달라진 상태

<a id="c09"></a>**C09.** 연구일지의 Goal·AGENTS·다음 작업·실행 상한·미완료 선언은 당시 연구의 자료다. 초기 비용 제한과 후속 실행 계획도 그 시점의 상태로 읽는다. 이번 정리는 새 학습·추론이나 과거 연구 Goal 재개를 포함하지 않는다.

<a id="c10"></a>**C10.** 파일 앞부분은 최신 상태에서 이전 상태로 거슬러 올라가지만, 아래에는 초기 확인·실행·RCTL 완료·후속 진단이 다시 이어진다. 파일의 줄 순서만으로 시간 순서를 정하지 않는다. 아래 연혁표는 원본 번호와 당시 수행 형태로 상세 기록을 찾게 하며, 각 상태를 현재의 최종 결론으로 통일하지 않는다.

<a id="c11"></a>**C11.** 초기 진단은 최종 20일 target을 읽지 않았다고 남겼지만, RCTL 완료 뒤에는 그 기간을 읽은 상태라고 명시했다. 이후 설계에 참조한 기간은 개발 자료다. 초기의 미관찰 문구만 떼어 후속 결과를 독립 test로 부르지 않는다.

<a id="c12"></a>**C12.** 초기의 RCTL 0회, 이후 29/29fit 완료, 뒤 문단의 29fit 재인용은 실행 상태의 변화와 반복 보고다. 같은 29fit을 문단마다 합산하지 않는다. 학습 완료·고정 checkpoint 재사용·저장 예측 재분석은 구별하고, 각 실행 비용은 원 기록의 타이머 범위를 따른다.

<a id="c13"></a>**C13.** 원24는 고정 RCTL의 recursive 재추론이고 원34는 train/validation 고정 가중치 재추론이다. 원80의 고정 RCTL gradient 진단도 학습 fit 추가와 다르다. 원26은 저장 RCTL 예측을 재사용하면서 Ridge/HGB 두 fit을 추가한 혼합 사례이므로 묶음 전체를 모델 호출 0으로 쓰지 않는다.

<a id="c14"></a>**C14.** 원08의 표본 중복, 원37의 정보이론 반례, 원57의 MAE 중요도 예는 정의와 가정을 점검한 계산이다. 새 traffic/RCTL 성능 결과로 세지 않는다. 반대로 원60·74의 실제 Tab 추론이나 원31의 단순 모델 fit은 문헌 검토·기호 산술과 구별해 보존한다.

<a id="c15"></a>**C15.** 원32를 요약한 265행의 “1~4 cluster”는 뒤에 원35를 요약한 244행에서 1, 2, 4, 6, 8, 12로 정정됐다. 파일에서는 정정 문장이 더 위에 있다. Table II의 without UPC 대시로 정확한 전후 개선율을 계산할 수 없다는 제한도 남긴다. 원33–35 상세 검수로 연결하며 오래된 표현을 재인용하지 않는다.

<a id="c16"></a>**C16.** 원30의 최초 metadata는 datetime 단위를 잘못 가정해 interval_seconds를 0.6으로 적었고, 명시적 ns 변환으로 600초로 수정했다. 최초 JSON을 보존했고 시간 정렬·활동량 비교와 다운로드 횟수는 바뀌지 않았다고 기록한다. 이 처리 오류를 데이터의 실제 0.6초 해상도나 새로운 과학적 결과로 해석하지 않는다.

<a id="c17"></a>**C17.** 원29의 제한적 다운로드 실패에는 상태 코드가 남지 않았다. 후속 원30은 첫날 API의 HTTP400과 guestbook 응답 요구를 확인했다. 뒤에 알아낸 원인을 앞선 실패의 확정 로그로 소급하지 않는다. 두 기록 모두 자료 접근 이력이며 새 예측 실험은 아니다.

<a id="c18"></a>**C18.** 원23은 float32 수치 검사 실패를 float64 계산으로 수정하고 최초 실패·비용을 보존했다. 원54는 모델 호출 전 preflight 오류를 수정한 뒤 실제 복원 확인을 수행했다. 최초 실패, 복구 후 수행, 복구 후 과학적 판단을 각각 찾도록 연결한다. 복구가 곧 후보 성능의 성공을 뜻하지 않는다.

## 긍정 증거와 재검토 조건

<a id="c19"></a>**C19.** 후보표는 원60·74·80의 직접 예측 긍정 증거를 유지한다. 원60의 짧은 global 입력 이득, 원74의 공통 입력 직접 teacher 이득, 원80의 저장 129분위수 평균 이득은 각각의 개발 조건에 관한 결과다. 특히 원80에는 새 Tab 호출이 없었다. 이득이 새 소속 선택·출력 압축·최종 RCTL 개선으로 이어졌다고 합치지 않는다.

<a id="c20"></a>**C20.** 원46의 공간 입력은 일부 cell에서 양쪽 주에 이득이 있었고 원26의 empirical 분할은 입력으로 정한 빠른 증가 상태에서 두 seed·시간 양 절반의 이득을 보고했다. 평균 손해가 있다고 이 증거를 지우지 않는다. 유리한 cell의 사후 선택이나 empirical 결과를 Tab clustering의 성공으로 옮기지 않는다.

<a id="c21"></a>**C21.** 원49의 실제 미래 합계를 아는 복원, 원42의 cell/sample별 사후 최선 선택은 실현 가능한 예측의 성능과 구별한다. 과거 validation 손실로 선택한 방식도 당시 RCTL 독립 소속 결정 조건과 다르다. 참 합계나 미래 정답 없이 무엇을 계산할 수 있는지가 재사용 조건이다.

<a id="c22"></a>**C22.** 원20의 delta target은 32cell 평균을 크게 줄였지만 개선한 cell은 4개였다고 기록한다. 원67·70은 전체·뒤 기간 손해와 일부 앞 기간·피크 이득을 함께 남긴다. 원82까지의 후보표를 “전부 실패” 또는 “평균 이득이면 성공”이라는 한 문장으로 줄이지 않는다.

<a id="c23"></a>**C23.** 원81은 scalar sample pooling의 반례를 공동 입력·cell별 출력 구조에 그대로 적용하지 않았다. 대신 기존 구조와의 차이, 실제 입력 분할 손해, 같은 hidden 폭의 global 다중 출력 대안을 요구했다. 기호 MAC의 비교를 실행속도·정확도 측정으로 바꾸지 않는다는 기존 검수를 유지한다.

<a id="c24"></a>**C24.** 후보표의 19행은 함수를 공유할 대상, 입력·출력 단위, 표본 재사용·압축, 보호할 손실, 관측·해상도, 동적 소속과 전이 등 서로 다른 결정을 묶은 지도다. 같은 loss 이름이나 모듈만 바꾸어 다시 제안할 때 먼저 해당 상세 기록을 찾는다. 행 수를 19번의 독립 실험으로 세지 않는다.

<a id="c25"></a>**C25.** 기존 실패의 원인을 바꾸는 결정, Tab 값이 바꾸는 선택과 단순 대안, 최종 RCTL에 전달하는 정보·target·학습 단위 및 RCTL 학습결과를 clustering에 넣지 않는 조건, 관찰한 구간의 개발자료 처리와 당시 비용 범위를 명시한다. 완전한 보장이 없다는 이유만으로 실증 후보를 기각하지 않으며 직접 예측 이득만으로 다른 모델의 clustering 개선을 통과시키지도 않는다.

<a id="c26"></a>**C26.** 이번에는 snapshot24의 두 누적 문서 전체와 원82 관련 고유 변경을 정리했다. 앞선 snapshot들의 모든 고유 개정본, 개별 상세 원자료 전체, 원83 이후, 전체 비용·실패 통합, 장기 원자료 접근과 최종 검색 검수의 완료를 뜻하지 않는다. 기존 후속 검수로 연결한 문헌과 결과는 새 독해·실험으로 중복 가산하지 않는다.
