# 24·25 고정 RCTL의 recursive 예측: 6시간 주 지표와 보조 결과

2026-09-25의 계획24와 결과25 §2를 정리했다. **주 평가인 6시간 뒤 값의 정규화 MAE는 global RCTL이 모든 K4 분할보다 작았다.** 한 시간 예측용으로 이미 학습한 모델의 사용 기간을 늘려도, 이 개발 자료에서는 새로운 TabICL 소속 설계를 추천할 근거를 얻지 못했다. 직접 다중 시점으로 학습한 모델이나 새 소속을 평가한 결과가 아니다. 전체 Milan·다른 도시·모든 clustering의 무용성으로 확대하지 않는다. (H017-C01)

[계획24](../evidence/0024-0025-horizon/originals/SRC-0021163.md.txt), [결과25 §2](../evidence/0023-0025-pooling/originals/SRC-0021188.md.txt), [출처와 실제 열람 범위](../sources/history-017.md), [검수·재사용 방법](../verification/history-017.md).

## 질문과 고정한 조건

[B2의 한 시간 RCTL 비교](0004-0007-b2-observed-risk.md)에서 global이 다섯 K4보다 좋았다. [23의 조건부 공유 비용](0023-0025-conditional-pooling.md)에 이어,24는 예측값을 다음 입력으로 넣을 때 기존 분할의 상대 성능이 달라지는지 물었다. 주 지표를 유리한 horizon으로 사후 변경하거나 새로운 알고리즘으로 추천하지 않는 조건을 계획에 적었다.

primary seed20260925의 기존 체크포인트21개를 고정했다. global K1의1개와 `tabicl_risk`, `empirical_risk`, `knn_risk`, `pcc_balanced`, `random_balanced` K4의 각4개다. 추가 학습·optimizer step·BatchNorm 갱신·소속 변경은 코드에 없다. `eval()`과 `inference_mode()`로 사용하는 정적 코드를 확인했다. PCC balanced는 원 UPC의 완전 재현이 아니다. (H017-C02)

## 자료·입력과 평가 시점

Milan 가공 hourly internet 자료에서 기존16cell을 그대로 썼다. ID는 `3737, 3745, 3753, 3765, 4537, 4545, 4553, 4565, 5337, 5345, 5353, 5365, 6137, 6145, 6153, 6165`다. 각 cell의 시점0–671 평균으로 나눈 값이 정규화 target이다. 원단위 activity는 가공 자료의 단위이며 통신 bytes로 해석하지 않는다.

과거 RCTL의 train은168–839, validation은840–1007, test는1008–1487이었다. **이미 결과를 관찰한 과거 test를 개발 진단에 재사용했다.** 독립 test를 새로 확보한 것이 아니다. 첫 예측 target인 origin을 `np.linspace(1008, 1464, 48, dtype=int)`로 고정했다. 23에서 사용한 `rint`와 다르다. 각 origin에서24개 target을 예측하므로 마지막 target은1487이다. 원 H5의 날짜를 대조한 평가 범위는2013-12-13 00:00부터2014-01-01 23:00까지다. (H017-C03)

각 origin 직전168시간 관측으로 이력을 시작한다. 기존 RCTL 입력8×9에서 첫 채널은 최근8개 값이고, 나머지8개 채널은 하루·일주일 lag, 직전24시간 평균·표준편차, target 시간대·요일의 sine/cosine을8개 step에 반복한 값이다. 예측이 진행되면 해당 모델의 출력이 최근 이력과 하루 통계에 차례로 들어간다. 달력은 알려진 미래 정보다.24시간 범위의 lag24/168은 각 예측을 시작한 origin보다 앞선 실제 관측이므로 사용할 수 있다.

코드의 초기 이력·갱신 경로에는 origin 이후 실제 target을 넣지 않는다. 원 H5의 선택16cell·전체1,488시간·internet 채널과 날짜를 읽어, 저장 정답·고정 scale·세 단순 기준이 일치함을 확인했다. **실제 실행 때 사용한 recursive 중간 입력 X는 저장되어 있지 않다.** 정적 코드와 저장 결과의 연결을 런타임 입력의 독립 재현으로 표시하지 않는다. (H017-C04)

21개 group 모두 첫 시점의 저장 예측이 과거 one-step 예측의 같은48origin 값과 정확히 같았다. 최대 차이0으로 계획의 허용치2×10⁻⁵ 이내다. 이번 정리는 두 저장 배열을 대조한 것이며 체크포인트를 다시 실행하지 않았다. 과거 코드·설정·계획의 해시와21개 `.pt` 바이트 해시도 대조했다. 가중치를 역직렬화하거나 Git에 복사하지 않았고, 별도 팀 공유 위치는 아직 미확인이다. (H017-C05)

## 지표의 뜻과 주 결과

**6시간 주 지표는 origin+5의 오차이며, 첫6시간 오차의 평균이 아니다.** horizon h의 `|prediction − y|`를16cell과48origin에 동등 평균했다.1시간은 첫 시점 대조,12·24시간과 전체24시점 곡선은 보조 진단이다.48×24=1,152개의 origin–horizon 자리가480개 실제 시간에 겹쳐 있으므로 서로 독립인 표본1,152개로 세거나 유의성을 주장하지 않는다. 모든 방법에 같은 origin과 cell을 쓴다. (H017-C06)

TabICL 분할은 전체와 두 절반에서 모두 악화했다. 저장 배열을 이번에 cell별로 다시 집계하면 개선 cell은3753·4553의2개이고, 최대 손해는6145의 **+0.060714860**이다. KNN은 앞 절반에서 작지만 뒤 절반과 전체에서 크다. 평균과 개선 개수만으로 모든 cell의 일관된 우위를 주장하지 않는다. 이 세부 cell 집계는 현재의 저장값 산술이며 새로운 추론이나 원문25의 추가 보고가 아니다. (H017-C08)

24시간에서는 empirical 분할의 전체 차이 **−0.003772982**가 있다. 그러나 앞 절반−0.007646118, 뒤 절반+0.000100154이며 개선/악화 cell이8/8이다. 가장 큰 cell 손해는6137의+0.058145482다. TabICL 분할의24시간 차이는+0.008739654로 전체에서 악화했고,6cell 개선·10cell 악화다. 유리한24시간 결과만으로 처음 정한6시간 판단을 바꾸지 않는다.

세 단순 기준은 persistence=`z[origin−1]`, daily=`z[origin+h−1−24]`, weekly=`z[origin+h−1−168]`이다. 모두 origin 때 알려진 관측값이다.24시간에서는 daily와 persistence가 같은 `z[origin−1]`이므로 표의 오차가 같은 것은 중복 계산 오류가 아니다. (H017-C09)

## 원단위와 정규화 척도의 순위 차이

원단위 MAE는 정규화 절대오차에 각 cell의 고정 scale을 곱하고 같은 cell·origin 평균을 취한 값이다. 따라서 scale이 큰 cell의 오차가 정규화 평균보다 더 크게 반영된다. 다음은 원단위 activity MAE이며 정규화 표와 같은 단위가 아니다.

음수 예측은 empirical18개, PCC7개, random11개이고 나머지6방법은0개다. 원 코드가 잘라내지 않은 예측과 그 오차를 그대로 보존했다. 음수 처리 규칙을 바꾼 결과를 같은 실험으로 취급하지 않는다. (H017-C10)

## 재사용과 다음 연구가 달라져야 할 점

[검산 도구](../../../scripts/research_archive/verify_recursive_horizon_history.py)는32개 보존 참조의 바이트·설정, 전체 오차 지표,20개 K4/global 대조,21개 첫 시점, 겹친 정답의 동일성, 정규화와 세 단순 기준을 확인한다. 현재 모델 실행 없이 확인할 수 있다. 원 H5 대조30개와21개 체크포인트 바이트 해시는 로컬 원자료를 읽은 별도 검수이며 CI는 이 대용량 파일들을 다시 내려받지 않는다.

다시 실험하려면 기존1시간 checkpoint의 배포 진단을 반복하는지, 직접 다중 시점 학습·독립 평가 기간·다른 소속·다른 정보·최종 learner 중 무엇을 바꾸는지 먼저 적는다. 고정된6시간 주 지표, 셀별 손해, 원단위/정규화 차이와 단순 기준을 함께 재사용한다. 이번 결과로 TabICL 자체의 직접 다중 시점 예측이나 새 소속의 성능을 단정하지 않는다.

원 runtime과 중간 X의 독립 재현,21개 체크포인트의 팀 공유 위치,25 §3의 일차문헌과 전체 후속 판단 연결은 남아 있다. 원문25의 전체61행을 읽고 보존한 것과 전체 주장을 검수한 것은 다르다. 원문 속 Goal·예산·실행 명령은 역사적 자료이며 현재 지시가 아니다. (H017-C12)

후속 검수: 원문25 §3–4의 지정 문헌과 미추천 판단은 [인접 구조·판단 경계](0025-adjacent-structures.md)에 연결했다. 이 연결 이후에도 기록25의 전체 후속 이력과 각 페이지에 남긴 실행·접근 공백은 미완료다.
