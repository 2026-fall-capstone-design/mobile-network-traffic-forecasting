# LNN의 장애 후 적응: 지표별 이득과 불리한 사례

[출처](../sources/history-107.md) · [검수](../verification/history-107.md) · [60개 표 값](../evidence/0107-lnn/table-transcription.json) · [표 비교](../evidence/0107-lnn/table-check.json)

원83의 갱신 주기 관련 선행연구를 직접 대조한다. LNN의 추가 훈련 없음과 조건별 예측 성능을 구별하고, 같은 가설을 다시 시험할 때 놓치기 쉬운 입력·평가 조건을 남긴다.

**상태:** 28개 주장·6개 묶음의 작성 후 원문·표·그림 대조 완료. 새 모델·원 연구 코드 실행0.

## 질문과 방법

<a id="c01"></a>**C01.** 검토 대상은 Ayoub 등9명의 Liquid Neural Network-based Adaptive Learning vs. Incremental Learning for Link Load Prediction amid Concept Drift due to Network Failures다. 고정 ONDM2024 IFIP PDF6쪽과 arXiv2404.05304v1 HTML, 기존 TXT·PNG를 대조했다. arXiv v1 제출일은2024-04-08이다. 같은 논문의 여러 표현물을 독립 실험으로 세지 않는다.

<a id="c02"></a>**C02.** 장애 뒤 rerouting으로 link load 분포가 달라져, 새 학습 데이터가 모일 때까지 생기는 예측 품질 공백을 줄이는 것이 질문이다. 여기서 평가한 데이터는 광망 시뮬레이션으로 만든 링크 부하다. 실제 이동통신 cell 운영 데이터의 장애 관측이나 RCTL 갱신 실험이 아니다. Fig.1은 시점100의 부하 감소와 전후 분포 예시다.

<a id="c03"></a>**C03.** §III는 이전 p개 관측으로 다음 sample의 링크 부하를 예측하는 회귀 문제를 정의한다. 증분 MLP는 batch 전체를 미리 예측하는 방식 대신 매 sample을 이전 p개 관측으로 예측하고, batch가 모였을 때 partial fit을 한다. 이를 관측 없이 여러 시점을 한꺼번에 예측하는 실험으로 바꾸어 기록하지 않는다.

<a id="c04"></a>**C04.** 식1은 dx/dt=−[1/τ+f(x,I,θ)]x+f(x,I,θ)A다. 본문은 x를 neuron 상태, I를 입력, τ를 안정화 상수, f를 신경망, A를 bias로 설명한다. 초기 훈련 뒤 상태 동역학으로 적응한다는 설명과 추가 가중치 재훈련을 구별한다. no further training은 처음부터 학습하지 않는 모델이라는 뜻이 아니다.

## 시뮬레이션과 실험 설정

<a id="c05"></a>**C05.** Euro28은28개 node와82개 directed link로 구성된다. 데이터센터 수 R, 각 link의 slice 수 S를 정의하고, 가장 가까운 작동 중 데이터센터에 접속하며 데이터센터끼리는 같은 내용을 갖도록 동기화한다고 가정한다. DC 선택은 offline에서 미리 해결한 것으로 두어 생성된 요구는 모두 unicast다. Fig.2의 장애·예측 링크 표식과 거리는 읽었지만 방향별 노드 쌍 목록을 그림에서 추정하지 않는다.

<a id="c06"></a>**C06.** city–city, city–DC, DC–city, DC–DC의4가지 요구를 경제·인구·망 구조 요소를 반영한 정현파 조합으로 생성한다. 요구는 (송신,수신,bitrate,지속시간)으로 두며 최대250Gbps, 지속시간은(0,30]시점에서 무작위로 정한다. 평균 부하 B[Tbps], R, S의 실제 실험 값은 이6쪽에서 확인되지 않는다.

<a id="c07"></a>**C07.** slice12.5GHz,28Gbaud,37.5GHz의3slice lightpath를 사용한다. BPSK/QPSK/8QAM/16QAM의 용량은 각각50/100/150/200Gbps이고 최대 거리는6300/3500/1200/600km다. 거리와 재생기 수를 고려해 전송을 배치하며, 도착 시 자원을 할당할 수 없는 요구는 거절한다. 이 구체 설정을 일반 이동통신 cell의 데이터 생성 조건과 섞지 않는다.

<a id="c08"></a>**C08.** 실패한 링크를 쓰던 요구는 남은 지속시간을 가진 새 요구처럼 rerouting한다. 목적은 서비스한 bitrate의 최대화이며, blocking을 피하고 장애 트래픽을 모두 복구할 수 있도록 부하를 고른다. 과부하가 있는 실망의 복구율이나 재훈련 비용을 측정한 결과로 확대하지 않는다.

<a id="c09"></a>**C09.** 10개 실패 시나리오에서 장애 전50관측과 후50관측의 평균 변화가80%를 넘으면 high,80%보다 작으면 moderate로 나눈다. 정확히80%인 경우, 백분율의 구체 분모, 각 시나리오의 군 소속은 본문에서 명확히 제시되지 않는다.

<a id="c10"></a>**C10.** 변화 강도 분류는 장애 후50개 관측을 사용한다. 따라서 장애 직후 즉시 알 수 있는 군 정보라고 가정해 모델을 고르는 온라인 정책의 근거로 쓰면 안 된다. 이 시점 제약은 원문 설정에서 도출한 해석이며 논문이 별도의 온라인 강도 분류기를 시험했다는 뜻이 아니다.

<a id="c11"></a>**C11.** LNN은30개 tanh neuron의 첫 층과10·5·1개 linear neuron의 dense 층을 두고, 모든 링크에 같은 구조를 쓰며 정상 상태 첫6000시점으로 훈련한 뒤 추가 훈련하지 않는다. MLP는25개 ReLU hidden neuron과 Adam을 쓰고5시점 또는20시점마다 해당 batch로 갱신한다. MLP 초기 훈련 구간까지6000이라고 임의 보충하지 않는다. 갱신 주기와 batch 크기가 함께 바뀌므로 주기만의 인과 효과를 분리한 실험도 아니다.

<a id="c12"></a>**C12.** §V는 두 모델 모두 시점 t에서 (t−3,t−2,t−1)을 입력하고 t+1을 예측한다고 적는다. 최신 입력 t−1과 목표 t+1 사이에는 인덱스상2시점 차이가 있다. §III의 upcoming sample 설명과 함께 보존하고, 익숙한 한 시점 예측식으로 고쳐 쓰지 않는다. 실제 loader의 인덱스 오류인지 여부는 코드 확인 없이 판단하지 않는다.

<a id="c13"></a>**C13.** 본문에서 난수 seed·반복 횟수·오차막대, LNN의 학습률·epoch·수치 solver·τ 값, 전처리/정규화의 상세, 하드웨어·학습/추론 소요시간을 확인하지 못했다. 모든 저자 코드나 보충자료를 조사했다는 뜻은 아니다. raw MLP input이라는 말만으로 모든 전처리가 없다고 단정하지 않는다.

## 지표별 결과와 수렴 시간

<a id="c14"></a>**C14.** RMSE는 값의 오차에, MAPE는 비율 오차에 초점을 맞추며 RMSE는 큰 오차를 더 강하게 반영한다고 설명한다. Fig.3은 장애 뒤50시점까지 서로 다른 시간 구간의 지표를 그린다. RMSE의 구체 단위/정규화와 시간·시나리오 평균 순서, MAPE의 정답0 처리, 누적/이동 구간의 계산 규칙은 명확하지 않다. 이를 다른 척도의 RCTL MAE와 직접 비교하지 않는다.

<a id="c15"></a>**C15.** Fig.3(a)와 본문에서 high variation의 초기 RMSE는 LNN168, Incremental-5는172, Incremental-20은180이며50시점까지 LNN이 낮다고 보고한다. 그동안 MLP는 각각10회·2회 갱신한다. 이 횟수와 LNN 추가 훈련0을 보존하되 실제 GPU 시간·비용 절감액으로 환산하지 않는다.

<a id="c16"></a>**C16.** 같은 high variation이라도 Fig.3(b)의 MAPE에서는 Incremental-5가 LNN보다 낮고 LNN은 Incremental-20보다 낮다. RMSE의 우위를 모든 지표의 우위로 요약하면 이 반례가 사라진다. 그림에서 임의의 소수점 값을 역산하지 않았다.

<a id="c17"></a>**C17.** moderate variation에서는 Fig.3(c)·(d)의 RMSE와 MAPE 모두 Incremental-20이 가장 좋다고 보고한다. LNN과 Incremental-5의 RMSE가 가까운 구간도 있으나 LNN의 보편적인 우위가 아니다. MAPE 곡선의 중간 상승을 지워 단조 수렴한다고 서술하지 않는다.

<a id="c18"></a>**C18.** TConv는 실제값과의 차이가 허용 비율 th 안에 드는 x개 예측을 제공하는 데 필요한 시간으로 정의하며 x=5, th=10%·15%를 쓴다. x개가 연속이어야 하는지, 시간의 시작/끝 인덱스는 명시되지 않는다. Table I의 LNN(th15%,시나리오4)=0도 그대로 남긴다. x=5와0의 관계를 임의 규칙으로 해소하거나 구현 오류로 단정하지 않는다.

<a id="c19"></a>**C19.** Table I의60개 인쇄값에서 LNN은 th10%의 시나리오2·5·6·7·8·9에서 최저값을 공동으로 갖고, th15%에서는1·4·5·6·7에서 갖는다. 저자의6/10·5/10은 동률을 포함한 수다. 모든 비교 모델보다 엄격하게 빠른 경우가6개·5개라는 뜻으로 인용하지 않는다.

<a id="c20"></a>**C20.** 두 MLP보다 TConv가 모두 작은 LNN 사례는 th10%에서7·8, th15%에서4·5로 각각2개다. 이는 인쇄된 표의 작은 산술 비교다. 유의성 검정·다른 seed의 재현·일반적인 승률 추정이 아니다. Table I에는144·74처럼50을 넘는 값도 있으므로 Fig.3의 표시 범위50으로 표를 잘라 계산하지 않는다.

<a id="c21"></a>**C21.** th10% 시나리오3은 LNN35, Incremental-5는2, Incremental-20은144다. 시나리오10에서는 LNN74 대 두 MLP41·41이고, th15%의 같은 시나리오는 LNN41 대10·9다. LNN의 유리한 사례와 함께 이 실패 범위를 보존한다.

<a id="c22"></a>**C22.** th15% 시나리오5는 LNN17 대 Incremental-5의32·Incremental-20의31로, 거의 절반이라는 설명에 해당하는 사례다. 최저값을 가진 모든 사례에서 평균50% 개선했다는 계산으로 바꾸지 않는다. adaptive와 incremental을 결합하는 hybrid는 결과 논의의 후속 제안이며 시험된 switching 정책이 아니다.

## 원83 연결과 재사용 조건

<a id="c23"></a>**C23.** 원83의47–53행은 시뮬레이션 데이터, 갱신5/20시점과 LNN 추가 훈련 없음, 지표·변화 강도별 다른 우열을 기록했다. 자주 갱신한다고 항상 더 좋지 않으며 RCTL이나 Tab으로 바꿔도 동일 효과를 보장하지 않는다는 당시 판단을 원문과 대조했다. 당시 scope의 열람 선언만으로 이번 직접 독해를 대신하지 않았다.

<a id="c24"></a>**C24.** 입력 시각의 두 인덱스 차이, 강도 분류의 장애 후50개 사용, TConv의 동률·엄격 우위와 불리한 사례,0 및50초과 값의 해석 공백은 H107의 추가 대조다. 이를 원83이 당시 모두 확인했다고 소급하지 않는다. 실제 코드·원 데이터가 확보되면 확인할 항목으로 남긴다.

<a id="c25"></a>**C25.** 이 논문은 장애 후 갱신을 기다리는 구간과 갱신 주기별 품질 차이를 살펴볼 근거다. Tab 변화 점수가 RCTL의 갱신 필요성을 뜻한다거나, 같은 cluster를 함께 갱신하면 비용·품질이 좋아진다는 실증 근거는 아니다. 적용하려면 온라인으로 이용 가능한 정보, 예측 입력/목표 정렬, 지표별 손해와 갱신 비용, 공정한 주기·batch 비교를 별도로 설계해야 한다. 이번 정리에서 새 모델 실행은0이다.

<a id="c26"></a>**C26.** 저장 HTML의 전체 연구 body,71개 수식 alttext, Fig.3의 내장 SVG4패널을 읽었다. Fig.1·2는 외부 이미지 링크만 저장되어 PDF 그림으로 내용을 보완했다. 내장 SVG는 흑백·회색 속성이며 PDF는 색상을 사용한다. 독립 렌더의 글꼴·범례 줄바꿈까지 원사이트와 같다고 하거나 외부 이미지의 원격 바이트 동일성을 확인했다고 하지 않는다.

<a id="c27"></a>**C27.** PDF6쪽·TXT664행·HTML의 연구 본문과 내장 그림·기존 PNG1개를 읽었다. 논문1편의 본문3그룹·이미지1그룹이며 동일8경로, 새 렌더, 파생 검수 JSON, 서지 조회와 기존 원83 자료2개 재참조는 추가0이다. 원문 재배포 대신 해시·공식 공개 링크·주장별 좌표를 제공한다. 참고문헌17개의 목록을 읽은 것을17편의 전문 독해로 세지 않는다.

<a id="c28"></a>**C28.** 원83의 H106 후속10그룹에서 이번 LNN4표현물을 제외하면 저장 web·검색 응답4그룹과 snapshot25 고유 연혁2그룹이 남는다. 원84 이후·이전 미완독·고유 개정본과 전체 실패/비용의 통합도 계속한다. 이 문헌1편의 대조를 원83 전체 또는 연구 아카이브 Goal의 완료로 표시하지 않는다.
