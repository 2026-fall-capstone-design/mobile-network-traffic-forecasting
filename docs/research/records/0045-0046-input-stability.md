# 45–46 공간 입력 이득은 다음 주와 다른 회귀기에서도 유지되는가

2026-09-26의 계획 45, 저장 예측 재분석 46, 판단 47의 수치·비용 부분을 연결한다. 46은 [18의 공간 정보 진단](0018-0021-spatial-information.md)에서 이미 만든 예측을 읽었다. 새 TabICL 추론·RCTL 학습/forward·단순 모델 적합은 모두 0이다. 이번 정리에서도 모델을 실행하지 않았다. 47의 문헌·입력 역할·논리 반례·규모 계산·종합 판단은 후속 검수 대상이다. [출처와 실제 열람 범위](../sources/history-027.md)

## 질문과 실제로 한 일

45는 다른 cell의 학습 **행**을 함께 쓰는 sample 공유와, 다른 cell의 과거 관측값을 예측 **열**에 추가하는 입력 공유를 구별했다. 46의 질문은 기존 공간 입력의 작은 평균 이득이 특정 cell에서 앞·뒤 주 모두 나타나고, Ridge와 HGB 사이에서도 유지되는지였다. 소속을 바꾸거나 RCTL 입력을 수정한 실험은 아니다.

32개 cell과 336시간을 모두 유지하고 첫 168시간/다음 168시간으로 나눴다. 각 cell·회귀기에서 첫 주 MAE가 가장 작은 입력을 고른 뒤, 그 입력의 저장된 다음 주 예측을 평가했다. 두 번째 주 정답으로 최선의 입력을 고르는 oracle도 별도로 계산했다. 결과를 본 뒤 특정 cell을 제외하지 않았다. 계획·코드·시작/완료 표시·결과·당시 스냅샷이 함께 남아 있다. [계획](../evidence/0045-0046-input-stability/originals/SRC-0021616.md.txt), [정적 코드](../evidence/0045-0046-input-stability/originals/SRC-0022883.py.txt), [저장 결과](../evidence/0045-0046-input-stability/originals/SRC-0027916.json)

## 첫 주의 입력 선택과 다음 주 평가

입력 순서는 자기→평균→PCC→8방향이다. `argmin`은 반올림 전 첫 주 MAE를 사용하고 정확한 동률이면 이 순서의 앞 대안을 택한다. 다음 주 정답은 첫 주 선택에 들어가지 않는다. 저장된 예측 중 하나를 선택했으며 새 모델을 적합하거나 두 번째 주에 재학습하지 않았다.

| 모델 | 자기 입력 고정 | 첫 주 선택 | 차이: 선택−자기 | 다음 주 정답 oracle |
|---|---:|---:|---:|---:|
| Ridge | 0.148158 | 0.148305 | +0.000147 | 0.145866 |
| HGB | 0.234062 | 0.233553 | −0.000509 | 0.231390 |

| 모델 | 선택 수: 자기/평균/PCC/8방향 | 다음 주에 자기보다 개선 | 다음 주 oracle과 입력 일치 |
|---|---|---:|---:|
| Ridge | 7 / 13 / 8 / 4 | 15/32 | 15/32 |
| HGB | 5 / 10 / 6 / 11 | 15/32 | 17/32 |

HGB의 작은 평균 이득을 보존하되 Ridge의 악화도 함께 기록한다. oracle은 미래 정답을 이용하므로 실행 가능한 예측 정책의 성능이 아니다. 이 두 주는 이미 여러 진단에서 관찰한 개발 구간이며 새 독립 시험 구간이 아니다. TabICLv2의 우월성이나 RCTL 소속 개선을 입증하지 않는다. [41–42의 16개 cell·480시간 RCTL 평가](0041-0042-cell-harm.md)와 직접 성능 순위를 매길 수도 없다.

## 비용·보존 범위

46에 기록된 시간은 `0.030363999998371582`초다. 입력·계획 해시 계산과 설정/시작 표시 저장 **이후**, NPZ 읽기부터 기존 18의 평균 MAE 대조까지 잰 값이다. RSS 읽기·상한 검사·원본 재해시·결과 저장 시간은 타이머 밖이다. `run_finished.seconds`도 같은 값이며 더 넓은 총 wall time은 아니다.

`peak_RSS_bytes=35,512,320`은 종료 무렵 한 번 읽은 RSS다. 연속 측정한 실제 최대 메모리가 아니다. 10초·1 GiB는 당시 진단의 설정 상한으로, 현재 정리 작업에 대한 예산이 아니다. 입력·계획·설정 해시를 확인했고, 코드 해시는 실행 후 스냅샷 보존 시 기록됐다. 실행 전에 코드 해시가 고정됐다고 주장하지 않는다.

| 당시 누적 항목 | 스냅샷 10에서 확인한 값 |
|---|---:|
| cheap 진단 합계 | 55.832847100초 |
| 기록된 modeling 합계 | 1,947.726745200초 |
| Tab context / query 행 | 45 / 35,712 |
| 당시 남은 Tab context / query 행 | 35 / 24,288 |
| RCTL fit / 당시 잔여 | 29 / 0 |

modeling은 cheap 합계에 Tab fit/predict, RCTL wall, 고정 RCTL inference 시간을 더한 당시 원장 정의다. [46 직후 원장](../evidence/0045-0046-input-stability/originals/SRC-0000661.json)의 마지막 cheap 항목이 `input_sharing_stability_46`이며 결과의 시간과 일치한다. 현재 누적 원장의 같은 prefix도 일치한다. 이는 저장 원장의 단일 반영 일관성 검수이며, 파일에 없는 실행이 없었다는 전수 증명은 아니다. 초기 미기록 전처리를 포함한 완전한 총시간도 아니다. 기존 18의 256번 단순 적합 비용을 46의 새 비용으로 더하지 않는다.

## 당시 판단·재사용·재검토 조건

46 결과는 `selection_changes_RCTL_clustering=false`, `accepted_research_direction=false`를 기록했다. 수치 부분의 판단은 일부 공간 입력 이득이 있으나 회귀기 간 교집합이 작고, 앞 주 선택이 뒤 주에 준 이득도 작거나 반대라는 것이다. 이것만으로 모든 공간 입력이 무용하다고 기각하지 않는다. 47의 문헌을 포함한 전체 미추천 논리는 별도 검수 전이다.

팀은 [근거 묶음](../evidence/0045-0046-input-stability/README.md)의 기존 NPZ, 46의 설정·cell별 결과·코드 사본과 스냅샷 원장을 재사용할 수 있다. 같은 32개 cell·같은 두 주의 단순 입력 선택 질문을 새 모델 실행으로 반복할 필요는 없다. 새 질문은 예측 시점에 실제로 사용 가능한 열의 구성, 독립 기간, 회귀기 사이에 선택이 유지되는지, 그 입력 설계와 RCTL 학습 단위의 연결을 구체적으로 바꿔 설명해야 한다. 이 조건은 실험 설계를 위한 구분이며 현재 새 실험을 승인·실행했다는 뜻이 아니다.

확장된 공간 입력 X와 적합된 단순 모델 객체는 저장되지 않았다. H012의 HDF5 대조는 입력 구성법·이웃/PCC·정답의 확인이며 과거 모델이 실제 받은 X의 별도 저장물을 확인한 것은 아니다. 라이브러리 환경 전체와 원 CDR 전처리의 재현, 47의 문헌·논리·규모 판단, 관련 후속 75번과 전체 연구 이력의 연결은 남아 있다. [검수 결과와 주장별 근거](../verification/history-027.md)
