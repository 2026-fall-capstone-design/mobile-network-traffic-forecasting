# 56·58 TimeDC의 합성 자료 압축과 재사용 조건

[과거 시도 색인](../prior-attempts.md) · [출처·독해 범위](../sources/history-046.md) · [인쇄표·근거](../evidence/0056-0058-timedc/README.md) · [주장별 검수](../verification/history-046.md) · [MAE 표본추출 반례](0056-0058-mae-sampling.md)

2026-09-26의 58번 기록은 TimeDC를 학습 자료 압축의 가까운 선행으로 검토했다. **전체 자료로 expert를 준비하고 합성 시계열을 만드는 방법이므로, 실제 입력·정답 쌍을 그대로 선택해 RCTL 학습량을 줄이려던 당시 목표에 바로 대입하지 않았다.** 이 판단은 TimeDC의 성능 실패나 다른 모델로의 전이 불가능성을 뜻하지 않는다. 현재 아카이브는 당시 보고를 주논문과 고정 공개 코드에 대조했으며, 새 학습·추론·원 스크립트 실행은 하지 않았다. (C01)

## 확인한 자료와 판본

Miao 등의 [Less is More: Efficient Time Series Dataset Condensation via Two-fold Modal Matching](https://www.vldb.org/pvldb/vol18/p226-miao.pdf)은 PVLDB 18(2):226–238, 2024, DOI `10.14778/3705829.3705841`이다. 저장 PDF와 현재 공식 응답은 같은 바이트다. 전체 13쪽 텍스트, 수식·알고리즘·그림이 있는 11쪽 시각 자료를 읽었고, 표 1–7의 수치 494개를 원 단위대로 연결했다. 수식의 모든 증명을 독립 인증하거나 raw run을 재현한 것은 아니다. (C02)

저장 arXiv 이력은 `2410.20905v1`, 2024-10-28 제출의 Extended Version을 가리킨다. 공개 README의 제목에는 PVLDB 2025, 인용 정보에는 2024가 쓰였다. 출판 주논문·행사 표기·별도 확장판을 하나의 동일 파일로 취급하지 않는다. 확장 PDF, 저장소의 Appendix·Additional_experiment·별도 그림은 이번에 읽은 주논문 범위에 포함하지 않았다. README의 숨겨진 HTML 주석도 소스 텍스트로 읽었지만, 렌더된 본문의 공개 결과 표처럼 인용하지 않았다. (C03)

공개 코드 기준은 [commit 6016968](https://github.com/uestc-liuzq/STdistillation/tree/60169680447a12ad77b050831ee71da8be7f48f7)이다. 저장된 코드·README 8개, 1,829줄이 이 commit의 Git blob과 일치한다. 직접 연결된 텍스트 27개도 같은 commit에서 받아 바이트를 검수했다. 그중 26개, 2,221줄은 전체를, `utils.py`는 imports·시간 표시·노이즈 함수 26줄만 읽었다. 저장소의 모든 파일·패키지 환경·가중치를 검토한 것으로 표시하지 않는다. (C04)

## 압축하는 대상과 최적화 방법

TimeDC는 원 자료의 M개 학습 시계열보다 훨씬 적은 N개의 **합성 학습 시계열**을 만든다. 행 수를 줄이는 이 목표는 원본 표본의 부분집합 선택, cell 소속 결정, 과거 입력 길이 단축과 다르다. 주논문 §3은 원 자료로 학습한 같은 구조의 TSOperator expert trajectory를 미리 buffer에 저장하고, 합성 자료로 학습한 파라미터 경로를 맞춘다. 원 자료 전체를 이용하는 사전 단계가 필요하다. (C05)

TSFE는 채널별 시계열을 patch로 나누는 Transformer 기반 특징 추출기다. 논문의 DDFM은 이동평균으로 추세와 잔차를 분해한 표현의 cosine 관계를 맞춘다. Fourier 변환을 적용한 방법이라고 바꾸어 설명하지 않는다. CT²M의 정규화된 파라미터 거리, 같은 초기화, expert 선택 조건도 목적함수의 일부다. 본문의 “theoretical upper bound”라는 표현만으로 원 자료 학습보다 항상 나빠야 한다는 성능 정리가 성립하지 않는다. (C06)

식 14의 음의 cosine 거리, 식 15와 Algorithm 2의 내림차순 정렬을 “비슷한 것부터 어려운 것까지”라는 서술에 대응시키면 방향을 다시 확인할 부분이 있다. 고정 예측 entrypoint에서는 buffer를 무작위로 섞고 순회하는 흐름을 확인했으며 명시적 cosine curriculum 정렬은 찾지 못했다. 저자 실행 판본과 수식의 정확한 대응을 확인할 공백으로 남긴다. (C07)

## 데이터·평가 조건

주요 예측 표에는 Weather, Traffic, Electricity, ETTh1/2, ETTm1/2의 **7개 데이터셋**이 있다. 본문 일부의 “six”와 구분한다. Traffic은 샌프란시스코 도로의 시간별 점유율이며 이동통신 트래픽이 아니다. Weather는 10분 간격 21개 변수, Electricity는 321개 client, ETT는 7개 변수의 변압기 관련 시계열이다. 시계열 분류는 ECG200·ElectricDevices·FordB의 별도 평가이며 RCTL 미래 예측 결과가 아니다. (C08)

논문은 예측 합성 자료 500개, 분류 50개, 예측 길이 96/192/336, ETT 6:2:2·그 외 7:1:2 분할을 보고한다. 기본 patch/stride는 16/8, TSOperator 3층, attention head 16개, 초기 학습률 .0001, expert 10개다. “NVIDIA GTX 3090”은 원문에 인쇄된 장치명이다. seed별 반복 수·정확한 CSV 시점·환경·실행 로그는 이 보고만으로 확인되지 않는다. (C09)

공개 예측 loader는 ETT를 30일짜리 월 기준 12/4/4개월의 행 경계로, Custom을 처음 70% 학습·끝 20% 테스트·나머지 검증으로 나눈다. 검증/테스트의 입력에는 경계 앞 `seq_len`만큼의 과거가 포함되고, StandardScaler는 학습 구간만으로 fit한다. 이 과거 입력 중첩을 미래 정답의 학습 유입과 동일시하지 않는다. 테스트는 `drop_last=True`여서 마지막 불완전 batch가 제외된다. 입력별 RevIN 역변환과 외부 StandardScaler의 원 단위 역변환은 다르며, `model_test`는 후자를 호출하지 않는다. (C10)

16개 shell 설정은 실행된 로그가 아니다. 대체로 입력 길이 336·`train_epochs=100`을 주지만 ETTh는 head 4개·d_model 16, 주요 다른 자료는 head 16개·d_model 128이다. Electricity의 720 예측과 illness의 104 입력·24/36/48 예측도 있어 논문의 주요 표 범위를 넘는다. 예측 buffer의 기본 expert 수 20과 논문 기본 10도 구분한다. `random_seed=2021`이라는 parser 인자만으로 실제 난수 고정을 확정하지 않는다. (C11)

## 성능 표에서 재사용할 사실과 예외

Table 1은 Random·K-Center·Herding·DC·MTT·TimeDC를 같은 TSFE 예측기로 비교하며, Whole Dataset은 원 자료 학습의 참고값이다. 인쇄된 21조건×2지표에서 TimeDC가 다섯 압축/선택 비교군보다 작다. 그러나 Whole Dataset보다 오차가 큰 항목은 41개, 작은 항목은 1개다. 이를 42개의 독립 반복 실험이나 통계적 유의성으로 세지 않는다. (C12)

| Table 1 조건 | TimeDC MAE / MSE | Whole Dataset MAE / MSE | 해석 |
|---|---:|---:|---|
| Weather, 96 | .257 / .188 | .239 / .182 | 두 오차 모두 증가 |
| Electricity, 96 | .274 / .267 | .252 / .268 | MAE 증가, MSE는 .001 감소 |

본문의 “최대 MAE 개선 13.49%”와 Table 1 인쇄값에는 차이가 있다. Weather·192의 가장 작은 기존 비교군 MAE .344에 대해 TimeDC .285를 대입하면 `(.344−.285)/.344×100 ≈ 17.1512%`다. MSE의 최대 감소율은 ETTh2·336의 .455→.334로 약 26.5934%다. 새 실행 결과가 아닌 표의 산술이며, 본문 숫자를 몰래 고치거나 원 실행 값이 어느 쪽인지 추정하지 않는다. (C13)

Table 2는 **TimeDC가 만든 합성 자료로 서로 다른 예측 구조를 학습한 비교**다. 각 구조를 원 자료로 학습한 대조 열이 없으므로 모든 구조의 원 자료 대비 보존율 표로 읽을 수 없다. 반대로 다른 구조에서도 학습한 결과가 있다는 사실을 지우고 “한 학습기에서만 작동”한다고 단정해서도 안 된다. 28개 조건 중 6개는 다른 구조의 인쇄값이 TimeDC보다 작다. ETTm2의 두 예측 길이·두 지표와 Electricity의 두 MSE가 해당한다. 예컨대 ETTm2·192 MAE는 Autoformer .334, TimeDC .401이다. 굵은 글씨만으로 전체 최솟값을 판정하지 않는다. (C14)

Fig. 5에서는 Weather·Electricity의 합성 자료를 500개에서 800개로 늘렸을 때 성능이 조금 나빠진다. Fig. 6은 patch·DDFM·CT²M 제거 비교, Fig. 8은 t-SNE 시각화, Fig. 9는 분류 정확도·recall 비교다. 곡선·막대의 원 좌표나 반복별 분산을 새로 복원하지 않았다. t-SNE에서 점이 겹친다는 사실을 모든 고차원 분포나 RCTL 효용의 일치 증명으로 사용하지 않는다. (C15)

## 지표 표기의 미해결 차이

§4.1.3의 문장에는 RMSE, 식 17과 Tables 1–2에는 제곱근 없는 MSE가 쓰였다. 공개 `process/metrics.py`는 MSE와 `sqrt(MSE)`인 RMSE를 별도로 정의한다. 따라서 인쇄 MSE를 RMSE로 이름만 바꾸어 인용하지 않는다. (C16)

Table 5의 Weather·I에서 TimeDC의 인쇄 MAE는 .656, RMSE는 .512다. 같은 관측·가중·척도의 절대오차와 제곱근 평균제곱오차라면 RMSE≥MAE이므로 그대로는 정의가 맞지 않는다. **인쇄 표기는 유지하고 집계 방식·실제 출력·오탈자를 확인할 항목으로 남긴다.** .512가 사실은 MSE였다고 확정하거나 논문 전체가 무효라고 결론 내리지 않는다. (C17)

## 학습 시간·메모리·저장의 분모

Table 4의 단위는 초/epoch다. 세 열은 각각 압축 과정, 합성 자료에서 예측기 학습, 원 자료에서 예측기 학습이다. (C18)

| 데이터 | 압축 | 합성 자료 학습 | 원 자료 학습 |
|---|---:|---:|---:|
| Weather | 22.39 | 4.31 | 35.26 |
| Traffic | 232.34 | 61.94 | 346.76 |
| Electricity | 314.56 | 41.14 | 522.85 |
| ETTh1 | 14.38 | 4.93 | 20.43 |

Weather의 4.31 대 35.26은 합성 자료 학습 한 epoch의 약 87.78% 감소다. expert 준비와 압축 비용을 포함한 총비용 88% 절감이 아니다. Electricity의 본문 39.84%도 314.56 대 522.85라는 서로 다른 단계의 단일 epoch 시간을 비교한 값이다. (C19)

재사용 비용은 `expert 준비 + 압축 epoch 수×압축 시간 + 후속 학습별 epoch 수×합성 자료 학습 시간 + 입출력·평가 등`으로 구분해야 한다. 원 자료를 여러 번 학습하는 기준과 비교하려면 반복 횟수, 각 단계의 종료 조건, 같은 품질 기준이 필요하다. 이 논문 표만으로 손익분기 반복 횟수를 숫자로 확정하지 않는다. (C19)

Table 3은 동적 온라인 tensor 메모리이며 미리 저장한 expert buffer까지의 전체 메모리·저장 비용은 아니다. Table 6은 **전처리된 학습 자료**의 저장 크기이며 원 CSV 크기·수집 센서 수·통신량 감소율과 다르다. ETTh1의 12.8MB/313.1MB는 약 4.088%로 본문의 4.09%와 맞는다. 다른 행의 GB/MB를 명시되지 않은 단위 환산으로 총 byte라고 바꾸지 않았다. Table 7의 Weather 1.8M·ETTh1 .2M은 TSFE 모델 파라미터 수다. 합성 표본 수나 총 훈련비를 뜻하지 않는다. (C20)

## Streaming 비교의 범위

§4.3은 원 자료를 B:I=7:3으로, 각각을 다시 7:1:2로 나눈다. B0는 초기 base 평가, B1은 incremental 학습 뒤 base 평가, I는 이후 incremental 평가다. TimeDC는 압축한 base와 신규 자료를 함께 쓰고 Autoformer fine-tuning은 신규 자료로 갱신한다. 구조와 과거 자료 재사용 방식이 함께 달라 압축 한 요소만의 효과를 분리한 비교가 아니다. 이는 주논문이 보고한 streaming 결과이며 이번 아카이브의 재현 결과가 아니다. (C21)

## 고정 공개 코드를 사용할 때 확인할 조건

아래는 [고정 코드](../sources/history-046.md)의 정적 관찰이다. 원 패키지 설치·import·pickle load·model forward를 수행하지 않았으므로 최초 실행 오류나 논문 실제 실행 경로를 확정하지 않는다. 과거 58에서 이미 지적한 X/y 선택·optimizer 연결 문제를 재확인했고 직접 의존성에서 추가 조건을 확인했다. (C22)

| 연결 지점 | 관찰한 내용 | 재사용 조건 |
|---|---|---|
| 합성 X/y | 초기 helper와 inner 학습에서 X·y 인덱스를 각각 추출한다. 초기 x_sys를 optimizer에 넣은 뒤 재대입하고 공통 TensorDataset은 x/y를 detach한다. | 원 입력·정답의 pairing, 실제 최적화할 tensor와 gradient 연결을 확인한다. |
| 예측 trajectory | target index가 `start_epoch + it//50`이다. | it=0…49에서 같은 유한 파라미터라면 정규화 분모가 0인 경로를 확인한다. 실제 NaN 관측으로 기록하지 않는다. |
| 논문 목적과 코드 | 검토한 예측 outer loss는 parameter loss이며 inner는 MSE다. 반환 res/trend는 outer cosine loss에 쓰이지 않고 예시 cosine 계산은 주석이다. | DDFM·curriculum을 포함한 정확한 저자 실행 판본을 확인한다. |
| 분류 모델 | `buffer_cls.py`가 import하는 ST_Model은 network_patch에 없다. distill_cls는 TSFE_Model만 import하고 ST_Model을 호출한다. 비분해 forward의 self.fc 선언은 주석이다. | 분류 entrypoint·모델 반환 형식·head 연결을 확인한다. |
| 예측 조기 종료 | evaluate_synset이 vail_loader를 받지만 early stopping에는 test_loader를 사용한다. | 그대로 실행하면 테스트가 모델 선택에 참여하므로 독립 validation/test 경로를 확인한다. |
| train/eval | 기본 use_amp=False의 model_train에는 model.train() 복귀가 명시되지 않으며 model_test는 eval()을 설정한다. | dropout·BatchNorm 모드를 epoch 경계에서 확인한다. |
| 분류 전처리 | 전체 UCR x를 scaler fit한 후 split하고 val/test에 같은 split[1]을 쓴다. | 실제 tsai 반환 형태·판본과 holdout 통계 유입을 확인한다. |
| 분류 train·지표 | train 함수의 return이 batch loop 안에 있다. accuracy는 포함 표본 전체, recall/precision은 각 batch의 첫 표본으로 계산한다. | batch_size>1에서 평가 모집단이 달라지는지 확인한다. |

이 차이는 **이 commit을 검증된 실행 baseline이라고 표시할 수 없는 이유**다. 코드를 고치거나 재학습한 결과가 아니며, 출판 논문에 사용한 비공개·다른 판본도 같은 경로였다는 증거는 아니다. 예측 evaluate_synset의 인자 수 자체는 호출과 맞는다. streaming helper의 네 반환값/세 변수 unpack 문제는 별도 경로다. (C23–C26)

shell의 `--model`도 주의할 부분이다. 두 예측 parser에는 `--model_id`만 있고 명시 `--model`은 없다. 기본 argparse 축약을 유지하면 유일한 접두사인 `--model_id`로 해석되어 앞의 값을 덮을 수 있다. 단순히 미인식 인자 오류라고 단정하지 않는다. 파싱 목록만 정적으로 대조했으며 shell을 실행하지 않았다. (C27)
