## 같은 조건에서 무엇을 바꿨는가

637은 48회 이분 탐색 뒤 혼합 CDF의 중앙값 잔차가 `1e-7` 미만인지 검사했다. Tab의 knot·탐색 구간은 float32여서 구간이 더 좁아지지 못할 수 있었다. HGB의 knot는 float64였다. 저장된 22개 지원 edge에서 Tab의 수치 유효 행은 각각 30–62개였고, HGB는 각각 128개였다.

638은 **이미 저장한 분위수의 값을 그대로 float64로 표현**했다. 분위수 수준, p 지원 임계값, 데이터, cell, K, 점수, 이동 규칙을 바꾸지 않았다. 637의 결과와 비용은 보존했다. [수정 계획](../evidence/0635-0638/originals/SRC-0022004.md.txt), [수정 코드](../evidence/0635-0638/originals/SRC-0022529.py.txt), [결과](../evidence/0635-0638/originals/SRC-0024153.json).

이 입력에서 수치 유효성은 두 모델 모두 edge당 128행으로 회복됐다. 실제 graph 집계에는 여전히 p 지원 mask와 절반별 조건을 적용한다. “모든 128행이 수치 유효”와 “모든 128행이 집계에 포함”은 다르다.

## 재사용 가능한 점수와 이동 명세

각 pair에서 D=1인 cell의 분포를 F1, 다른 cell을 F0, 입력 소속 확률을 p라고 둔다. 0.1–0.9의 정렬된 9분위수 사이를 선형 보간하고, 바깥 CDF는 각각 0.1·0.9, 밀도는 0으로 둔다.

```text
p F1(q) + (1-p) F0(q) = 0.5
f_mix = p f1(q) + (1-p) f0(q)
w = sign(F0(q) - F1(q))
a = p f1(q) / f_mix
S = w (D-a) {0.5 - 1[Y <= q]}
C_half = max(0, (mean(S | cell 1, half) + mean(S | cell 0, half)) / 2)
J_half = sum(C_half for supported edges inside the same cluster)
```

q·a·w는 학습 자료로 추정한 분포와 p로 정한다. 개발 query의 실제 Y는 S에 사용한다. q는 혼합 분포의 보조 중앙값이며 실제 공동 context Tab 예측이라고 부르지 않는다. 양의 부분 clipping에는 유한 표본 편향 가능성이 있고 비용 0은 동등성 인증이 아니다.

인접 knot의 간격이 `1e-10 × max(1, max|knot|)`보다 커야 하며, 혼합 밀도가 양수·유한하고 root 잔차가 `1e-7` 미만이어야 한다. 두 모델의 수치 유효성 및 p 지원 mask를 함께 적용한다. 각 cell·각 절반에서 최소 8입력·2관측 날짜 조건을 다시 확인한다.

UPC K4에서 cell ID 순서로 최대 3회 sweep한다. 출발 cluster를 비우지 않고, 목적지에 유효 edge 이웃이 2개 이상 있으며, 두 절반의 J가 각각 `1e-12`보다 크게 줄어들 때만 이동한다. 가능한 목적지 중 두 변화량 평균이 가장 작은 곳을 고르고 동점은 cluster 번호순이다. 이동 없는 sweep 또는 3회 종료가 정지 조건이다. 이는 제한된 graph의 지역 탐색이며 모든 관계나 전역 최적해를 보장하지 않는다.

식의 선행연구 독창성은 이 수치 검수의 범위 밖이다. 원문이 연결한 512·634의 재가중 공식 검토는 후속 문헌 묶음에서 확인한다.

## 확인한 근거와 한계

과거 검수 파일은 22,600개 검사, 독립 선형 해와 최대 차이 `1.9984014443252818e-15`, 새 모델 0을 기록한다. 이는 당시 프로그램의 검사 횟수이지 독립 실험 횟수가 아니다. [당시 검수](../evidence/0635-0638/originals/SRC-0024160.json).

이번 아카이브에서는 보존한 분위수·p·truth를 읽어 **5,632개의 혼합 중앙값**을 별도 구간 보간 계산으로 대조했다. 최대 차이는 같은 값이었고, 회복 행 수·공통 mask·graph 비용·이동의 두 목적 감소도 일치했다. 원본 PC 경로 없이 저장소의 사본만으로 이 대조를 실행했다. 모델을 다시 실행한 독립 재현으로 표현하지 않는다. [검수 방법과 결과](../verification/pilot-001.md).

당시 판단은 “다른 소속이 나왔으므로 봉인된 소속의 작은 RCTL 확인으로 진행”이었다. 소속 선정 과정에서 RCTL 결과를 읽지 않는다는 코드·기록을 확인했으며, 이 단계의 새 RCTL 학습은 0이다. 미래 관측에 대한 정보 누출 전체를 감사한 것은 아니다. 두 query 절반은 모두 개발 자료다.

이 결과를 재검토할 때는 저장 예측과 같은 명세로 먼저 수치 대조를 사용한다. 새로운 cell·기간·지원 기준·분위수·모형을 도입하면 별도 실험으로 조건 차이를 남긴다. [639](0639-rctl-bridge.md)에서 최종 RCTL 효과와 기간별 손해·척도별 순위 차이를 확인할 수 있다. 640의 기여 범위와 641의 캐시 대조는 후속 검토 대상이다.
