## 공식 기능 예제와 평가 실험을 구분하기

예제는 `make_moons(n_samples=200, noise=0.15, random_state=42)`로 만든 두 특성 자료를 사용한다. `n_estimators=4`, `categorical_features=[]`, CPU, 모델 seed 42다. 네트워크 cell 자료나 시계열은 아니며 날짜·시간 분할·네트워크 단위는 해당하지 않는다. 문서는 이 비지도 구현을 큰 벤치마크에서 평가하지 않은 실험적 기능으로 소개한다.

먼저 **완전한 X로 `model.fit(X)`를 호출하고, 이후 같은 X의 복사본에 결측을 만든다.** mask 생성기는 seed 0을 사용하며, 200행 중 정확히 100행을 고르고 각 행의 두 특성 중 하나만 가린다. 따라서 결측이 있는 행은 50%, 결측 스칼라 원소는 100/400=25%다. 여기서 “cells”는 행렬 원소이며 기지국·네트워크 cell 25%를 뜻하지 않는다.

완전 관측 자료가 이미 context에 들어간 기능 시연이므로, 처음 보는 표본의 복원·운영상 관측 생략·미래 예측 성능을 입증한 결과로 사용하지 않는다. mask가 무작위라는 사실만으로 독립 평가가 되지 않는다. 시간 순서 검증, 단순 복원 비교군, held-out MAE/RMSE, 반복 seed의 불확실성은 이 예제에 없다.

누락 위치를 그린 가운데 패널도 NaN이 들어간 `X_masked`의 좌표를 표시한 것이 아니다. **원래 X의 좌표에 “결측을 적용한 행”을 사각형으로 표시**한다. 마지막 패널에는 복원된 좌표를 그린다. 두 패널의 모양만으로 실제 결측값을 정확히 찾았거나 복원 오차가 작다고 판정하지 않는다. [고정 tutorial](https://github.com/soda-inria/tabicl/blob/0dbff3ec8fc68c123c87af77b0ea8b25cd2d23f3/tutorials/unsupervised_learning.py).

## 저장 코드의 impute 절차

`unsupervised.py` 230–329행과 626–765행에서 확인한 동작은 다음과 같다. 전체 wrapper는 765행을 읽었으며 아래 설명은 이 고정 버전에 한정한다.

1. 입력을 `float32`로 바꾸고 복사한다. 결측이 있는 열을 결측 비율 오름차순으로 정렬하고, 원래 결측 위치를 별도 mask로 보존한다. 결측이 없으면 변환된 복사본을 반환한다.
2. 수치형 결측은 training 열의 중앙값, 범주형 결측은 최빈값으로 우선 채운다. 이는 query 쪽의 초기화이며 저장 context 전체를 새로 완전 관측 자료로 만드는 절차는 아니다.
3. 기본 2회 반복에서 각 결측 열을 대상으로, **나머지 모든 열의 현재 값**을 조건으로 사용한다. 같은 반복에서 먼저 대체한 값도 이후 열의 조건에 들어간다. 원래 관측된 위치를 대체 대상으로 바꾸지는 않는다.
4. target이 관측된 training 행을 사용해 조건부 estimator를 구성하고, 수치형은 분위수 분포, 범주형은 class 확률에서 값을 얻는다. 순서는 처음 정한 결측 비율 순서로 반복한다. 고정 횟수 반복이며 수렴 판정으로 일찍 중단하는 분기는 없다.

docstring의 한 번 “left-to-right” 순회 설명과 실제 결측 비율 정렬을 구별한다. 관측 위치를 대체하지 않는다는 말도 임의 입력 dtype의 비트 단위 보존을 뜻하지 않는다. `float32` 변환의 정밀도 변화는 별도다. [고정 impute 코드](https://github.com/soda-inria/tabicl/blob/0dbff3ec8fc68c123c87af77b0ea8b25cd2d23f3/src/tabicl/_unsupervised/unsupervised.py#L230).

이 절차는 MICE와 비슷한 반복 조건부 대체다. MICE라는 이름만으로 수렴·올바른 joint distribution·통계적 다중 대체 추론·불확실성 calibration까지 검증됐다고 표시하지 않는다. 저장 코드의 기본 반환은 한 개의 대체된 행렬이며, 예제는 여러 대체본의 추정량을 결합하는 평가를 하지 않는다.

### 적은 training 값과 전부 결측인 열

target의 유효 training 값이 5개 미만이면 조건부 모델 대신 `nanmean`을 넣는다(314–318행). 이 분기는 범주형에도 적용된다. 예를 들어 범주 값이 0과 2뿐인 두 개 관측의 평균은 1이며, 관측된 범주에 없는 값이다. 이는 **코드 경로와 작은 산술 예**로 확인한 경계이지, 해당 모델의 전체 성능 실패나 실제 데이터에서의 발생 빈도 측정이 아니다.

training target이 전부 NaN이면 수치형 초기 중앙값·fallback 평균에서 유효한 값을 얻는다는 근거가 없다. 범주형 초기값 0도 이후 반복의 `nanmean`을 유효하게 만들지는 않는다. query에서만 일부 값이 빠진 기능 예제를, 학습 context 자체가 심하게 결측인 환경의 검증으로 확대하지 않는다.

## 온도와 점수의 의미

수치형 sampling은 `F^-1(0.5 + (u - 0.5) × temperature)` 형태이고, 최종 분위수 위치를 `1e-6`부터 `1-1e-6`까지 제한한다. 온도 0.5는 중앙 분위수 구간 [0.25, 0.75] 안을 사용하며 0이면 중앙값이다. 기본 impute 온도 `1e-8`은 중앙값에 매우 가깝고, 예제는 0.5를 사용한다. 범주형은 온도가 `1e-8` 이하이면 최빈 class를 선택하고, 그 외에는 log 확률을 온도로 나눈 분포를 사용한다.

따라서 낮은 온도를 설명한 일반적인 “mode” 문구를 수치형의 최빈값이라는 뜻으로 옮기지 않는다. 대체값이 덜 퍼지는 것과 정답에 가까워지는 것은 다르다. 온도·반복 횟수 선택에 따른 held-out 오차나 calibration 수치는 이 예제에서 확인되지 않는다.

`score_samples`는 한 순서 안에서 열별 log density를 합하고, 여러 순서의 결과를 평균한 뒤 **지수화**한다(183–228행). 반환값 자체가 log density는 아니다. 순서별 density의 기하평균이며, 정규화된 결합확률밀도 또는 밀도비라는 추가 해석에는 별도 조건이 필요하다. 이 문제와 정확한 수학 예는 [39·40의 기존 검수](0039-0040-sample-reuse.md)에 있다. 연속형 density를 확률값처럼 항상 0–1이라고 제한하지 않는다.

이상치 그림의 제목은 log-density라고 하지만 실제 색상은 `log(1 + score)`이고 colorbar도 그렇게 표기한다. 예제는 training 점 200개와 인위적으로 지정한 이상치 5개의 출력을 비교하며 ROC/AUC·새 분포의 탐지 성능을 제공하지 않는다.

## 순열 수와 비용을 설정값만 보고 세지 않기

`n_estimators=4`는 내부 조건부 예측의 ensemble 설정이고, `score_samples(..., n_permutations=4)`는 바깥 열 순서 요청이다. 저장된 `Shuffler`는 기본 Latin 방식에서 열 수 D가 4000 이하이고 요청이 1이 아니면 D개 순서를 반환한다. 이 예제의 D=2에서는 요청 4와 달리 **순서 2개**다. `score_samples`는 반환 목록을 잘라 쓰지 않는다.

| 경로 | 충분한 training target이 있는 경우의 구조적 처리량 | 확대하면 안 되는 해석 |
|---|---|---|
| score, 두 특성·요청 4 | 순서 2개 × 열 2개 = 조건부 처리 4회/호출 | 실제 순서 4개·모델 forward 4회라는 뜻이 아님 |
| impute | 처리 가능한 결측 열 m개 × 반복 I회 | query 원소마다 estimator를 새로 만드는 계산이나 실측 시간으로 바꾸지 않음 |
| generate | 원래 열 순서로 D개 조건부 처리 | score의 여러 순열 평균·impute의 모든 다른 열 조건과 다른 경로 |

Latin 방식의 비용 차이는 [39·40에서 이미 확인한 사항](0039-0040-sample-reuse.md)이다. 여기서는 공식 두 특성 예제에 연결했다. 모든 TabICL ensemble이 요청을 무시한다고 일반화하지 않는다. 같은 파일의 `EnsembleGenerator`는 조합 목록을 `self.n_estimators`로 자르는 코드가 있다(1125–1126행). [고정 Shuffler](https://github.com/soda-inria/tabicl/blob/0dbff3ec8fc68c123c87af77b0ea8b25cd2d23f3/src/tabicl/_sklearn/preprocessing.py#L785).

wrapper의 `fit`은 context를 저장하고 필요한 분류/회귀 가중치를 로드한다. 가중치를 공유해도 조건마다 estimator를 만들고 `est.fit`과 예측을 호출하는 준비는 남는다. `_estimator_kwargs`는 `kv_cache=False`다. 여기서 라이브러리의 `fit` 호출을 새로운 가중치 학습과 동일시하지 않으며, 학습 가중치 로드 1회를 전체 복원 비용 1회로 세지도 않는다. 내부 ensemble·query 행·전처리·분포 구성·모델/API 버전의 비용은 별도로 확인해야 한다.

`generate`의 첫 열처럼 조건 열이 없으면 random noise를 dummy 입력으로 사용하는 경로도 있다. 이 문서를 만들 때 그 난수나 모델을 실행하지 않았다. 점수·생성·대체의 호출 구조를 읽은 것이 전체 의존성의 작동이나 실시간성을 검증한 결과는 아니다.

## 팀원이 재사용할 판단

54에서 실제로 비교한 것은 관측 가능한 같은 입력을 사용하는 직접 회귀 네 개다. 이 공식 MICE 예제를 실행한 실험이 아니다. [54 기록](0052-0054-partial-observation.md)에 정리한 단순 회귀 대비 손해·앞뒤 기간 순위 변화·실패와 비용을 함께 참고한다. 직접 회귀 결과로 MICE의 성능을 측정했다고 말하거나, 예제의 그림으로 54의 부정 결과를 뒤집지 않는다.

새 실험 제안에는 다음 차이를 적어야 한다. 이 항목은 설계 검토 기준이며 현재 실행 지시가 아니다.

- training context와 query에서 각각 어떤 값이 실제로 관측 가능한지, 평가 시점의 미래값·정답이 들어가지 않는지 명시한다.
- 관측 대상을 **선택하는** 알고리즘과 주어진 결측값을 **복원하는** 알고리즘을 나눈다. `impute` 자체는 cell grouping·sensor selection 규칙이 아니다.
- 전날값·Ridge·HGB 등 같은 가용 입력을 쓰는 강한 단순 대안과 비교하고, 데이터·정규화·평가 분할·seed를 고정한다.
- 반복 대체의 온도·순서·횟수·학습 결측과 범주 fallback 조건, 열별 처리량·메모리·지연을 기록한다. 가중치 학습이 없다는 이유로 운영 비용을 0으로 두지 않는다.
- 복원 오차와 최종 미래 예측/RCTL 성능을 각각 확인하고, cell·기간별 손해 및 전체 비용까지 통과한 차이를 설명한다.

공식 기능이 있다는 사실은 재사용 근거다. 지금까지의 기록만으로 새로운 관측 정책·새 clustering 기여·최종 예측 이득이 확인된 것은 아니다. Ciena 본문, 전체 51·53·55 종합, 그 밖의 과거기록·누적 비용·팀 자료 접근·최종 검색 검수는 계속 진행한다.
