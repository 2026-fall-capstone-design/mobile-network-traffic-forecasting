# 18·21: 주변 cell 입력의 추가 가치

기록 17이 시간에 따라 context를 버리는 구조를 추천하지 않은 뒤, 기록 18은 주변 cell의 관측 이력을 더하는 가장 단순한 비교를 계획했다. 기록 21의 공간 진단 부분은 그 저장 결과를 보고한다. **Ridge는 세 추가 입력 모두의 전체 MAE가 나빠졌고, HGB 이웃 평균의 작은 전체 이득도 모든 cell·기간의 이득으로 이어지지 않았다.** 당시에는 방향 정렬·attention·별도 clustering을 추가할 직접 근거를 확보하지 못했다고 판단했다. **H012-C01·H012-C05·H012-C11**

[17의 앞선 질문](0017-adaptation-literature.md) → [18 사전 계획](../evidence/0018-0021/originals/SRC-0021026.md.txt) → [21 당시 종합](../evidence/0018-0021/originals/SRC-0021095.md.txt)의 20–29행을 연결한다. [보존 근거](../evidence/0018-0021/README.md)·[출처 범위](../sources/history-012.md)·[검수](../verification/history-012.md)·[주장별 출처](../verification/history-012-primary-review.json)를 함께 읽는다. 이번에는 원 모델을 실행하지 않고 저장된 수치를 검산했다.

## 계획과 실제 확인한 조건

| 항목 | 조건·확인 범위 |
|---|---|
| 자료 | 같은 가공 Milan hourly Internet activity, H5 `data[:,:,2]`. bytes/bps 척도 아님 |
| Cell | 기록 16에서 고정한 32개, 기존 16+활동량 사분위별 4개씩 추가 16. 선택·제외를 다시 하지 않음 |
| 정규화 | 자기 cell과 각 이웃별 첫 672시간 평균. 저장 target과 이웃/PCC metadata를 H5에 대조 |
| 학습 target | 시간 168–671의 504행, cell별 적합 |
| Query target | 시간 672–1007의 336행,2013-11-29–12-12. 두 주를 모두 평가한 개발 진단 |
| 자기 입력 | 기존 16열: 최근 8시간·일/주 lag·24시간 요약·달력 |
| 이웃 평균 | 자기 16열+8개 방향의 정규화값 평균 최근 8시간=24열 |
| PCC 이웃 | 학습 구간의 동시 raw PCC가 최대인 유효 이웃의 최근 8시간 추가=24열 |
| 8방향 개별 | 고정 8방향×각 8시간을 추가=80열. 방향 순서와 lag 순서를 코드로 확인 |
| Ridge | StandardScaler+Ridge(alpha=1) |
| HGB | absolute_error,max_iter100,max_leaf_nodes15,min_samples_leaf20,l2_regularization1,early_stopping=False,random_state20260925 |
| 지표 | 첫 28일 cell 평균으로 정규화한 MAE. 모든 cell/hour 동일 가중치. RCTL MAE 아님 |
| 실제 저장 범위 | pred(2,4,32,336),y(32,336),cell_ids,query_times,neighbor_cell_ids의 5배열과 시작/완료/summary |

모델은 504행으로 한 번 적합한 뒤 두 주 동안 고정한다. 각 query는 그 시각 직전까지 실제 관측한 자기·이웃 lag를 사용한다. 자기 입력 16열은 앞선 시간 진단 NPZ의 X를 읽어 재사용했고, 공간 진단의 모델은 다시 적합하는 코드다. 따라서 **관측 이력을 갱신하는 1시간 앞 예측**이며, origin에서 336시간을 한꺼번에 내다보는 예측이 아니다. **H012-C02·H012-C04**

16–17 시간 진단은 매주 다시 적합했으므로 두 번째 주부터 학습 조건이 다르다. 공간 진단의 자기 입력 조건 첫 주 예측은 앞선 expanding 첫 주 예측과 두 모델 모두 정확히 같다. 이번 아카이브는 그 저장값의 일치를 확인했으며 독립 재현을 새로 수행한 것으로 세지 않는다. **H012-C10**

## 이웃·경계·동점 처리

1부터 시작하는 cell ID에서 `(ID−1)//100`, `(ID−1)%100`으로 100×100 격자의 행/열을 구하고 NW, N, NE, W, E, SW, S, SE 순서의 8개 offset을 사용했다. 이 이름은 배열 방향이며 원 위경도의 물리적 북쪽·동쪽을 확인한 결과가 아니다. **H012-C03**

Cell 79의 NW/N/NE는 격자 밖이어서 자기 cell 79로 채웠다. 이 세 자리도 평균·8방향 입력에 포함되지만 PCC 선택에서는 제외했다. PCC는 query 이전 학습 구간168–671의 동시 raw값으로 계산하고, 최대값이 같으면 고정 방향 순서의 첫 항목을 선택했다.

저장 PCC의 정확한 동점은 cell 3745의 0/1/2번, cell 79의 3/5/6번, cell 4621의 6/7번 방향에 있다. 선택은 각각 0/3/6번이다. 방향 번호는 0부터 시작하며 모두 H5 대조에서 같은 이웃이 선택됐다. 작은 상관 차이나 임의 tie-breaking으로 이웃을 바꾼 재실험은 같은 조건의 재현이 아니다.

차이는 추가 입력 조건에서 자기 입력의 MAE를 뺀 값으로, 음수는 추가 입력의 이득이다. Cell 수는 각 cell의 두 주 평균, cell×주는64개 자리, 날짜는 전체 32cell의 일 평균이다. 서로 다른 분모를 구분한다. 날짜별 집계는 당시 summary에 없던 아카이브 추가 산술이다. **H012-C06**

## 실행 근거·비용·확인하지 못한 부분

계획18의 해시가 시작 metadata에 연결되고, 전체 5개 배열의 유한값과 256fit 완료 marker·summary를 대조했다. 보고 elapsed는 13.466453200초, fit/predict는 13.255779400초, RSS는 362,549,248bytes다. Elapsed는 선행 NPZ/H5 읽기와 입력 구성 전부터 최종 결과 쓰기 전까지이며, RSS는 입력 구성을 마친 뒤의 초기값과 각 fit/predict 뒤 관측한 최댓값이다. 연속 측정한 process peak나 이번 새 실행 시간이 아니다. 추가 TabICL/RCTL은 0회로 기록돼 있다. **H012-C09**

**확장된 실제 입력 X는 공간 NPZ에 저장돼 있지 않다.** 원 H5의 자기·이웃285개 cell 구간, 저장 이웃 ID/PCC/정답, 읽은 코드의 입력 구성은 대조했으나, 당시 모델이 소비한 확장 배열 자체를 별도 저장물에 대조한 것은 아니다. 당시 패키지 버전·환경 lock과 원 CDR 가공·보간 과정도 이번 범위에서 확인하지 못했다. **H012-C04**

## 재사용과 다음 질문

동일 32cell·분할·입력으로 비교하려면 먼저 5개 저장 배열,이웃 선택,전체 cell/day 반례를 재사용한다. 새 질문은 다른 입력·자료·모델 용량·기간·grouping 규칙 중 무엇이 달라지는지 적어야 한다. 공간 입력을 추가하는 효과와 cell을 묶어 학습하는 효과는 분리해 평가한다. 이 결과로 물리적 공간 영향이 없다고 결론 내리거나 새 소속의 RCTL 효용을 기각하지 않는다. **H012-C11**

기록 21에서 다룬 19/20의 pooled cell ID·target 표현 진단과 누적 비용·추가 문헌은 후속 검수 범위다. 기록 21 전체를 읽은 것과 전체 주장을 검증·통합한 것은 다르다. 이후393의 공간 정보 기록도 탐색만 했으며 완료로 세지 않았다.
