# 66·68 — 통신 트래픽 q-FFL의 공정성·운영 손해·구현 구분

이 기록은 2026-09-26의 [66번 계획](../evidence/0063-0068-synthesis-risk/originals/SRC-0022017.md.txt)과 [68번 판단](../evidence/0063-0068-synthesis-risk/originals/SRC-0022019.md.txt)을 원문에 대조한 후속 검수다. q-FFL의 손실 편차 감소는 모든 집단의 정확도 향상이나 서비스 부족 감소와 다르다. 통신 논문의 표에서는 q=0→10일 때 5개 집단 중 4개의 MSE와 5개 연결 모두의 부족 할당량이 증가한다. 이를 기존 clustering의 보호 효과나 새 RCTL 학습의 성과로 옮기지 않는다.

검토 논문은 Panda·Panayiotou·Ellinas·Behera의 *A Fair Federated Learning Framework for Collaborative Network Traffic Prediction and Resource Allocation*이다. [arXiv v2](https://arxiv.org/abs/2502.06743v2)는 2025-02-17판이며, [IEEE DOI](https://doi.org/10.1109/ICC52391.2025.11161740)의 Crossref 메타데이터에서 ICC2025, 1438–1444쪽을 확인했다. **IEEE 최종 PDF의 수식·표까지 대조한 것은 아니다.** 현재 받은 arXiv PDF는 보존된 원본과 바이트가 같다.

## 과거 기록에서 이어지는 질문

원66은 절대 최악 손실, 같은 함수집합의 최적 위험 대비 regret, 기준 모델 대비 상대 개선을 구분하려 했다. 원68은 목표를 바꾸는 것만으로 기존 후보의 신규성이나 실효성이 생기지 않는다고 판단했다. q-FFL은 큰 손실을 가진 클라이언트에 더 큰 영향을 주는 **학습 목적**의 선행 사례다. 집단이 주어진 연합학습이며 cell 소속을 결정하는 clustering 알고리즘은 아니다.

당시 기록에 적힌 Tab/RCTL 예산과 다음 행동은 역사적 자료다. 이번에는 원문과 코드를 정적으로 읽고 인쇄값을 계산했으며, 새 모델 학습·추론·잡음 생성·원코드 실행은 하지 않았다. [기존 저장 예측 진단](0066-0068-group-risk.md), [MMR](0066-0068-mmr.md), [MRI](0066-0068-mri.md)는 별도 근거다.

## 목적함수와 보장 범위

논문 2쪽 식1–2는 클라이언트 k의 손실을 F_k(w), 표본 비중을 p_k=n_k/Σn_k로 두고 다음 목적을 설명한다.

```text
f(w)   = Σ_k p_k F_k(w)
f_q(w) = Σ_k p_k F_k(w)^(q+1) / (q+1)
```

q=0이면 식1의 목적과 같다. q가 클수록 큰 손실의 영향이 커진다. 이 정의에는 MMR의 집단별 최적 위험 차감이나 MRI의 baseline·개선 가능 폭 정규화가 없다. 서로 다른 목적을 같은 보호 효과로 부르지 않는다.

저자는 q=10 부근 이후 편차가 더 줄지 않는 관찰을 min-max 공정성에 접근한 것으로 해석한다. 유한 q=10, 편차의 평탄화, 비볼록 LSTM의 유한 학습만으로 정확한 최악 손실 최적해를 증명한 것은 아니다. 크거나 잡음이 큰 손실의 영향, 집단 간 손실 척도와 전처리가 무엇을 보호하는지에 미치는 영향을 함께 고려해야 한다.

통신 논문은 local SGD와 가중 연합 평균의 절차를 설명하고 원래 q-FFL 연구를 인용한다. 전체 집계 분모와 세부 구현은 이 설명만으로 확정되지 않는다. 아래의 원알고리즘 코드를 통신 실험 코드와 구분하는 이유다.

## 원래 q-FedAvg 구현과 통신 실험 구현

통신 논문이 인용하는 Li et al.의 원래 q-FFL은 ICLR2020 연구다. [공식 fair_flearn 저장소](https://github.com/litian96/fair_flearn/tree/f09797113147b5ae66eb0348e93f575d5d63baed)를 commit `f09797113147b5ae66eb0348e93f575d5d63baed`에 고정하고 README·LICENSE·requirements와 코드5개, 총8개 파일890행을 정적으로 읽었다. 저장소 전체나 모든 model·data 경로를 읽은 것은 아니다. OpenReview의 원알고리즘 PDF 요청은403으로 끝나 이번 검토의 논문 전체 독해에 포함하지 않았다.

[qffedavg.py 48–65행](https://github.com/litian96/fair_flearn/blob/f09797113147b5ae66eb0348e93f575d5d63baed/flearn/trainers/qffedavg.py#L48)과 [집계 함수](https://github.com/litian96/fair_flearn/blob/f09797113147b5ae66eb0348e93f575d5d63baed/flearn/trainers/fedbase.py#L170)는, 갱신 전 global model에서 구한 local training loss L_k와 local model 차이를 사용한다.

```text
g_k     = (w_before − w_local,k) / η
Δ_k     = (L_k + 10⁻¹⁰)^q g_k
h_k     = q (L_k + 10⁻¹⁰)^(q−1) ||g_k||² + (L_k + 10⁻¹⁰)^q / η
w_after = w_before − Σ Δ_k / Σ h_k
```

`norm_grad`는 L2 norm의 **제곱**이다. 단순히 모델에 loss^q를 곱해 가중 평균하는 것과 위 집계를 혼동하면 안 된다. q=0에서는 선택된 local models의 단순 평균으로 약분된다. 실제 실행 없이 작은 scalar 예제로 이 약분만 확인했다.

[fedbase.py 116–149행](https://github.com/litian96/fair_flearn/blob/f09797113147b5ae66eb0348e93f575d5d63baed/flearn/trainers/fedbase.py#L116)의 sampling1은 균등 비복원 추출, sampling2는 local training 표본 수에 비례하는 비복원 추출이다. `aggregate2` 안에는 표본 수 가중치가 별도로 없다. 크기가 다른 전체 클라이언트를 모두 선택할 때, q=0 결과가 표본 수 비례 FedAvg 평균과 자동으로 같다고 할 수 없다. 목적 정의의 p_k, 추출 확률, 집계 가중치를 각각 고정해야 한다.

또한 [Client 분할](https://github.com/litian96/fair_flearn/blob/f09797113147b5ae66eb0348e93f575d5d63baed/flearn/models/client.py#L10)은 train/eval 자료를 합쳐 seed≠0일 때 무작위80/10/10으로 나누고, seed=0일 때 validation=test로 설정한다. 이 구조를 통신 시계열의 마지막100개 test 분할로 간주할 수 없다. requirements의 TensorFlow GPU1.10과 분류 중심 dataset/model 목록도 통신 논문의 TensorFlow2.10.1·Abilene 회귀 설정과 다르다.

이 저장소는 **원알고리즘의 구현 근거**다. Panda 논문의 실제 통신 실험이 이 commit 또는 이 코드로 실행됐다는 근거는 확보하지 못했다. 확인한 논문·abs·TeX 목록·제목/저자 검색에서 통신 실험 저장소 연결을 찾지 못했다는 한정된 결과이며, 어디에도 코드가 없다는 주장은 아니다. 의존성 설치·원코드 import·모델 실행은0이다.
