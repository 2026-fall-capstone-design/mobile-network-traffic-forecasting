# 64·65: TACTiS-2의 조건부 주변분포와 copula 분리

[연구 안내](../README.md) · [과거 시도](../prior-attempts.md) · [출처·판본](../sources/history-060.md) · [주장 검수](../verification/history-060-claims.json) · [인쇄 수치](../verification/history-060-paper-numeric-check.json)

TACTiS-2는 관측 정보에 따른 주변 CDF를 학습한 뒤 고정하고, 변환된 여러 미래값의 공동 의존을 별도 copula로 학습한다. 따라서 **CDF 변환과 이후의 공동 예측을 연결하는 원리 자체는 기존 선행에 있다.** Tab으로 CDF를 추정한다는 변경만으로 새 알고리즘이나 RCTL 개선이 입증되지는 않는다. 한편 개별 미래값의 PIT가 균등하다는 이유로 공동 예측의 역할까지 없어진다고 해석해서도 안 된다.

이 기록은 [64 원문](../evidence/0063-0065-ecai-interface/originals/SRC-0022015.md.txt)의 분포 변환 질문과 [65 원문](../evidence/0063-0065-ecai-interface/originals/SRC-0022016.md.txt) §6의 판단을 확장한 문헌 검수다. 원65는 논문 일부와 공식 코드 링크만 확인했다. 이번에는 저장 논문 전체 28쪽의 텍스트·시각, 15그림·12표와 고정 공개 코드 16파일 전체를 읽었다. 당시 검토를 새 실험으로 바꾸거나 원문을 수정하지 않았다. Tab·UPC·RCTL 실행, 외부 연구 코드 실행/import, 난수 생성은 모두 0이다.

## 질문과 방법

대상은 관측값·시각·공변량과 결측 mask를 조건으로 한 여러 계열·시점의 미지값 분포다. 관측이 모두 이전에 있으면 forecasting, 미지값의 양쪽에 있으면 interpolation이며 backcasting도 문제 정의에 포함한다. 논문의 유연한 조건부 문제와 팀의 시간 순서에 따른 미래 예측을 구분해야 한다. [원논문 §2–4](https://arxiv.org/pdf/2310.01327v2#page=2)

| 구성 | 논문의 역할 | 팀 연구에 옮길 때의 경계 |
|---|---|---|
| 주변 CDF | 관측 조건에서 각 미지값의 분포를 DSF로 추정 | 최근 100개 경험 CDF나 달력별 정규화와 동일하지 않음 |
| 두 encoder | 주변분포와 copula에 별도의 표현 생성; 값·series 정보·mask·위치 사용 | 입력과 가용 정보의 정의 없이 Tab/RCTL 대응을 정하지 않음 |
| 1단계 | 독립 copula의 밀도 1을 두고 주변분포 NLL 학습 | 유한 표본의 추정 오차가 사라진다고 보장하지 않음 |
| 2단계 | 주변분포 파라미터를 고정하고 copula NLL 학습 | 공동 의존을 학습하는 문제이며 단일 변환값 MAE 예측과 다름 |
| 생성 | copula에서 공동 표본을 만든 뒤 각 CDF의 역변환 | 원척도 지표·표본 설정·역변환 근사를 별도 확인 |

논문의 `O(d!) → O(d)`는 분포 파라미터 `φ`로 기술한 최적화 문제의 규모다. 신경망 파라미터 `θ`, 전체 encoder/decoder 연산, 메모리와 같은 의미가 아니다. 여기서 `d`는 미지값의 수이며, 계열 수만 세거나 전체 attention이 선형이라고 인용하지 않는다. [§3–4, 식7–12](https://arxiv.org/pdf/2310.01327v2#page=4)

## 두 정리가 보장하는 것

Proposition 1과 Appendix B.1은 주변 CDF와 unit-cube 밀도를 단순 공동 최적화하면 **전체 결합분포는 맞아도 분해가 유효한 copula가 아닐 수 있음**을 보인다. 연속 주변분포·무한 표현력을 가정하고, 임의의 가역 단조 변환과 그 역변환을 진짜 주변 CDF·copula에 합성하는 구성이다. 합성된 unit-cube 분포의 주변분포는 일반적으로 균등하지 않다. 이를 결합밀도 자체가 항상 틀리다는 주장으로 바꾸지 않는다.

Proposition 2와 B.2는 모집단 기대 NLL의 최적해와 무한 표현력에서 먼저 진짜 주변분포를 얻고, 이를 고정한 PIT 위에서 진짜 copula를 얻는 논증이다. NLL의 strictly proper 성질을 두 번 사용한다. 실제 유한 네트워크·표본·SGD가 정확한 CDF를 얻는다는 보장이나 Tab 정확성 정리는 아니다. 본문 §7도 유한 표본과 비볼록 최적화에서의 validity를 남은 문제로 둔다. [증명 21–22쪽](https://arxiv.org/pdf/2310.01327v2#page=21)

원65의 단일 시점 논리는 유지된다. RCTL이 가진 전체 정보 `H`를 조건으로 하는 정확한 연속 CDF에서 `U=F(Y|H)`의 조건부 중앙값은 0.5다. 이를 역변환하면 원래 CDF의 중앙값이다. 그러나 여러 미래값 각각의 조건부 PIT가 균등해도 **그 값들 사이의 조건부 공동 의존은 남을 수 있다.** TACTiS-2가 학습하는 것은 이 공동 구조다. 달력만 조건으로 제거하는 변환은 최근 이력의 추가 정보가 남을 수 있는 또 다른 설계다. 이 구분은 새 Tab→RCTL 성능 실험이 아니다.

B.3/Figs3·14·15의 설명용 2변량 분포는 Clayton 계수 9.75와 −0.99의 동일 가중 혼합, Gamma α=1.99, Double Weibull c=3을 사용한다. **이 예시는 첫 변수의 강제 균등분포를 제거한 수정 decoder**라고 각주2가 명시한다. 공동 분포의 적합과 분해의 적합을 분리해서 보여주는 예시이며 모든 유한 학습의 copula 유효성을 검증한 것은 아니다. [22–24쪽](https://arxiv.org/pdf/2310.01327v2#page=22)

## 지표·오차·그림 해석

A.1의 CRPS는 계열별 실제값의 평균절대값으로 정규화한 뒤 계열·시간을 평균한다. CRPS-sum은 **같은 공동 표본 안에서 계열을 먼저 합한 뒤** CRPS를 계산한다. 개별 CRPS 합이 아니다. Energy score는 Euclidean norm에 β=1을 사용하고, NLL은 예측 차원 수로 나눈다. 원단위 MAE·소속 선택 점수·최종 RCTL 성능과 서로 바꾸어 쓰지 않는다.

표의 ±는 Newey–West 표준오차로 설명된다. A.1은 R `sandwich`, Bartlett kernel, 3 lags, automatic bandwidth selection을 함께 명시한다. 정확한 함수 인자·원평가 배열·CI 신뢰수준은 미확인이다. 본문은 NLL의 세 자료에서 CI가 겹치지 않는다고 서술하지만 여기서 별도 유의성 검정을 만들지 않는다. GP-Copula의 3회 iid SD/SE에 썼던 산술 조건도 이 오차에 이식하지 않는다. 평균순위는 전체 평가 창·자료에 걸친 순위이며, 다섯 인쇄 평균의 순위를 다시 평균한 값이 아니다.

Fig1은 FLOPs ×10^16, Figs4·6의 kdd-cup은 ×10^15, Fig7의 solar는 ×10^16이다. Fig1의 y축 생략을 보존한다. Figs6·7은 별도로 5 seeds 사이의 표준오차를 표시한다. 같은 TACTiS-2 구조를 공동 NLL로 학습하는 no-curriculum ablation과 비교하지만, 그림의 모든 좌표를 원배열로 복원하거나 모든 계산 예산에서의 우위를 정리로 주장하지 않는다.

Figs8·9 forecasting 사례는 **특히 잘 맞는 예시를 골랐다고** A.4가 명시한다. Figs10–13 보간 사례는 무작위로 골랐다고 A.5가 보고한다. 선택 절차 자체를 검증한 것은 아니다. Fig5의 보간·불규칙 정성 예시와 전체 benchmark 평균을 구분한다. [A.1–A.5](https://arxiv.org/pdf/2310.01327v2#page=15)

D.1은 규칙 자료를 변형해 불규칙·비동기 조건을 만든다. 유지한 관측에서 다음 관측 간격을 {1,2,3} 중 고르거나 계열별 빈도를 {1,1/2,1/4}로 바꾼다. kdd-cup·solar 두 자료, 단일 backtest, 5 seeds에서 Tables11·12의 네 NLL 비교 모두 TACTiS-2 평균이 낮다. 자연발생 결측, 전체 rolling 평가, 모든 지표의 결과로 확대하지 않는다. 해당 표의 ±를 A.1의 backtest 축과 동일한 집계로 확정하지 않았다. [D.1](https://arxiv.org/pdf/2310.01327v2#page=28)

## 학습 설정과 비용

논문 C.2는 Docker, Tesla-P100 12GB, CPU 2개, RAM 32GB를 보고한다. 학습 batch는 1–256의 2 거듭제곱 중 메모리에 맞는 최대값이다. 그러나 **bagging 없는 sampling/NLL 평가에는 필요하면 더 많은 메모리 자원을 사용했다.** 전체 평가까지 12GB로 가능했다는 기록이 아니다.

한 epoch는 512 batches, 조기종료는 50 epochs 개선 없음, 반환 모델은 validation NLL 최상 checkpoint다. 비 curriculum 모델의 학습 상한은 72시간, 두 단계 각각은 36시간이다. TACTiS/TACTiS-2 HPO는 **자료·모델마다 6일 동안 50개 학습을 병렬 실행**했다고 보고한다. SPD는 목표함수를 바꿔 같은 프로토콜을 따른다. 50개가 전체 trial 수라는 뜻도, 실측 총비용이 7,200 GPU-hours라는 뜻도 아니다. 완료 trial 수·정확 seed 목록·모든 자원 사용 합계는 확인되지 않았다.

Tables7–9의 후보·선택 첨자 58행을 구조화했다. 자료별 290개 선택 칸 중 288개는 명확하지만 Table7의 decoder transformer 층 수는 **electricity 첨자 e가 3과 7에 중복, solar 첨자 s는 없음**을 시각으로 확인했다. 추출 오류로 지우거나 추정 설정으로 보정하지 않는다. Table10의 20개 학습률은 별도이며 TACTiS-2 두 단계 값도 다르다. [C.2–C.4](https://arxiv.org/pdf/2310.01327v2#page=25)

## 공식 코드의 확인 범위와 재사용 조건

[ServiceNow/TACTiS 고정 커밋](https://github.com/ServiceNow/TACTiS/tree/19df68b20b574f662fb1b2e1bf022f4116027f90)의 선택 16파일을 전부 정적으로 읽었다. 파일별 해시·줄수·URL은 [코드 검수](../evidence/0064-0065-tactis2/code-audit.json)에 있다. 현재 공개 스냅샷을 논문의 실제 실행 커밋·config와 동일하다고 확인한 것은 아니다. 노트북·나머지 repo·외부 데이터·환경 설치·benchmark 실행은 검수 완료로 세지 않는다.

확인한 주요 구현은 다음과 같다.

| 항목 | 고정 코드에서 확인한 내용 | 재사용 경계 |
|---|---|---|
| 단계 분리 | trainer88–175에서 주변/flow 쪽 `requires_grad=False`, copula 파라미터만 optimizer에 전달 | stage2 동결 구현 확인이며 최적 CDF/유효 copula의 실증 보장 아님 |

| 순서와 bagging | decoder는 `arange` 순서; bagging은 series 부분집합과 제시 순서를 변경 | 매 decoder 호출에서 무작위 permutation을 뽑는다고 주석만 인용하지 않음 |
| 샘플 범위 | train.py137–138의 min_u=.05/max_u=.95; decoder263은 역변환 전 `.05+.9u` | 단위구간 전체의 수정 없는 copula 샘플과 다름. 논문의 실제 표본 설정은 별도 확인 |
| 정규화·NLL | history 평균/불편표본SD, SD최소1e−8; trainer549–550은 loss의 원척도 환산 미구현을 명시하며 정규화 Jacobian도 포함하지 않음 | 다른 모델의 원척도 likelihood와 직접 비교 불가 |
| 지표 기본값 | 19분위수 .05–.95, 100samples, `skip_energy=True`를 CLI가 유지 | Table5의 Energy 결과까지 기본 명령으로 재현된다고 하지 않음 |
| 단계별 설정 | CLI는 LR1e−3 등 한 설정을 두 단계에 전달 | Table8·10의 자료별·단계별 선택 설정과 다름 |
| 시간 집계 | training loop 시간만 합산하고 validation 전에 멈춤, 129600초/단계 | validation·batch 탐색·대기 포함 전체 wall-clock이 아님 |

코드의 기본 dropout은 클래스마다 다르지만 `train.py`가 전달하는 두 encoder·decoder·위치인코딩 dropout은 모두 0.0이다. 주변 파라미터가 동결된 뒤 기본 dropout 때문에 계속 변한다고 단정하지 않는다. decoder의 mask 분할은 batch 안에서 같은 mask를 가정하며, Gluon wrapper는 정렬된 동일 빈도 정수 시각을 만든다. 논문의 일반적 mask/비동기 기능을 기본 CLI가 자동 제공하는 것으로 해석하지 않는다.

다음은 재사용 전 점검할 **정적 코드 경로**다. 실제 오류 발생이나 논문 결과에 대한 영향을 실행으로 확인하지 않았다.

- `trainer.py220–267`: 메모리 탐색 중 줄인 지역 `batch_size`를 이후 `self.batch_size`로 다시 설정한다. 자동 축소가 실제 학습에도 유지된다고 가정하지 않는다. checkpoint에서 읽은 epoch/best/time 카운터도 초기화되므로 가중치·optimizer 로드와 진행 상태의 정확한 재개를 구분한다.
- `dataset.py`의 solar pre-backtest 날짜는 한 주 앞이다. 72×10분 horizon을 쓰면 1주일은 **14 horizons**로 C.2의 7 horizons 설명과 다르다. 실제 데이터 배열과 2024 실행판은 미검증이다.
- `tactis.py1017–1018/1301`: 보간 sampling에서 history 시각의 끝 h를 자른 뒤, 이미 잘린 배열의 끝 h를 prediction 시각으로 취해 연결한다. 정렬된 36시점/h=12 예에서는 `0..23 + 12..23`이 되어 원래 `0..35`와 다르다. 값·mask 순서를 복구하는 코드와 시각 배열은 별개다. 직접 작성한 작은 list 산술로 이 인덱스만 확인했으며 원 PyTorch 모델은 실행하지 않았다.

## 후속 실험에서 먼저 남길 차이

1. 변환이 제거할 정보와 이후 예측기가 배울 정보를 명시한다. 전체 이력 조건부 CDF, 달력 조건부 CDF, 경험 주변 CDF를 구분한다.
2. 단일 시점 중앙값 보정인지 여러 미래값의 공동 분포 학습인지 정한다. UPC 소속 점수와 최종 RCTL 목적을 연결하는 추가 근거가 필요하다.
3. 단순 경험 CDF·계절 정규화보다 Tab이 추가하는 정보와 전체 비용을 정한다. 변환·공유 예측 연결을 다시 발견한 것을 신규성으로 세지 않는다.
4. 실제 가용 정보, 학습·validation·평가 시각, marginal 동결 시점, 원척도 평가, 샘플 범위·개수, 선택 설정을 고정한다. 공개 코드 경로와 논문 조건이 다른 항목은 먼저 해결한다.
5. 평균 이득과 자료별 손해를 함께 기록한다. NLL 개선으로 MAE 개선을 대신하거나 Traffic 예외를 생략하지 않는다.

논문 §7의 distribution-shift 해석, 공유 copula의 대규모 학습·multitask/pretraining은 미래 연구 제안이다. 이 논문에서 이미 수행한 성과나 팀의 후속 실행 지시로 세지 않는다.
