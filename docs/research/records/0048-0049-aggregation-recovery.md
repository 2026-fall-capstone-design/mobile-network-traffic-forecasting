# 48–49 합계를 알면 개별 cell을 정확히 복원할 수 있는가

2026-09-26의 계획 48과 진단 49는 군집 합계 하나를 예측한 뒤 cell별 비중으로 나누는 구조를 검토했다. **합계를 정확히 아는 것, 개별 cell을 정확히 복원하는 것, 정해진 비중에서 개별 MAE를 최소화하는 것은 서로 다르다.** 49는 원자료와 고정 비중의 산술 진단이며 새로운 TabICLv2·RCTL·통계 모델의 학습이나 추론은 없다.

[50 원문](../evidence/0048-0049-aggregation-recovery/originals/SRC-0021725.md.txt)의 저장 수치·구조적 관계·비용을 함께 대조했다. 문헌의 세부 방법·표·신규성 종합은 후속 검수 범위로 남겼다. [출처](../sources/history-029.md), [검수와 주장별 근거](../verification/history-029.md)

## 질문과 실제 수행 범위

[47](0047-input-sharing-roles.md)이 학습 행의 공유와 입력 열의 추가를 구별한 뒤, 48은 **출력을 군집당 scalar 하나로 줄였을 때의 복원 손실**을 물었다. 모델 수·출력 수·처리하는 시계열 수·라이브러리 호출 횟수는 같은 단위가 아니다. batch 한 번으로 여러 cell을 처리하는 것도 출력 문제 자체를 줄인 것과 다르다.

계획·입력 및 코드 해시가 있는 설정·시작/완료 표시·결과 JSON·NPZ·당시 원장 스냅샷이 남아 있다. 49는 HDF5의 고정 구간을 읽어 네 partition과 세 비중 규칙을 비교했다. 저장된 48개 복원 배열을 확인했고 새 모델 적합·Tab context/query·RCTL 호출은 0으로 기록됐다. 이번 정리에서도 원 연구 코드·모델·난수 생성을 실행하지 않고 저장 배열과 지정 원자료 구간만 검산했다.

## 무엇을 고정하고 무엇을 바꿨는가

전체 32개를 한 그룹으로 묶는 조건과, 4개씩 8그룹인 위치/PCC/무작위 조건을 비교했다. 1그룹과 8그룹은 압축률이 달라 같은 출력 비용의 비교가 아니다.

위치·PCC는 미배정 cell 중 ID가 가장 작은 것을 anchor로 하고 가장 가까운/상관이 높은 세 cell을 추가한다. 동점은 cell ID로 정한다. 위치는 `(id−1)//100, (id−1)%100` 격자의 제곱거리이며 실제 거리 단위나 최적 공간 군집으로 해석하지 않는다. PCC는 앞 672시간의 원 활동량으로 계산했다. 무작위 조건의 기록된 seed는 `20260926`이다. 이번에는 저장된 무작위 그룹의 중복·누락·크기만 확인했고 난수열을 재생성하지 않았다.

비중 `p_i`는 같은 그룹 안에서 다음 중 하나를 합으로 나눈 값이다.

- `last`: 직전 실제 관측값.
- `day_lag`: 24시간 전 실제 관측값.
- `hour_profile`: 앞 672시간에서 index를 24로 나눈 나머지가 같은 시점들의 cell별 평균.

비중은 비음수이고 합이 1이다. 참조 합계가 0이면 코드가 균등 비중을 사용한다. 확인한 구간에서는 이 0합계 분기가 나타나지 않아 정적 구현만 확인했다. 미래 정답은 이 세 비중 계산에 사용하지 않는다.

각 비중에서 곱할 scalar를 네 가지로 바꿨다. `true_total`은 **미래 실제 합계**, `best_scalar`는 **미래 실제 cell값으로 구한 사후 최적 scalar**, `last_total/day_total`은 직전/전날 실제 합계다. 앞의 두 방법은 배포할 수 없는 oracle 진단이다. 뒤의 두 방법만 해당 관측을 이용할 수 있다는 가정 아래 실행 가능한 단순 기준이다.

## 정확한 합계가 최소 복원 오차는 아니다

그룹의 실제값이 `90,10`, 고정 비중이 `0.8,0.2`이고 척도가 둘 다 1이라고 하자. 정확한 합계 100을 배분하면 `80,20`이 되어 절대오차 합은 20이다. scalar를 112.5로 바꾸면 `90,22.5`가 되어 절대오차 합은 12.5다. 이는 코드에 저장된 두 cell 예를 정확한 유리수로 확인한 결과이며, 새로운 합성 표본 실험이 아니다.

고정된 비중과 양의 척도 `m_i`에서 최소화할 값은 다음과 같다.

```text
min over z >= 0:  Σ_i |y_i − p_i z| / m_i
```

`p_i>0`이면 값 `y_i/p_i`, 가중치 `p_i/m_i`의 weighted median이 최적 scalar다. `p_i=0`의 오차는 z와 무관한 상수다. 실제값·비중이 비음수이므로 선택한 median도 비음수다. 코드의 동률 처리와 별개로, 저장된 최적 scalar 양쪽의 가중치가 각각 전체의 절반을 넘지 않는 convex L1 최적 조건을 대조했다. 최적값이 여러 개일 수 있다.

이 하한은 **그 시점의 비중을 고정하고 그룹당 비음수 scalar 하나를 쓰는 구조**에만 적용된다. 비중을 바꾸거나 개별 출력을 유지하는 모든 예측기의 공통 하한이 아니다. 미래 정답으로 시점마다 최적화했으므로 실행 가능한 성능이나 RCTL이 달성할 수 있다는 보장으로 쓰지 않는다. [저장 산술 검사](../verification/history-029-saved-check.json)

## 원단위 오차 관계와 RCTL 연결의 한계

비음수 비중의 합이 1이고 실제 합계가 S, 예측 scalar가 z이면 원단위 절대오차 합은 다음 범위에 있다.

```text
max(0, 정확한 합계의 복원 오차 합 − |S−z|)
  ≤ 개별 예측 오차 합
  ≤ 정확한 합계의 복원 오차 합 + |S−z|
```

삼각부등식으로 얻는 관계이며 저장된 직전 합계 조건을 대조했다. cell별로 다른 척도로 나눈 손실에는 계수 1이 그대로 적용되지 않는다. 정규화된 절대오차 **합**의 추가항에는 `|S−z| × Σ_i p_i/m_i`가 들어간다. 이는 척도를 명확히 하기 위한 같은 삼각부등식의 대수 설명이지 새 성능 결과가 아니다.

합계 RCTL은 기존 cell 행 pooling과 target·표본 수·입력이 달라진다. 기존 checkpoint를 그대로 평가한 것처럼 비교할 수 없다. 49에는 합계를 학습하는 RCTL도 TabICL로 partition을 고르는 모델도 없다. 원단위 오차 관계나 oracle 하한을 최종 RCTL 이득 보장으로 바꾸지 않는다.
