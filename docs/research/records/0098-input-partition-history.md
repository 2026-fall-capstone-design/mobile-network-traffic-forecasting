# 원81의 결론이 후보표와 연구일지에 반영된 과정

[출처](../sources/history-098.md) · [검수](../verification/history-098.md) · [변경 비교](../evidence/0098-input-partition-history/unique-deltas.json) · [원81 판단](0090-input-partition-decision.md)

팀원이 같은 입력 공유 후보를 다시 조사하기 전에 당시 보류 이유, 남겨 둔 긍정 증거, 재검토 조건을 찾는 기록이다. 원본 번호는81이며 H098은 snapshot22→23의 고유 연혁 변경을 다룬다.

**상태:** 18개 주장·6개 검수 묶음의 작성 후 원문 대조 완료. 새 모델 실행0.

## 어떤 변경이 추가됐는가

<a id="c01"></a>**C01.** snapshot 22→23의 후보표는42행에서43행으로 바뀌며 새11행만 추가된다. 연구일지는378행에서389행으로 바뀌고7행 제목 교체와9–19행 삽입이 있다. 전체 파일의 행 차이를 계산하면 후보표42행·연구일지377행은 그대로다. 이 기계 비교를 누적 연구일지 전체의 의미 독해로 세지 않는다.

<a id="c02"></a>**C02.** 후보표의 새 행은 공동 입력·cell별 다중 출력이라는 학습 단위 변경을 DGCformer·DUET·CCM·Fuchs–Wang에 연결한다. 원47·74–75·81을 다시 찾을 수 있게 하고, 실제 입력 분할 손해와 Tab이 바꾸는 결정의 근거 없이 subset/graph 검사를 반복하지 않겠다는 당시 판단을 남긴다.

<a id="c03"></a>**C03.** 연구일지의 최신 상태는2026-09-26 원81의 문헌·정적 코드·기호 비용 검토다. 새 Tab 추론이나 수치 pilot을 수행하지 않았다고 기록한다. 17행부터 이전 원79–80 상태를 보존하므로 아래의 원80 진단을 원81의 새 실행으로 합치지 않는다.

## 보류 이유와 재사용할 판단

<a id="c04"></a>**C04.** 검토한 대안은 여러 cell의 sample 행을 같은 scalar 함수에 모으는 방식에서, 같은 시각의 cell 이력을 서로 다른 입력 열로 두고 cell별 미래값을 따로 출력하는 방식으로 바꾸는 것이다. 문서의 구조 제안과 실제 다중 출력 모델 구현·학습 완료는 구별한다.

<a id="c05"></a>**C05.** 원47의 동일 scalar 입력에서 출력이 충돌하는 반례를 cell별 출력 좌표가 있는 방식의 기각에 그대로 쓰지 않았다. 그렇다고 새로운 구조가 기존 방법보다 낫다는 결론을 낸 것도 아니다. 다른 학습 단위로 바뀌는 점과 유용한 새 선택이 입증되지 않은 점을 함께 남긴다.

<a id="c06"></a>**C06.** 연구일지는 DGCformer2405.08440v1·DUET2412.10859v3·CCM2404.01340v2·Fuchs–Wang2312.16544v1의 지정 방법 절, HTML/서지8개와 선택 외부코드8파일을 기록했다. 이는 당시 보고한 범위다. 후속 정리의 실제 검수는 H091–H097에서 확인하며 당시 PDF0·외부코드 실행0을 이후 보충 자료 확보나 독립 재현으로 바꾸지 않는다.

<a id="c07"></a>**C07.** Fuchs–Wang 예2.11은 pairwise linkage만으로 집합 의존성을 일반적으로 대신할 수 없다는 선행 경로로 재사용됐다. 공동 효과나 hypergraph라는 설명만으로 신규성을 주장하지 않았고 i.i.d. 추정 일치성을 시계열로 옮기지 않았다. 예2.11을 임의의 독립 분포에 확대하는 문제와 순위 기반 의존성·미래 MSE의 차이는 H096의 후속 검수에서 확인한다.

<a id="c08"></a>**C08.** 기록된 선형 MAC은 C(F,s)=L(169728+96F+16s)다. 서로소 K개 cluster의 cell 수 합계를N, cell별 특징 수를q, 공통 특징 수를c로 두고 F_g=q s_g+c이면 총합은 L[(96q+16)N+(169728+96c)K]다. 같은 hidden 폭·입력 길이·해당 출력 수를 가정하며 기호식의 항별 검수는 H090에 연결한다.

<a id="c09"></a>**C09.** 같은 폭의 global 다중 출력 K=1과 K>1을 비교하면 추가 선형 MAC은 L(K−1)(169728+96c)다. L>0이고 c가 비음수인 특징 수일 때 양수다. 같은 폭은 같은 총 parameter 수가 아니며 latency·메모리·통신·정확도 우위가 이 식에서 나오지 않는다. 새 모델의 실행시간을 측정한 결과로 인용하지 않는다.

<a id="c10"></a>**C10.** 새 후보 행이 추가되어도 기존 후보표의 긍정 증거 부분은 내용이 같다. 원60·74·80의 Tab 직접 예측 이득과 원46의 일부 cell 공간 입력 이득, 기존K4의 일부 조건 이득을 보존한다. 이런 개발 구간의 관찰을 새 입력 분할·소속 수정·다중 출력 RCTL의 성공으로 합치지 않는다. 원74와 원80의 조건은 H090의 재인용 검수를 따른다.

<a id="c11"></a>**C11.** 새 행과 연구일지는 현재 형태를 채택하지 않는다고 기록하지만 모든 다변량 군집화가 불가능하다고 결론 내리지 않는다. 직접 예측이 좋다는 관찰과 다른 소속을 골라 최종 모델을 개선했다는 증거가 다르기 때문이다. 원81은 최종 추천 방향과 Word 문서도 미완료로 남겼다.

<a id="c12"></a>**C12.** 후보표는 이미 다룬 실패 원인을 실제로 바꾸는 결정, Tab 값이 바꾸는 선택과 단순 대안, 최종 RCTL에 전달되는 정보·target·학습 단위와 RCTL 학습결과를 clustering에 쓰지 않는 조건, 개발자료 재사용과 남은 역사적 예산이라는 네 질문을 유지했다. 팀은 이를 새 제안의 비교표로 재사용할 수 있다. 문서 안의 pilot 진입 문구와 과거 Goal 지시는 이번 정리에서 실행할 명령이 아니다.

## 보관·비용·검수 범위

<a id="c13"></a>**C13.** 연구일지19행은 snapshot22 보관 뒤에 추가한 확인 문장이라고 명시한다. 49파일·5,272,991바이트, PDF1개16쪽·관련3쪽 시각검수와 과거 검사 완료를 보고한다. 현재 snapshot22 manifest의49항목·총바이트·PDF1/PNG3 및 각 사본 해시는 대조했지만, 그 문장만으로 과거 모든 검사나16쪽/3쪽 열람을 이번에 다시 수행했다고 세지 않는다.

<a id="c14"></a>**C14.** snapshot23의 manifest는42파일·3,524,587바이트이며 snapshot22와 자료 주제가 다르다. 두 명세의 공통 경로4개 중 AGENTS와 누적 원장은 같은 해시이고 후보표·연구일지만 바뀌었다. 이번에91개 명세 항목의 현재 사본 크기·해시가 모두 맞음을 확인했다. 49→42를 파일 유실이나 모델 비용 감소로 해석하지 않는다.

<a id="c15"></a>**C15.** 두 snapshot의 원장은 원80 종료원장과 SHA-256 f3e370ba0bb39b220a3448daf00ab532729b91b93bce80b6d92a43a7ea71f2a9로 같다. 기록상 Tab 사용69context·39,360query행과 상한80·60,000의 차이는11·20,640이다. RCTL fit 사용/상한은29/29로 잔량0이다. 이 값은 당시 상태이며 현재 실행 허가나 새 예산으로 사용하지 않는다.

<a id="c16"></a>**C16.** 첫 독해는 새 후보표43행과 이전 후보표42행 전체, 새 연구일지1–30행과 이전 연구일지1–22행이다. 세 명세/원장 JSON과 원81은 기존 자료를 재참조했다. 전체 사본을 보존하고 전해시를 확인해도 새 연구일지31–389행과 이전23–378행을 이번 묶음에서 전부 의미 검수한 것은 아니다. 이전 후보표의 비교 범위 확대도 새 그룹으로 중복 가산하지 않는다.

<a id="c17"></a>**C17.** H090은 당시 진입 판단·기호 비용을, H091은 DGCformer를, H092–H093은 CCM 문헌·코드를, H094–H095는 DUET 문헌·코드를, H096은 변수 집합 의존성을, H097은 저장 검색을 검수했다. H090 당시 남았던 자료 폴더29그룹은 그 후속 기록으로 연결됐다. H098은 여기에 snapshot23의 두 연혁문서 고유 변경을 더하며 같은 문헌 조사를 처음부터 반복하지 않도록 한다.

<a id="c18"></a>**C18.** 이번 완료 범위는 두 연혁문서의 원81 관련 고유 변경과 비교 근거다. 실제 다중 출력 RCTL의 학습·시간/정확도 비교, didec 실행과 판본별 API, 앞선 문헌의 미확인 실행 조건은 여전히 별도 연구 질문이다. 과거 누적 기록의 나머지 의미 검수·원82 이후·전체 실패/비용 통합·팀의 원자료 접근과 최종 검수도 남아 있으므로 전체 연구나 현재 정리 Goal의 완료로 표시하지 않는다.
