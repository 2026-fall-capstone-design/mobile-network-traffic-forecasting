# 61. 긴 이력의 식별 정보와 짧은 RCTL의 구조적 비용

**과정을 알면 짧은 기억으로 충분한 예가 성립하고, 입력 길이를 줄이면 RCTL의 표준 행렬 연산 수도 줄어든다.** 61번은 이 두 사실을 정확 산술로 확인했다. 실제 트래픽에서 clustering이 필요하다거나 짧은 RCTL의 예측 성능이 유지된다는 근거까지 얻은 것은 아니다. [61 사전 계획](../evidence/0059-0062-history-grouping/originals/SRC-0021961.md.txt) · [62 당시 판단 §3–5](../evidence/0059-0062-history-grouping/originals/SRC-0021984.md.txt)

기록일은 2026-09-26이다. H052는 보존 코드·결과·시작/종료 표지와 전후 원장을 연결하고, 다른 적분 표현과 층별 분해로 수치를 대조했다. [60번의 실제 예측](0059-0062-history-grouping.md)과 구별한다. 당시와 현재 모두 이 산술을 위한 Tab 호출·RCTL 생성/forward/학습·난수 추출은 없다.

## 실제 작업과 적용 단위

| 항목 | 61번에서 다룬 범위 |
|---|---|
| 질문 | 긴 관측이 과정 식별에 쓰이는 것과 과정 내부의 기억 길이를 구별할 수 있는가; 짧은 입력이 어떤 비용을 줄이는가 |

| 학습·환경 | 새 학습·튜닝·checkpoint·seed·추론 장치 선택은 해당 없음. 당시 산술 프로세스의 전체 환경/콘솔은 별도 미확인 |

원 코드는 `Fraction`으로 정해진 식을 계산하고 결과를 저장한다. 잠재 과정의 표본을 생성하거나 새 모델을 적합한 합성실험이 아니다. [산술 코드 보존본](../evidence/0061-history-logic-cost/originals/SRC-0022880.py.txt) · [저장 결과](../evidence/0061-history-logic-cost/originals/SRC-0027870.json)

## 상태를 아는 것과 cell을 아는 것

cell 유형을 A/B로 두고 사전 확률을 각각 1/2로 둔다. A의 잠재 상태 지속확률은 0.9, B는 0.1이다. 관측은 `X_t = 2 + S_t + ε_t`, `ε_t ~ Uniform(-1/20, 1/20)`이다. 두 상태의 관측 구간 `[1.95,2.05]`와 `[2.95,3.05]`가 겹치지 않으므로 한 관측에서 현재 상태를 구별한다.

저장값을 얻으려면 **최근 관측 이전 잠재 상태의 확률이 두 cell에서 같다는 조건**도 필요하다. 이번 검수는 각 대칭 Markov 과정의 정상분포인 `P(S=0)=P(S=1)=1/2`를 cell과 독립으로 명시했다. 원 계획은 초기 분포를 수식으로 적지 않았고, 코드는 이를 생성하지 않고 식을 바로 계산한다. 따라서 이 조건은 저장값의 해석을 명확히 한 검수 가정이다. 초기 상태 분포 자체가 cell을 알려 준다면 같은 수치를 자동 적용할 수 없다.

한 관측에서 상태를 알아도 A/B의 주변 관측 분포는 같아 cell은 알 수 없다. 두 관측에서는 상태가 유지됐는지 바뀌었는지가 cell에 대한 정보를 준다. 이 예는 [33–35에서 검토한 과정 식별과 적합 간극](0033-0035-process-fit-gap.md)의 직관을 보여 주며, 그 원리를 새로운 기여로 주장하지 않는다.

## MAE에 맞는 중앙값과 정확 위험

확률이 큰 쪽의 관측 구간을 중심 0으로 옮기거나 반사하고, 그 확률을 `p ≥ 1/2`, 잡음 반폭을 `e=1/20`로 둔다. 다른 구간의 중심은 1이다. 선택할 수 있는 중앙값 하나는 `m=−e+e/p`이며, 절대 오차를 두 Uniform 구간에서 적분하면 다음과 같다.

```text
R(p) = p × ((m+e)² + (e−m)²)/(4e) + (1−p) × (1−m)
     = 1−p + e(2p−1)/(2p)
```

조건부 평균을 사용하는 제곱오차의 계산과 구별한다. `p=1/2`에서는 두 구간 사이의 여러 중앙값이 같은 위험 1/2를 주며, 위 식은 그중 하나를 택한다. 표의 값은 상태·cell·잡음에 대한 기대 절대 오차다.

| 알고 있는 정보 | 유리한 다음 상태의 확률 p | 정확 Bayes MAE | 소수 |
|---|---:|---:|---:|
| cell을 알고 최근 관측이 1개 이상 | 9/10 | 11/90 | 0.1222222222 |
| cell을 모르고 최근 관측 1개 | 1/2 | 1/2 | 0.5000000000 |
| cell을 모르고 최근 관측 2개 | 41/50 | 409/2050 | 0.1995121951 |

cell을 아는 경우 A는 상태 유지, B는 상태 반전을 더 높은 확률로 예상한다. 과정이 1차 Markov이고 현재 상태가 관측에서 식별되므로 추가 과거가 이 위험을 더 낮추지 않는다. 저장 항목 `known_cell_any_length`는 **관측이 적어도 하나 있는 길이**를 뜻한다. 관측 0개까지 포함한 주장이 아니다.

두 관측의 네 상태 쌍을 정확히 열거하면 다음과 같다. 모든 쌍의 발생확률은 1/4다. 둘을 관측해도 cell을 완전히 확정하지는 못한다.

| 최근 두 상태 | P(A / 관측 상태 쌍) | P(다음 상태=1 / 관측 상태 쌍) |
|---|---:|---:|
| 00 | 9/10 | 9/50 |
| 01 | 1/10 | 9/50 |
| 10 | 1/10 | 41/50 |
| 11 | 9/10 | 41/50 |

각 경우 높은 쪽의 다음 상태 확률은 41/50이므로 같은 위험 `409/2050`을 얻는다. 이는 cell을 모르면서 필요한 긴 이력과, cell을 알고 난 뒤의 짧은 기억을 구별하는 예다. 실제 좋은 cell 소속을 찾는 절차나 실데이터의 필요 입력 길이를 검증하지 않는다. [현재 정확 계산](../verification/history-052-numeric-check.json)

## 이름과 실제 차이값의 불일치

원 결과의 `history_gain_pooled_minus_known`에는 **cell을 모를 때의 관측 1개→2개 개선량**이 저장돼 있다. 코드의 식도 `pooled1-pooled2`다. 이름만 읽어 known과의 차이로 재사용하면 비교 대상을 잘못 해석하게 된다. 보존본의 키와 값은 바꾸지 않고 아래와 같이 구별한다.

| 실제 비교 | 정확 차이 | 소수 |
|---|---:|---:|
| unknown 1개 − unknown 2개; 원 항목의 실제 값 | 308/1025 | 0.3004878049 |
| unknown 1개 − known | 17/45 | 0.3777777778 |
| unknown 2개 − known | 713/9225 | 0.0772899729 |

계산값 자체의 오류로 처리하지 않는다. 원 항목의 이름과 비교 대상이 다른 문제이며, 기본 순서 `known < unknown 2개 < unknown 1개`는 그대로 성립한다.

## RCTL 구조와 표준 MAC

구조 근거는 [보존된 RCTL port 60줄](../evidence/0639/originals/SRC-0023048.py.txt)이다. 당시 결과에 기록된 구조 SHA와 현재 보존 바이트가 같다. 모델 객체를 만들거나 가중치를 불러오지 않았다. 원 논문 모든 구현의 보편적 연산 수가 아니라 이 코드 버전과 채널 9의 계산이다.

출력 채널은 `[16,32,64,64,32,16]`인 여섯 block이다. 각 block에는 kernel 3의 causal convolution 두 개, 1×1 shortcut 두 개, LSTM, BatchNorm 두 개가 있다. 첫 세 block의 projection, 마지막 root shortcut, 길이와 연결되는 Dense도 센다. dilation은 1/2/4/6/8/10이다. causal padding을 포함한 표준 dense 계산량이며, 0과의 곱셈을 별도 절약으로 빼지 않는다.

입력 채널 a, 출력 채널 c인 block의 한 시점 행렬 MAC은 다음처럼 나뉜다.

```text
conv 2개 + shortcut 2개 + LSTM 입력·순환 4 gate
= (3ac + 3c²) + (ac + ac) + (4c² + 4c²)
= 5ac + 11c²
```

MAC은 곱셈·누산 한 쌍의 단위다. 아래 수치를 측정한 FLOPs나 실제 지연으로 바꾸지 않는다.

| block | 입력→출력 채널 | 한 시점 행렬 MAC | 전체 parameter | 고정 parameter |
|---|---:|---:|---:|---:|
| 1 | 9→16 | 3,536 | 3,792 | 64 |
| 2 | 16→32 | 13,824 | 14,336 | 128 |
| 3 | 32→64 | 55,296 | 56,320 | 256 |
| 4 | 64→64 | 65,536 | 66,560 | 256 |
| 5 | 64→32 | 21,504 | 22,016 | 128 |
| 6 | 32→16 | 5,376 | 5,632 | 64 |

여섯 block의 행렬 수는 시점당 165,072다. projection 5,376, root shortcut 144, Dense의 시점당 기여 16을 더하면 **170,608 MAC/시점**이다. 길이 L의 한 입력 창에는 `170608 × L`을 센다.

## 연산 수와 parameter 수의 차이

block의 전체 parameter는 행렬 가중치 `5ac+11c²`에 convolution/shortcut bias `4c`, LSTM의 두 bias `8c`, BatchNorm의 학습 가능한 scale/shift `4c`를 더한 `5ac+11c²+16c`다. BatchNorm의 running 통계와 추적 buffer는 parameter 수에 넣지 않는다.

Torch port는 추가 LSTM hidden bias를 0으로 초기화하고 `requires_grad_(False)`로 고정한다. 총 **896개**가 이에 해당한다. 저장 결과의 `parameters`는 이를 포함한 전체 수다. 학습 가능한 parameter 수를 같은 값으로 부르면 안 된다.

| 입력 길이 | 한 입력 창 행렬 MAC | 전체 parameter | 학습 가능한 parameter | 고정 parameter |
|---|---:|---:|---:|---:|
| L=8 | 1,364,864 | 174,433 | 173,537 | 896 |
| L=2 | 341,216 | 174,337 | 173,441 | 896 |

길이별 MAC 비율은 정확히 1/4다. Dense를 제외한 parameter는 174,304개이고 Dense는 `16L+1`개여서 줄어드는 수는 96개뿐이다. 전체 174,433개 대비 감소율은 `96/174433`, 약 **0.0550355%**다. cell 그룹 수를 늘리면 거의 같은 크기의 모델을 여러 개 보관하는 비용이 남는다.

활성화, BatchNorm 연산, bias 덧셈, 메모리 이동, 학습/backprop과 실제 runtime은 MAC에서 제외한다. 입력 축소의 실제 지연·학습 시간·예측 성능은 측정하지 않았다. 따라서 MAC 1/4를 실제 4배 속도 향상으로 보고하지 않는다.

## 실행 근거와 시간 측정 범위

시작 파일의 plan/code/structure SHA, 결과의 같은 SHA, 종료 파일의 `hashes_unchanged`와 duration을 대조했다. 원 코드에는 시작 표지가 이미 있으면 중단하는 guard가 있고, 모델 대신 표준 라이브러리 산술을 사용한다. 저장 결과와 종료 표지는 서로 일치한다. 62의 “exit0·한 번 실행” 보고와 구분해, 원 콘솔의 exit code나 외부 모든 시도 이력까지 확보한 것으로 표시하지 않는다. [시작](../evidence/0061-history-logic-cost/originals/SRC-0027872.json) · [종료](../evidence/0061-history-logic-cost/originals/SRC-0027871.json)

기록된 `cheap_numeric_seconds`는 `0.00009660000068834051초`, 약 96.6µs다. 타이머는 source hash 계산과 시작 표지 쓰기 **뒤**에 시작하고, 주요 Fraction·구조 산술과 assertion 뒤에 끝난다. 결과 dictionary 작성, 일부 보고용 ratio/소수 변환, 결과 쓰기, 최종 hash와 종료 표지 쓰기는 밖이다. 프로그램 전체 실행시간이나 모델 속도가 아니다.

계획의 300ms는 엄격한 성능 조건으로 두지 않았다. 코드의 5초 assertion도 계산 뒤에 확인하므로 실행 중 강제로 중단하는 장치가 아니다. 누적 cheap 600초는 과거 예산 맥락이며 현재 새 실행을 허용하는 지시가 아니다.

## 전후 원장의 한 번 반영

[61 직전 원장](../evidence/0059-0062-history-grouping/originals/SRC-0027869.json)과 [snapshot 14의 이후 원장](../evidence/0061-history-logic-cost/originals/SRC-0000901.json)의 전체 JSON 차이는 `new_cheap_diagnostic_seconds.history_logic_cost_61` 항목 하나다. 값은 저장 duration과 같고, [회계 코드](../evidence/0061-history-logic-cost/originals/SRC-0023215.py.txt)의 한 번 반영과 일치한다. 같은 이후 원장은 snapshot 15와 67 직전 원장에도 바이트가 같은 사본으로 연결된다.

Tab은 누적 65 contexts·38,016 query행·245.5397765초, RCTL은 29 fits·추가 허용 0으로 그대로다. 이후 cheap 합은 **64.00884490000549초**, 기록된 modeling 합은 **1,977.5556332000033초**다. 62의 반올림 총계와 일치하며, 이전 전처리와 타이머 밖 모든 비용을 포함한 완전한 총시간은 아니다. 60의 비용을 새 모델 비용으로 다시 더하지 않았다.

## 재사용과 재검토 조건

이 예를 다시 쓸 때는 cell 혼합·상태 초기 분포·관측 잡음·예측 손실·이용 가능한 정보를 먼저 명시한다. 같은 과정 식별 직관이나 입력 길이 후보를 추가했다는 이유만으로 새로운 clustering 방법이 성립하지 않는다. 실제 제안에는 좋은 소속을 찾는 규칙, 새 평가 기간, 최종 RCTL 성능과 선택/준비 비용의 직접 근거가 필요하다.

원본 10묶음·31경로를 연결했고 새 사본은 6개·11,865bytes다. 기존 계획·62 보고·RCTL 구조·직전 원장 4개를 재사용했다. [작은 근거와 검수 명령](../evidence/0061-history-logic-cost/README.md) · [출처별 범위](../sources/history-052.md) · [주장·검수·남은 범위](../verification/history-052.md)

H052는 61의 산술과 62의 해당 판단을 검수했다. 59의 ALW는 [후속 H053](0059-alw.md)에서 검토했다. Optimal Look-back 일차자료와 62 전체 종합, 그 뒤의 새로운 연구 방향은 별도 미완료 범위다. 현재 검수를 독립 연구자의 모델 재현이나 실제 트래픽에 대한 필요성 증명으로 표시하지 않는다.
