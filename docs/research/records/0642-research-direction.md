# 642 — 연구 방향 제안 완료와 아직 실행하지 않은 본실험

642는 634–641의 결과를 묶어 **관측 정답을 사용하는 관계 점수로 UPC 소속을 수정하는 연구를 시작하자**고 제안한 기록이다. 연구 방향·구현 명세·보고서·Word 문서의 작성 완료를 뜻하며, 독립된 새 기간이나 도시에서 성능을 검증한 기록은 아니다. 새 모델·예측·traffic 수치 실험은 모두 0이다. [완료 범위 원문](../evidence/0642/originals/SRC-0024216.json), [정산 원문](../evidence/0642/originals/SRC-0024221.json)

이 정리본은 2026-10-04 파일명의 **최종 보고서와 7쪽 Word 판본**을 다룬다. 저장 시각은 2026-10-03 17:20–17:23 UTC다. 초기 10쪽 렌더, 이후 개정 문서, 인용된 모든 과거 기록과 논문은 별도 검토 대상이다. 과거 Goal의 완료 선언도 이 기록의 자료로 보존했다. 현재 아카이브 전체가 끝났다는 뜻은 아니다. [원문·판본 안내](../sources/pilot-005.md)

## 어떤 결정을 내렸는가

질문은 “TabICLv2의 직접 예측 정확도가 좋아지는가”에서 더 나아가, “자기 cell의 고정 context로 얻은 분포가 다른 cell과 자료를 공유할 소속을 정하는 데 도움이 되는가”다. 최종 예측기는 RCTL이며 TabICLv2의 역할은 소속 결정에 필요한 분포 추정이다. 보고서는 633의 직접 예측과 소속 효용 불일치를 동기로 인용한다. **633의 전체 실험 근거 대조는 아직 대기 중**이다. [642 보고서 원문](../evidence/0642/originals/SRC-0000099.md.txt)

제안은 이미 수행한 작은 확인을 근거로 본실험에 착수하자는 판단이다. 새로운 보정식, 최초의 조건부 clustering, Tab만 가능한 기능, 보편적인 MAE 개선을 확정하지 않는다. 가까운 선행과 겹치는 요소, 점수의 재가중 관계, 적용 가정은 [640](0640-contribution-boundary.md)에서 다뤘다.

| 구분 | 642가 이용한 근거 | 이 근거로 확정하지 않은 것 |
|---|---|---|
| 구현과 실행 | [635–637](0635-0637-execution-recovery.md)의 실패·복구와 저장 분포 | 오류·부분 실행을 지운 완전한 첫 실행 |
| 실제 소속 변화 | [638](0638-numeric-precision.md)의 정밀도 정정 후 Tab 3cell, HGB 1cell 이동 | 모든 cell·기간의 관계를 정확히 복원함 |
| 후속 예측 효용 | [639](0639-rctl-bridge.md)의 소속 봉인 후 RCTL 평가 | 미래 기간·새 도시의 일반적 우위 |
| 같은 출력의 결정 대조 | [641](0641-cached-score-controls.md)의 네 대조 모두 UPC 유지 | 관측 정답 사용의 인과 효과나 사전 등록 실험 |
| 완료 선언 | 보고서와 전 페이지 검수 Word, 근거 등록부 | 본실험·논문 검증 전체 완료 |

## 실제 조건과 비용

근거가 되는 실행은 A 집합 16cell·K=4·seed 20260925의 한 개발 조건이다. Tab/HGB에 같은 504행 자기 context, 16개 입력 열, 9분위수, 64개 query를 사용한 관계 단계와 480시점의 RCTL 평가를 연결한다. 이후 읽은 기간도 개발 자료로 취급한다. 소속·자료 분할·정규화·실제 ID·RCTL 학습 규칙과 재사용 조건은 635–639에 보존되어 있다. 642에서는 이 설정으로 새 실행을 추가하지 않았다.

지원 구간은 **Tab과 HGB 분위수의 공동 유효성**에도 의존한다. HGB를 외부의 무료 비교값으로 가정하거나, 아래 197.086초를 Tab 단독 배포 비용으로 쓰면 안 된다.

| 작업 | 새 실행과 재사용 | 당시 기록된 비용 |
|---|---|---:|
| 635–638 | 실패·부분 복구, 두 추정기와 지원·점수·소속 처리 | 합계 197.086초 |
| 639 | 새 RCTL 3group·165epoch, 기존 13평가 자리 재사용 | RCTL 158.336초 + 기타 2.737초 |
| 641 | 저장 출력의 대조, 기존 RCTL 연결 | 0.330초 |
| 642 | 결과 인용·문서 작성·렌더 검토 | 새 연구 모델/traffic 계산 0; 문서 작업 시간은 연구 모델 원장 밖 |

위 단계 비용은 [앞선 검수](../verification/pilot-001.md), [RCTL 검수](../verification/pilot-002.md), [641 검수](../verification/pilot-004.md)를 연결한 값이다. 누적 원장의 `used`와 642의 복사본도 정확히 대조했다. 누적 Tab context 466회·query 260,842행·2,427.164초, RCTL optimizer 173fit·9,249epoch·12,707.395초, 통계 적응 9회가 기록되어 있다. 같은 원장의 통계 적응·frozen inference·gradient·cheap 작업은 별도 항목이다. 이것을 독립적인 성공 실험 수로 세지 않는다. [문서·원장 대조 결과](../verification/pilot-005-document-check.json)

## 평균 이득과 함께 읽어야 할 반례

보고서 §6과 Word 세 번째 표의 정규화 MAE **12개 값 각각**을 639의 저장 scalar와 대조했고, 두 문서 모두 소수 여섯 자리에서 일치했다. 새 예측이나 MAE 배열 계산을 수행한 것은 아니다.

| 비교 기준 | Tab 소속의 정규화 MAE 변화: 전체 | 그대로 남는 한계 |
|---|---:|---|
| 작은 UPC θ=0 | −3.97% | 개선 9cell, 악화 4cell, 동일 3cell |
| 같은 관계 점수의 HGB | −4.69% | 동일 정보의 한 개발 조건 비교 |
| 강한 기존 HGB 소속 | −1.93% | 앞 절반 +2.71%; 전체 6cell 악화 |

변화율은 `(Tab / 비교군 − 1) × 100`이며 음수가 개선이다. 642의 보고서와 Word는 정규화 MAE를 중심으로 제시한다. 아카이브에서는 [639의 원척도 반례](0639-rctl-bridge.md)를 빠뜨리지 않고 연결한다: **HGB_free 대비 원단위 MAE는 전체 +6.58%, 앞 절반 +8.04%, 뒤 절반 +5.54%로 모두 악화**했다. 두 척도의 결과가 다르므로 “HGB보다 성능이 좋다”로 합치지 않는다.

## 원 UPC 조건과 공식 구현의 구분

원 UPC 논문의 PDF 4쪽(인쇄 6263쪽)과 5쪽 Algorithm 1은 피크 그룹의 cell 수가 `θ`를 **초과**할 때 대표값을 만들고, 그렇지 않으면 `None`을 둔다. 본문 설정은 `θ=10`이다. 여기서 그룹 크기는 날짜나 query 수가 아니라 cell 수다. [원 논문](https://doi.org/10.1109/TNSM.2025.3599168)

PCC가 정의된 서로 다른 피크 그룹 네 개로 K=4의 초기 군집을 구성한다는 조건에서, 각 그룹에는 최소 11cell이 필요하므로 `4 × 11 = 44cell`이 필요하다. **44는 이 조건에서 도출한 필요조건**이다. 피크 그룹 분포와 유효 PCC까지 보장하지 않으므로 충분조건이 아니다. 16cell·θ=0의 작은 실험을 원 θ=10 설정의 재현으로 표현하지 않는다.

공식 GECOS의 지정 commit `a7519dd…`와 보관 `main.py`의 바이트가 일치함을 확인했다. 이 코드는 준비된 상관행렬을 입력으로 받고, 순번의 나머지로 초기 소속을 만든 뒤 이동을 반복한다. 원 논문의 피크 그룹 생성·θ 검사 전체가 들어 있지는 않다. `np.triu(..., k=1).mean()`의 분모에도 그룹 크기 효과가 있으므로 논문의 모든 단계를 구현했다고 동일시하지 않는다. 코드는 실행하지 않았다. [확인한 공식 코드](https://github.com/Superint-Lab/GECOS/blob/a7519dde9d6f5deb3006689df047d99ea0dac7b7/main.py)

TabICLv2 원문의 §3·§4.2·부록 I.1–I.3에서는 열 임베딩→행 상호작용→ICL 구조, 회귀 분위수와 분포 구성, 추론 최적화를 확인했다. 이 모델 설명은 현재 traffic 점수의 보정 정확도·잡음 불변성·RCTL 우위를 증명하지 않는다. 642가 인용한 나머지 문헌은 기존에 검수한 [640 범위](../references/conditional-clustering.md)와 아직 검토하지 않은 인용을 구분한다. [TabICLv2 v2](https://arxiv.org/html/2602.11139v2)

## 당시 제안한 다음 실험 — 모두 미실행

| 남은 질문 | 당시 제안한 설계 | 결과에 따른 판단 |
|---|---|---|
| 원 UPC에 실제로 추가 효용이 있는가 | 미사용 기간·충분한 cell·θ=10 적용 가능성을 먼저 고정 | 적용 불가를 기록하고 성능을 본 뒤 θ/K를 바꾸지 않음 |
| HGB/TabPFN보다 Tab이 필요한가 | 같은 정보 비교와 같은 실제 시간 상한 비교를 구분 | 더 싼 대안이 같은 효용이면 Tab 중심 기여를 축소 |
| 관계 점수가 RCTL에도 도움이 되는가 | score·검색·지원·세 번 순회를 고정하고 소속을 먼저 봉인 | 새 기간에서 악화하면 현재 연결 가설 재검토 |
| graph 크기·singleton 효과인가 | 소속 크기와 이동 후 크기를 통제하는 비교 사전 설계 | 구조 효과로 설명되면 관계 점수의 기여 축소 |
| 도시·규모가 바뀌어도 가능한가 | 새 도시·전체 도시 비용 및 일반화 검증 | 16cell 비용을 1만 cell 실측처럼 외삽하지 않음 |

위 표는 새로운 실행 지시가 아니라 642에 남은 연구 계획이다. 현재 아카이브 작업에서는 실행하지 않는다. 같은 개발 조건을 반복하기 전에 638 소속, 639 결과, 641 대조를 재사용하고, 새롭게 검증하려는 조건을 기록한다.

## 재사용과 검토 범위

[보존 보고서](../evidence/0642/originals/SRC-0000099.md.txt)와 [Word](../evidence/0642/originals/SRC-0000011.docx)는 원본 바이트를 유지했다. 원문 안의 개인 경로·당시 지시는 역사적 자료다. 팀은 [출처 안내](../sources/pilot-005.md)의 저장소 링크를 사용한다. 원본 문서의 주장을 아카이브의 추가 반례로 덮어쓰지 않았다.

보고서 전체, 최종 Word의 7쪽·5표와 관련 완료 자료를 읽었다. Word 내부의 숨은 텍스트·주석·변경 추적·그림/수식 개체 여부도 검사했다. 문서 생성 코드는 지정 구간을 읽고, 직접 출력하지 않은 보고서 문자열 구간은 읽은 보고서와 AST 추출 텍스트의 일치를 확인했다. 줄바꿈이 달라 바이트 중복으로 처리하지 않았다. [검수 범위와 남은 자료](../verification/pilot-005.md)
