# 93. 후보 판정 기준과 기존 비교의 적용 범위 재점검

2026-09-26. 직전92는 원문·구현·반례를 확인하고 후보 판정과 근거 파일을 변경했으므로 progress다. 현재 progress, snapshot34 검증, 누적 비용 원장과 후보 인덱스를 확인했다. 추가 RCTL fit0, Tab 잔여11 context/20,640 query는 유지한다.

이번 단계는 새 후보를 합격시키기 위해 기준을 낮추는 작업이 아니다. 원래 goal의 '성능 전체를 보장할 필요는 없지만 핵심 원리를 모두 본 실험으로 넘기지 않는다'와 '같은 결정이어도 별도의 계산·통계 효율 기여가 있으면 검토한다'를 실제 판정 기록에 일관되게 적용한다.

## 확인할 범위

1. 07·34의 RCTL 부정 결과는 어떤 자료·학습 조건·partition에 해당하는가? global K1과 K4를 같은 모델 수 비교로 부르지 않았는지, 같은 K4의 강한 단순 대안과 비교한 부정 결과는 남는지 실제 실행 설정·코드·결과를 대조한다.
2. 74·80의 'Tab 예측이 더 좋아도 소속은 같음'은 해당 방법의 추가 효용 부재인지, 모든 Tab 기반 clustering의 불가능성인지 구분한다. 새로운 추론 없이 저장 결과·판정문만 확인한다.
3. 86·89·91의 이론·설계 검토에서 'global로도 표현 가능하다'를 '분할은 절대로 실익이 없다'로 강화한 문장이 있는지 확인한다. 표현 가능성, 유한 학습, 실제 비교를 분리한다.
4. 후보 인덱스의 '다른 결정을 만드는가'를 필수 조건 하나로 두지 않는다. 동일한 유용한 결정을 더 적은 계산 또는 더 안정적인 추정으로 얻는 방향도 진입 가능하되, 같은 결과만 나왔다는 사실을 효율 개선으로 인정하지 않는다.
5. 핵심 자료나 실행이 없는 안은 '미검증·미추천'으로 분류한다. 반례가 특정 해석을 무너뜨린 경우와 실제 비교에서 실패한 경우를 구분한다. 새 근거 없이 추천으로 승격하지 않는다.

모델 호출·새 자료 진단·성능 재계산은 하지 않는다. JSON·설정·소스의 읽기와 기록 정합성 검사만 한다. 기존 성능에 맞춘 threshold·K·가중치 조정, 유리한 cell/날짜 선별, 추가 fit 상한 변경은 하지 않는다. 수정한 판정 기준으로 실제 남는 설계상의 선택을 명시하며, 이번 감사 자체를 최종 추천안이나 목표 완료로 제시하지 않는다.
