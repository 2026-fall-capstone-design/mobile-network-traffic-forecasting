# 93. 후보 판정 기준과 기존 비교의 적용 범위

2026-09-26. 93 사전 계획에 따라 기존 실행 설정·기록·코드 hash를 감사했다. 새 데이터 진단이나 모델 실행은 없다. 결과는 `results/candidate_gate_audit_93/result.json`이며 37개 근거 파일을 대조했다.

## 수정할 판정 기준

후보 인덱스의 진입 문구에는 두 가지 보완이 필요했다.

1. **소속이 반드시 달라져야 하는 것은 아니다.** 같은 유용한 결정을 더 적은 계산이나 더 작은 추정 변동으로 얻는 방법도 원래 goal의 검토 대상이다. 반대로 같은 소속이 나왔다는 사실만으로 효율이 개선됐다고 볼 수는 없다. 기존 74·80에는 추가 Tab 계산을 상쇄하는 효율 이득이 확인되지 않았으므로, 이 보완이 해당 후보의 성공을 뜻하지 않는다.
2. **RCTL에 새 입력이나 새 target을 추가해야 하는 것은 아니다.** clustering이 달라져 함께 학습하는 실제 sample의 구성이 달라지는 것도 최종 학습을 바꾸는 경로다. 이것을 명시하면 되며, 연구를 성립시키려고 모델 구조를 더 복잡하게 만들 필요는 없다. 공유할 자료가 달라질 때의 이득을 설명하고 확인해야 한다는 조건은 유지한다.

또한 작은 탐색 실행의 진입 조건과 최종 추천 조건을 분리한다. 탐색 전에는 확인할 현상·예측·비교·비용을 구체적으로 정해야 하지만, 그 탐색에서 알아낼 성능 차이를 이미 입증하라고 요구하지 않는다. 최종 추천에서는 원래 goal의 직접 근거·신규성·실현 가능성 조건을 모두 만족해야 한다. 기존 실패와 같은 원리를 새 이름으로 다시 실행하지 않는 원칙도 유지한다.

## 실제 RCTL 비교에서 유효한 부분

보존된 학습 코드와 모델 코드의 SHA-256이 실행 전 설정과 일치했다. 29개 fit의 history 길이, 선택 epoch의 validation MAE, 종료 사유, 조건별 16 cell의 누락·중복 여부, fit별 기록과 요약 MAE의 정합성을 확인했다. 모든 fit은 validation patience로 종료했으며 80 epoch 상한에 닿지 않았다. 이는 최적 수렴의 증명이 아니다.

| 비교 | 실제 기록 | 해석 |
|---|---|---|
| Tab risk와 empirical risk, K=4 | 같은 16 cell·입력·시간 구간·MAE 목적·batch256·학습 정책. 각 모델은 4 cell의 자료를 받음 | 두 seed 모두 empirical의 MAE가 작다는 기존 부정 결과는 유지한다. 동일한 데이터·모델 수의 강한 대안과 비교했다. |
| global K=1과 K=4 | global 모델의 학습 행10,752개, cluster 모델당2,688개. epoch당 update는 각각42회와11회 | 모델 수, 모델당 자료량, update 수가 다르다. global의 좋은 결과는 실용적 비교 기준이지만 clustering 전체의 불가능성을 증명하지 않는다. |
| K=4의 train/validation gap | 기존34의 저장 checkpoint 진단에서 train 오차 감소와 validation 악화가 함께 관찰됨 | 학습·일반화 절충을 살펴야 할 근거다. 과적합 하나가 원인이라고 확정하거나, 학습 공유를 붙이면 해결된다고 단정하지 않는다. |

epoch와 batch loop로 계산한 update 회수는 다음과 같다. 이는 새 학습이나 실행 시간 측정이 아니다. K=4 열은 서로 다른 네 모델의 update를 합한 값이므로 한 모델에 그만큼 update했다는 뜻이 아니다.

| 조건 | seed | 실제 실행한 update 합 | 선택 checkpoint까지의 update 합 |
|---|---:|---:|---:|
| global | 20260925 | 1,890 | 1,470 |
| Tab risk K4 | 20260925 | 2,431 | 1,991 |
| empirical risk K4 | 20260925 | 2,453 | 2,013 |
| Tab risk K4 | 20260926 | 2,585 | 2,145 |
| empirical risk K4 | 20260926 | 2,376 | 1,936 |

같은 early-stopping 정책이 같은 update 횟수나 완전히 같은 최적화 경로를 보장하지는 않는다. 그러나 두 번째 seed에서 empirical은 update 합도 더 작으면서 오차도 작다. 단순히 empirical에 더 많은 학습을 주었기 때문이라고 기존 결과를 무효화할 근거는 없다. 이것 역시 차이의 원인을 인과적으로 확정하는 분석은 아니다.

따라서 문헌과 기호 검토에서 미추천한 안을 모두 '실험으로 실패가 확정된 안'으로 묶지 않는다. 반대로 미검증이라는 이유로 유망하다고 올리지 않는다. 현재 직접 근거가 부족하다는 상태를 그대로 남긴다.

## 다음 설계에 주는 구체적 변화

다음 후보는 모델에 새 모듈을 붙여야 한다는 전제에서 시작하지 않는다. 다음 둘 중 하나를 명확히 선택한다.

- **예측에 관한 기여:** 실제로 함께 학습할 sample의 구성을 바꾸고, 현재 강한 단순 대안이 놓치는 중요한 상황에서 그 변경이 왜 도움이 되는지 확인한다.
- **추정·계산에 관한 기여:** 이미 유용한 것으로 정한 비교 또는 결정을 더 적은 비용·변동으로 얻는다. 비용 절감이 잘못된 비교를 더 빨리 계산하는 데 그치지 않도록, 출발하는 결정 자체의 타당성을 확인한다.

이 구분은 새 추천안이 아니다. 같은 결과를 더 비싸게 얻은 74·80을 계산 기여로 되살리거나, 실패한 B2를 그대로 빠르게 구현하는 안을 자동 채택하지 않는다. 강한 단순 대안과의 비교, Tab의 실제 기여, RCTL 학습으로 전달되는 경로, 누적 비용 조건은 유지한다.

현재 남은 연구 문제는 여전히 구체적인 개선 방향의 선택이다. 이번 감사는 과도한 진입 조건을 바로잡았지만 최종 추천을 가능하게 하는 새로운 성능 증거를 만들지는 않았다. 원장 불변, 새 모델 호출0, 추가 RCTL fit0, Tab 잔여11 context/20,640행이다. 최종 Word와 목표 완료를 선언하지 않는다.
