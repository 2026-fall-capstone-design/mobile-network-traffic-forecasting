# 공간 입력의 역할 정렬 검토

2026-09-26. 91의 사전 계획에 따른 원문·공식 코드·기호 검토다. 새로운 모델 추론, 학습, 데이터 수치 진단은 하지 않았다. 이 문서는 채택한 연구 방향이 아니다.

## 판단

**cell마다 이웃 입력의 역할을 맞춘 뒤 clustering하는 안은 현재 추천하지 않는다.** 이웃의 중요성을 추정하거나 입력 열을 정렬하는 기술이 없어서가 아니다. 현재 자료에서 고정된 동서남북 입력 때문에 발생한 예측 손해가 확인되지 않았으며, 정렬의 효과와 cluster별 학습의 효과도 분리해야 한다.

기존 47·75의 이웃 선택, 81의 다중 출력과 다른 결정은 확인했다. 이번 후보는 입력으로 쓰는 이웃 집합을 유지하고, 각 cell의 입력 열 대응을 바꾼다. 그러나 이 구별 자체가 유용성이나 신규성을 입증하지는 않는다. 임의로 입력 순서를 훼손한 다음 복구하는 실험으로 실제 문제를 만들지 않는다.

## 1. CPiRi: 이름의 순서와 예측 역할은 다르다

[CPiRi, arXiv:2601.20318v2](https://arxiv.org/html/2601.20318v2), §3.1–3.5, Algorithm 1, §4 및 Appendix A.5를 읽었다. frozen Sundial의 channel별 시간 표현을 공간 Transformer에 전달하고, 다시 channel별 예측을 만든다. Algorithm 1은 입력과 정답의 channel을 같은 permutation으로 바꾼다. §3.5의 핵심 성질은 F(PX)=PF(X)다. 입력 목록의 순서가 바뀌면 출력 목록도 같이 바뀐다는 뜻이다.

이는 A의 북쪽 이웃과 B의 동쪽 이웃이 같은 역할인지 알아내는 절차가 아니다. 자기 target을 고정하고 북쪽과 동쪽의 **값만** 바꾸는 연산도 아니다. 위치, 방향, 자기 cell 표시 등 의미를 가진 특징은 해당 관측과 함께 다뤄야 한다. 불필요한 목록 순서와 유용한 공간 정보를 혼동하지 않는다.

공식 저장소 commit `3f1e00f62b42782062c3484792f47fe905e5b743`에서 6개 파일을 저장해 정적으로 읽었다. 실행하지 않았다.

- `arch.py:34–44`: 사전학습 Sundial을 불러오고 gradient를 고정한다. 공간 Transformer의 dropout은 0.3이다.
- `arch.py:55–77`: channel별 시간 처리 → 마지막 표현 → channel 간 attention → flow sampling이다. inference도 20회 sample 평균이므로 동일한 두 forward의 출력이 항상 정확히 같다는 식으로 설명하지 않는다.
- `runner.py:171–193`: 같은 index로 input과 target을 변경한다. 기본 분기는 전체 channel을 보존한다. 부분 순서 변경 비율이 1보다 작아도 나머지를 뒤에 붙인다. 별도 `rand_index=True` 분기는 기본 호출이 아니므로 channel 제거가 기본 방법이라고 해석하지 않는다.
- `METR-LA_LTSF.py:108–109, 152–173`: 저장된 설정에는 epoch 11에서 backbone의 gradient를 다시 허용하는 옵션이 있고, train/val/test channel shuffle 설정은 주석이다. runner는 해당 epoch에서 `requires_grad_(True)`를 호출한다. optimizer가 실제 어떤 parameter를 갱신하는지까지 확인하지 않았으므로 논문의 모든 frozen/shuffle 실험을 이 한 설정으로 재현했다고 말할 수 없다.

위 구현 차이는 원문 전체의 성능을 부정하는 근거가 아니다. 논문의 학습 구성과 현재 저장소의 특정 설정을 구별하는 기록이다. 구조가 이미 equivariant인 결정론적 계산에서 동일 permutation은 대칭 손실값을 바꾸지 않는다. dropout·확률 decoder·optimizer·정규화의 실제 효과는 별도이며, 유한 shuffle 자체가 의미 있는 역할 대응을 알아낸다는 보장은 없다.

## 2. CRAFT: 예측에 맞춰 channel을 정렬하는 원리는 존재한다

[CRAFT, WWW 2026 저자 공개 PDF](https://zheng-kai.com/paper/2026_www_fang.pdf), §2.2, §3.1–3.4, §4.1–4.3.1을 읽었다. 추세/계절 표현에서 channel 점수를 만들고 정렬한 뒤, 연속된 channel을 묶어 그룹 내부·그룹 사이 attention을 수행한다. attention 관계에서 얻은 정렬 신호와 순위 loss, 위치 loss, 예측 MSE를 함께 학습한다.

현재 후보와의 공통점은 관련 channel의 배열을 예측에 맞춘다는 것이다. 차이는 CRAFT가 최종 예측기와 함께 정렬을 학습하고, 현재 후보는 고정된 TabICLv2를 이용해 RCTL 앞에서 cell별 입력 대응을 정하려 한다는 점이다. 따라서 완전히 같은 알고리즘이라고 할 수는 없다. 다만 '예측에 유리한 순서로 열을 정렬한다'는 주장만으로는 차별성이 부족하다.

14개 고차원 시계열의 7:1:2 시간 분할과 입력 길이·폭·그룹 크기 탐색을 확인했다. 통신 cell의 방향별 입력 역할 불일치를 직접 보여준 실험은 아니다. source의 attention 비용은 O(GP²+PG²), GP≈C다. 자체 정리하면 O(C(P+C/P))이며 P≈√C에서도 O(C^(3/2))다. 원문의 'linear complexity'라는 표현을 N개 cell의 전체 clustering 비용이 선형이라는 근거로 옮기지 않는다. 이는 식의 해석이며 실행시간 측정이 아니다.

## 3. TIDES: 통신 트래픽의 clustering과 사전학습 모델 결합

[Wireless Traffic Prediction with Large Language Model — TIDES, arXiv:2512.22178v1](https://arxiv.org/html/2512.22178v1), §IV, §V.A–C 및 I, Table I–II를 읽었다. 2025-12-19 v1 원문이며 이 검토에서 후속 저널 버전과 공식 실행 코드는 확인하지 않았다.

§IV.A 식13–17은 위·경도, 평균, 아침·저녁·야간 traffic과 local Moran's I를 특징으로 만들고 표준화한 뒤 K-means로 region을 나눈다. 이웃은 haversine 거리의 kNN이고 가중치는 1/d다. §IV.B는 cluster별 traffic을 RevIN·patch·수치와 주기 정보를 포함한 prompt로 처리하고, 공간 attention과 단어 embedding 정렬을 거쳐 frozen DeepSeek 계열과 학습 가능한 주변 모듈로 예측한다. 여기서 domain alignment는 이웃 열의 역할 대응을 추정하는 연산이 아니다.

데이터는 중국 사업자의 약 19,000 sector에서 수집한 4G downlink traffic이며, region 단위로 집계해 K=4 zone으로 나눈다. 2024-07-28~08-25의 15분 자료를 사용하고 96시점으로 4시점을 예측한다. 4 A100, batch 16, 100 epoch/early stopping 설정이 명시되어 있다. Milan의 hourly Internet 활동 지수나 cell별 scalar RCTL과 같은 단위로 간주하지 않는다.

Table I에서 TIDES는 Zone A/C/D의 MAE가 가장 작지만, Zone B는 Time-LLM 0.3567 대비 TIDES 0.4208이다. 모든 zone에서 우수하다고 요약하지 않는다. Table II의 다른 zone→A 전이는 각 zone에서 5개 region을 뽑은 비교이며 모든 도시쌍 일반화 실험이 아니다. 본문에서 확인한 결과만으로 clustering, Moran 특징, 공간 attention 각각의 독립 기여를 확정할 수 없다. 정확한 시간 분할과 재현용 데이터·코드의 접근성도 이번 읽기 범위에서는 확인되지 않았다.

식25의 mask는 `(1−L_sym)×(−1000)`으로 인쇄되어 있다. 이를 익숙한 이진 adjacency mask로 임의 수정해 구현하지 않는다. 이 식과 서술의 일치 여부는 코드를 확인하지 않아 미해결이며, 현재 후보에 복사하지 않는다.

**연구 방향에 반영할 점:** telecom의 clustering→foundation forecaster라는 큰 틀은 이미 존재한다. 차별성은 backbone 명칭이나 공간·주기 특징 추가가 아니라, 어떤 소속 결정의 오류를 어떤 정보로 줄이는지에 있어야 한다. TIDES의 수치를 현재 RCTL의 개선 근거로 대신 사용하지 않는다.

## 4. 역할 정렬의 논리와 한계

다음은 직접 만든 기호 예이며 새로운 정리나 실제 traffic 결과가 아니다.

1. **모든 cell에 같은 순서 변경:** 입력 열에 공통 permutation을 적용하고 원입력을 읽는 모든 convolution·skip projection의 입력-channel 계수를 그에 맞게 재배열하면 같은 함수를 표현할 수 있다. RCTL의 고정 열 순서 하나가 그 자체로 표현 불가능성을 만들지는 않는다. 동일한 학습 경로까지 보장하는 주장은 아니다.
2. **cell마다 다른 대응:** A는 Y=u, B는 Y=v라면 B의 두 이웃 열만 바꾼 후 두 cell 모두 첫 열을 읽는 함수로 표현할 수 있다. 고정된 역할 정렬은 함수 공유를 단순하게 할 가능성이 있다. 동시에 이 예에서는 정렬 뒤 **한 global 모델로 충분하다.** 정렬의 필요성을 cluster 분리의 필요성과 동일시할 수 없다.
3. **역할 정보를 지우는 대칭화:** Y=u일 때 u,v를 구분하지 않는 집합으로만 주면 어떤 값이 target과 연결되는지 잃을 수 있다. 정렬은 의미를 보존하는 대응이어야 한다. 무조건적인 평균·정렬·permutation 불변성이 좋은 것은 아니다.
4. **중요도 순위의 불충분성:** Y=uv와 Y=−uv는 각각 u와 v의 대칭성이 같지만 입력 순서를 바꿔도 두 함수가 같아지지 않는다. 열별 중요도가 비슷하다는 사실은 공동 예측 관계의 동등성을 뜻하지 않는다. Tab attention을 중요도 순위로 읽는 것만으로 해결하지 않는다.

따라서 실제로 남아야 할 증거는 '같은 이웃 열 이름 때문에 학습 공유가 손해를 보고, 관측 가능한 입력 역할을 맞추면 그 손해가 줄며, 여전히 한 global보다 구분해야 할 관계가 남는다'이다. 현재의 46·47 진단에서는 일부 cell의 이웃 정보 이득이 있지만 전체·모델 간 일치는 제한적이다. 그것을 입력 역할 불일치의 직접 근거로 바꾸지 않는다.

## 5. 비용과 다음 판단

d개 이웃의 모든 permutation을 각각 Tab으로 비교하면 cell당 d!개의 후보가 된다. 셀 쌍마다 수행하면 O(N²d!)개의 비교 구조다. 정렬 거리로 근사해 이 비용을 줄이는 것과 실제 예측 관계를 보존하는 것은 별도 문제다. 이번에는 이 탐색을 실행하지 않았다.

고정된 대응 하나를 적용하는 RCTL의 입력 복사는 O(NTd)지만, 대응을 찾는 비용을 제외한 수치다. CRAFT의 학습형 정렬, PCC 기반 이웃 순서, global+cell 정보 같은 대안도 동일한 입력·target·비용에서 비교해야 한다. 현재 진입 근거가 없어 Tab의 남은 11 context·20,640 query행을 소모하지 않았다. RCTL 추가 fit은 0이다.

이 후보의 미채택은 역할 정렬 전체가 불가능하다는 판정이 아니다. 현재 goal의 추천 조건을 충족하는 직접 근거가 없다는 판단이다. 같은 역할 정렬 점수를 다시 포장하지 않는다. 또한 08–09에서 이미 검토한 residual covariance와 24–25의 horizon 변경을 신규 대안으로 반복하지 않는다. 추천안과 최종 Word는 아직 미완료이며, 기존 84 중간 Word를 최종안으로 표시하지 않는다.
