# 113 동일 K와 동일 cluster 크기를 구별하는 진단

2026-09-26. 112의 시각 보정은 첫 예측 기준을 통과하지 못했으므로 RCTL 확인으로 진행하지 않는다. 시각 이동을 더 유연하게 만드는 후속 변형도 지금 추가하지 않는다.

## 별개로 확인할 비교 조건

원 UPC의 Algorithm 1과 설명(pp.6263–6264)은 피크 시각 group을 만든 뒤 PCC로 N개 cluster에 배정한다. 각 cluster의 cell 수를 같게 만드는 조건은 없다. 반면 기존04의 risk-table 실험은 16→8→4의 round별 pairing으로 모든 cluster가4cell이 되도록 제한했다. 두 조건은 다르다.

원문을 이미 추출한 `tmp/review_20260925/Urban Mobile Data Prediction With Geospatial Clustering and Dual Residual Learning.txt`의 해당 부분과 `04_observed_query_risk_plan.md`8번·실제 partition 코드를 대조했다. 원 UPC의 작은 group 처리와 원문/공개코드 차이는 기존11·12의 미해결 범위로 유지한다. 이번에 원 UPC를 재현했다고 하지 않는다.

이 진단은 과거 pilot에 추가한 제약의 영향 범위를 확인한다. 제약을 없앤 것 자체를 UPC보다 새로운 알고리즘이나 독립적인 연구 문제로 내세우지 않는다. 기존 실패가 모두 cluster 크기 때문이었다는 주장도 하지 않는다.

## 고정 비교

- 기존16cell·K4·상태64·수정값257·Tab129분위수·empirical-target risk를 그대로 사용한다. `results/observed_risk_tables.npz`의 risk table과 base_followweek를 읽으며 f0·KMeans·TabICL을 다시 적합하지 않는다.
- 각 rule의 기존 balanced partition 결과를 그대로 재현한다. risk 값은 각 cluster의 상태별 합산 곡선 최소값의 합이다.
- 대안은 매 단계 모든 현재 cluster 쌍 중 증가 비용이 가장 작은 한 쌍만 합치고 K4에서 멈춘다. 크기 제한이나 새로운 벌점은 없다. 동점은 두 그룹의 최소 cell 번호 순서다. group을 최소 cell 순서로 다시 정렬한다. 비용 추정값과 병합 순서만 소속을 정하며 RCTL 결과와 다음 주 정답을 사용하지 않는다.
- 두 rule(Tab·실제값) 각각에 balanced/크기 제한 없음의 소속을 얻는다. 네 소속을 Tab 수정값/실제값 수정값 양쪽으로 평가하여 소속 결정 효과와 최종 수정값 효과를 구별한다. 모두 f0(x)+상태별상수라는 기존 제한 함수군이다.
- 이미 사용한 다음 주840~1007 실제값을 모든16cell의 동일 query에서 읽고 cell 평균 MAE를 구한다. 분할·이동·cell·기간을 그 값으로 다시 고르지 않는다. 최종 RCTL이나 독립 미래 성능으로 해석하지 않는다.
- 각 cluster의 cell 수와 RCTL을 학습한다면 갖게 될 실제 훈련 행672×cell수, 고정batch256에서 epoch당 처리 batch 수 합을 산술로 기록한다. 새 RCTL 학습은 하지 않으며 실제 종료 epoch·시간 절감은 추정하지 않는다.

## 판단과 한도

크기 제한을 없애도 소속이나 다음 주 예측이 의미 있게 달라지지 않으면 이 제약으로 기존 실패를 설명하지 않는다. 좋아져도 동일 K의 단순 rule과 비교하고, 내부 제약 제거를 TabICL 신규성으로 포장하지 않는다. Tab의 유용한 결정과 실제 RCTL 연결이 없으면 새 RCTL 적합을 사용하지 않는다.

실행 전 설정·코드·입력 hash를 보존한다. 두 rule에서 각각16개 singleton에서 시작해12개 pair를 병합한다. 전수 score 계산은 rule당 최대670개다. 배열 계산10초·RSS1GiB·CPU4thread 이하, 새 학습·예측 모델 호출0이다. 실제 배열 시간만 원장에 한 번 추가한다. 사용량·상한·18개 잔여Tab context와9회 잔여RCTL적합은 변경하지 않는다.
