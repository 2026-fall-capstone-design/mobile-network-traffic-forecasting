# 자료 진단과 최초 TabICLv2 기능 확인: 실행 전 고정

2026-09-25. 이 단계는 후보 알고리즘의 성공 판정이 아니다. 공개 가공 Milan 자료에서 시간 정보의 필요성과 기본 추론 비용을 확인한다. RCTL과 clustering 결과는 아직 계산하지 않는다.

- 데이터: STCNet 저자 저장소의 1488시간 × 10000 cell × 3채널 H5. 인터넷 활동량은 채널 2. byte 또는 bps로 해석하지 않는다. 반올림·집계·결측 보충 가능성이 있는 가공 자료이다.
- 처음 42일을 설계 자료, 나머지 20일을 별도 최종 확인 자료로 둔다. 마지막 20일의 target은 지금 읽어 진단하지 않는다.
- 진단 cell: 0-based row [37,45,53,61], column [36,40,44,48,52,56,60,64]의 32개를 고정한다. 성능이나 후반 target으로 고르지 않는다. 모든 cell이 관측되는지, 누락 시각·음수·중복·상수 여부부터 확인한다.
- TabICL 최초 동작: 위 격자의 네 모서리 4개 cell. context target 시점 168~671에서 256개를 일정 간격으로 선택. query target 시점 672~735의 64개를 고정. target h=1시간, 최근 8개 값과 24시간·168시간 lag, 최근 24시간 평균·표준편차, 시각 sin/cos, 요일 sin/cos를 사용한다.
- 정규화: cell별 최초 672시간의 평균 활동량으로 입력과 target을 나눈다. 0이면 해당 cell은 진단 불가로 기록하고 대체하지 않는다. 정답 단위 환산도 보존한다.
- API: 공식 고정 checkpoint, CPU, torch threads 4, interop threads 2, n_estimators=1, random_state=20260925, median 출력. 매 cell 최대 fit 1회·predict 1회. 최대 4 contexts, 256 query rows. 내부 native 분위수와 반환값을 구분한다.
- 비교: 같은 입력·context의 Ridge(alpha=1), 최근값, 하루 전 값. 이 비교는 API sanity check와 후속 가설 구성에만 사용하며 논문 성능 주장에 사용하지 않는다.
- 가능한 결과: API 실패 또는 지나친 비용이면 원인을 기록하고 확대 실행을 중지한다. 정상 동작하면 시간·메모리·실제 내부 ensemble을 기록한 후 후속 예산을 고정한다. 4 cell의 성능으로 추정기 선택을 최적화하지 않는다.
- 최초 비용 한도: 최대 4 cell, 각 준비+추론 10분, 전체 30분; RAM 24 GiB 이내. 다운로드 자산은 확보한 H5/checkpoint를 재사용한다. 이후 실행은 별도 가설·설정·누적 예산을 먼저 기록한다.
- 데이터 진단에는 처음 672시간과 672~1007시간(설계 자료)의 관측값만 사용한다. 더 후반 값은 별도 설계가 고정될 때까지 봉인한다.

확인 전제: context의 과거 정답이 query의 알려진 lag에 들어가는 것은 예측 시점에 이미 관측된 값의 정상적인 이용이다. query의 미래 target을 context에 포함하는 것은 금지한다. 시간 간격과 block 재추출은 의존성 평가 목적에 맞춰 따로 정한다.
