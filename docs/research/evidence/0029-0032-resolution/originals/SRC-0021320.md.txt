# 동일 출처의 10분·1시간 자료에서 공유 손해를 구분하는 작은 진단

2026-09-25. 30에서 확보·검사한 세 cell의 원시 internet 집계값을 사용한다. 아직 이 자료에 새 예측 모델을 적합하지 않았다. TabICL이나 RCTL의 성능을 확인하는 실험은 아니다.

## 확인할 질문과 범위

원래 10분 자료에도 달력·일주기·주간 이력을 반영한 뒤에 cell별로 학습하는 방법과 하나로 함께 학습하는 방법 사이에 차이가 남는지 확인한다. 1시간 집계 자료에서도 같은 비교를 함께 기록한다. 시간 내 세부 변동이 크다는 사실만으로 clustering이 필요하다고 추론하지 않는다.

세 cell은 공개 대체본에 있는 4159·4556·5161 모두이며 제외하거나 바꾸지 않는다. 5161은 배포자가 두 달 전체에서 최대 활동량으로 선정했다. 전체 도시를 대표하는 표본이나 독립적인 최종 평가로 취급하지 않는다.

## 자료와 입력

- 현지 시각 2013-11-01~11-30, 10분 간격 4,320개. UTC+1은 이미 확인한 STCNet 변환과 같다. 결측·중복이 없음을 30에서 확인했으며 보간하지 않는다.
- 정규화 척도는 cell별 11월 1~20일 평균이다. 원래 activity 단위를 함께 보존한다. 1시간 자료는 완전한 여섯 개 관측의 합이며 해당 해상도의 학습 평균으로 정규화한다.
- 앞 7일은 주간 lag를 만드는 이력이다. 학습 target은 11월 8~20일, 진단 target은 11월 21~30일이다. 진단을 앞·뒤 5일로 나누어 같은 차이를 기록한다.
- 예측은 각 해상도의 다음 한 관측값이다. 10분과 1시간 MAE는 서로 다른 target의 결과이므로 직접적인 우열 비교를 하지 않는다.
- 입력 S: 같은 시각 전날·전주 값, 직전 하루 평균·표준편차, target 시각의 하루·주간 sin/cos, 총 8열. 미래 시각은 알 수 있지만 미래 트래픽은 사용하지 않는다.
- 입력 S+L: S에 직전 8개 관측값을 추가한 16열. 각 해상도의 학습 공유/분리 비교는 정확히 같은 입력을 사용한다. 두 해상도 간에는 최근 이력의 실제 시간 범위가 다름을 명시한다.

## 실행과 비교

Ridge(alpha=1, StandardScaler)와 HistGradientBoostingRegressor(max_iter=100, max_leaf_nodes=31, min_samples_leaf=20, learning_rate=0.1, l2_regularization=1, early_stopping=False, random_state=20260925)를 사용한다. 설정을 결과에 맞춰 바꾸지 않는다.

각 해상도·입력·추정기에서 global 1개와 local 3개를 적합한다. 총 2×2×2×4=32개의 저비용 fit이다. pooled에는 세 cell의 모든 실제 학습 행을 넣는다. local보다 행이 세 배 많다는 점은 공유의 성질이며, 동일 학습 행 수 비교로 표시하지 않는다. cell ID는 입력에 없다.

모든 cell·진단 시점의 normalized MAE, cell별 MAE, 앞·뒤 절반의 global−local 차이, raw 단위 MAE를 기록한다. persistence·전날·전주 기준도 같은 target에서 계산한다. 평균 일중 profile을 제거한 잔차의 세 cell 간 PCC, 시간 내 변동의 분산 비율, 시간별 정규화된 최고 10분 값/평균 비율은 기술 통계로 기록한다. PCC는 관계 차이나 공유 손해의 증명이 아니다.

주된 확인은 S+L 조건에서 global−local 오차 차이다. 3개 cell의 평균·개별 결과와 앞뒤 절반을 모두 공개한다. 통계적으로 충분한 반복이라고 주장하거나 사후 성공 임계값을 만들지 않는다.

## 결과에 따른 판단

1. 두 추정기 모두에서 global의 손해가 유지되고 여러 cell·앞뒤 구간에 퍼지면, 10분 조건의 공유 손해를 추가로 확인할 후보 문제로 남긴다. TabICL과 새 clustering의 효용은 아직 확인되지 않은 상태다.
2. global이 비슷하거나 더 좋으면, 이 세 cell에서도 단순 공유의 손해가 확인되지 않았다고 기록한다. 세부 변동을 추가 모듈의 근거로 바꾸지 않는다.
3. 추정기·시간·cell별 방향이 다르면 용량·자료량·시간 변화의 영향을 구분해야 하는 결과로 기록한다. 한 조건만 택하여 성공으로 만들지 않는다.

벽시계 60초, RSS 2 GiB, CPU 최대 4 threads 이내로 제한한다. 초과하면 중지하고 부분 결과를 보존한다. RCTL fit/forward 0, TabICL 호출 0. 기존 누적 비용을 초기화하지 않는다.
