# 시간 해상도에 따른 판단 범위와 원본 접근 확인

2026-09-25. 새 알고리즘 또는 대규모 모델 실험 계획이 아니다. 기존 hourly 결과가 답하지 못하는 범위와, 더 작은 원본 확인이 가능한지를 정리한다.

## 이미 확인한 사실

- 원 UPC·RCTL 논문의 §IV.A는 첫 30일, 10분 간격의 4,320개 관측값, 앞 20일 학습을 명시한다. §IV.A의 hyperparameter 설명에서 q=8을 사용한다.
- UPC Algorithm 1의 초기 peak 그룹은 시간대 H=0..23을 사용한다. UPC의 시간대 요약과 최종 RCTL 입력의 10분 해상도는 서로 다른 단계다.
- 현재 pilot의 q=8은 hourly 집계 관측 8개다. 원 논문의 10분 관측 8개와 같은 시간 범위가 아니다. 예측 target도 다음 1시간 값이다. lag·달력 특징과 평균 척도 정규화도 추가했다.
- STCNet 전처리 공개 코드에는 `groupby([times.hour, 'id']).sum()`이 있다. 1시간 안의 10분별 순서는 집계 후 복원할 수 없다. 예를 들어 [0,0,0,0,0,60]과 [10,10,10,10,10,10]은 모두 합 60이다. 이 예시는 실제 관측 통계가 아닌 정보 손실의 설명이다.

따라서 기존 pilot은 hourly 조건의 후보 검토이며 원 UPC+RCTL 재현이 아니다. 원래 10분 조건에서의 우열을 확정하지 않는다. 반대로 ‘10분이면 좋아질 것’이라고 추정해 기존 실패를 지우지도 않는다.

## 이번 접근 확인의 범위

기존 Harvard Dataverse metadata에서 첫날 파일 id=2674255, 파일명 `sms-call-internet-mi-2013-11-01.txt`, 크기 322,874,887 bytes를 확인했다. 전체 일별 파일이나 새 checkpoint를 받지 않는다.

공개 API에 HTTP Range로 처음·중간·끝 각 최대 16 KiB, 총 세 구간만 요청한다. 응답이 Range를 지원하지 않으면 최대 16 KiB만 읽고 중지한다. redirect에 임시 서명이 있으면 URL 전체를 출력하거나 저장하지 않는다. 모델 호출·학습은 없다. 목적은 제한된 cell·시간 자료를 작은 요청으로 읽는 경로가 있는지 확인하는 것이다.

- 206과 정확한 Content-Range가 확인되면 선택한 byte 구간 접근이 가능하다는 사실만 기록한다.
- 세 구간에서 ID 정렬이 관찰되어도 전체 파일이 완전히 정렬됐다고 확정하지 않는다. 실제 cell 추출에는 경계 및 누락 검사가 필요하다.
- 200 또는 Range 무시이면 전체 파일을 내려받는 방식으로 자동 확대하지 않는다.
- 원자료의 존재만으로 10분 조건의 성능이나 신규성을 확인했다고 하지 않는다.

추가 raw 진단, 새로운 TabICL 호출, RCTL 확인은 아직 실행하지 않는다. 기존 RCTL 29-fit 상한은 그대로다.

## 실행 결과

첫 구간 요청에서 HTTPError가 반환되어 즉시 종료했다. 둘째·셋째 요청은 하지 않았고 원본 내용도 확보하지 못했다. `results/raw_range_probe/summary.json`에 실패를 기록했다. 예외 URL의 임시 서명 노출을 피하려고 유형만 저장했으며, 상태 코드는 남기지 않아 실패 원인을 403·404 등으로 특정할 수 없다. Range 미지원 자체나 자료 비공개를 입증한 결과는 아니다. 큰 파일 다운로드로 전환하지 않았다. 모델 호출은 0이다.
