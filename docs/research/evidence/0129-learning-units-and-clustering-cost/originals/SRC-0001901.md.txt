## 확인할 주장

네트워크 트래픽의 clustering 선행연구에서 보고한 정확도·비용 이득이 현재의 cell별 scalar RCTL pooling을 직접 뒷받침하는지 확인한다. 기존 05의 초록 수준 해석을 방법·실험 단위·용량·K 선택 과정까지 좁힌다. 81·87·93·95의 일반 논의를 반복하는 대신, 직접 네트워크 논문의 원문과 현재 구현을 명시적으로 대응한다.

## 읽기와 고정 계산 범위

1. Cash 등의 2025 `2509.15072`와 2026 `2604.26081` 최신 공개판의 본문, 입력/출력, clustering, GRU 구조, K 선택, runtime, 평가 표를 확인한다. 이미 확보된 원문은 재사용한다.
2. Ma 등의 Validation-Driven Clustering `2604.13748`에서 series-wise pooling과 학습·validation 손실 사용을 확인한다. 현재 RCTL 독립성과 구별한다.
3. 공개 공식 코드 링크가 원문에 있는지 확인하고, 없으면 구현을 재현했다고 쓰지 않는다. PyTorch 공식 GRU 정의를 이용한 용량 산술은 저자 checkpoint 실측과 구분한다.
4. 현재 RCTL의 실제 입력 shape, 학습 row 구성, parameter 수, 보존된 시간 측정 범위를 확인한다. 모델을 다시 호출하지 않는다.
5. 각 cluster가 d_k차원 GRU와 선형 출력층을 사용한다고 명시적으로 가정한 용량식을 도출한다. PyTorch식 bias가 두 개인 한 층 GRU 기준으로 hidden width H=200, sum(d_k)=D일 때 P_K=K(3H²+6H)+(4H+1)D. 실제 head 구현 미확인 시 이 식을 저자 모델의 정확한 파라미터 수라고 쓰지 않는다.
6. 128/1,024/10,000 cell의 scalar RCTL pooling 작업량을 N×학습 sample 수, cluster별 batch의 합, 동일 시각 예측 행 수로 산출한다. 기준 T=672, batch=256, K=1/4/16/32, 가능한 한 균형 크기. 이는 학습 코드의 조건을 확대한 산술값이며 실행시간·정확도 실측이 아니다. Tab의 일회 cell별 M=504/Q=168/R=1, 129개 float32 분위수 저장량도 별도 표시한다. 이 값들은 검토한 B2 설정의 규모 계산이며 새 알고리즘 추천이 아니다.

## 가능한 판단

- 다중 출력 차원 감소와 sample 공유 효과가 섞이면 해당 논문을 RCTL pooling의 직접 성능 근거로 쓰지 않는다. 그렇다고 clustering 전체를 무효화하지 않는다.
- 같은 K이더라도 전체 용량·input/output 단위가 달라질 수 있는지 구별한다. 용량 증가가 관찰된 개선의 유일한 원인이라고 단정하지 않는다.
- 논문이 최종 learner의 validation 손실로 소속/K를 고르면 독립 clustering의 직접 해법으로 채택하지 않는다.
- 현재 문제에서 단순 global/naive grouping보다 나아지는 Tab의 결정이 제시되지 않으면 이 확인만으로 추천안을 확정하지 않는다.
