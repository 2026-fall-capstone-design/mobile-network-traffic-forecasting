TabICLv2 기반 clustering 연구의 근거 검토
교수님 검토용 중간 보고  2026 년 9 월 26 일
현재 확인한 결과는 TabICLv2 를 예측기로 활용할 가능성을 보여 줍니다. 다만 그 예측을 이용해
cell 을 묶는 판단이 기존보다 좋아졌다는 근거는 아직 확보하지 못했습니다. 본 문서는 직접 예측,
clustering 결정, 최종 RCTL 성능을 구분하여 재설계의 출발점을 정리한 중간 검토본입니다.
1 현재 근거가 보여 주는 것
TabICLv2 의 직접 예측에는 긍정적인 결과가 있습니다
Milan 의 기존 4 개 cell 에서 모든 예측기에 같은 28 개 입력 열과 cell 당 context 256 개를
제공했습니다. 최근 이력, 전일·전주 이력, 달력 정보가 포함됩니다. 이후 168 시간의 개발 구간에서
얻은 결과는 다음과 같습니다. 수치는 정규화한 활동량 기준이며, 아래에서는 TabICLv2 의 mean
출력을 사용했습니다. [실행 기록 74]
예측기 MSE MAE
Ridge 0.014360 0.089565
HGB 0.011925 0.078400
TabICLv2 0.009580 0.066828

이 결과는 같은 작은 context 에서 입력과 이후 결과의 관계를 추정하는 데 TabICLv2 가 도움이 될 수
있다는 근거입니다. 이웃 입력 자체의 효과나 RCTL 을 함께 학습할 cell 의 선택 효과를 확인한 결과는
아닙니다.
같은 수의 cluster 를 비교한 RCTL 결과는 다릅니다
별도의 16 개 cell 확인에서는 cluster 4 개, 각 cluster 4 개 cell 로 소속과 설정을 먼저 고정한 뒤
RCTL 을 학습했습니다. 표는 같은 480 시간에서 구한 cell 평균 정규화 MAE 입니다. 두 seed 는 학습의
변동을 살핀 것이며, 두 독립 데이터셋을 뜻하지 않습니다. [실행 기록 07]
소속 결정 방법 seed 20260925 seed 20260926
실제 관측값 기반 risk 0.081600 0.083516
TabICLv2 기반 risk 0.087328 0.087760

TabICLv2 군집안의 오차가 각각 7.02%, 5.08% 컸습니다. 따라서 이 군집안은 채택하지 않습니다. 두
표는 cell, 입력, 기간과 지표가 다르므로 표 사이의 숫자를 직접 비교해서도 안 됩니다.

2 좋은 예측이 좋은 clustering 을 뜻하지 않는 이유
TabICLv2 가 답해야 하는 첫 질문은 “이 입력 다음에 얼마가 관측되는가”입니다. clustering 이 답해야
하는 질문은 “어떤 cell 의 자료를 한 RCTL 이 함께 학습할 때 유리한가”입니다. 두 번째 질문에는 예측
관계의 차이 외에도 자료의 양, 입력으로 cell 을 구별할 수 있는 정도, RCTL 의 용량과 학습 방식이
영향을 줍니다.
예를 들어 A 와 B 의 이후 값이 다르더라도 요일과 최근 이력이 두 cell 의 상황을 구별해 준다면,
하나의 모델이 서로 다른 결과를 함께 학습할 수 있습니다. 반대로 예측 관계가 비슷해도 이미 충분한
자료가 있거나 두 cell 의 자료가 중복되면 합치는 이득이 작을 수 있습니다. 예측값 사이의 거리를
좁히는 것만으로 이 문제를 해결할 수는 없습니다.
실제 소속이 바뀌었는지를 별도로 확인했습니다
16 개 cell 의 후속 확인에서는 관측 입력과 TabICLv2 의 예측 평균을 함께 비교하여 군집을
구성했습니다. TabICLv2 의 직접 예측 오차는 Ridge 와 HGB 보다 작았지만, 입력만 이용한 방법, 실제
입력과 정답을 이용한 방법, TabICLv2·Ridge·HGB 를 이용한 방법이 모두 같은 소속을 선택했습니다.
이 설정에서는 더 좋은 예측이 새로운 clustering 결정으로 이어지지 않았습니다. [실행 기록 80]
가장 가까운 선행연구와의 연결
HCP 2025 는 분리 모델과 합친 모델을 실제 학습하고, 확인용 자료의 손실을 비교하여 병합합니다.
현재 연구처럼 최종 RCTL 을 clustering 에서 호출하지 않으면 그 비용은 줄일 수 있지만, HCP 가 직접
관측한 공동 학습의 효과를 다른 점수가 대신해야 합니다. 이 연결을 생략한 채 “HCP 를 더 빠르게
구현했다”고 설명할 수는 없습니다. [1]
RMB-CLE 는 task 별 모델의 교차 예측 오차로 유사도를 만들고, clustering 뒤에 별도의 최종 예측기를
학습합니다. 따라서 “예측 관계로 묶고 다른 모델로 예측한다”는 구조 자체는 선행연구에 있습니다.
TabICLv2 로 모델 이름을 바꾸는 것 외에, 어떤 잘못된 병합을 줄이거나 어떤 계산을 절감하는지
제시해야 합니다. [2]
ETAP 은 task 간 gradient 유사도와 실제 공동 학습 이득의 차이를 보정합니다. 대리 점수와 최종
성능의 차이가 이미 연구되는 문제라는 뜻입니다. 다만 최종 학습기의 정보를 사용하는 방식을
그대로 가져오면 현재 연구의 RCTL 독립 조건과 맞지 않습니다. [3]
네트워크 traffic matrix 를 다룬 clustering 연구는 무작위 분할과 global 예측도 비교합니다. 이를
반영해 현재 검토에도 같은 cluster 수의 무작위 분할과 global RCTL 을 넣었습니다. 의미 있어 보이는
군집이 강한 단순 대안보다 나은지는 별도로 확인해야 합니다. [4]

3 시간 흐름과 실행 비용에서 유지할 설계
하루와 주간의 흐름을 sample 안에 명시합니다
현재 예측 시점에서 관측된 최근 이력에 전일·전주 같은 시간의 이력, 시각과 요일을 함께 제공합니다.
다른 시간대에서 짧은 증가 모양만 비슷한 sample 을 모으면 주기적 상황을 놓칠 수 있기 때문입니다.
이 입력 정보는 TabICLv2 와 모든 비교 방법에 동일하게 주어야 합니다. 시간·lag 특징의 중요성은
TabPFN-ST-AR 를 참고하되, 도로 속도의 결과를 통신 활동량의 성능으로 옮기지는 않습니다. [5]
한 sample 은 해당 시점까지의 입력과 이후 실제 관측값으로 구성합니다. context 에는 두 항목을
함께 주고, query 의 실제값은 오차 계산에만 씁니다. query 의 예측 시점에 이미 관측된 이력이
context 의 과거 정답과 겹치는 것만으로 누출은 아닙니다. 미래 정답이 들어가는 누출과 가까운 시간
sample 의 의존성을 구분하며, 의존성을 살피기 위한 간격은 입력 길이와 평가 목적에 맞춰 정합니다.
후보 수는 비싼 검사 전에 제한해야 합니다
전체 cell 쌍을 TabICLv2 로 검사한 다음 좋은 후보만 남기면 최초 계산량은 줄지 않습니다. 먼저
저렴한 입력 요약으로 cell 당 후보를 제한하고, 그 후보에만 추론을 적용해야 합니다. 아래는 cell 당
context 256 개, query 64 개, 방향별 후보 최대 16 개를 가정한 작업량입니다. 설정의 최적성이나
실제 실행 시간을 뜻하지 않습니다.
cell 수 전체 교차 query 방향별 후보 제한 후보를 양방향 검사
128 1,040,384 131,072 262,144
1,024 67,043,328 1,048,576 2,097,152
10,000 6,399,360,000 10,240,000 20,480,000

단위는 예측할 query 행 수입니다. 자기 context 로 자기 query 를 평가하는 N×64 행은 별도입니다. 양방향 열은
중복을 제거한 후보 쌍마다 양쪽을 검사할 때의 상한입니다.
전체 교차 검사는 N×(N−1)×64 행, 방향별 후보 검사는 최대 N×16×64 행입니다. 후보를 무방향
쌍으로 만든 뒤 양방향으로 검사하면 최대 2×N×16×64 행이 됩니다. 한쪽에서 선택한 후보가
반대쪽에서도 선택되었다고 가정해 후보 수를 임의로 절반으로 줄이면 안 됩니다.
cell 별 context 를 고정한 교차 예측은 준비 결과를 재사용할 수 있습니다. 반면 sample 교체나 cluster
병합으로 context 내용이 바뀌면 새 준비 비용이 생깁니다. 이를 포함하지 않은 호출 수는 전체
비용이 아닙니다. 후보 제한으로 놓친 유용한 조합도 작은 전체 탐색과 비교해야 합니다. 이 절은
재설계의 공통 요건이며, 신규성이 확인된 최종 알고리즘은 아닙니다.

4 아직 필요한 결정과 근거
현재 자료에서는 하나의 global RCTL 도 강한 기준선이었습니다. 첫 seed 의 MAE 는 0.071068 로,
확인한 4 개 cluster 방법보다 작았습니다. 이는 모든 데이터에서 global 모델이 낫다는 결론이
아닙니다. 다만 cluster 를 나눠야 하는 이유를 먼저 구체화해야 한다는 결과입니다. 모델 수가 다른 이
비교는 같은 K 의 주 비교와 구분합니다. [실행 기록 07]
판단 항목 현재 확보한 근거 남은 핵심
TabICLv2 실행 가능성 공식 회귀 가중치로 실제 추론 도시 전체 규모의 비용
직접 예측의 이점 4 개·16 개 cell 의 국소적 이득 새 기간과 데이터의 재현성
clustering 의 필요성 global 및 같은 K 대안 비교 단순 대안이 남기는 실제 손해
TabICLv2 가 바꾸는 결정 일부 후보는 소속이 변하지 않음 다른 유용한 결정을 만드는 근거
RCTL 성능과의 연결 고정 군집안 사후 학습 완료 Tab 군집안의 이득은 미확보
신규성과 최종 추천 근접 방법과 중복 원리 확인 채택할 새 방향은 미확정

다음 설계를 바꾸는 정보
데이터 분리, 모델당 메모리·지연 한도, cell 별 갱신 주기처럼 global 모델을 쓰기 어려운 실제 조건이
있다면, clustering 의 목표를 그 조건 아래의 비용과 정확도로 정의할 수 있습니다. 아직 해당 조건은
제공되지 않았습니다. 연구를 성립시키기 위해 임의의 운영 제약을 가정하지 않습니다.
그러한 제약을 전제로 하지 않는다면, 계절·lag·정규화와 global 학습을 적용한 뒤에도 남는 손해를
새로운 직접 근거에서 찾아야 합니다. 기존 개발 구간의 유리한 cell 만 골라내거나 이미 탈락한
점수에 보정항을 붙이는 방식은 다음 후보의 근거가 되지 않습니다.
남은 실행 범위
누적 예산에서 TabICLv2 는 context 11 개와 query 20,640 행이 남아 있고, 추가 RCTL 학습은
허용되지 않습니다. 이번 정리에서는 모델을 새로 실행하지 않았습니다. 따라서 새 규칙을
제안하더라도 RCTL 성능 확인을 완료했다고 표시할 수 없습니다. 먼저 저장된 근거와 원문으로
판단할 수 있는 결정을 특정해야 합니다.
현재까지 사용한 Milan 기간은 후속 설계에 참조되었으므로 개발 자료입니다. 최종 추천 방향과
독립적인 최종 평가의 요건은 남아 있습니다. 본 문서는 그 요건을 충족했다고 주장하는
연구계획서가 아니라, 확인된 사실과 미해결 연결을 교수님께 검토받기 위한 자료입니다.
