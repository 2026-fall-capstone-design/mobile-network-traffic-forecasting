# 추가 확인을 허용할 경우의 범위 제안

2026-09-26. **아직 허용되지 않은 제안이며 기존 누적 원장을 변경하지 않았다.** 현재 추천 후보가 확정된 상태도 아니다. 아래 상한 변경은 긍정적인 연구 결과를 보장하지 않는다.

## 확인이 필요한 이유

목표 문서9절은 후보를 바꾸어도 누적 실행 상한을 초기화하지 않도록 요구한다. 고정된 RCTL29회는 실제로 모두 실행했다. 현재 결과에는 채택 가능한 새로운 clustering의 RCTL 개선 근거가 없다. 이후 새 partition을 실제 RCTL로 확인하려면 실행 범위를 변경해야 한다.

문헌·코드·기호 분석을 통한 대체 확인도 진행했지만 현재 유한 RCTL의 학습 효과를 대신하는 직접 근거는 확보하지 못했다. 추가 학습을 허용하더라도 알고리즘이 구체화되지 않은 상태에서 여러 구조를 돌려보지 않는다.

## 조건부로 추가할 최대 작업

- 기존 cell의 연속 traffic, clustering 이후 RCTL, clustering에서 RCTL 호출 금지 조건을 유지한다.
- 문헌과 실제 자료의 진단을 통과하고 알고리즘을 고정한 **새 후보 한 개**만 대상으로 한다. 후보·입력·정규화·시간 경계·실제 K·비교 방법·seed·중단 조건을 별도 실행 계획에 먼저 저장한다.
- 현재의 K4 비교를 사용한다면 후보4개 모델, 강한 단순 비교4개, Global1개로 seed당 최대9fit이다. 첫 seed의 결과가 핵심 가정을 지지하지 않으면 추가 seed를 자동 실행하지 않는다. 반복이 필요할 때 두 번째 seed까지 **총18fit**을 상한으로 한다. 이는 통계적 충분성의 보장이 아닌 계산 한도다.
- 새 fit은 기존29회에 누적하여 합계 최대47회다. 추가 epoch는 fit당80회 이하, 총1,440회 이하다. 추가 RCTL wall time은 최대1,800초, CPU만 사용하며 유료 연산은 하지 않는다. 넘긴 작업을 자동 재시작하지 않는다.
- TabICLv2의 기존 잔여2context/4,512query행은 그대로 유지한다. 이 범위로 필요한 비교를 구성하지 못하면 그 비교는 별도 범위 변경 없이 실행하지 않는다.
- 기존 결과를 본 기간은 계속 개발 자료로 표시한다. 독립 미래 검증으로 이름을 바꾸지 않는다. 이미 본 결과에 유리하도록 cell·시간대·목적 지표를 고르지 않는다.
- RCTL 결과가 나온 뒤 소속·threshold를 바꾸어 재시도하지 않는다. 추가 실험의 실패도 그대로 기록하며 성공할 때까지 한도를 반복 늘리지 않는다.

## 허용하더라도 남는 선행 작업

새 후보가 해결할 실제 손해, 가장 가까운 선행 방법과의 차이, TabICLv2가 바꿀 결정, 동일 정보·비용 비교를 먼저 확정해야 한다. 현재 문서는 그 후보를 대신하지 않는다. 이번 요청은 다음 최소 확인을 준비할 수 있는 범위에 대한 것이며, 지금18fit을 실행하겠다는 계획이 아니다.

기존 상한을 유지한다면 새 RCTL 학습은 실행할 수 없다. 현재의 부정적 결과를 성공으로 바꾸거나, 단순 모델 결과를 RCTL 확인으로 대체하여 목표를 완료하지 않는다.
