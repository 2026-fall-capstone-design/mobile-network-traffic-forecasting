## 3 TabICLv2가 맡는 역할

회귀용 TabICLv2는 입력과 실제 정답이 짝지어진 표의 여러 행을 context로 참고하여 새로운 입력을 예측하는 사전학습 Transformer입니다. 열 정보, 한 행의 특징, context와 query 사이의 관계를 처리하며, target-aware embedding과 repeated feature grouping을 포함합니다. 현재 연구에서는 공식 회귀 checkpoint의 가중치를 고정하고 **cell별 조건부 분위수**를 구하는 데 사용합니다. 사전학습을 다시 하거나 cell마다 신경망을 최적화하지 않습니다. 다만 context 준비·전처리·추론 비용은 발생합니다. [TabICLv2 v2](https://arxiv.org/html/2602.11139v2), [공식 구현](https://github.com/soda-inria/tabicl)

한 sample은 ‘현재까지 관측한 입력 → 다음 시점 실제 트래픽’입니다. 한 cell의 앞 구간 sample 전체로 context를 만들고 뒤 구간의 같은 query를 여러 이웃 cell의 조건부분포로 평가합니다. 네트워크의 고정 가중치는 같아도 context가 다르면 예측 분포가 달라집니다. 이 분포 차이를 실제 관측값과 대조합니다. attention이나 내부 표현 자체를 cell 유사도나 RCTL의 학습 효과로 해석하지 않습니다.

현재 구현은 native 999개 분위수 중 API로 0.1부터 0.9까지 9수준을 요청합니다. MAE와 맞추기 위해 중앙값 주변의 관계를 다룹니다. 분포를 사용하는 이유는 점예측 하나만으로는 같은 기준값 주변에서 두 cell의 결과가 어느 쪽으로 치우치는지와 그 밀도를 구할 수 없기 때문입니다. 공식 분포의 모든 기능을 사용한 구현은 아니며, 아래의 9점 선형 보간과 꼬리 제한은 이 연구에서 고정한 근사입니다.

HGB 분위수 회귀와 회귀용 TabPFN도 같은 역할을 할 수 있습니다. TabICLv2를 선택한 이유는 공개 회귀 가중치, 고정된 context로 조건부분포를 여러 이웃에 재사용할 수 있는 구현, 그리고 현재 같은 정보 HGB와 실제로 다른 유용한 소속을 만든 관측입니다. TabPFN은 이번 비교에서 실행하지 않았으므로 TabICLv2만 가능하거나 더 빠르다고 주장하지 않습니다. 최종 예측기는 계속 RCTL입니다.

### 4.2 하루 흐름으로 비교할 이웃을 먼저 제한합니다

앞 504개 target을 시각별로 평균한 24차원 하루 profile을 만들고 L2 정규화합니다. cKDTree로 cell마다 가까운 8개 cell을 찾습니다. 동점은 cell 번호순으로 정하고 양방향 검색의 합집합을 무방향 이웃 목록으로 만듭니다. 실제로 79개 pair가 남았습니다. 모든 pair에 Tab을 먼저 실행한 뒤 일부를 버리는 방식이 아닙니다.

각 pair의 앞 구간 입력만으로 작은 HGB 분류기를 학습하여, 입력이 주어졌을 때 어느 cell에서 나온 sample인지에 대한 확률 p를 구합니다. p가 0.1–0.9이고, query의 각 절반에서 각 cell에 8개 이상·2개 날짜 이상의 입력이 있어야 비교를 진행합니다. 입력 겹침이 부족한 pair는 관계가 같다고 처리하지 않고 미판정으로 남깁니다. 이웃 검색과 p 추정은 TabICLv2의 역할이 아닙니다.

### 4.3 각 cell의 조건부분포를 준비하고 재사용합니다

지원 pair에 등장하는 cell별로 자기 504개 sample을 context로 준비합니다. 해당 cell과 이웃의 query에서 9개 분위수를 얻습니다. 동일한 예측을 여러 pair 계산이 재사용하므로 소속 이동마다 context를 다시 준비하지 않습니다. HGB도 같은 sample·16열·9수준을 사용합니다. 현재 실행에서는 14개 cell의 분포와 3,712개 고유 query 예측 행을 확보했습니다.

**완료된 비교의 실제 지원 규칙:** 입력 조건에 더해 Tab과 HGB에서 모두 분위수 보간·밀도 계산이 가능한 query와 pair의 교집합을 사용했습니다. 최종 비교 pair는 22개입니다. 따라서 HGB는 현재 실험에서 외부 비교기인 동시에 공통 평가 가능 범위를 정하는 데 관여합니다. 그 분포 준비 비용을 전체 비용에서 빼지 않습니다. Tab만으로 지원 범위를 정하는 독립 운용 버전은 이번에 검증하지 않았으며, 문서에서 이미 실행한 방식으로 바꾸어 쓰지 않습니다.

### 4.4 실제 정답과 대조하여 관계 충돌 점수를 만듭니다

직관적으로는, 같은 최근 입력·시간 조건에서 두 cell의 예측 관계가 다르다고 추정될 때 실제 다음 값도 그 방향 차이를 뒷받침하는지 확인합니다. 두 분포 사이의 공통 중앙 기준 q를 구하고, 실제값이 q보다 위인지 아래인지 이용합니다. 입력 분포와 q 주변 밀도에 따른 출처 비중을 보정하고, 앞 구간에서 정한 방향으로 부호를 맞춥니다. 서로 다른 입력에서 차이의 방향이 뒤집혀 단순 평균에서 상쇄되는 것을 줄이려는 계산입니다.

정확한 구현식은 다음과 같습니다. 출처를 D=1 또는 0으로 표시하고, cell별 조건부 누적확률과 밀도를 F1·F0, f1·f0로 둡니다.

`pF1(q)+(1−p)F0(q)=0.5`

`a=pf1(q)/{pf1(q)+(1−p)f0(q)}`, `w=sign(F0(q)−F1(q))`

`S=w(D−a){0.5−1[Y≤q]}`

q·a·w는 앞 구간으로 추정한 모델과 query 입력에서 정합니다. query 정답 Y가 들어가는 곳은 마지막 위·아래 비교뿐입니다. S는 −0.5와 0.5 사이입니다. 각 시간 절반에서 cell별 S 평균을 먼저 구하고 양 cell 평균에 같은 비중을 준 뒤 양의 부분을 pair 비용으로 사용합니다. 정답이 큰 sample 하나의 절대 오차를 그대로 pair 손해로 삼는 방식과 다릅니다.

CDF는 정렬한 9개 분위수 사이에서 선형 보간합니다. 양 꼬리는 0.1·0.9로 제한하고 바깥 밀도는 0으로 둡니다. 겹친 knot, 비유한 값, 0인 혼합 밀도는 미판정입니다. knot 최소 간격은 `1e−10×max(1,최대 분위수 절댓값)`, root 잔차 허용치는 `1e−7`이며 계산은 float64입니다. 현재 구현은 smoothing이나 값 벌리기를 하지 않습니다.

이 점수는 미래 MAE 개선량이나 유의성 검정 통계가 아닙니다. 작은 값이 관계 동일성 또는 안전한 병합을 인증하지도 않습니다. 연속 밀도·올바른 p와 기준값 아래의 일차 민감도 소거는 기존 분위수 추정 이론과 연결되지만, 실제 시간 변화와 유한 추정 오류를 제거하는 보장은 아닙니다. 지원 구간 선택 뒤 cell별 평균을 다시 같은 비중으로 합치므로, 앞 구간에서 학습한 p가 평가 분포의 출처확률과 같다는 보장도 없습니다. 이론적 이상식과 현재의 실용적 점수를 구별합니다. [Belloni 등 v4](https://arxiv.org/abs/1312.7186v4), [Kallus와 Oprescu](https://proceedings.mlr.press/v206/kallus23a.html)

### 4.5 UPC 소속을 제한적으로 수정합니다

UPC의 초기 K=4 소속에서 시작합니다. 각 시간 절반의 목적값은 같은 cluster 안에 있는 유효 pair 비용의 합입니다. cell 번호순으로 최대 세 번 순회합니다. 출발 cluster가 비지 않고, 목적지에 유효 이웃이 두 개 이상이며, 이동으로 두 절반의 목적값이 각각 `1e−12`보다 크게 줄 때만 이동합니다. 여러 목적지가 가능하면 두 절반의 감소량 평균이 가장 큰 곳을 선택하고 동점은 cluster 번호순으로 정합니다. 이동 후에는 관련 합만 갱신합니다. 이동 없는 순회 또는 세 번째 순회에서 종료합니다.

Tab 점수는 3745·6153·3765를 group 3으로 옮겼고, HGB 점수는 3745만 옮겼습니다. 이동 전후 K=4입니다. 최종 Tab 구성은 group 0 `[3753,5337,6165]`, group 1 `[5345]`, group 2 `[4537,4545,4565,5353,5365,6137,6145]`, group 3 `[3737,3745,3765,4553,6153]`입니다. 이 소속은 RCTL 결과 파일을 읽기 전에 저장·봉인했습니다.

목표는 확인된 충돌을 줄이는 것이므로 graph 밖의 pair를 검사했다고 주장하지 않습니다. 비용 합은 group 크기·연결 수에 영향을 받고 singleton도 허용합니다. 따라서 단순히 목적값이 줄었다는 이유로 좋은 clustering이라고 결론내리지 않고, 고정 소속의 RCTL과 강한 대안을 실제로 비교했습니다.

### 4.6 기존 RCTL에 전체 실제 자료를 전달합니다

cluster별로 원 RCTL의 TCN·LSTM·이중 잔차 구조를 유지합니다. 현재 재현 구현은 8×9 입력, MAE, Adam(lr=0.001, eps=1e−7), batch 256, 최대 80epoch, validation patience 10, seed 20260925입니다. Tab의 16열 입력은 소속 판단용이며 RCTL 입력을 그대로 대체하지 않습니다. Tab 분위수나 일부 context로 RCTL 정답·학습 자료를 바꾸지 않습니다. RCTL의 손실·예측·가중치는 clustering에 되돌려 주지 않습니다.

네트워크·시계열·표 기반 모델 연구는 다음과 같이 실제 설계에 반영했습니다.

- **TabPFN-ST-AR [8]:** 도로 교통의 최근 lag·시간·공간 특징을 표에 명시한 연구입니다. ‘traffic’이라는 이름만으로 통신 트래픽과 같은 문제로 취급하지 않습니다. 현재 16열에 최근·일·주 이력과 달력을 넣은 근거로 활용하고, 공간 입력은 원 RCTL 구조에서 별도로 유지합니다.
- **TabPFN-TS [9]:** 표 기반 모델로 시계열을 구성할 수 있음을 보여주지만 해당 비자기회귀 구성은 미래 lag 부재 때문에 lag를 넣지 않는 설계입니다. 이를 lag 입력의 직접 근거로 인용하지 않습니다. 관측 범위를 넘는 추세 외삽의 약점은 현재의 ‘관측 입력이 겹치는 범위만 비교’와 미판정 처리에 연결합니다. 이것이 TabICLv2의 동일 한계를 증명한 것은 아닙니다.
- **ISP 트래픽 foundation model 연구 [10]와 MobiGPT [11]:** 집계 수준, 간헐성, 도시 간 전이가 결과를 바꾼다는 점을 반영합니다. 현재 cell 결과를 개별 IP·새 도시로 일반화하지 않습니다. 최종 예측기가 RCTL인 지금은 이 모델들로 바꾸는 것이 소속 규칙 검증을 대신하지 못합니다.
- **5G CoT·ICL 연구 [12]와 다변량 표 기반 예측 [13]:** throughput·RSRP·handover 같은 실제 공변량과 채널 구성의 중요성을 참고합니다. Milan에 없는 공변량을 가정하지 않으며, 여러 cell의 행을 섞는 것만으로 공간 관계가 입력됐다고 쓰지 않습니다.
- **Traffic matrix clustering 연구 [14]와 TIDES [15]:** 시계열 clustering 후 별도 예측기를 쓰는 구조 자체는 기존 연구에 있습니다. random·global·profile 기준과 같은 K를 비교해야 소속 효과와 모델 수 효과를 분리할 수 있습니다. 현재 제안의 신규성을 clustering→RCTL이라는 순서에 두지 않습니다.
- **TabICLv2와 context 선택 계열 [2·3]:** 공식 forecasting 기능과 기존 국소 context 연구를 고려하여 ‘처음 시계열에 적용’이나 ‘context를 바꾸는 것’만으로 신규성을 주장하지 않습니다. 고정된 자기 context에서 추정한 관계가 실제 소속 결정을 바꾸는 역할로 좁힙니다.

## 7 전체 비용과 규모 제한

| 실제 작업 | 새 실행과 재사용 | 실패를 포함한 실측 |
|---|---|---:|
| 635–638 후보 검색·지원·두 추정기·score·소속 | 14개 cell의 완성 분포. Tab 준비 15회 시도, query 3,840행 시도 중 고유 완료 3,712행. HGB 분위수 126fit, 출처 분류 80회 시도 중 79개 완성 | 197.086초 |

| 641 저장 예측의 두 결정 대조 | 새 모델·forward 0, 기존 RCTL 정확한 소속 연결 | 0.330초 |

197.086초는 두 추정기의 공통 지원을 준비한 전체 실행이며 Tab 단독 배포 시간도, 모든 방법의 처음부터 공정한 총시간도 아닙니다. 검색·HGB·저장 등의 일부 시간은 합산되어 있어 각 부분의 독립 실측으로 나누지 않습니다. 635 저장 실패, 636 중단·부분 결과와 그 비용을 포함합니다. 원래 RCTL 전체 비교의 과거 학습비는 누적 원장에 보존되어 있으므로 이번에 새로 쓴 158.336초만으로 전체 연구 비용을 설명하지 않습니다.

N개의 cell에서 각 k개 이웃을 검색하면 무방향 pair E는 Nk 이하입니다. 각 cell의 context 준비는 최대 N회, cell당 Q개 query일 때 분포 예측 행 상한은 Q(N+2E), graph 저장은 O(E), 9분위수 저장은 O(9Q(N+2E)), 고정 세 번의 이동 계산은 O(3KE)로 정리할 수 있습니다. 이 외에 E개의 출처 분류, 입력 검색, 모델 준비 비용이 있습니다. KDTree의 최악 비용이 항상 NlogN이라는 보장은 없으며 16개 cell의 측정으로 1만 개 cell의 실행 시간을 추정하지 않습니다.

최신 누적 원장에는 Tab context 466회·query 260,842행·2,427.164초, RCTL optimizer 173fit·9,249epoch·12,707.395초, 통계 적응 9회가 기록되어 있습니다. frozen inference 26.946초, frozen gradient 21.961초와 기존 cheap 수치 작업도 별도 보존합니다. 보고서 작성·렌더링은 새 traffic 모델 실험이 아니며 이 원장을 초기화하거나 다시 충전하지 않습니다. 전체 원장과 값의 기준 hash는 근거 등록부에 보관합니다.
