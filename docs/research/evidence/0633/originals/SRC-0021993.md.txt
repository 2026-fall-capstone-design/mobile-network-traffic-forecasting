# 633. 같은 전체 자료에서 공동 예측기가 바꾸는 소속 선택

문제 ID: `membership_gain_beyond_refreshed_simple_assignment`.

## 확인할 질문과 달라질 판단

**동일한 실제 학습 행, query, 고정 소속 후보를 사용할 때 TabICLv2와 HGB는 어느 소속을 선택하는가?** 632의 강한 HGB 결과는 group당504개 reference의 일회 배정과 cell당504개 전체 자료의 공동 평가·갱신을 비교한 결과이기도 합니다. 자료 및 평가 방식의 차이를 Tab 추정 자체의 열세로 확정하지 않습니다. 이를 sample 수만의 인과 설명으로 바꾸지도 않습니다.

이번에는 새 후보를 발굴하지 않습니다. 이전부터 정해진 세 소속의 공동 예측 위험을 **같은 전체 자료**로 평가하는 한정 대조입니다. 이로써 Tab이 추가하는 선택 정보가 있는지, 강한 단순 대안과 같은 선택에 도달하는지 구별합니다. 결과가 달라도 신규성이나 최종 RCTL 우위를 자동 채택하지 않습니다.

## 고정 자료와 소속

1. 616의 두16cell cohort, K4, 최근8값·하루/주 lag·최근통계·시각/요일의16열을 유지합니다. 행 순서는 cell ID 순, cell 내부 시간순으로 고정합니다.
2. 각 cell의 학습 target168–671의504개를 전부 사용합니다. 전체 group context는 `504 × 소속 cell 수`개입니다. cell별 정규화는 첫672시간 평균을 그대로 사용합니다. context를 줄이거나 다른 주를 선별하지 않습니다.
3. query는 562/567/616의 target672–839 중 기존64시각/cell을 그대로 사용합니다. 정답은 context·query 전처리에 제공하지 않고 예측 봉인 후 오차에만 사용합니다. 입력과 정답의 실제 배열·행 ID·hash를 HGB 실행 자료와 일치시킵니다.
4. 각 cohort의 후보는 **UPC, 579의 Tab 소속, 631의 수락 HGB 소속** 세 개뿐입니다. A의 HGB 소속은 변경되지 않았고 B는 갱신된 소속입니다. 현재 RCTL 오차를 기준으로 어떤 cohort·소속을 포함할지 다시 정하지 않습니다. 이 세 역할을 두 cohort에 동일하게 적용합니다.
5. cell ID·순서·소속·예측기간·최소 비교 규칙은 실행 전에 JSON과 hash로 봉인합니다. 같은 group은 한 번만 평가합니다.

## 예측과 선택 규칙

회귀 TabICLv2는 562/567에서 검수한 동일 checkpoint와 source, `n_estimators=1`, `batch_size=1`, `kv_cache=True`, `output_type='median'`, 기존 seed 및 변환 설정을 재사용합니다. **신경망 학습·fine-tuning은 없습니다.** context만 해당 group의 전체 실제 자료로 바꿉니다. query batch는 기존512행 이하이며 query 간 예측 의존성이 없는 동일 설정을 유지합니다.

각 group은 소속 cell의 고정 query만 예측합니다. cell별 MAE를 구한 뒤 16cell에 같은 비중을 주어 각 소속의 공동 MAE를 계산합니다. Tab과 HGB 각각에서 전체64query MAE가 가장 작은 소속을 선택합니다. 동점은 UPC→HGB→Tab 순으로 고정합니다. 앞32·뒤32는 안정성 설명에 함께 보존하며, 그것을 보고 전체 선택을 바꾸지 않습니다.

HGB는 616·631의 **동일 구성원·전체 학습 행·query·설정**의 저장 예측을 재사용합니다. 기존 HGB 모델을 다시 적합하지 않습니다. 설정이나 배열이 일치하지 않으면 실행 전 계약 누락으로 기록하고 자동으로 다른 자료의 결과를 채우지 않습니다. 작은context의 기존 Tab 출력도 전체context 출력으로 잘못 재사용하지 않습니다.

예측과 native 선택을 봉인한 뒤에만 581·621·632의 같은 소속 RCTL 결과를 연결합니다. 이미 평가한 개발 자료라는 사실을 유지하며 새 독립 검증으로 세지 않습니다. 같은 소속의 RCTL을 다시 학습하지 않습니다. 이 과정이 기존 RCTL 수치를 선택 손실로 사용하는 구현이 되지 않도록 worker 입력에서 RCTL 결과 경로를 제외합니다.

## 가장 가까운 연구와 이전 확인의 재사용

실제 group 자료로 적합하고 확인 오차로 선택하는 목적은 267/622의 예측 기반 clustering과 같은 알려진 원리입니다. Tab으로 추정기를 바꾼 것만을 신규성으로 제시하지 않습니다. 384/472의 표현·손실 벡터 재명명, 629의 일반 효용 회귀나 모수 병합을 후속 해법으로 붙이지 않습니다.

616은 같은 고정 메뉴에 대한 **HGB** 공동 평가를 완료했습니다. 이번의 누락은 그 자료와 정확히 일치하는 **Tab** 공동 출력입니다. 464는 다른32cell·80열·기간 구성의 HGB 비교, 495/497은 다른 고정 교환의 전체context 완성입니다. 이 결과를 현재 두16cell·16열·세 소속의 완료 출력으로 취급하지 않되, 같은 수나 전체context가 항상 좋은 선택을 보장하지 않는 근거로 보존합니다.

현재 질문을 위해 필요한 새 문헌 검색은 없습니다. 원문 전체 재검토나 모든 오차 원인 규명, 성능 개선의 사전 증명을 실행 조건으로 요구하지 않습니다.

## 최소 실행과 전체 비용

소속 metadata 대조에서 A의 고유group은12개, B는10개이며 총22개입니다. group에 포함된 cell의 중복을 group 간에 합하면94회입니다. 따라서 상한은 **22context, 47,376context행, 6,016query행**, 가장 큰 한context는12cell의6,048행입니다. 전체cell쌍을 계산하지 않습니다. 후보 생성은 세 완료 소속의 읽기와 고유group 제거이며, 새 후보 검색 비용이 숨겨져 있지 않습니다.

실행 준비에서 기존 전체context/체크포인트/프로토콜의 정확한 cache를 다시 대조하여 중복을 줄일 수는 있지만 수를 늘리지는 않습니다. 준비·모델 load·context 처리·추론·저장·검수 비용을 모두 남깁니다. Tab300초, 기타30초, 최대4CPU, RSS4GiB를 계획 상한으로 둡니다. 562의504행/4context/3,584query 약6.65초보다 큰 context이며, 495/497의2,688context·1,344query/80열 실행도 참고한 여유 상한입니다. 실제 속도·메모리 충족은 보장하지 않습니다. 원장 확인과 필요한 최소 증액·예약 후에만 모델을 실행합니다.

예상 추가 HGB 적합0, RCTL0, optimizer0입니다. source·checkpoint·전체sample행·query행·소속hash, 동일group 재사용, 독립 scalar/vector MAE·선택·정산을 검수합니다. 이미 완료된 group을 중단 복구 때 다시 추론하지 않습니다. 시간·메모리 한계로 중단하면 완료출력과 실제 비용을 먼저 보존하고, 성능 기각과 구분합니다. 결과를 얻으려고 context·cell·기간을 임의로 줄이지 않습니다.

## 결과별 결정과 종료

- **두 추정기가 같은 소속을 선택:** 현재 세 메뉴에서 Tab의 추가 선택 정보는 확인되지 않은 것으로 이 대조를 닫습니다. 점수 차이를 새로운 선택 정보라고 부르지 않습니다.
- **선택이 다름:** 각 추정기가 어떤 전체 공유 오차 차이로 선택을 바꿨는지 기록하고, 봉인 후 기존 RCTL 결과를 연결합니다. 유용한 차이가 남으면 그 판단을 유지하는 구체적 소속 규칙을 후속 설계 대상으로 삼습니다. 단순 Tab 치환의 신규성이 확보됐다는 뜻은 아닙니다.
- **native 선택 차이와 고정 RCTL 효용이 맞지 않거나 혼재:** 현재 한정 연결을 그대로 기록하고 끝냅니다. 신규 seed·소속·기간·추정기 혼합·보정·fine-tuning으로 자동 구제하지 않습니다.
- **구현/자원 실패:** 부분출력·실패 비용·미확인 범위를 보존합니다. 실제 조건이 달라진 복구 근거 없이 같은 실행을 반복하지 않습니다.

이 한 대조가 끝나면 새 근거에 따라 Tab의 남은 소속 결정 역할을 판단합니다. 모든 후보·문헌을 처음부터 조사하거나 같은 비교의 이름만 바꿔 이어가지 않습니다. 최종 RCTL에는 확정cluster의 전체 실제 학습 자료를 전달하는 계약을 유지합니다.
