# 85 기각 범위와 고정 처리량 sample 배분의 재검토

2026-09-26. 85계획에 따라 기존 결과와 원문을 읽고 기호적으로 확인했다. 새 모델 학습·추론·수치 pilot은 0회다. 이번 판단은 기존 기각 사유의 범위를 바로잡는 것이며, 최종 추천 후보를 확정한 결과가 아니다.

## 1. 유지할 결과와 넓혀 말하면 안 되는 결과

35의 train–validation 차이는 일반화 손해와 일치하는 관찰이다. 자료 기간, sample 수, 최적화와 early stopping 조건도 영향을 주므로 원인을 과적합 하나로 확정하지 않는다. 작은 실험의 한계를 인정하는 것과 기각한 안을 다시 추천하는 것은 다르다.

## 2. 비용 판단의 수정

고정된 cell 소속과 cluster별 RCTL을 유지하면서, 한 epoch에 처리하는 실제 sample의 총수를 N으로 고정할 수 있다. 전체 자료에서 N번 추출하고 각 추출을 하나의 RCTL에 배분하면, 외부 sample을 쓴다는 이유만으로 sample–모델 처리 횟수가 KN으로 늘지는 않는다. 각 RCTL이 모든 자료를 처리하는 구현과 구별해야 한다.

다만 N회라는 것은 sample–모델 평가의 수다. 비중 추정, 후보 검색, 배분, batch 구성, 불균형한 모델별 처리량과 실제 wall time까지 같다는 뜻은 아니다. 동일 sample을 여러 epoch에 보내는 방식도 새 관측을 N개 늘리는 것과 다르다.

따라서 40의 비용 사유는 **모든 외부 자료를 각 모델에서 추가로 처리하는 구현**에 한정한다. 고정 처리량 배분은 비용 측면에서 실행 가능한 대안이다. 이것만으로 신규성이나 예측 이득이 생기지는 않는다.

## 3. 가장 가까운 원문이 이미 포함하는 부분

**Bickel et al., ICML 2008.** *Multi-Task Learning for HIV Therapy Screening* §4는 pooled sample에서 task별 분포에 맞게 재추출하는 방법을 먼저 제시하고, loss 가중을 그 대안으로 설명한다. §4.1 식 8은 joint ratio를 task-origin posterior와 task prior의 비로 표현한다. 따라서 ‘모든 자료를 모든 모델에 계산하지 않고 적합한 실제 sample만 재추출한다’는 발상도 이미 포함된다. 원문의 최종 문제는 분류이며, 식의 loss identity와 회귀 실증을 구별한다. [공식 PDF](https://icml.cc/Conferences/2008/papers/520.pdf)

**Katharopoulos & Fleuret, ICML 2018.** *Not All Samples Are Created Equal* §3.1–3.2는 선택 확률의 역수로 SGD 기여를 보정하고 gradient 추정 변동을 줄이는 원리를 다룬다. Algorithm 1은 후보를 읽고 확률을 계산하는 비용까지 고려하여 importance sampling 적용 여부를 판단한다. 현재 모델의 gradient 크기와 TabICLv2 예측 오차는 같은 값이 아니다. [공식 논문 페이지](https://proceedings.mlr.press/v80/katharopoulos18a.html)

이 두 연구만으로 최신 연구 전체의 범위를 확정하지 않는다. 다만 이번 배분안의 핵심이 새로운 원리라는 주장은 이미 이 원문들과 충돌한다. 40의 Kumagai2021 및 Cherkaoui v2/2026 분석도 유지한다.

## 4. hard 소속, soft 비중, 한 번의 확률 배분을 구별한다

아래는 논문 실증 결과가 아니라 직접 기호적으로 확인한 범위다. 고정된 group의 모집단 분포를 P_g, 혼합 분포를 Q=Σπ_g P_g, 관측 입력과 실제 target의 쌍을 Z=(X,Y)라고 한다. π_g>0이다. 정확한 posterior responsibility를 r_g(Z)=P(G=g|Z)=π_g dP_g/dQ로 둔다. 실제 자료에서 이것을 정확히 안다는 가정은 하지 않는다.

예측 함수·파라미터를 고정하고 group g의 loss를 ℓ_g(Z)로 쓴다. 목표가 Σa_g E_Pg[ℓ_g]일 때:

- 원래 출처만 이용한 기여: H_g=1{G=g}(a_g/π_g)ℓ_g(Z).
- 모든 group의 비중을 이용한 기여: U_g=(a_g/π_g)r_g(Z)ℓ_g(Z).
- E[H_g|Z]=U_g이며, 제2모멘트가 존재하면 Var(H_g)=Var(U_g)+E[Var(H_g|Z)]이다.

즉 원래의 소속 표시를 정확한 조건부 확률로 평균하면 고정된 loss 추정의 변동이 줄 수 있다. 그러나 U를 모두 계산하는 구현은 한 sample을 여러 모델에 계산한다.

sample을 J~p(.|Z)인 한 모델에만 보내고 S_g=1{J=g}a_g r_g(Z)ℓ_g(Z)/(π_g p_g(Z))로 보정하면 E_J[S|Z]=U이다. r_g가 양수인 곳에서 p_g도 양수여야 한다. 이때 확률적으로 하나를 고르는 변동이 다시 생긴다. 특히 p=r이고 모집단의 독립적인 한 번의 추출이면 (Z,J)의 결합 분포가 (Z,G)와 같다. 따라서 이 조건에서 단일 pass의 자동적인 변동 감소를 주장할 수 없다.

**이 결론을 여러 epoch에도 그대로 적용하면 안 된다.** 같은 Z와 고정된 ℓ에 대해 E번 독립적으로 J를 다시 추출해 평균하면 변동은 Var(U_g)+(1/E)E[Var(H_g|Z)]이다. 원래 G를 매번 고정하여 반복하는 것과 다르다. 반복 배분은 soft 비중의 계산을 근사할 수 있다. 다만 파라미터가 변하는 실제 학습, 함께 움직이는 시간·cell 자료, 추정한 r, 고정된 group별 quota에는 이 식을 그대로 적용하지 않는다. 새 관측 자료 증가나 RCTL 성능 향상을 증명한 식도 아니다.

## 5. RCTL과 TabICLv2에 실제로 남는 문제

1. **회귀 TabICLv2의 출력과 필요한 비중은 다르다.** 다음 트래픽의 조건부 분포를 잘 예측해도 특정 실제 (입력, target) sample의 출처 posterior를 잘 추정한다는 뜻은 아니다. 입력 분포와 prior도 필요하다. source 분류로 직접 추정하는 Bickel의 방식과 비교해야 한다.
2. **RCTL의 학습 계산은 batch에 의존한다.** 현재 구현은 BatchNorm을 사용한다. sample별 loss가 독립적인 고정 함수라는 위 대수와, batch 자체를 바꾼 훈련 gradient는 구별해야 한다. 고정 inference 함수의 loss identity를 batch-normalized SGD 경로 보장으로 바꾸지 않는다.
3. **소속 고정 뒤 학습기의 정보를 쓰는 일과 clustering 의존성을 구별한다.** RCTL gradient로 cell 소속·후보·병합 기준을 바꾸면 현재 독립성 조건을 위반한다. 반면 소속과 절차를 먼저 고정하고 최종 RCTL의 optimizer 안에서 표준 importance sampling을 사용하는 것은 자동으로 위반이 되지는 않는다. 이번에는 어느 쪽도 실행하지 않았다.
4. **지켜야 할 비교는 단순한 고정 quota 재추출이다.** 상태·시간대별 재추출 또는 기존 joint-ratio 방식보다 TabICLv2가 다른 유용한 sample 배분을 하고, 그 판단 비용을 회수하는지 보여야 한다. 현재의 직접 예측 우위는 이 증거가 아니다.

## 6. 결정

고정 처리량 sample 배분은 ‘비용 때문에 불가능한 안’으로 기각하지 않는다. 그러나 **이번 형태를 신규 추천안으로 채택하지 않는다.** 기대 목적과 재추출 원리가 기존 연구에 있고, TabICLv2가 개선하는 배분 결정이 아직 특정되지 않았기 때문이다. 새로운 수치 pilot도 시작하지 않는다.

다음 탐색에서 sample 공유를 다시 다루려면 원래의 분리 손해를 줄이는 구체적인 행동, 단순 source 분류·quota 재추출보다 Tab이 유리한 직접 근거, 새 최종 학습 없이 남은 예산으로 확인 가능한 질문이 필요하다. 비용 문장을 고쳤다는 사실만으로 해당 분야를 다시 처음부터 탐색하지 않는다.

새로 확보한 자료는 source manifest에 있고, 원문 읽기 범위는 별도 JSON에 기록했다. 웹 검색 도구 인증 오류 때문에 최신 검색 범위는 제한되었지만 공개 원문과 Crossref에는 직접 접근했다. 자격 증명을 조회·수정하지 않았다. 이 접근 오류를 연구 전체의 외부 blocker로 해석하지 않는다.
