# 100. 사전학습 clustering과 시간 조건 정규화는 무엇을 해결하는가

2026-09-26. 100 계획에 따른 원문·공식 코드 검토다. 이번에는 TabClustPFN의 K 선택과 APT의 시간 조건 변환이 현재 연구의 빈 연결을 채울 수 있는지 확인했다. 새 모델 학습·추론은 수행하지 않았다.

## 판단

**두 방법을 현재의 clustering → RCTL 앞에 그대로 추가하는 안은 채택하지 않는다.** TabClustPFN은 표의 잠재 집단을 복원하고, APT는 시간 조건에 맞추어 입력과 출력을 변환한다. 어느 쪽도 현재 필요한 ‘어떤 기존 cell의 실제 sample을 같은 RCTL에 학습시킬 것인가’를 직접 정하지 않는다.

이것은 두 방법의 성능을 부정하는 판단이 아니다. TabClustPFN의 최신 PDF에는 큰 표에 대한 추가 평가가 있고, APT에는 시간대 정보를 활용하는 구체적인 학습 절차가 있다. 그 결과를 다른 결정의 성능 보장으로 바꾸지 않는다는 뜻이다. 05의 TabClustPFN 구분을 방법과 코드 수준으로 보완했으며, 같은 논문을 처음 발견했다고 세지 않는다.

## 1. TabClustPFN: 같은 계열의 encoder를 사용해도 다른 문제를 학습한다

기준은 2026-05-14 공개된 **2601.21656v3 PDF**다. 기존 저장본의 버전과 hash를 확인하여 재사용했다. 초기 검색에서 읽은 v1의 범위를 최신판의 한계로 옮기지 않았다. §3.1–3.4와 관련 결과를 읽고 방법 그림·식을 PDF 3–4쪽에서 대조했다. [원문](https://arxiv.org/pdf/2601.21656v3)

| 확인 항목 | 실제 내용 | 현재 연구에 주는 의미 |
|---|---|---|
| 한 입력 단위 | 표의 한 행 | 우리 표에서 한 행을 lag sample로 만들면 sample을 묶는다. cell partition이 자동으로 나오지 않는다. |
| 사전학습 정답 | 합성 자료의 잠재 소속과 집단 수 | 다음 트래픽의 실제값 또는 RCTL 공동 학습의 유불리가 정답은 아니다. |
| 모델 | TabICL 2025 encoder를 초기값으로 사용한 별도 PIN/CIN | 회귀 TabICLv2의 고정 가중치와 같은 모델로 취급하지 않는다. |
| 소속·개수 학습 | SoftARI와 실제 K의 cross-entropy | 예측 오차를 허용하면서 RCTL 수를 줄이는 목적과 다르다. |
| K 선택 | CIN의 선택지는 2부터 Kmax | global K1을 명시적으로 선택하는 검사가 없다. |

공식 코드 commit `5673beaab72d69bb9db30da2740aef90975a3e0c`의 `model/tabcluster.py:401–420`은 열·행 표현을 먼저 계산하고, `_compute_all_k_logits`에서 그 표현을 재사용한다. `259–279`는 K=2부터 `max_classes`까지 **cluster decoder**를 반복 호출한다. `exp/run_Softari.py:423–439`는 `argmax + 2`로 K를 반환한다. 기본 Kmax=10이면 decoder 검사는 9개다. 전체 encoder를 9번 다시 계산한다고 설명해서도 안 된다. [공식 구현](https://github.com/Tianqi-Zhao/TabClustPFN/blob/5673beaab72d69bb9db30da2740aef90975a3e0c/model/tabcluster.py)

따라서 ‘한 번의 forward’는 데이터마다 다시 최적화하지 않는 API 실행이라는 의미로 읽는다. 내부 후보 검사가 없다는 뜻은 아니다. 반대로 이 반복만으로 느리다고 결론 내리지 않는다. 속도는 이번에 측정하지 않았다.

CIN이 K1을 선택하지 않는다는 말과, 출력 label이 우연히 한 종류로만 나올 가능성이 없다는 말도 다르다. 후자는 코드만으로 금지되어 있지 않다. 그런 collapse를 global 예측기가 충분하다고 검증한 결과로 사용할 수는 없다.

**최신판에 대한 수정:** 사전학습의 N≤1,000, D≤64를 실행의 절대 상한으로 쓰지 않는다. v3 PDF 6–7쪽은 N=10,000까지의 추가 평가와 고차원에서 PCA를 사용한 비교를 제시한다. 그 실험은 표의 잠재 소속 복원이며, 통신 cell 예측의 검증은 아니다. 이전에 확인한 ‘별도 clustering 사전학습 모델’이라는 구분은 유지하고, 단순히 작은 표만 다룬다는 이유로 배제하지 않는다.

## 2. APT: 하루·요일 흐름을 보존하는 구체적인 참고 방법

기준은 AAAI 2026 출판본, DOI `10.1609/aaai.v40i18.38542`, pp.15180–15188이다. 방법·학습 절차·Table 2를 확인했다. arXiv v1의 Appendix B–C에서 설정과 데이터 단위를 추가 확인했다. [출판본](https://ojs.aaai.org/index.php/AAAI/article/view/38542), [부록](https://arxiv.org/html/2511.12945v1#A2)

APT는 입력 구간 시작 시각과 예측 구간 끝 시각의 시간대·요일을 사용한다. 이들을 학습된 prototype에 대응시키고, 그 표현으로 scale과 offset을 만든다. 변환한 입력을 예측모델에 넣은 뒤 출력에서 변환을 되돌린다. **미래의 달력 시각은 미리 알 수 있는 정보이며 미래 트래픽 정답과 다르다.**

논문은 처음에 backbone과 정규화를 고정하여 APT를 준비하고, 이후에는 예측 loss로 함께 학습한다고 명시한다. 공식 commit `98a4c9c017666207b02029f842eff92818f0eab8`에서도 `normal_tsf_runner.py:236–249,266–318,325–384`에 준비 단계와 공동 학습 단계가 있다. 일반 분기에는 준비 뒤 APT만 예측 loss로 맞추는 한 epoch도 보인다. ‘사전학습’이라는 표현만 보고 외부에서 학습된 고정 파라미터를 바로 사용하는 TabICLv2와 동일시하지 않는다. [공식 runner](https://github.com/blisky-li/APT/blob/98a4c9c017666207b02029f842eff92818f0eab8/baselines/Normalization/runner/normal_tsf_runner.py)

확인한 ETTh1 설정은 시간대·요일, prototype 30개, top-k=3, embedding 20, hidden 32, `independent=False`다. 실제 공개 APT 모듈은 내적 top-k와 softmax로 prototype을 조합한다. 주석에 cosine 또는 Top5라는 표현이 있어도 이 설정의 실제 연산·k와 구별했다. 모든 데이터의 설정이 같다고 쓰지 않는다. [공식 설정](https://github.com/blisky-li/APT/blob/98a4c9c017666207b02029f842eff92818f0eab8/baselines/Normalization/ETTh1_itransformer.py)

이 기본형에서 동일한 예측 시작·종료 시각을 가진 cell들은 같은 시간 표현과 변환을 받는다. cell ID를 사용하지 않는 시간 모듈 자체가 cell별 소속을 구별하는 것은 아니다. 선택적 ID 경로는 존재하지만, 이를 학습시키는 절차와 유용한 공유 소속 판단은 별도다.

Table 2에는 개선과 악화가 모두 있다. 예를 들어 Traffic의 iTransformer+RevIN은 APT 추가 시 MAE 0.289→0.293, MSE 0.412→0.415다. 이 Traffic은 부록에서 도로 센서 자료로 설명된다. 네트워크 트래픽에서 개선을 확인했다고 쓰지 않는다. 전체 성능이나 복잡성의 우열을 이 한 행만으로 판정하지도 않는다.

## 3. 이번 검토에서 직접 확인한 두 가지 구별

다음은 새 트래픽 실험이나 논문의 결과가 아니라, 현재 설계에 적용하는 직접 추론이다.

### 관측값이 둘로 나뉘어도 필요한 예측 함수는 하나일 수 있다

A의 입력이 0~1에, B의 입력이 2~3에 주로 나타나고 두 cell 모두 `다음 값 = 10 + 2 × 최근 값 + 같은 분포의 잡음`을 따른다고 하자. 입력의 두 덩어리를 잘 복원하는 clustering과, 두 cell에 같은 예측 규칙을 사용해도 되는지의 판단은 답이 다를 수 있다. 이 예에서는 공통 함수 하나가 두 관계를 표현한다.

이것은 실제 학습한 global RCTL이 반드시 더 좋다는 증명이 아니다. 유한 자료·학습 용량의 문제는 남는다. 다만 잠재 집단 수의 posterior 또는 ARI가 좋다는 사실이 필요한 RCTL 수를 잘 선택했다는 근거가 되지 않음을 보여준다. 반대 방향의 입력 분포가 같은데 함수가 다른 예시는 78에 이미 있으므로 새 발견으로 반복 계산하지 않았다.

### 같은 affine 변환이 모든 변화 규칙을 같게 만들지는 않는다

정규화의 다른 효과를 제외하고, 한 시각에서 동일한 `z=γx+β`를 입력과 target에 적용한다고 하자(γ≠0). 원래 관계가 `y=ax+b`이면 변환된 관계는 다음과 같다.

`γy+β = a z + γb + (1−a)β`

scale과 offset을 바꾸어도 이 조건에서는 기울기 a가 유지된다. 수준 차이를 정리하는 것과, 증가 뒤 다음 값이 움직이는 관계까지 동일하게 만드는 것은 다르다. APT 전체의 한계를 증명한 것이 아니다. 비선형 backbone, 서로 다른 normalization/de-normalization 통계, 조건에 따라 바뀌는 변환까지 포함하면 별도로 분석해야 한다.

현재안에서 시간대 정보를 보존한다는 설명은 이 둘을 구별해야 한다. **시간 조건은 비교해야 할 상황을 지정하고, cell 소속은 그 상황들에서 실제 자료를 함께 학습할 유불리를 결정한다.** 전자를 잘 처리하는 모듈만 추가해 후자가 검증되었다고 쓰지 않는다.

## 4. 연구 설계에 반영할 결정

| 이전에 가능해 보였던 경로 | 이번 확인 뒤 판단 |
|---|---|
| TabICL 계열의 clustering 모델로 바꾸면 목적과 K 선택도 해결 | TabClustPFN의 별도 사전학습 목적과 K1 제외를 확인했다. 목적 정렬 근거 없이 대체하지 않는다. |
| 단일 forward 모델이면 모든 후보 검사가 없어짐 | 표현 재사용과 K별 decoder 계산을 나누어 비용을 적는다. |
| 시간 prototype을 넣으면 전체 흐름과 cell clustering을 함께 해결 | 시간 조건 보강과 cell grouping을 별도 결정으로 다룬다. |
| APT가 backbone을 처음 고정하므로 최종 모델과 독립 | 최종 공동 학습을 확인했다. 그 결과로 RCTL 소속을 정하는 변형은 현재 조건과 다르다. 소속 고정 뒤 활용은 원칙상 별도 대안이다. |
| normalization으로 관계 차이를 모두 제거 | 제거 가능한 수준·scale 차이와 남는 함수 차이를 구별한다. 단순 affine 추가를 신규성으로 세지 않는다. |

74·80의 Tab 직접 예측 우위는 유지한다. 이번 검토로 그 정보가 더 좋은 소속 결정으로 이어졌다고 판단하지 않는다. 새로운 adapter, 추가 사전학습, prototype clustering pilot도 시작하지 않았다. 독립 실행이 가능한 모듈을 찾는 일과 유용한 grouping을 찾는 일을 분리한 것이 이번의 설계 진전이다.

## 5. 접근·열람·실행 범위

- PDF 2편 44쪽을 준비했다. TabClustPFN 35쪽은 기존 v3를 재사용했고 APT 출판본 9쪽을 확보했다. 전 페이지의 결과를 검증했다고 주장하지 않는다. 방법과 표의 지정 5쪽을 렌더링하여 대조했다.
- 공식 코드 2개 repository의 commit을 고정하고 선택한 11개 파일을 저장했다. checkpoint 링크의 존재를 확인했지만 가중치는 받지 않았고 외부 코드는 import·실행하지 않았다.
- TabClustPFN v1/v3와 APT v1/출판본을 구별했다. v3 PDF에 추가된 큰 N 평가를 최종 판단에 포함했다. 최신 HTML과 PDF의 편집·부록 배치는 동일하다고 가정하지 않았다.
- 새 Tab/RCTL/기타 모델 fit·predict·gradient·BN 갱신 0, 실제 traffic 통계 재계산 0이다. 누적 원장과 기존 Word를 유지했다. 잔여 Tab 11 context/20,640행, 추가 RCTL fit 0이다.
- 최종 추천안과 최종 Word는 아직 미완료다. 새 외부 blocker는 확인되지 않았다. 이번 방법 검토를 전체 목표 완료로 표시하지 않는다.
