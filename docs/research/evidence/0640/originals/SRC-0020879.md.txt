# 116. 관계 추정의 불확실성을 clustering에 쓰려면 필요한 정보

2026년 9월 26일. 116 계획의 원문·구현 검토 결과다. 새 TabICL·RCTL 실행과 교통 자료 수치 실험은 없다. 추천 방향의 확정이나 전체 goal 완료를 의미하지 않는다.

## 이번에 해결한 질문과 판단

**추정된 관계의 차이를 그 추정 오차로 표준화하는 clustering은 이미 있다. 그러나 TabICLv2의 미래값 분위수나 기본 ensemble 차이가 그 추정 오차를 제공하는 것은 아니다.** 시간 block으로 context를 바꿔 보는 방법은 구현할 수 있지만, 무엇의 변동을 측정하는지 정의해야 한다. 이를 자동으로 참 관계의 불확실성이나 RCTL 공동 학습 이득으로 해석할 수 없다.

따라서 이번에는 ‘Tab 분위수 폭으로 거리를 나누는 방법’이나 ‘ensemble을 추가한 spectral clustering’을 새 후보로 채택하지 않는다. 불확실성 보정을 모든 상황에서 배제하는 판단은 아니다. 다음에는 새 모델을 반복 실행하기 전에 **이미 고정된 Tab 예측만으로도 query에 포함되는 하루가 바뀔 때 cell 소속이 얼마나 달라지는지** 확인한다. context 추정의 변동과 query 구성의 변동을 분리하려는 진단이다.

## 2. 선행연구는 무엇을 비교하는가

각 개체에서 회귀 계수 β를 먼저 추정한다. 두 개체의 추정 계수가 다르더라도, 그 차이가 추정 과정의 변동에 비해 작은지 큰지를 구별한다. 식 (4)는 계수 차이에 추정 오차 공분산의 역제곱근을 곱한 뒤 L2 norm을 계산한다. 제곱 거리가 아니다. 독립 개체의 예시에서는 두 계수 추정량의 공분산을 더한다.

Algorithm 1은 이 거리를 `exp(-거리)`로 바꾸어 인접 행렬을 만들고, 정규화 Laplacian의 작은 고윳값에 대응하는 벡터를 이용해 K-means를 수행한다. G는 먼저 주어진다고 두며, 별도로 상대 eigengap을 이용한 G 선택을 제시한다. 저자도 spectral 알고리즘 자체를 새 기여로 주장하지 않는다.

불확실성이 큰 방향의 차이는 작게, 정확하게 추정된 방향의 차이는 크게 반영한다. 이것은 **같은 계수를 갖는 집단을 복원하는 판단**이다. 실제 sample을 합쳐 유한한 RCTL을 학습했을 때 미래 MAE가 작아지는지를 직접 계산한 것은 아니다. 추정이 부정확해서 차이를 구별하기 어렵다는 결과를 ‘함께 학습해도 손해가 없다’로 바꿀 수 없다.

## 3. 이론이 보장하는 것과 가져올 수 없는 것

### 두 알려진 중심 중 하나를 고르는 국소 결과

Theorem 2.1은 두 중심의 차이가 `T^(-1/2)×Δ`인 국소 모형에서 분류 확률을 비교한다. i.i.d. 자료, 손실·기대 손실의 매끄러움, 식별 조건, 점근 정규성과 일관된 공분산 추정이 필요하다. 이 조건에서는 공분산으로 표준화한 계수 거리가 원래 손실을 비교하는 규칙보다 점근적으로 불리하지 않다.

원문 8쪽은 이 결과를 반복 grouping 절차의 성능 분석에 직접 사용할 수 없다고 명시한다. 참 중심 두 개의 구별, 전체 집단 복원, 최종 예측 성능은 서로 다른 주장이다. 현재 TabICL query의 MAE를 이 정리의 분류 확률과 같다고 설명하지 않는다.

### 전체 group 복원의 결과

Theorem 3.1은 집단 내·집단 간 인접 행렬 값에 관한 유한 행렬의 충분조건이다. 그 조건을 확인하지 않고 실제 자료의 정확한 복원이 보장된다고 할 수 없다.

Theorem 3.2는 개별 계수 추정 오차가 집단 간 최소 차이보다 작아지고, 적절히 축소되는 공분산 추정 행렬의 고윳값이 안정적이며, 집단 간 분리가 n·T 증가에 비해 충분하다는 조건에서 group 복원을 보인다. 전형적인 `b_T=T` 예시에서는 최소 차이가 `log(n)/sqrt(T)`보다 충분히 커야 한다.

**여기서 정확한 전체 공분산을 알아야만 이론이 성립하는 것은 아니다.** 15쪽은 대각 근사나 일부 약한 개체 간 의존성의 생략도 상위 가정을 만족할 수 있다고 설명한다. 따라서 ‘Tab의 완전한 공분산을 얻지 못한다’는 한 가지 이유만으로 모든 적용을 배제하지 않는다. 다만 기본 ensemble의 변동이나 고정 context의 분위수 폭이 이 가정을 충족한다는 근거는 별도로 필요하다. group의 참 계수가 유한한 몇 값으로 나뉜다는 모형도 현재 traffic에서 확인된 사실이 아니다.

### 시계열 확장

§3.2.2는 선형 조건부 분위수 관계에서 시간 의존성을 다룬다. 식 (18)의 sandwich 공분산에는 분위수 score의 여러 lag 공분산이 들어간다. 정상성·mixing, 조건부 밀도와 입력의 정칙 조건, bandwidth와 n·T의 증가 조건을 사용한다. 단순한 미래 target의 분산을 대입하는 계산이 아니다. 이 정리를 비선형 TabICL의 context 추론이나 RCTL의 학습 위험에 그대로 적용하지 않는다.

## 4. 실험과 공식 구현에서 확인한 적용 범위

Table 4의 한 조건(n=30, T=60, 정규 오차)에서는 spectral+분산 정보의 평균 소속 정확도가 0.95, 분산 정보를 뺀 방법은 0.64다. 이는 생성 모형의 정답 group을 맞힌 비율이며 traffic 예측 개선율이 아니다. 반면 하나의 절편으로 grouping하는 Model 4에서는 분산 정보의 추가 이득이 없었다고 저자들이 설명한다. 불확실성 보정이 항상 유리하다는 주장을 지지하지 않는다.

Table 3의 알려진 G, n=60·T=150 조건은 spectral 1.61초, C-LASSO 12.30초, iterative K-means 225.92초, SBSA 0.85초다. 저자의 다섯 자료 생성 반복 평균이며, 현재 장비의 측정이 아니다. 1만 cell에서의 실행 시간을 보여 준 표도 아니다. 공개 코드는 모든 개체 쌍의 거리와 dense eigen decomposition을 계산하므로, 단순히 ‘계수를 한 번 구한다’는 이유로 전체 비용을 선형이라고 할 수 없다.

공식 `MembershipEstimation.R`의 주요 위치는 다음과 같다.

- 51–54행: 두 추정 공분산을 더해 역행렬·제곱근을 구한다. **코드는 `norm(..., type="I")`를 사용한다.** 열벡터에 대한 이 norm은 최대 절댓값이므로 2024 본문의 L2 norm과 다르다. 오래된 코드와 최종 방법을 동일 구현으로 표시하지 않는다.
- 76–85행: 개체별 `rq` 적합, `summary.rq(..., se="nid", covariance=TRUE)`로 공분산 산출. 절편을 제외한 계수로 grouping한다. 이 파일에는 시계열 HAC 공분산 확장이 구현돼 있지 않다.
- 88–119행: 모든 쌍 계산 → exponential adjacency → dense Laplacian/eigen → row 정규화 → K-means.
- 함수가 외부 `tau`, `p`에 의존하고, group 수 코드에는 `Gmax` 인자와 `maxG` 전역 이름이 혼재한다. 제공된 simulation 예제에 맞춘 코드이므로 범용 실행 API로 간주하지 않는다. 이 확인은 정적 코드 분석이며 실제 실행 오류를 측정한 것이 아니다.

## 5. TabICLv2에서 준비할 수 있는 정보의 차이

| 구할 수 있는 값 | 실제로 달라지는 것 | 이번 선행연구가 요구한 추정 오차와의 관계 |
|---|---|---|
| 한 context의 여러 분위수 | 새 target 값의 예측 분포 | 관계 추정량의 반복 표집 분산과 같지 않다. 미래 noise와 추론의 불확실성이 분리돼 반환되는 것도 아니다. |
| 기본 ensemble | 같은 sample의 정규화·열 순서 | 자료를 다시 관측했을 때의 변동이 아니다. 이를 posterior parameter draw라고 할 수 없다. |
| context 시간 block 재추출 | 참고하는 과거 자료 | 정한 추출 규칙 아래 추론의 민감도를 볼 수 있다. 계절 구성·기간 변화·중복 window·공통 충격·추정 편향도 함께 영향을 준다. |
| context 고정, query 시간 block 변경 | 위험을 집계하는 입력·시간대 비중 | 관계 추정은 그대로이며 어떤 확인 입력에 평가 비중을 두었는지가 달라진다. context 불확실성과 구별한다. |

설치 코드의 근거: `regressor.py` 31–55행은 ensemble의 정규화·feature permutation을 설명하며, 425–434행에서 이를 생성한다. `preprocessing.py` 1062–1063행은 같은 X·y를 보관하고, 1181–1187행 및 1214–1223행에서는 열 순서를 바꾸면서 y 행들은 그대로 반복한다. `regressor.py` 737–752행은 각 variant의 출력을 역변환한 뒤 평균한다. 여기에는 시간 block bootstrap이나 독립적인 사전학습 파라미터 표집이 없다.

여러 context 반복으로 관계 벡터를 만든다면 모든 반복에서 비교할 입력 좌표와 전처리 기준을 고정해야 한다. cell 간 공통 시간 충격을 고려할 때는 paired block 설계도 필요하다. 반복 수가 B인 p차원 벡터의 경험 공분산은 rank가 최대 B−1이므로, 적은 반복으로 긴 query 벡터의 역공분산을 바로 구할 수 없다. 대각 근사·축소 추정은 가능하지만 새로운 방법 자체는 아니며 성능과 비용을 별도로 확인해야 한다.

## 6. 현재 설계에 반영한 변경

1. **분위수 폭·ensemble 차이·context 변동·query 구성 변동을 서로 다른 항목으로 기록한다.** 이들을 하나의 ‘불확실성’으로 합쳐 병합 임계값을 만들지 않는다.
2. 완전한 공분산 부재만으로 적용 불가능을 주장하지 않는다. 반대로 대각 근사가 가능하다는 사실을 현재의 유용성 근거로 사용하지 않는다.
3. 불확실성 표준화, spectral clustering, Tab으로 계수 추정기를 대체하는 것만으로 신규성을 주장하지 않는다. 현재는 알려진 원리의 적용 후보 수준이며 새 소속 규칙의 직접 근거가 없다.
4. 112의 실패를 추정 분산 때문이라고 확정하지 않는다. 101의 Tab·RCTL 순위 차이도 이번 논문으로 해결됐다고 하지 않는다.
5. **다음 117 진단은 query 구성의 민감도만 먼저 분리한다.** 기존 B2의 저장된 168시간 query에서 하루씩 제외하고 동일한 병합 규칙의 소속 변화와 비용 순서 변화를 계산한다. 새 context 반복을 불필요하게 시작하지 않기 위한 원인 구별 확인이다. 미래 RCTL 오차나 ‘참 group’의 증명으로 사용하지 않는다.

116의 새 모델/traffic 수치 실험 0. 비용 원장 SHA는 `e1d20df37477e899afd4fc91782cd0fddb786deb9e25281cdfd1d174af11c09c`로 검토 전후 동일하다. Tab 누적 92 context·58,584행, RCTL optimizer 29회+통계 적합 9회는 그대로다. 117은 별도 계획·상한을 고정한 뒤 실행한다.
