# 267. population 단위 예측 기반 clustering과의 직접 비교

## 이번에 바뀐 판단

**‘예측에 도움이 되는 집단만 합친다’, ‘Bayesian 예측 점수를 쓴다’, ‘시간 순서로 확인한다’는 설명만으로는 현재 연구의 차별성을 확보할 수 없다.** 새로 확인한 직접 선행은 이 세 요소를 이미 포함한다. 반면 266에서 확인한 소속 선택의 실익은 유지한다. 기존 방법과 겹친다는 사실은 예측 정보가 쓸모없다는 뜻이 아니다.

이번에는 새 traffic 계산이나 모델을 실행하지 않았다. 17쪽 원문을 확보했고 알고리즘, 모형, 실험, 표를 대조했다. 다음 수치 확인은 Tab을 다시 실행하기 전에 **파형 후보 제한과 단순 회귀만으로 현재 개선을 얼마나 적은 비용에 얻을 수 있는지** 살피는 것이다. 전수 비교를 약한 기준선으로 두고 Tab의 계산 절감을 주장하지 않기 위해서다.

## 직접 선행에서 확인한 내용

Sadeghkhani, *Prediction-guided hierarchical clustering for population-level regression*, International Journal of Data Science and Analytics 22, 223, 2026-07-06. [출판사 원문](https://link.springer.com/article/10.1007/s41060-026-01197-4), DOI 10.1007/s41060-026-01197-4. 아래는 원문 §2–5와 Algorithm 1, Table 6의 요약이다.

| 항목 | 확인한 규칙 |
|---|---|
| 단위 | 관측 population 전체를 묶으며, 일반 sample clustering과 구별한다. |
| 일반 모형 | 집단 prototype과 population별 편차를 갖는 계층 모형. posterior predictive 손실 합을 사용한다. |
| 결정 | singleton에서 시작해 모든 현재 pair의 pooled 모델을 평가한다. 검증 손실 합이 가장 크게 줄어드는 pair만 병합하며, 양의 이득이 없으면 종료한다. |
| 실제 실험 | Gaussian 실험과 Gapminder는 OLS와 검증 SSE, 혼합 응답 실험은 Gaussian·logistic plug-in likelihood를 사용한다. 전체 계층 MCMC의 성능 재현과 구별한다. |
| 시간 | Gapminder는 무작위 분할과 함께 앞 6시점 학습, 다음 3 검증, 마지막 3 test를 사용한다. |
| Table 6 | 순서 분할 RMSE: 개별 4.77, 제안 5.21. 무작위 분할은 개별 2.91, mixed-effects 2.73, 제안 3.31. |
| 구현 확인 | 출판사 본문은 공개 자료를 안내한다. 해당 페이지와 제목·저자 검색에서는 공식 실행 코드를 확인하지 못했다. |

PDF 8·13·15쪽을 렌더링해 알고리즘·분할·수치를 시각 확인했다. 본문의 포괄적인 ‘개별 모델이 가장 좋다’는 문장보다 Table 6의 분할별 수치를 기준으로 기록한다. 무작위 분할의 최저값은 mixed-effects다. 전체 자료 공유가 항상 유리하다거나, 이 논문에 시간 검증이 없다고 설명하지 않는다.

## 우리 설계에 적용할 때의 구별

다음은 원문의 재진술이 아니라 현재 연구 기록과의 비교·판단이다.

| 현재 검토하는 요소 | 이미 확보한 근거와 남은 차이 | 판단 |
|---|---|---|
| 최근 입력과 이후 traffic의 관계로 cell을 묶기 | UPC의 peak/PCC와 다른 정보를 쓰지만, population 회귀 clustering과 목적이 겹친다. | 연구의 필요성과 신규성을 분리한다. |
| 실제 sample을 공통 context에 합쳐 확인 | 101에서 실행했고 210에서 HCP(2025)와 목적을 대조했다. | 모델만 TabICLv2로 바꾼 것을 핵심 기여로 삼지 않는다. |
| K를 유지하고 cell 하나의 소속 변경 | 현재 264는 학습 SSE+규제 비용의 이동 후 재적합, 직접 선행은 검증 손실의 병합이다. | 알고리즘은 다르지만 fixed-K 이동 자체는 알려진 최적화다. |
| 다른 최종 예측기로 소속 전달 | 우리의 최종 학습은 RCTL이다. clustering 점수에 RCTL은 들어가지 않는다. | 독립성은 유지하되 다른 예측기의 점수 감소를 RCTL 향상으로 치환하지 않는다. |
| Tab의 분위수 출력 | 예측 분포와 개별 가중치·partition의 posterior는 다른 객체다. | 분위수 폭만으로 소속 posterior나 모든 구성원의 보호를 주장하지 않는다. |
| 일·주기와 시간 순서 | 현재 16개 입력에 lag·요일·시각이 있고, query 정답을 context에서 분리한다. | 필요한 자료 구성이다. 이 처리만으로 새 알고리즘이라고 하지 않는다. |

이번 결과는 앞선 92의 Bayesian coding, 98의 목표 분위수 주변 정보, 210의 전체 자료 pooling 논의를 다시 실행해야 한다는 뜻이 아니다. 이 논문을 직접적인 비교 대상으로 추가하되 해당 원리들의 기존 판단을 재사용한다.

## 계산 비용에서 과장하지 않을 비교

Algorithm 1의 전수 pair 적합을 그대로 세는 경우와 **변하지 않은 group 비용을 재사용하는 구현**을 구별해야 한다. 고정한 전처리·모형·validation·seed에 대해 group S의 평가값 C(S)가 다른 group 구성에 의존하지 않는 경우를 생각한다. 이 조건은 현재의 결정론적 group별 회귀 기준선에 적용할 수 있다.

N개 singleton에서 1개까지 모두 병합한다고 가정하면, 매 단계 모든 pair를 다시 적합하는 작업 수는 `N(N²−1)/6`이다. 처음 pair들을 평가하고 이후 새 group과 남은 group의 조합만 평가하면 서로 다른 pooled group 평가 수의 상한은 `(N−1)²`다. 초기 singleton N개는 두 계산에 별도로 더한다. 아래는 실행 시간이 아닌 알고리즘 작업 수의 산술이다.

| N | 첫 단계 pair | 매번 전수 적합 | 변하지 않은 평가를 재사용 |
|---:|---:|---:|---:|
| 16 | 120 | 680 | 225 |
| 128 | 8,128 | 349,504 | 16,129 |
| 1,024 | 523,776 | 178,956,800 | 1,046,529 |
| 10,000 | 49,995,000 | 166,666,665,000 | 99,980,001 |

일찍 멈추면 실제 작업은 줄어든다. 모형이 다른 group과 전역 모수를 함께 갱신하면 단순 재사용 조건도 다시 확인해야 한다. 따라서 이 표를 원문의 실측 복잡도나 모든 Bayesian 모형의 cache 보장으로 제시하지 않는다. 재사용 자체 역시 신규성이 아니다.

현재 264의 fixed-K 이동은 첫 단계 48후보에 대해 출발 group의 삭제 함수를 공유하여 64회 적합을 사용했다. 더 강한 대안은 파형으로 **처음부터** 후보를 줄인 뒤 남은 후보만 회귀로 평가하는 것이다. 265에서 예측 목적 최적 후보가 파형 순위 3위였으므로, 이를 무시하고 ‘전수 64적합보다 적다’만으로 Tab 검색기를 추천할 수 없다.

‘이미 평가한 설정과 성능을 context로 주고 미평가 성능을 예상해 다음 평가를 고른다’는 ICL 사용도 알려져 있다. [PFNs4BO의 공식 ICML 2023 소개](https://proceedings.mlr.press/v202/muller23a.html)와 [PriorLabs의 Bayesian optimization 예제](https://github.com/PriorLabs/tabpfn-extensions/blob/main/examples/bayesian_optimization/bayesian_optimization.py)에서 이 원리를 확인했다. 이는 원리 중복을 확인한 범위이며, 해당 optimizer 전체를 구현·재현했다고 주장하지 않는다. 따라서 여기서 곧바로 Tab을 이용한 새로운 검색 모듈을 추가하지 않는다.

## 새로 수행할 확인 하나

268에서 265의 파형 순위를 고정하고, 첫 1개부터 48개까지 후보를 평가했을 때 얻는 최선의 **학습 목적값**과 필요한 서로 다른 group 적합 수를 264의 저장 결과로 계산한다. 삭제 결과의 공통 사용도 센다. 실제 query는 후보 선택에 사용하지 않는다. 순위 3까지만 확인하는 것을 결과를 보기 전에 정한 최적 예산으로 포장하지 않고, 전체 예산 곡선의 관측으로 기록한다.

적은 후보만으로 전수 탐색의 결정을 회복한다면, 이 데이터에서 전수 탐색 비용을 근거로 Tab 검색 연구를 추진하지 않는다. 많은 후보가 필요하다면 어떤 후보 정보가 파형 순위에 빠졌는지 구체적으로 남긴다. 어느 경우든 이번 자료의 결과를 모든 도시의 결론으로 확대하지 않는다.
