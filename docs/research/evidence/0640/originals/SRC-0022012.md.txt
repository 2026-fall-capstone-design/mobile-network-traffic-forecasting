# 641. 저장된 예측으로 관계 score의 추가 소속 판단 확인

문제 ID: `independent_UPC_membership_decision_information`. 640에서 좁힌 질문 하나는 **현재 관계 score가 같은 추정 함수의 직접 비교와 다른 소속을 만드는가**입니다. 결과가 다르다는 사실을 성능·신규성으로 대신하지 않습니다.

## 고정 입력과 재사용

- 첫 A16cell, UPC 시작 소속K4,635의3sweep·ID순서·양 절반 감소·목적지 지원 이웃2개·비공백 규칙을 그대로 사용합니다.
- 637에 완료된14cell의 Tab/HGB9분위수,638의 공통 유효22edge 및 query mask를 그대로 재사용합니다. 각 cell64개 query, 앞/뒤32개와 두 출처 같은 비중도 유지합니다. 시간·cell·seed·정규화·k8·지원 기준은 변경하지 않습니다.
- 현재 score의 소속은638의 봉인 결과를 읽어 대조합니다. 현재 알고리즘 자체는 다시 실행하지 않습니다. RCTL의 예측·손실은 읽지 않습니다.

## 계산할 대조 두 개

1. **직접 중앙값 거리**: 각 지원 query 입력에 대한 두 cell의 저장 중앙값 차이의 절댓값을 계산합니다. 각 출처·시간 절반에서 평균을 낸 후 출처 평균 둘을 같은 비중으로 합칩니다. 이 거리를 동일 graph 배정에 넣습니다. Tab/HGB 각각 한 번 계산합니다. 이는 함수 거리 계열의 명시적 단순 대안이며 Yang/Yu의 원 알고리즘 전체를 재현한 것이 아닙니다.
2. **정답 없는 plug-in 충돌**:638에 저장된 `p`, `w`, `F1`, `F0`로 `w×p×(1−p)×(F0−F1)`를 계산하고, 같은 지원·평균·배정에 넣습니다. 추정한 함수가 정확할 때의 조건부 score 기대값을 대입한 대조입니다. 현재 구현의 cell별 재가중 분포와 추정오차 때문에 유한 표본에서 동일량이라고 단정하지 않습니다. Tab/HGB 각각 한 번 계산합니다.

두 대조 모두 query의 실제 Y를 점수에 사용하지 않습니다. 같은 저장 npz 안에 Y가 들어 있어도 해당 배열을 읽지 않습니다. queryY를 없앤 차이와 확률/traffic 단위의 차이를 구분하기 위해 두 대조를 미리 함께 고정합니다. 결과를 본 뒤 더 좋은 정의를 선택하지 않습니다.

## 검수와 비용

원문·worker·cache·source hash와 누적 정산을 확인하고 실행 파일·설정 hash를 봉인한 뒤12초의 cheap numeric 예산을 예약합니다. 새 Tab/HGB/RCTL fit·forward0, 추가 원시 traffic0입니다. 기존 numpy 연산과 CPU4개 이내·RSS1GB 상한의 짧은 단일 worker만 실행합니다. 실제 경과시간과 실패 비용을 원장에 기록합니다. 기존 잔여가 충분하면 상한을 늘리지 않습니다.

독립 scalar 방식으로 edge 평균과 이동 목적값·선택을 확인합니다. source byte 불변,22edge와64query/14cell 대응,두 절반 목적 감소,K4비공백,결정론적 동점 규칙,결과 소속을 검수합니다. 지원 mask를 다시 추정하거나 예측을 재실행하지 않습니다.

## 결과별 다음 행동

- 현재Tab 소속과 두 대조가 모두 같으면 이 작은 조건에서 추가 score의 결정 기여는 없습니다. 639는 효용의 근거로 보존하되 복잡한 score를 신규성으로 채택하지 않고 관측 문제별 판단으로 넘어갑니다.
- 대조 중 하나만 같으면 그 동등한 결과를 숨기지 않습니다. 어떤 정보·연산을 제거해도 같은 결정인지 명시한 뒤 그 범위에 맞춰 기여 주장을 좁힙니다. 같은 소속의 RCTL은 재학습하지 않습니다.
- 하나 이상 다른 소속이면 모든 대조 소속을 먼저 봉인합니다. 추가 효용이 핵심 질문으로 남으면 Tab의 두 대조 중 서로 다른 고유 소속에 한해, 같은 조건 RCTL cache의 정확한 재사용과 빠진 group 수부터 확인하여 최소 연결 계획을 정합니다. 사후로 유리한 대조만 남기지 않습니다. HGB 대조는 동일 정보 추정기 차이의 판별이며 자동 신규 RCTL 실행 대상이 아닙니다.
- 실패하면 과학적 기각으로 바꾸지 않고 완료 출력·실패 비용을 보존합니다. 누락 복구가 필요한지 해당 오류만 판단합니다.

모든 자료는 개발 자료입니다. 강한 HGB_free의 전반 우세와6cell 손해, 원 score의512 재가중 동등성, 기존 선행의 no-refit/조건부 분위수 clustering을 그대로 보존합니다. 이번 행동은 새 구조를 제안하거나 관계 score를 보정하는 작업이 아닙니다.
