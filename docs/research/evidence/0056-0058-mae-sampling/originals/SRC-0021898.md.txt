# 58. 학습 sample 압축 방향의 원문·계산 검토

2026-09-26. 56 계획, 57 정확 산술 확인에 따른 기록이다. 새 추천안과 최종 Word는 아직 미완료다.

## 판단

**TabICLv2의 큰 예측 오차를 sample 중요도로 사용하여 RCTL 학습량을 줄이는 안은 채택하지 않는다.** 같은 경험 손실을 추정한다는 성질과 실제 학습이 빨라진다는 성질은 다르다. 더 근본적으로, sample 추출용 strata와 최종 RCTL을 나누는 cell cluster도 다른 결정이다. 전자를 잘 만들었다고 후자가 정해지지 않는다.

학습 비용을 줄일 문제 자체는 남는다. 기존 34 결과에서 global의 optimizer step은1,890, Tab K=4는2,431이었다. cell clustering만으로 처리량 감소가 보장되지 않음을 직접 확인했다. 그러나 비용 문제의 존재가 특정 Tab 기반 해결책의 타당성을 대신하지는 않는다.

## 3. MAE에서 ‘큰 오차 sample’이 중요한 학습 sample인가

57에서 예측식 fθ(x)=θ, θ=0, 동일 입력 세 개와 실제값 [-1,-1,10]을 고정했다. 절대오차는 [1,1,10], θ 방향 gradient는 [1,1,-1]이다. 큰 오차10은 gradient의 크기가10이라는 뜻이 아니다.

선택 확률 p로 뽑은 sample에는 1/(3p)를 곱했다. 결과를 추정하는 반복 실험 대신 가능한 세 결과를 유리수로 정확히 계산했다.

| 선택법 | 확률 | 가중 loss 평균 | 가중 loss 분산 | 가중 gradient 평균 | 가중 gradient 분산 |
|---|---|---:|---:|---:|---:|
| uniform | 1/3,1/3,1/3 | 4 | 18 | 1/3 | 8/9≈0.888889 |
| loss 비례 | 1/12,1/12,10/12 | 4 | 0 | 1/3 | 121/45≈2.688889 |

loss 비례 선택은 전체 오차를 **변동 없이** 추정하지만 gradient 분산은 **3.025배**다. 따라서 loss 추정 효율을 학습 효율이라고 부를 수 없다. 심지어 이 예는 다른 예측기인 TabICL의 오차가 아니라 현재 학습기 자신의 정확한 오차를 알고 뽑는다.

이 결과는 실제 RCTL의 학습 시간이나 네트워크 트래픽 예측 오차를 측정한 것이 아니다. 모든 압축법이 실패한다는 뜻도 아니다. “오차를 잘 재현하므로 RCTL 학습이 빨라진다”는 일반적 연결만 반박한다.

현재 RCTL에는 training-mode BatchNorm과 dropout도 있다. 개별 gradient를 고정한 단순 목적과 달리 BatchNorm 계산은 batch 구성에 영향을 받는다. 따라서 고정 checkpoint를 eval 모드로 읽어 계산한 분산을 실제 training-mode 분산과 같다고 보고하면 안 된다. 현재 `rctl_torch.py`에서 각 block의 `BatchNorm1d`·`Dropout`을 확인했다.

## 4. 수정 가능한 부분과 이번에 수정하지 않는 부분

**반영할 원칙:** cluster 수, 처리한 sample 수, optimizer step 수, 총 실행 시간을 분리한다. 샘플링/압축의 사전 비용을 이후 재학습 횟수에 걸쳐 회수하는지 본다. 실제 정답을 유지해도 선택 확률과 가중에 따라 학습 목적이 달라질 수 있으므로 이를 명시한다.

**채택하지 않는 안:** (a) TabICL loss 순으로 중요한 sample 선택, (b) Tab context Shapley 값을 RCTL 학습 가치로 사용, (c) 기존 시간대 stratification이나 antithetic sampling에 Tab 이름만 추가, (d) 전체 자료 expert 학습비를 제외한 압축 비용 주장. 이들은 현재 제약의 새 clustering 결정을 제공하지 못하거나, 이전의 학습기 간 효과 대체 가정을 되풀이한다.

**이번 검토로 확인하지 않은 것:** 실제 RCTL 자료 압축의 최적 비율, 학습 시간 절감, 압축 후 예측 정확도, TabICLv2의 sample 선택 우위. 새 RCTL fit0, Tab context0, 단순 회귀 fit0이다. 기존29개 RCTL 상한은 유지한다.

## 5. 실행 기록과 다음 탐색 경계

`57_mae_sampling_plan.md` 고정 뒤 `mae_sampling_audit_57.py`를 한 번 실행했다. exit0, numeric0.000162초, 네 성질을 확인했다. 결과는 `results/mae_sampling_57/`에 저장했다. 재실행하지 않는다.

다음에는 sample 선택 점수를 다른 이름으로 바꾸지 않는다. **실제로 RCTL이 처리하는 입력·학습 단위를 줄이면서, 줄인 정보가 불필요하다는 직접 확인이 가능한 문제**가 남는지 검토한다. 예를 들어 필요한 과거 길이의 차이는 입력 연산량과 연결되지만, adaptive lookback 연구와 구별되고 현재8시점 RCTL에서도 의미 있는 차이가 있는지부터 확인해야 한다. 이는 아직 추천안이 아니다. 이미 확인한 GPI/CF 분리·long-context caching을 새 방법이라고 다시 제안하지 않는다.
