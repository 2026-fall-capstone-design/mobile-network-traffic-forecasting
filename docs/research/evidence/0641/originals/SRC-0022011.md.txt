# 641. 실제 정답을 사용하는 score가 소속 판단을 바꿨습니다

**같은 Tab 예측으로 직접 중앙값 거리와 정답 없는 plug-in 충돌을 계산하면 둘 다 UPC를 유지했습니다. 실제 query 정답을 사용하는 현재 score에서는 세 cell이 이동했습니다.** 현재 후보의 이득을 단순히 사전학습 예측이 더 정확한 효과로만 설명할 수 없는, 한 조건의 결정 비교입니다.

## 비교에서 고정한 것

완료된14cell의9분위수, 동일한22개 입력 지원 edge, query64개와 지원 mask, UPC 초기 소속K4, 목적지 이웃2개, 양 시간 절반에서의 목적 감소, 최대3sweep를 유지했습니다. 같은 cached 출력에 적용하는 점수만 바꿨습니다. 두 대조 모두 계산 전에 고정했고, RCTL 파일을 읽기 전에 모든 소속을 봉인했습니다.

| 추정기·소속 점수 | UPC에서 이동한 cell | 최종 RCTL 전체 MAE |
|---|---|---:|
| Tab·직접 중앙값 거리 | 없음 | 0.084757 |
| Tab·정답 없는 plug-in 충돌 | 없음 | 0.084757 |
| Tab·실제 정답을 이용하는 관계 score | 3745·6153·3765 | **0.081396** |
| HGB·직접 중앙값 거리 | 없음 | 0.084757 |
| HGB·정답 없는 plug-in 충돌 | 없음 | 0.084757 |
| HGB·실제 정답을 이용하는 관계 score | 3745 | 0.085398 |

직접 거리는 동일 입력에서 두 중앙값 예측의 절댓값 차이입니다. plug-in은 `w p(1−p)(F0−F1)`로, 기존 score의 이상적 조건부 기대값에 추정한 분포를 대입한 비교입니다. 두 대조의 정의와 역할은 [고정 계획](641_cached_relation_score_ablation_plan.md)에 있습니다. 직접 거리 비교를 Yang/Yu 원 알고리즘의 전체 재현으로 부르지 않습니다.

## RCTL은 새로 실행하지 않았습니다

네 대조의 소속이 모두 기존 UPC와 정확히 같았습니다. 소속을 봉인한 후639의 실제 cell ID·group 구성·seed·학습 protocol·예측 artifact hash를 대조했습니다.16개 group 연결을 확인했고,639에서 이미 검수한 UPC 지표를 그대로 연결했습니다. 원시 예측 배열을 다시 읽거나 MAE를 재계산하지 않았습니다.

따라서 새 Tab/HGB/RCTL 학습과 forward는0입니다. 대조 소속의 RCTL을 다시 학습하지 않았으며, 위 값이641의 새로운 학습 결과인 것처럼 보고하지 않습니다. [정확한 재사용 연결](results/cached_relation_score_ablation_641/frozen_utility_alias.json)에 source와 hash를 기록했습니다.

현재 score의 UPC 대비 전체3.97% 개선과 두 절반의 개선은639의 결과 그대로입니다. 강한 HGB_free 대비 전체1.93% 개선, 전반2.71% 악화·후반5.46% 개선도 유지합니다. 새 대조가UPC와 같다고 강한 대안의 반례가 해소된 것은 아닙니다.

## 지금 확보한 것과 남은 것

1. **결정식의 기여:** 같은 Tab 추정 출력·graph·이동식에서 함수 거리나 plug-in만 사용하면 현재의 소속 변경이 나오지 않았습니다. 실제 정답에 대조하는 score가 이 조건의 추가 결정을 만들었습니다.
2. **추정기의 기여:** 같은 관계 score에 HGB를 넣으면 이동과 실제 RCTL 효용이 달랐습니다. Tab 자체의 예측 MAE와 최종 소속 효용을 혼용한633의 주장을 반복하지 않습니다.
3. **연결 효용:** 소속을 먼저 고정한 뒤 실제 자료로 학습한 RCTL에서 평균 이득이 있었습니다. 최종 예측기를 Tab으로 바꾸거나 RCTL의 손실을 소속에 사용하지 않았습니다.

이는 현재 조합의 한 개발 조건에서의 직접 근거이며, score의 새로운 수학적 발명·모든 함수 clustering보다 우수함·입력 빈도/잡음 문제의 완전 해결은 아닙니다. queryY를 이용하는 연산의 유한 표본 변동과 사후 비교라는 범위도 남습니다. 같은 정보라고 계산 비용이 같다는 뜻은 아니며, Tab의 추가 비용을 성능과 함께 제시해야 합니다.

결정 비교와 연결 근거가 갖춰졌으므로 추가 원인 진단이나 다른 seed를 자동으로 붙이지 않습니다. [642 추천안 정리 계획](642_bounded_relation_recommendation_plan.md)에서 이 조합을 연구 방향으로 추천할 수 있는 범위를 정하고, 실제 근거·선행 차이·원 UPC와의 조건 차이·전체 비용·남은 본 실험을 보고서로 연결합니다. 최종 완료 조건을 충족하는지 문서와 근거를 함께 검토하며, 약한 부분을 신규성으로 포장하지 않습니다.
