# 106 동일 K의 분할 차이가 나타나는 구간 확인

2026-09-26. 새 사용자 진행 지시에 따른 첫 분석이다. 새 모델 학습·추론은 하지 않는다.

## 확인할 질문

Tab-risk K4의 RCTL 오차가 empirical-risk K4보다 컸다는 기존 결과에서, 차이가 훈련 구간부터 나타나는지, 이후 구간에서 순위가 뒤집히는지 cell별로 구별한다. 같은 K4·cluster당4cell·훈련 행 수2,688의 비교이므로 모델당 sample **개수** 차이로 두 방법의 순위를 설명할 수 있는지 확인한다. 자료의 구성·난이도·학습 경로는 다르므로 특정 원인을 증명하는 분석은 아니다.

34는 분할과 global의 훈련/validation 평균, 42·67은 이후 구간에서 global 대비 cell별 손해를 다뤘다. 이번에는 Tab 대 empirical의 동일 K 비교를 두 seed의 훈련→validation→이후20일에 걸쳐 연결한다. 기존 수치를 재사용하며 신규 성능 실험으로 세지 않는다.

## 고정 자료와 계산

- `results/frozen_fit_gap_34/predictions.npz`의 저장 훈련·validation 예측 및 정답.
- `results/rctl_pilot/all_predictions.npz`의 이후480시간 예측·정답.
- `results/rctl_pilot/fit_results.json`의 cluster 구성과 `frozen_settings.json`.
- 기존16cell 전부, seed20260925·20260926. 정규화와 소속은 변경하지 않는다. 이후20일은 이미 사용한 개발 자료다.
- 각 구간에서 cell별 MAE 차이 `Tab − empirical`를 계산한다. 양수면 Tab 소속으로 학습한 RCTL이 불리하다. 이후20일은 사전에 같은 길이의 앞10일·뒤10일로 나누어 방향 지속 여부도 기록한다.
- 훈련/이후 차이의 부호 조합 네 종류를 모두 보고한다. 1e-10 이내는 수치 동점으로만 표시하며 성능 동등성 검정으로 사용하지 않는다.
- `이후 차이 = 훈련 차이 + 두 방법의 (이후−훈련) 변화량 차이`의 산술 항등식도 확인한다. 원인의 기여율이나 인과 분해로 해석하지 않는다.
- 두 seed 모두, 그리고 두10일 구간 모두 불리한 cell 수를 기록하되 그 cell만 새 알고리즘의 평가 대상으로 선택하지 않는다. 20개 날짜에서 방법별 차이를 계산하며 서로 독립인20개 실험이라고 표현하지 않는다.

## 결과에 따른 판단

1. 훈련부터 불리한 cell과 이후에 뒤집히는 cell이 함께 있으면 원인을 하나로 묶지 않는다. '분할로 자료 수가 줄어서 생긴 실패'라는 해석만으로 새 보정을 제안하지 않는다.
2. 같은 모델당 sample 수인데 두 분할의 차이가 남으면 다음 설계에서 **얼마나 많이 모으는가**와 **어떤 자료를 함께 모으는가**를 분리한다. 이 관찰 자체를 새로운 clustering 기여로 부르지 않는다.
3. 입력 누락·시간 변화·학습 변동을 구별할 수 없으면 식별 불가로 기록한다. 저장 RCTL 오차를 소속 결정에 쓰지 않고, 원래 입력에서 관측 가능한 자료 구성 차이를 확인하는 최소 후속 분석을 명세한다.

## 비용·검증

모델 호출0, RCTL fit0, 데이터 다운로드0. 저장 배열의 산술만 수행한다. 최대30초, CPU1process. 입력 hash와 cell 순서·누락/중복, 원래 MAE 재현을 확인한다. 소속·checkpoint·기존 원장 파일을 덮어쓰지 않는다. 실행 코드·결과·측정 시간을 별도 보관한다.
