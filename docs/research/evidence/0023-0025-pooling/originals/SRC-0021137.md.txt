# 조건부 공유 비용의 제한된 확인 계획

2026-09-25. 새 결과를 계산하기 전에 저장한다. 새 모델을 만들거나 RCTL을 다시 학습하지 않는다. 이 후보는 아직 추천안이 아니다.

## 질문 하나

동일한 입력에서의 예측 관계 차이와 입력 분포의 겹침을 동시에 반영한, 이상적인 MAE 공유 비용이 기존의 제한된 risk table보다 최종 예측의 분할 문제를 더 잘 설명할 단서를 주는가?

현재 알고 있는 반례를 유지한다. 이 비용은 충분히 유연한 함수가 참 조건부 분포를 알 때의 값이며, 유한 sample의 학습 이득·RCTL의 최적화·모델 용량을 계산하지 않는다. 따라서 이 값 자체를 RCTL의 성능으로 부르지 않는다. 예측 오차를 넘긴 사후 최적화도 하지 않는다.

## 계산 정의

입력 x에서 cell i일 조건부 비중을 p_i(x), 각 cell의 조건부 target 분포를 F_i(y|x)로 둔다. 한 cluster가 같은 입력에서 하나의 값을 출력할 때의 최소 기대 MAE와, cell마다 자신의 중앙값을 출력할 때의 기대 MAE 차이를 계산한다. cluster의 최적 출력은 p_i(x)로 가중한 분포들을 합친 **mixture의 중앙값**이다. 분포의 중앙값들을 먼저 평균한 값이 아니다. 입력별로 다른 값을 선택하므로 B1 anchor 대체나 B2의 상태별 상수 수정값 제약은 사용하지 않는다.

새 이론이라고 주장하지 않는다. 손실에 따른 정보량·함수 압축·예측 목적 clustering과의 동등성을 따로 확인한다. 확장 방향의 필요성은 원래 데이터 공유 문제에 있어야 하며, B1/B2의 내부 제약을 고친 것만으로 신규성이 생기지는 않는다.

## 모델 없이 확인할 정확한 예

1. 입력 지원이 겹치지 않는 두 cell은 함수가 달라도 공유 비용이 0이다.
2. 같은 입력에서 정답이 각각 0과 2인 두 cell이 같은 빈도로 나타나면 공유 MAE 증가가 1이다.
3. 같은 중앙값을 갖고 변동 폭만 다른 대칭 분포는 MAE 공유 비용이 0이다.
4. 알려진 입력 함수 b(x)를 모든 target·예측에 함께 더해도 공유 비용은 변하지 않는다.
5. 이 비용이 0이어도 독립 sample pooling과 완전 중복 pooling의 유한 자료 이득은 다르다. 앞서 실행한 08의 반례를 재사용하며 새 계산으로 포장하지 않는다.

## 실제 자료 진단

- 이전 16 cell, context target 시점 168~671, 이미 저장된 B1의 실제 입력 query 64개/cell을 그대로 사용한다. `risk_table_predictions.npz`의 첫 64 anchor는 버리고 뒤의 실제 query 분포만 읽는다.
- query 총 1,024행. 모두 개발 자료다. 과거 RCTL 결과를 이미 관찰했으므로 새 독립 검증이라고 부르지 않는다.
- pooled context 입력에서 표준화를 고정하고 k=32 최근접 context의 cell 빈도로 p_i(x)를 추정한다. k=16,64는 미리 정한 민감도 진단이며 유리한 값을 골라 주 결과로 교체하지 않는다.
- 거리 계산에는 이후 정답을 사용하지 않는다. 최근 8시점·일/주 lag·달력 입력을 보존한다. p_i(x)는 추정치이므로 실제 입력 지원에 대한 인증서가 아니다. query 소유 cell의 추정 비중이 0인 비율을 반드시 보고한다.
- 같은 전체 context를 이용한 cell별 32-NN target의 경험 분포와 TabICLv2의 저장된 129 분위수 분포, TabICLv2 중앙값만 사용한 분포를 비교한다. KNN에 새 모델 학습은 없으며 label·sample 양은 같은 실제 context에서 나온다.
- 입력별 최적 mixture MAE와 local Bayes MAE 차이를 적분한다. 관측 target으로 평가할 때에는 그 cell이 속한 cluster의 mixture 중앙값을 해당 query에 사용한다. 해당 cluster의 비중이 0이면 자기 cell의 예측으로 돌아가고 그 횟수를 별도 표시한다. 이는 진단용 처리이며 실제 공동 학습을 재현하지 않는다.
- 새 partition을 RCTL 결과에 맞춰 탐색하지 않는다. `results/rctl_pilot/frozen_settings.json`에 이미 고정된 5개 K=4 partition과 global K=1에만 점수를 계산한다. 점수 배열과 설정 hash를 저장한 뒤 기존 RCTL 평균 오차와 순위의 관계를 기술적으로 확인한다. 관찰한 순위를 이용한 계수·임계값 조정은 하지 않는다.

## 결과별 행동

- 실제 입력을 보존해도 점수의 순위가 불안정하거나 단순 KNN이 같거나 더 유용하면, 이 점수에 TabICLv2를 넣는 방향을 추천하지 않는다.
- 좋은 관계가 보여도 표본 5개 partition·한 도시·개발 자료의 결과로 기록한다. 새로운 partition의 RCTL 성능을 확인한 것으로 처리하지 않는다. 독립 평가와 novelty가 해결되기 전에는 추천 확정하지 않는다.
- 후보가 알려진 조건부 Bayes risk/정보 압축에 모델만 바꾼 것이라면 신규성으로 채택하지 않는다. 정확한 동등성 비교를 남긴다.

## 비용

추가 TabICL/RCTL 호출 0회. cheap numeric wall 60초, RSS 2 GiB 상한. 기존 누적 ledger에 실행 시간을 더하며 상한을 초기화하지 않는다. B1에 이미 지출한 N×N×Q cross query 비용을 새 방법의 무료 계산으로 주장하지 않는다. 새로운 대규모 설계라면 그 최초 추론 비용부터 다시 산출해야 한다.
