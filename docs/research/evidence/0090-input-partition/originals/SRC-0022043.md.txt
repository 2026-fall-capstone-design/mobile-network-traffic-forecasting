# 81. 공동 입력을 보존하는 cell 분할의 검토 계획

2026-09-26. 47·75의 입력 공유 검토, 74의 출력 압축 결과, 80의 동일 partition 결과를 먼저 읽었다. 기존 결과를 반복 실행하지 않는다. 현재 단계는 원문·코드·기호식 검토이며 새 모델 학습이나 수치 pilot을 허용하는 계획이 아니다.

## 확인할 결정

검토할 변경은 cell의 sample을 같은 scalar RCTL에 모으는 대신, cluster에 속한 cell들의 같은 시각 이력을 여러 입력 열로 제공하고 각 cell의 실제 미래값을 별도 출력으로 예측하는 것이다. 이때 clustering은 함께 학습할 sample뿐 아니라 예측 시 사용할 수 있는 입력 집합을 정한다. 원래 RCTL의 TCN·LSTM·이중 잔차 core는 유지하되 입력·출력 폭과 학습 단위가 달라지므로 원래 방법과 같은 구조라고 쓰지 않는다.

47의 반대 부호 함수 반례는 식별되지 않는 동일 scalar 함수 공유를 대상으로 했다. 고정된 cell별 출력 좌표를 두면 그 반례의 조건은 달라진다. 그러나 이것만으로 새로운 방법이나 성능 이득이 생기지는 않는다. 74의 full-output 기준, 18·46의 공간 입력 이득 부족, 기존 Granger feature selection을 모두 강한 반론으로 유지한다.

## 이번 단계에서 답할 질문

1. DGCformer·DUET와 관련 channel clustering은 이미 같은 결정을 하는가? clustering과 최종 예측기의 분리 여부, 실제 입력·출력 및 학습 목적을 원문·공식 코드에서 확인한다.
2. 입력을 일부 제외할 때의 최적 MSE 증가를 조건부 평균의 차이로 나타내는 성질은 무엇을 보장하는가? 비가산적인 여러 입력의 효과와 단순 pair graph를 구분하되 알려진 feature selection·variable clustering을 새 이론으로 부르지 않는다.
3. 같은 전체 관측 정보와 실제 출력 수에서 single global multi-output RCTL, cluster별 multi-output RCTL, 기존 scalar RCTL의 비용을 비교한다. 출력 수나 cluster 수만 세어 계산 절감을 주장하지 않는다. 입력·출력층 및 반복되는 core 비용을 기호식으로 분리한다.
4. TabICLv2가 단순 회귀 또는 기존 channel clustering보다 다른 유용한 입력 분할을 찾을 직접 이유가 있는가? context가 줄거나 query 열이 사라질 때 기존 cache를 그대로 재사용할 수 있다고 가정하지 않는다.

새 원문은 최대 네 방법을 중심으로 검토한다. 우선 DUET, DGCformer를 읽고 두 개의 가장 가까운 후속/변수 clustering 자료를 추가한다. 이미 읽은 HiGP·DIC-ST·Granger·TabDistill은 기존 기록을 재사용한다. 새 PDF 총 15 MB 이내, 그 외 공식 HTML·코드는 필요한 부분만 보존한다. 외부 코드는 실행하지 않는다.

기존 구조와 같은 결정으로 환원되거나 비용 이득의 근거가 없으면 새 Tab 추론을 시작하지 않는다. 유효한 새 결정이 남을 경우에만 자료·가설·비교·호출 수를 고정한 별도 수치 계획을 작성한다. RCTL fit 상한 29회는 소진되었으며 변경하지 않는다. 남은 TabICL 예산은 11 context, 20,640 query행이다.

이번 검토는 input partition 방향의 진입 판단이다. 원문에서 다른 도메인의 이득을 확인하더라도 네트워크 트래픽이나 RCTL의 실증 결과로 바꾸지 않는다. 최종 추천·Word 또는 전체 goal 완료로 간주하지 않는다.
