# 입력 공유와 예측 단위 변경에 대한 검토

2026년 9월 26일 · 연구 방향 재설계 중간 기록

**현재까지 확인한 TabICLv2의 장점은 직접 예측 성능입니다. 이를 clustering의 장점으로 연결하려면 추가 근거가 필요합니다.** 이번에는 여러 cell의 관측값을 함께 입력하는 방향을 검토했습니다. 알고리즘을 추가하기 전에 선행연구와 실제 RCTL의 계산 구조를 확인한 결과, 입력 공유만으로 새로운 연구 방향을 확정하기는 어렵다고 판단했습니다.

## 1. 무엇을 바꾸는 방향인지

기존 방식에서는 A와 B의 과거 sample을 같은 RCTL의 학습 자료로 모읍니다. 예측할 때 한 sample이 받는 입력은 해당 cell의 이력입니다.

검토한 방식에서는 한 sample에 **같은 시각의 A와 B 이력**을 각각 입력 열로 넣고, A와 B의 다음 값을 서로 다른 출력으로 예측합니다. 이 경우 clustering은 모델의 학습 자료뿐 아니라 **예측에 사용할 수 있는 다른 cell의 정보**를 정합니다.

| 비교 | 기존 sample 공유 | 검토한 입력 공유 |
|---|---|---|
| 모델에 보여 주는 자료 | A의 이력 또는 B의 이력 | 같은 시각의 A와 B 이력 |
| 한 sample의 정답 | 해당 cell의 다음 값 하나 | A와 B의 다음 값 각각 |
| 함께 묶는 이유 | 같은 예측 규칙을 학습하기에 적합해서 | 서로의 관측값이 예측에 필요해서 |

두 목적은 다릅니다. B의 관측값이 A의 예측에 유용하더라도, 두 cell에 같은 예측 규칙을 적용해야 한다는 뜻은 아닙니다. 다중 출력은 이 혼동을 줄일 수 있지만, 원래 RCTL의 입력·출력 규격을 변경하는 것이기도 합니다.

## 2. 이 구조 자체를 신규성으로 삼기 어려운 이유

**DGCformer**는 이미 관련 channel을 clustering한 뒤, 같은 cluster의 정보가 예측에 전달되도록 구성합니다. clustering과 예측을 분리하는 방향도 제시되어 있습니다. **DUET**는 주파수 관계에서 channel 연결을 학습하고, **CCM**은 cluster별 출력 규칙을 소속 확률에 따라 결합합니다. 따라서 “관련 cell을 묶어 함께 예측한다”는 설명만으로는 차별성이 부족합니다. [DGCformer 원문](https://arxiv.org/html/2405.08440v1), [DUET 원문](https://arxiv.org/html/2412.10859v3), [CCM 원문](https://arxiv.org/html/2404.01340v2)

또한 Fuchs–Wang의 변수 clustering은 두 변수의 관계를 단순 합산하는 대신 **여러 변수를 함께 알았을 때 생기는 예측 정보**를 비교합니다. 그러므로 “pairwise 관계를 넘어 공동 효과를 본다”는 발상만으로도 신규성을 확보하기 어렵습니다. 다만 이 연구는 현재의 미래 트래픽 오차나 RCTL 학습을 직접 다루지는 않습니다. [원문 §2 및 Example 2.11](https://arxiv.org/html/2312.16544v1)

TabICLv2를 이 자리에 넣으려면, 기존 기준이 실제로 잘못 선택하는 입력 묶음을 구체적으로 제시하고 **TabICLv2가 다른 선택을 하여 무엇을 개선하는지** 보여야 합니다.

## 3. 계산량 비교에서 바로잡은 점

여러 cell을 한 번에 출력하면, cell마다 RCTL을 호출하는 방식보다 반복 계산이 줄어들 수 있습니다. 그러나 비교 대상에는 **모든 cell을 한 번에 출력하는 단일 global RCTL**도 포함해야 합니다.

저장된 RCTL 구현을 기준으로 선형 연산을 검토하면, 같은 hidden 폭에서 입력·출력층의 전체 계산량은 전체 cell 수에 비례합니다. 반면 cluster별 모델을 여러 개 두면 TCN·LSTM core 계산이 그 수만큼 반복됩니다. 따라서 이 설정에서는 단일 다중 출력 모델의 산술 계산량이 더 작습니다.

이는 단일 모델의 정확도가 더 좋다는 뜻은 아닙니다. 여러 모델로 나눴을 때 용량이나 학습 안정성의 이점이 생길 수 있지만, 그 이점이 확인되어야 더 큰 계산량을 정당화할 수 있습니다. 이번에는 모델을 실행하지 않고 구현의 연산식을 검토했으므로 실제 속도 측정 결과와 구분합니다.

## 4. 현재 증거로 판단할 수 있는 범위

- **TabICLv2의 직접 예측 이득은 관찰했습니다.** 기존 네 cell 진단에서 개발 MSE는 TabICL 0.00958, HGB 0.01192, Ridge 0.01436이었습니다. 모두 같은 입력을 받았습니다.
- **그 차이를 공간 입력 효과라고 할 수는 없습니다.** 같은 조건에서 자기 cell 입력만 준 TabICL 결과와 비교한 실험이 아니기 때문입니다.
- **clustering의 차별성도 아직 확보되지 않았습니다.** 직전 16개 cell 진단에서는 TabICL과 단순 기준들이 동일한 cell 소속을 선택했습니다.
- **입력 공유 방식의 RCTL 성능은 미검증입니다.** 기존 scalar RCTL 실험을 새 다중 출력 구조의 결과로 사용할 수 없습니다.

현재 형태에 subset 탐색이나 복잡한 graph를 추가하는 것은 추천하지 않습니다. 먼저 확인해야 할 것은 **기존 방법이 잘못 선택한 입력 묶음 때문에 발생하는 실제 예측 손해**입니다. 그 손해와 TabICL이 바꿀 수 있는 결정이 연결될 때 알고리즘을 구체화하는 것이 적절합니다.

이번에 확인한 범위는 네 논문의 지정된 방법 절과 두 공식 저장소의 관련 코드입니다. 새 모델 실행은 하지 않았고 기존 예산을 유지했습니다. 최종 추천 연구 방향과 최종 Word 문서는 아직 확정하지 않았습니다.
