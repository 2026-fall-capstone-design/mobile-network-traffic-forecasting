# 96. RCTL 가중치 병합을 추가할지에 대한 판단

2026-09-26. 원문 4편과 현재 RCTL 코드를 대조했다. 새 모델 학습·추론·gradient·BatchNorm 갱신은 수행하지 않았다.

## 판단

**TabICLv2로 예측 관계가 비슷한 cell을 찾은 다음 RCTL 가중치를 합치는 변경은 현재의 추천 방향으로 채택하지 않는다.** 학습된 여러 모델을 하나로 합치는 원리는 이미 연구되어 있으며, TabICLv2가 추정한 예측 관계만으로 RCTL의 파라미터 병합 결과를 판단할 근거가 없다. 이 변경을 넣으면 앞선 대리 점수 문제를 해결하기보다 다른 형태로 다시 만들 수 있다.

이는 모델 병합이 불가능하다는 결론이 아니다. 소속을 먼저 확정하고 그 안에서 학습·병합하는 것은 현재 독립성 조건에서 검토할 수 있다. 다만 이번 후보에는 알려진 병합 방법보다 유용한 결정을 내리는 TabICLv2의 역할이 특정되지 않았다. 따라서 저장된 checkpoint를 임의로 평균해 보는 실행도 추가하지 않았다.

## 예측 관계만으로 병합 가능성을 알 수 없는 이유

이 부분은 실제 traffic 실험이 아닌 직접 계산한 반례다. 한 개의 ReLU를 가진 함수 `f(x)=a·ReLU(w·x)`를 생각한다.

- 모델 A의 계수가 `(a,w)=(1,1)`이면 출력은 `ReLU(x)`다.
- 모델 B의 계수가 `(a,w)=(1/2,2)`여도 출력은 모든 x에서 `ReLU(x)`다.
- 두 계수를 각각 평균하면 `(3/4,3/2)`가 되고, 출력은 `(9/8)·ReLU(x)`로 바뀐다.

따라서 **원래 두 함수가 완전히 같다는 사실만으로 가중치 평균의 함수가 같다고 결론 내릴 수 없다.** 예측값을 평균하면 원래 함수가 유지되지만 파라미터 평균은 그렇지 않다. TabICLv2가 두 cell의 참 예측 관계를 정확하게 추정했다고 가정해도 이 차이는 남는다.

반례는 실제 RCTL이 그 두 계수로 학습된다는 증거가 아니며, 공통 초기화에서 수행한 SGD의 성공 가능성을 부정하지 않는다. 반박하는 것은 ‘예측 관계가 비슷하므로 가중치 병합도 안전하다’는 일반적인 추론이다. 최종 RCTL의 내부 좌표·학습 경로를 통제하는 별도 조건이 필요하다.

## 현재 RCTL에서 추가로 결정해야 하는 것

보존된 `train_rctl_pilot.py`는 각 fit 직전에 같은 seed를 설정한다. 같은 seed·구조의 cluster 모델은 같은 무작위 초기값에서 출발하지만 각자의 자료·epoch·validation 선택에 따라 달라진다. 공통으로 사전학습된 RCTL checkpoint에서 fine-tuning한 실험이 아니다.

`rctl_torch.py`의 여섯 block에는 각각 두 BatchNorm과 LSTM, 잔차 경로가 있다. BatchNorm의 affine 파라미터와 running 평균·분산은 구별해야 한다. 앞단 가중치가 변하면 뒤의 activation 분포도 변하므로, 기존 running 통계를 단순 평균한 값을 새 모델의 올바른 통계라고 할 수 없다. LSTM의 gate와 recurrent 연결, 잔차 경로에도 일관된 좌표 대응이 필요하다.

고정된 BatchNorm을 앞 convolution에 접어 넣는 inference 변환은 가능한 대안이다. 그러므로 ‘BN 재추정 없이는 어떠한 병합도 불가능하다’고 판단하지 않는다. 그러나 이 변환은 나머지 비선형 층의 병합 가능성이나 Tab 기반 cell 선택의 효용을 증명하지 않는다. BN 통계 재추정도 자료를 이용해 모델 상태를 바꾸는 작업이므로 현재의 새 fit 0 상한을 우회하는 frozen inference로 처리하지 않는다.

## clustering 독립성과 비용을 함께 보면

소속을 정하기 전에 RCTL들을 학습하고, 그 가중치·표현·혼합 손실을 보고 합칠 cell을 선택하면 현재의 독립성 조건을 충족하지 않는다. 반대로 **cell 소속을 먼저 고정한 뒤, 각 cluster 내부에서 여러 RCTL을 학습·병합**하는 순서는 허용 가능한 학습 방식이다. 이때에도 왜 처음부터 cluster의 전체 자료로 RCTL 하나를 학습하는 것보다 유리한지 설명해야 한다.

기존 구성에서는 N개 cell의 서로 다른 입력을 각각 담당 모델 하나에 넣는다. 모델 수가 K라고 해서 각 입력을 K개 모델에 모두 넣는 것은 아니다. 병합으로 저장량이 KP에서 P로 줄더라도 N개 입력을 예측하는 일은 남는다. 95에서 확인한 batch 크기·호출 수 이득과, 신경망 연산 자체의 절감을 구별한다.

모델을 먼저 여러 개 학습하는 총비용은 각 모델이 처리한 sample·update·epoch와 병합 준비비용을 합쳐야 한다. 서로소 자료를 나누어 학습했다면 모델 수만으로 학습량이 K배라고 계산할 수 없다. 반대로 하나의 모델로 합쳤다는 이유로 과거의 여러 학습 비용이 없어지는 것도 아니다. 현재 보존된 global RCTL이 강한 정확도·비용 기준이므로 이를 제외한 비교는 하지 않는다.

## 최신 병합 이론을 인용할 때의 제한

UAI 2026 원문에서 식 23과 Algorithm 1의 residual 분모 표기, 식 24의 `ηI`와 Appendix A 식 31의 pseudoinverse는 서로 다르다. PDF 6·13·14쪽을 시각 대조했다. 이는 정리의 그대로 적용 여부를 따로 확인해야 하는 부분이다.

예를 들어 식 22의 스칼라 경우 `θ=1, γ=1`에서 목적은 `log(1+(ζ−1)^2)`이고 정상점은 `ζ=1`이다. 식 24에 `η>0`를 넣으면 그 점에서 `F(1)=1/(1+η)`가 되어 그대로 고정점이 되지 않는다. 따라서 양의 conditioning 항을 추가한 반복식과 원래 목적의 정상점이 같다는 해석을 이번 설계의 보장으로 쓰지 않는다. 이 계산은 해당 식의 적용 범위를 확인한 것이며 논문의 모든 실험·방법을 무효로 판정한 것이 아니다. 공식 코드는 이번에 검토하지 않았다.

## 다음 설계에 남기는 조건

자료를 묶는 결정과 학습된 파라미터를 합치는 결정을 구별한다. TabICLv2가 더 잘 예측했다는 관찰을 모델 병합 가능성으로 바꾸어 쓰지 않는다. 공통 초기화, BN 처리, 알려진 파라미터 정렬을 덧붙인 것만으로 새 clustering 기여라고 하지 않는다.

이번 후보에는 새로운 Tab 기반 결정과 단순한 union-data RCTL 학습 대비 개선 근거가 없으므로 채택하지 않았다. 모델 병합 실험을 실행하지 않은 상태를 성능 실패로 표기하지 않는다. 최종 추천 방향과 최종 Word는 미완료다.
