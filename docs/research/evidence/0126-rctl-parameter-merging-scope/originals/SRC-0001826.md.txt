# 96. RCTL 가중치 병합 방향의 적용 범위 확인

2026-09-26. 95의 실제 batch 비용 확인을 이어받는다. 새 모델·수치 실행 전에 정한 범위다.

## 확인할 주장

clustering을 먼저 확정하고 실제 자료로 학습한 RCTL들을 가중치 공간에서 합치면, 기존 core를 유지하면서 저장량·예측 비용을 줄일 수 있는가. 특히 TabICLv2가 추정한 입력–출력 관계가 합칠 대상을 정할 정보가 되는지, 알려진 model merging과 구별되는 기여가 있는지 확인한다.

## 앞선 기록과의 차이

- 79의 FMCL은 foundation 표현으로 소속을 먼저 정하고 후단 학습을 수행한다. 이 순서 자체를 신규성으로 주장하지 않는다.
- 86은 초기화·고정 표현·지속 파라미터 공유를 구별했다. 이번에는 이미 학습된 여러 파라미터를 하나로 합치는 연산을 살핀다.
- 95의 기본 비교는 같은 시점 cell의 batch 처리다. 느린 cell별 호출을 기준으로 새 효과를 만들지 않는다.

## 문헌·구현 확인

Model soups, Git Re-Basin, 시계열의 adaptive model fusion, 2026년 fine-tuning parameter-space merging 중 실제로 접근 가능한 원문의 방법을 확인한다. 예측값 혼합과 파라미터 혼합, 공통 사전학습 초기화와 공통 무작위 초기화, 학습된 모델을 읽는 결정과 자료만 읽는 결정을 구별한다. 관련 PDF는 최대 4편·편당 15MB 이내로 수집한다. 모든 실험을 재현했다고 쓰지 않는다.

현재 RCTL의 초기화, BatchNorm running 통계, LSTM 및 잔차 구조를 정적으로 확인한다. 단순한 스칼라 신경망 반례로 함수가 같아도 파라미터 평균의 함수는 달라질 수 있음을 검토하되, 실제 RCTL 실패 결과로 간주하지 않는다.

## 판단과 비용

1. 기존 모델 병합 원리를 그대로 적용하는 것뿐이면 새 clustering 후보로 추천하지 않는다.
2. 학습된 RCTL의 가중치·표현·예측 손실로 소속을 정해야 한다면 현재 독립성 조건의 알고리즘으로 채택하지 않는다. 소속을 먼저 고정한 뒤의 학습·병합 대안까지 금지하지 않는다.
3. 실제로 새로운 자료 기반 결정과 비용 개선 원리가 특정되는 경우에만 별도 수치 계획을 작성한다. 이 계획은 병합 모델의 실행을 허가하지 않는다.
4. 이번 단계는 새 Tab 호출, RCTL fit, gradient, BN 통계 갱신 및 frozen inference 모두 0이다. 잔여 Tab 11 context/20,640 query행, 새 RCTL fit 0, 기존 원장 hash `ad8926ba4ef3517043ce8ddc82afe981307352f7c52fc7c1fd251869a2e5e9b7`를 유지한다.

결과는 상세 판단과 공개 요약, 출처·읽기 범위, 후보 인덱스에 기록한다. 기존 Word와 snapshot을 변경하지 않는다. 이번 후보가 실패해도 연구 전체의 불가능성이나 goal 완료로 확대하지 않는다.
