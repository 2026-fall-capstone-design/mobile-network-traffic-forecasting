# RCTL 가중치 병합을 추가할지에 대한 검토

2026년 9월 26일 · 연구 방향 재설계 중간 기록

**이번 검토에서는 ‘TabICLv2로 비슷한 cell을 찾은 다음 학습된 RCTL 가중치를 합친다’는 방향을 추가하지 않았습니다.** 모델 병합은 가능한 기술이지만, 현재의 핵심 문제인 ‘TabICLv2의 판단이 왜 RCTL에 유용한가’를 해결하는 근거가 되지는 않았습니다.

## 1. 예측이 비슷한 것과 가중치를 합칠 수 있는 것은 다릅니다

두 모델이 모든 입력에서 같은 답을 내더라도 내부 가중치는 다를 수 있습니다. 예를 들어 한 모델이 입력을 그대로 전달하고, 다른 모델이 중간에서 두 배로 키웠다가 마지막에 절반으로 줄이면 두 출력은 같습니다. 그러나 각 단계의 계수를 단순 평균하면 두 배와 절반의 관계가 깨질 수 있습니다.

실제로 `a·ReLU(w·x)`에서 `(a,w)=(1,1)`과 `(1/2,2)`는 같은 함수입니다. 두 계수를 평균한 `(3/4,3/2)`의 출력은 원래 출력의 9/8배가 됩니다. 이것은 직접 계산한 설명용 반례이며 실제 RCTL 실험 결과는 아닙니다.

따라서 TabICLv2가 두 cell의 예측 관계를 정확하게 알아냈다고 해도, 그 cell들로 학습한 RCTL 가중치를 합쳐도 되는지는 별도의 문제입니다.

## 2. 관련 연구는 어떤 정보를 사용합니까

| 선행연구 | 실제 방법 | 현재 연구와의 관계 |
|---|---|---|
| Model soups, ICML 2022 | 같은 사전학습 모델에서 fine-tuning한 가중치를 합칩니다. Greedy 방식은 합친 모델의 validation 성능을 확인합니다. | 가중치 평균 자체는 새로운 기여가 아닙니다. 이 성능으로 cell 소속을 정하면 RCTL을 clustering에서 사용하게 됩니다. |
| Git Re-Basin | 학습된 모델의 hidden unit을 대응시킨 뒤 가중치를 합칩니다. BatchNorm 통계 처리도 다룹니다. | 입력–출력 관계 외에 학습된 모델 내부의 정보가 필요합니다. |
| TIMEFUSE, ICML 2025 | 입력의 요약 특징으로 여러 모델 예측의 혼합 비중을 계산합니다. | 하나의 RCTL로 압축하는 방식이 아닙니다. 예측을 섞기 위해 여러 모델의 출력을 계산합니다. |
| 파라미터 공간의 확률적 병합, UAI 2026 | 공통 backbone에서 fine-tuning한 파라미터 변화량을 이용해 합칠 값을 계산합니다. | TabICLv2의 회귀 출력과 다른 정보를 사용합니다. 그대로 가져와 RCTL 독립 clustering의 근거로 삼을 수 없습니다. |

원문: [Model soups](https://proceedings.mlr.press/v162/wortsman22a.html), [Git Re-Basin](https://arxiv.org/html/2209.04836v4), [TIMEFUSE](https://proceedings.mlr.press/v267/liu25cm.html), [UAI 2026](https://proceedings.mlr.press/v337/bui26a.html).

## 3. 현재 구조에서의 판단

현재 RCTL들은 같은 seed에서 출발했지만, 공통으로 사전학습된 RCTL을 복사하여 fine-tuning한 것은 아닙니다. 각자의 실제 자료로 학습했고, BatchNorm·LSTM·잔차 경로를 포함합니다. 단순한 가중치 평균이 이 내부 관계를 유지한다고 볼 근거는 없습니다.

소속을 먼저 고정한 다음 cluster 안에서 여러 RCTL을 학습·병합하는 방식은 연구 범위에서 검토할 수 있습니다. 다만 이 경우에는 **처음부터 해당 cluster의 전체 자료로 RCTL 하나를 학습하는 방법보다 나은 이유**가 필요합니다. 현재까지는 그 차이를 만들어 주는 TabICLv2의 역할이 특정되지 않았습니다.

비용도 구별해야 합니다. 현재는 각 cell의 입력을 담당 RCTL 하나가 예측합니다. 모델 수가 줄어도 서로 다른 cell의 입력은 계속 처리해야 합니다. 저장량 감소와 batch 처리의 이득은 가능하지만, 전체 예측 계산이 모델 수에 비례하여 줄어든다고 설명할 수는 없습니다.

이번 판단은 불필요한 구조 추가를 피하기 위한 것입니다. 원문 4편과 현재 코드를 대조했으며, 새로운 학습이나 병합 모델 실험은 실행하지 않았습니다. 최종 추천 방향은 아직 확정하지 않았습니다.
