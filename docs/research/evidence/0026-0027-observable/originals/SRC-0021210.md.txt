# 예측 당시에 알 수 있는 상태별 손해 확인

2026-09-25. 새 집계와 단순 모델 실행 전에 저장한다. 앞선 goal turn은 23·24의 실행·결과·보관본을 추가했으므로 progress다. 현재 실행 중인 외부 작업은 없다.

## 질문과 범위

global RCTL의 전체 평균이 좋은 경우에도, 입력만으로 정의할 수 있는 상태에서 중요한 손해가 반복되는가? 그 손해가 기존 분할이나 강한 단순 예측에서 줄어드는지 확인한다. 새로운 소속·점수·임계값을 RCTL 오차에 맞추지 않는다. 이번 분석은 원래 문제의 존재를 확인하는 개발 진단이다.

이전에 사용한 실제 target의 상위 5% peak는 예측 당시 알 수 없고, 해당 구간에서 sample 수도 적었다. 이번에는 다음 값이 아니라 **이미 관측한 최근값과 변화량**으로 상태를 정한다. 이는 peak를 더 잘 예측하는 새 알고리즘이 아니다.

## 고정 자료와 상태

- 기존 16 cell 모두, 학습 target 168~839, 평가 target 1008~1487의 480시점 전부를 사용한다. 이미 관찰한 구간이며 새 독립 test가 아니다.
- cell별 척도는 기존 RCTL 파일과 같게 고정한다. 입력은 최근 8시간, 24/168시간 lag, 최근 하루 평균·표준편차, 시간대·요일이다.
- 각 cell의 학습 구간 입력에서 아래 세 요약값의 10/90 분위수를 정한다. 성능을 본 뒤 분위수나 cell을 바꾸지 않는다.
  1. 최근 수준: z[t−1].
  2. 최근 변화: z[t−1]−z[t−2].
  3. 하루 전 같은 시각과의 차이: z[t−1]−z[t−25].
- 각각 낮은/중간/높은 구간으로 나눈다. 최근 수준과 최근 변화의 3×3 교차 상태도 전부 보고한다. 높은 상태는 `>q90`, 낮은 상태는 `<=q10`, 나머지는 중간이다. threshold 동점과 희소 구간의 영향을 숨기지 않는다.
- 상태마다 전체 행 수, cell별 행 수, 관측된 시간 수, cell별 연속 episode 수를 기록한다. 연속 시간 및 여러 cell의 동시 발생은 독립 관측이라고 세지 않는다.

## 비교

이미 저장된 모든 8개 RCTL 조건(두 추가 seed 포함)을 읽는다. 소속과 학습 결과를 수정하지 않는다. persistence, 하루 전 값, 일주일 전 값도 포함한다.

같은 학습 구간·입력으로 pooled Ridge(alpha=1, 표준화)와 HistGradientBoosting(max_iter=100, max_leaf_nodes=31, min_samples_leaf=20, l2=1, learning_rate=.1, early_stopping=False, seed=20260925)를 각 1회만 학습한다. 단순 대안도 새로운 RCTL fit으로 위장하지 않고 별도 small fit으로 기록한다. validation이나 평가 결과로 hyperparameter를 고르지 않는다. 모든 cell의 관측 자료를 같은 비중으로 사용한다.

각 상태에서 conditional MAE, cell별 conditional MAE, under/overprediction의 평균 크기와 전체 평균 오차에 기여하는 양을 계산한다. global 대비 차이를 앞뒤 240시간에서도 보고한다. 상태 내부의 평균과 전체에서 해당 상태가 차지하는 빈도를 구별한다. 평가 정답은 오차 계산에만 사용한다.

## 결과별 다음 행동

- global이 대부분 상태에서 유리하거나, partition의 이득이 희소하고 앞뒤 기간에 반복되지 않으면 '평균에 가려진 보호 필요 상태'를 근거로 새로운 clustering을 추천하지 않는다.
- 단순 Ridge/HGB가 상태별 손해를 줄인다면 모델 적합/입력 관계 문제와 소속 문제를 구별한다. 이를 TabICL의 독자적 필요성으로 바꾸지 않는다.
- 특정 관측 상태의 손해가 실제로 반복될 때만 원인의 다음 확인을 설계한다. 결과를 보고 보호 조건이나 clustering 임계값을 RCTL에 맞추지 않는다. 새로운 방향의 독립 검증으로 이 구간을 다시 사용하지 않는다.

## 비용

RCTL 추가 fit/forward 0, TabICL 추가 context/query 0, 단순 모델 fit 2회. cheap numeric wall 60초, RSS 2 GiB, CPU 4 thread 상한. 누적 600초 cheap 한도와 전체 6,000초 한도에 합산한다. 시작·종료 기록, 계획/코드 hash, threshold, 전체 예측·상태 배열·모든 비교를 보존한다. 작업 실패 때 기존 기록을 덮거나 비용을 초기화하지 않는다.
