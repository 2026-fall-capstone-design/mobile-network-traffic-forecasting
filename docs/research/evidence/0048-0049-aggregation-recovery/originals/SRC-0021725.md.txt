# 50. 합계 예측과 개별 cell 복원의 연결 검토

2026-09-26. 추천안 채택 전의 추가 검토이다. 48 계획을 먼저 저장하고 49 진단을 한 번 실행했다. 기존 연구 방향을 성공으로 변경하거나 RCTL 상한을 늘리지 않았다.

## 이번에 새로 구별한 세 가지 계산

| 구조 | 한 시점에 예측하는 값 | clustering의 역할 | 현재 범위와의 관계 |
|---|---|---|---|
| sample 공유 | 각 cell의 다음 값 | 어느 자료로 같은 함수를 학습할지 결정 | 기존 UPC → RCTL과 가까움 |
| 여러 출력을 함께 예측 | cluster에 속한 각 cell의 다음 값 전체 | 함께 입력하고 출력할 변수 범위를 결정 | RCTL 입력·출력 변경이 필요 |
| 합계 한 개를 예측하고 배분 | cluster 합계 또는 대표 값 하나 | 함께 압축해도 복원 가능한 cell을 결정 | RCTL target·학습 단위와 복원 규칙 변경이 필요 |

모델 개수, 처리하는 시계열 수, 출력 값 수, 라이브러리 호출 횟수는 서로 다르다. batch로 N개 cell을 한 번 호출하는 것과 N개의 예측 문제를 K개로 줄이는 것도 다르다. 단순히 호출 횟수가 줄었다고 지연시간이 같은 비율로 줄었다고 하지 않는다.

## 읽은 원문과 실제로 바뀐 판단

**HiGP, Cini et al., ICML 2024.** §3.1 식 4–8은 하위 cell과 상위 합계 모두의 표현·출력을 유지한다. §3.2 식 9의 assignment는 Gumbel-softmax와 forecasting loss로 학습한다. §3.3 식 12는 이미 생성한 계층별 예측을 일관되게 맞추는 projection이다. 전체 합계 하나만 예측해 cell 값을 나누는 방법이 아니다. §5/Table 1–2의 도로 속도·에너지·대기질 결과를 통신 활동량의 근거로 옮기지 않는다. 학습된 hierarchy를 RCTL 독립 clustering으로 그대로 쓰는 것도 맞지 않는다. 다만 고정 graph pooling도 허용한다는 원문 설명은 유지한다. [출판본](https://proceedings.mlr.press/v235/cini24a.html)

**Knapińska et al., ONDM 2023.** §II의 aggregated model은 2k개 일간·주간 lag 입력과 k개 출력을 가진 multioutput regression이다. §III/Table I는 Seattle 측정값을 generator로 Euro28에 배분한 자료에서 개별·전체·node별 모델을 비교한다. LR 평균 MAPE는 0.0949 → 0.0871 → 0.0821이다. 전체 모델과 node별 모델은 다른 시계열의 입력도 사용하므로 개선을 모델 수 감소만의 효과로 볼 수 없다. 본문은 undirected pair라고 쓰면서 28×27=756을 보고한다. 이 불일치를 임의로 해결하지 않는다. 이 논문은 총량 하나를 예측한 뒤 비중으로 배분하는 증거가 아니다. [원문](https://dl.ifip.org/db/conf/ondm/ondm2023/1570874472.pdf)

**HTS-Cluster, Han et al., arXiv:2205.14104v1.** §3.1–3.2 식 5–6/Algorithm 1은 Soft-DTW와 하위 cluster 분포의 Wasserstein 비교를 사용한다. Proposition 3.1은 clustering 목적함수의 감소이며 예측 오차 감소 정리가 아니다. §3.4 식 7은 cluster 대표 예측을 거리 기반 가중치로 조합해 개별 예측을 복원한다. 따라서 대표만 예측하여 비용을 줄인다는 발상은 기존에 있다. Table 3의 M5 최하위 LSTNet MASE는 82.36 → 98.78로 악화한다. Table 4의 상대 시간은 0.16이지만 모든 level의 MASE가 no-cluster보다 크다. 속도와 정확도는 따로 판단해야 한다. [원문](https://arxiv.org/abs/2205.14104)

PDF 3개를 확보하고 관련 7쪽을 렌더링하여 표·수식을 직접 대조했다. 공개 코드의 실행은 없다. 위 세 방법의 공식 구현을 재현한 것으로 표시하지 않는다. 검색·접근·검토 범위는 `sources/aggregation_48/review_scope.json`에 남긴다.

## 49 진단: 새 학습 없이 확인한 복원 오차

46과 같은 32개 cell을 사용했다. 첫 672시간으로 척도와 PCC를 계산하고 672–1007의 336시간을 확인했다. 앞·뒤 168시간도 각각 보고했다. 과거에 이미 확인한 개발 자료이며 독립 검증이 아니다. 인터넷 활동량을 각 cell의 앞 구간 평균으로 나눈 MAE이다. Mbps나 MAPE가 아니다.

가장 최근 관측에서 A 80, B 20이었다면 비중은 0.8과 0.2이다. 다음 합계가 100이라고 완벽하게 알아도 실제값이 A 90, B 10이면 비중 복원의 예측은 80과 20이어서 오차가 남는다. **합계의 예측 가능성과 개별 값의 복원 가능성은 별개다.**

| partition | 실제 미래 합계를 알려줬을 때의 복원 MAE | 같은 비중을 유지하는 모든 scalar 출력의 사후 최저 MAE | 실제로 직전 합계만 사용한 MAE |
|---|---:|---:|---:|
| 32개를 한 그룹 | 0.130482 | 0.122352 | 0.156030 |
| 위치 기준 4개씩 8그룹 | 0.104548 | 0.086065 | 0.156030 |
| 과거 PCC 기준 4개씩 8그룹 | 0.099702 | 0.084782 | 0.156030 |
| 무작위 4개씩 8그룹 | 0.116032 | 0.089983 | 0.156030 |

표의 앞 두 열은 미래 정답을 미리 쓰는 진단이다. 실행 가능한 성능 결과가 아니다. 또한 첫 열을 '이 구조의 최소 오차'라고 부르면 안 된다. 예를 들어 위의 90·10에 비중 0.8·0.2를 고정하면, scalar를 112.5로 정한 90·22.5의 절대오차 합 12.5가 정확한 합계 100을 사용한 절대오차 합 20보다 작다. 합계의 정확성과 개별 MAE 최소화는 같은 목적이 아니다.

둘째 열은 각 시점에 `Σ |실제값_i − 비중_i × scalar| / 척도_i`를 최소화한 값이다. 양의 비중에서 `실제값_i / 비중_i`의 weighted median으로 정확히 계산했다. 가중치는 `비중_i / 척도_i`이며 비중 0은 상수 오차로 처리했다. 합성 2개 cell 예와 실제 전체 진단에서 최소값·삼각부등식·유한값 조건을 검사했다. 독립 표본이나 forecasting 모델 가정은 이 산술 결과에 필요하지 않다.

마지막 열은 모든 partition에서 cell별 직전값 예측과 정확히 같다. `직전 비중 × 직전 합계 = 직전 cell 값`이기 때문이다. 전날 비중 × 전날 합계도 cell별 전날값 예측과 같다. 새로운 계산 경로를 만들었다는 이유로 기존 예측과 다른 방법이라고 세지 않는다.

좋은 관찰도 남긴다. 정확한 미래 합계를 주는 조건에서 PCC 8그룹의 복원 오차는 무작위 8그룹보다 작았다. 앞뒤 주에서도 0.101408/0.097995 대 0.119305/0.112758로 같은 방향이다. 따라서 압축의 손해가 partition에 따라 달라진다는 직접 근거는 있다. 그러나 단순 PCC로 얻은 결과이며 TabICL의 기여나 새 clustering의 우월성이 아니다.

시간대별 평균 비중을 고정하면 실제 합계를 주어도 MAE 0.331048–0.424745였다. 전날 비중도 직전 비중보다 나빴다. **이 32개 cell에서는 평소 시간대별 비중을 고정하는 것보다 직전 비중을 갱신하는 편이 복원에 유리했다.** 이를 모든 도시나 horizon의 결론으로 확대하지 않는다. cell당 현재 평균 척도, 각 partition·비중의 cell별/주별 수치는 JSON에 보존했다.

## RCTL 연결에서 확인한 것과 확인하지 않은 것

고정된 비중을 p, 실제 합계를 S, 예측 합계를 s라고 하면 원 단위 절대오차 합은 다음 관계를 만족한다.

`개별 예측 오차 합 ≤ 정확한 합계로 복원했을 때의 오차 합 + |S − s|`

이는 p가 비음수이고 합이 1일 때의 삼각부등식이다. cell별 정규화 손실에는 같은 계수가 자동으로 적용되지 않으므로 원 단위 식과 구별한다. 이 관계는 최종 예측 모델과 무관하게 합계 오차와 복원 오차를 분리한다. 그러나 RCTL이 합계를 정확히 학습한다는 정리나 이득 보장은 아니다.

RCTL을 scalar 합계 예측기로 바꾸는 경우, 전체 cell 행을 pooling하는 기존 학습과 target·sample 수·입력이 달라진다. 기존 checkpoint를 사용한 것처럼 비교할 수 없다. 여러 cell의 출력 전체를 유지한다면 위의 압축 오차는 없어지지만, ONDM/HiGP와 같은 multioutput 학습 문제가 된다. 이때는 모든 cell 입력을 같은 위치에 정렬하고 해당 실제 target을 출력해야 한다. 모델 수만 줄고 출력량은 그대로일 수 있다.

## 비용과 이번 판단

그룹당 4개 cell을 하나의 scalar로 예측한다고 가정하면, N=128/1024/10000에서 scalar 예측 수는 각각 32/256/2500이다. 모든 원시 입력을 읽고 개별 값을 복원하는 작업은 여전히 O(N)이다. 학습 이력 T의 단순 통계 준비는 O(NT), 직전 비중 갱신은 시점당 O(N), 대표 RCTL 연산은 K개의 입력 행이다. 실제 속도·메모리 절감률을 측정한 결과는 없다. 49의 N² PCC는 32개 cell의 저비용 비교용으로 계산했으며 10000개 규모의 제안 알고리즘이라고 하지 않는다.

현재 셋업의 TabICLv2를 합계 예측기에 넣어 우수한 후보를 고르기만 하면 기존의 '다른 모델의 점수가 RCTL 성능을 대변한다'는 가정이 다시 생긴다. 복원 오차는 실제 과거값으로 직접 계산할 수 있으므로, 그 값만 다시 추정하는 역할에는 TabICLv2를 추가할 이유가 아직 없다. 미래 정답으로 계산한 최저 오차를 TabICLv2가 예측했다고 표현하지 않는다.

따라서 **단순한 합계 예측·고정 비중 배분을 새 추천안으로 채택하지 않는다.** 압축 가능성을 다루는 문제 자체를 기각한 것은 아니다. 남은 가능성을 검토하려면 (1) 기존 대표 예측과 다른 결정, (2) 실제 과거값 계산을 넘어 TabICLv2가 제공하는 정보, (3) 개별 cell 정확도와 실제 추론 비용의 절충을 함께 설명해야 한다. 셋 중 하나를 생략한 확장은 실행하지 않는다.
