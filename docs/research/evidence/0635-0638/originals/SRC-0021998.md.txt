# 635. 제한된 중앙값 관계 graph가 실제 UPC 소속을 바꾸는가

문제 ID: `independent_UPC_membership_decision_information`.

## 한 질문과 비교

633에서 처음 사용한 cohort A의 동일16cell·K4에서, 634의 bounded 관계 점수로 정한 소속이 UPC와 달라지는가? 같은 정보 HGB 분위수를 넣었을 때와 다른 결정을 만드는가? 이는 소속 규칙의 최소 실행이며 최종 신규성·RCTL 우위 검증이 아닙니다. 어느 쪽도 지표가 좋아 보이는 cohort·기간을 사후 선택하지 않습니다. 이미 목록의 첫 cohort를 한 번 확인하며 다른 cohort의 반복은 자동 편성하지 않습니다.

## 자료와 예측

- `results/fixed_reference_vs_joint_pool_616/inputs_0.npz`의16cell, cell당 학습504행(target168–671),16열, query64행(target672–839)을 그대로 사용합니다. 실제값은 같은 폴더 `errors_0.npz`의 truth입니다. 모든 기간은 개발 자료입니다.
- 최근8lag·전일/전주lag·24시간 평균과 표준편차·시각/요일 sin/cos를 유지합니다. cell별 첫672시간 평균 척도를 바꾸지 않습니다. UTC/hour index를 유지하며 날짜를 재선별하지 않습니다.
- 회귀 TabICLv2의 기존 v2 checkpoint·ensemble1·KV cache·seed20260925·CPU 설정을 사용합니다. cell당 전체504행 context 한 개이며 해당 cell와 입력 graph 이웃의 query만 예측합니다. 가중치 학습은 없습니다.
- Tab은 `output_type='quantiles', alphas=[.1,.2,...,.9]`를 요청합니다. HGB는 같은504행으로 동일9수준의 quantile regression을 합니다. HGB `max_iter=32, max_leaf_nodes=15, min_samples_leaf=16, l2_regularization=1, learning_rate=.1, early_stopping=False, random_state=20260925`를 고정합니다. 9출력을 정렬해 crossing을 해소하며 발생 수를 기록합니다. 정보와 출력 수준을 맞추는 대안이며 HGB 계산을 무료로 세지 않습니다.
- 완료633의 중앙값만 있는 출력은 이 cross-cell9분위수의 cache가 아닙니다. 과거 출력이 일부 있어도 새 분포 출력과 다른 입력행을 완료한 것으로 표시하지 않습니다.

## 후보를 먼저 좁히는 계산

1. 초기504개의 실제 과거 target을 hour-of-day별 평균한24차원 profile을 구합니다. profile의 L2 norm으로 나눈 뒤 cKDTree로 cell마다8개 이웃을 찾습니다. 동일 거리의 cell ID 순서를 고정하고 두 방향의 합집합을 무방향 edge로 둡니다. query target은 사용하지 않습니다. 전체 Tab pair 평가 후 top-k를 남기는 방식이 아닙니다.
2. 각 검색 edge에서 양 cell의 초기 X만 사용한 binary HGB classifier를 적합합니다. `max_iter=24, max_leaf_nodes=7, min_samples_leaf=24, l2_regularization=1, early_stopping=False, random_state=20260925`로 p(X)를 예측합니다. p가 .1–.9인 확인 입력만 관계 비교에 사용합니다.
3. 앞32·뒤32 query 각각에서 각 cell의 사용가능 입력이8개 이상이고2개 이상의 관측 날짜에 걸쳐 있을 때 edge를 남깁니다. 부족하면 미판정입니다. 이 경험적 조건이 참 입력 겹침의 보장이라고 말하지 않습니다. retained edge가 없으면 여기서 종료합니다.
4. 이웃 검색과 p는 Tab/HGB 두 비교에 완전히 같습니다. retained edge에 연결된 cell만 분위수 추정을 준비합니다. 소속과 실제 K는 아직 바꾸지 않습니다.

## 관계 점수

각 edge의 두 source query에서 q를 `p F1(q)+(1−p)F0(q)=.5`의 해로 구합니다. F와 f는 정렬한9분위수 사이의 선형 CDF와 해당 구간 기울기를 사용합니다. 양 끝 바깥에서는 CDF를 .1 또는 .9로 고정하고 밀도는0으로 둡니다. 겹친 분위수 knot·비유한 값·혼합 밀도0이면 그 입력은 미판정입니다. 분위수 knot의 최소 간격 조건은 `1e−10 × max(1, max|q_k|)`로 고정하며 값을 임의로 벌리지 않습니다. 이산 target이 연속 분포라는 보장을 얻었다고 하지 않습니다.

학습 자료로 추정한 분포와 p만으로 w=sign(F0(q)−F1(q)), a=p f1/f_mix를 고정합니다. query의 실제 정답으로 계산하는 것은 `S=w(D−a){.5−1[Y≤q]}`뿐입니다. q는 두 분포의 혼합 중앙값을 구하기 위한 보조 값이며 실제 공동 context의 Tab 예측으로 해석하지 않습니다.

각 절반에서 양 cell의 sample 평균을 먼저 각각 구하고 두 평균에 같은 비중을 줍니다. edge 비용은 그 평균의 양의 부분 `C=max(0,mean(S))`입니다. 이 clipping은 유한 표본에서 양의 편향을 만들 수 있는 명시적 heuristic입니다. 작거나0인 비용은 동일 관계의 인증이 아닙니다. 각 절반의 각 cell에서8입력·2날짜를 다시 만족해야 유효 edge입니다. Tab/HGB의 유효 edge 교집합만 둘 모두의 배정에 사용합니다. 지원의 차이를 추정기 효과로 섞지 않습니다.

## 유지·이동·종료

UPC의 K4 소속에서 출발합니다. 두 절반의 graph 목적은 각각 `J=Σ(edge가 같은 cluster에 있으면 C_edge)`입니다. 검색 밖 관계를 검사한 것처럼 표시하지 않습니다. 알려진 충돌을 줄이는 목적이며 미판정 edge를 유사성이나 실제 병합 손해0으로 입력하지 않습니다.

고정 cell ID 순서로 최대3회 sweep합니다. 한 cell을 다른 cluster로 이동하려면 (a) 출발 cluster가 비지 않고, (b) 목적지에 유효 edge로 연결된 cell이2개 이상 있고, (c) 이동으로 **두 절반의 J가 모두 1e−12보다 크게 감소**해야 합니다. 모든 출발·도착 관련 edge의 합을 계산합니다. 가능한 목적지 중 두 절반 변화량 평균이 가장 작은 것을 선택하며 동점은 cluster 번호순입니다. 이동 뒤 관련 합을 갱신합니다. 한 sweep에서 이동이 없거나3sweep을 마치면 종료합니다.

이 규칙은 제한된 graph의 지역 탐색입니다. 모든 관계·미래 성능·최적해·유효한 통계적 검정을 보장하지 않습니다. 두 절반 모두 소속 선택용 개발 자료이며 독립 미래 확인으로 부르지 않습니다. graph가 소속 판정을 충분히 지지하는지는 실제 결과로 기록합니다. 초기UPC·Tab규칙·동일HGB규칙의 최종 소속을 먼저 봉인합니다. RCTL의 결과·가중치·예측 파일은 worker에서 읽지 않습니다.

## 비용과 작은 확인의 종료 분기

N=16·k=8에서 최초 graph는 최대120edge입니다. 이웃별 query를 중복 제거하면 분위수 모델당 전체 예측 행의 합은 `64(N+2E)≤16,384`입니다. Tab context 최대16·query최대16,384, HGB quantile 최대144fit와 p분류 최대120fit입니다. 실제 support 이후 사용량만 계산하고 불필요한 모델을 실행하지 않습니다.

일반 N에서는 검색한 edge가 E≤Nk이고 Tab준비N회·query Q(N+2E)입니다. KDTree의 최악 비용을 항상 NlogN이라고 보장하지 않으며, 높은 차원·이웃 분류·quantile fit·graph준비 비용을 포함합니다. graph 저장 O(E), 분포 저장 O(9Q(N+2E)), 최대3sweep의 이웃 비용 O(3KE)입니다. 큰N의 실용성은 이16cell 실행으로 확정하지 않습니다.

Tab180초·기타120초·합계300초·4CPU·RSS4GiB를 상한으로 둡니다. 633의20context/5888query46.7초, 작은504행의 기존 측정에 대비한 여유이며 실측 보장이 아닙니다. 부족한 원장 상한만 최소 증액·예약합니다. 과정별 attempted/completed·실패시간·source hash·부분 출력·동일비교 마스크를 저장하고 중단 실행은 재호출하지 않습니다. RCTL 추가는 이 계획에서0회입니다.

- 지원 또는 유효 edge가 없으면 이 입력·점수의 명세를 미지원으로 기록하고 범위를 넓혀 통과시키지 않습니다.
- Tab가 UPC를 그대로 두면 실제 개선 행동을 만들지 못한 것으로 현재 조합을 닫습니다. HGB가 다르면 그 단순 대안의 행동을 함께 보존합니다.
- 둘이 동일한 변경 소속이면 Tab 추가 선택 정보는 확인되지 않은 것입니다. 유용성 확인이 필요한 동일 소속의 RCTL은 한 번만 계획합니다.
- Tab가 UPC·HGB와 다른 소속을 반환하면 이를 성공으로 부르지 않고 **고정 소속의 작은 RCTL 연결 확인**으로 진행합니다. 같은 조건 완료 group을 먼저 대조하고 필요한 학습만 다음 계획에 예약합니다. 학습 target·자료량은 기존 RCTL 계약 그대로이며 전체 실제 sample을 전달합니다.
- 실패하면 실제 실패·비용·남은 범위를 기록합니다. 결과에 맞춰 k·분위수 수준·기간·모델·threshold를 자동 변경하지 않습니다.

최소 검수는 실제 입력hash·모델 호출 수·미래정답 부재·bounded값·서로 다른 구현의 score 집계·각 이동의 두 목적 감소·비공백K·고정seed·원장정산입니다. 문헌 공식과 동일한 직교성을 수치로 재확인하는 실험을 별도 성과로 만들지 않습니다.
