## 이전 판단의 재검토

63–65의 target 변환과59–62의 입력 길이 검토를 다시 읽었다. 알려진 구성 요소를 쓴다는 이유만으로 모든 결합을 제외하지 않는다. 같은 정보에서 같은 행동이 되는지, 실제로 개선할 문제와 최종 RCTL에 전달되는 결정이 달라지는지를 기준으로 한다. 해당 기존안에는 이득의 직접 근거 부족도 있으므로 지금 바로 채택하지 않는다.

## 새로 확인할 구체적 결정

후보는 **분산된 기존 cell의 자료로 cluster별 RCTL을 학습할 때, RCTL을 반복 적합하여 cluster를 찾는 탐색을 고정 TabICLv2 추론으로 대체할 수 있는가**이다. 최종 대상은 연속 트래픽량이고 TCN·LSTM·이중 잔차 RCTL과 실제 관측 target 학습을 유지한다. 이 후보는 중앙집중 학습의 이름만 바꾸는 것이 아니라 학습 위치·자료 이동·optimizer update 방식이 달라지는 방향이다. 현재 goal의 다른 학습 단위 변경 조건에 해당하는지, 그 변경의 실제 수요가 있는지 먼저 확인한다. 분산 조건을 사용자 데이터의 확인된 사실로 쓰지 않는다.

1. 실제 통신 traffic 연구에서 raw data 이동 또는 cell별 재학습·모델 통신이 문제로 측정되었는지 확인한다. 없는 privacy/SLA/통신비용을 임의로 만들지 않는다. 데이터를 보내지 않는 것과 formal privacy 보장을 구별한다.
2. 기존 clustered federated learning은 무엇으로 소속을 정하는지, 초기 및 반복 local model 적합이 필요한지, 더 싼 data-only 또는 pretrained-feature 대안이 있는지 비교한다.
3. TabICLv2의 context/공통 query/예측값을 cell마다 어떻게 준비해야 하는지, 공통 입력이 관측 지원 밖이 되는 문제가 해결되는지 확인한다. 서로 다른 cell에서 같은 시간인 것을 동일 입력으로 취급하지 않는다.
4. source 표현·task head 전이 점수를 최종 RCTL 공동학습의 보장으로 사용하지 않는다. global centralized 결과를 federated 결과로도 옮기지 않는다. 반대로 federated라는 조건만 붙여 이미 실패한 proxy를 채택하지 않는다.
5. 논문3편 이내의 방법·공식 코드와 최신 중복 연구를 확인한다. 새 PDF 총15MB 이내. 기존 q-FFL 검토는 재사용한다. 미검토 FedCAP2026은 가장 가까운 통신 대안 후보이며 접근 가능할 때 원문을 확인한다.
6. 같은 global federated RCTL과 model-independent clustering 대안보다 달라지는 결정이 없으면 새 추론을 하지 않는다. 신규성이 model 이름 교체에만 있으면 제외한다. 새로운 수치 확인에는 별도 사전 계획이 필요하다.

이번 검토로 확정할 것은 분산 학습 방향의 진입 가능성이다. 최종 추천 또는 RCTL 성능 검증을 통과했다고 쓰지 않는다. Tab69contexts/39360query, 잔여11/20640; RCTL29fits/잔여0. 예산 변경·재실행·유료연산 없음.
