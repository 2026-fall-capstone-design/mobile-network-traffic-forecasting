# TabICLv2 연구 재설계: 시간에 따라 cell 소속을 바꾸는 방향의 판단

2026-09-26. 새 선행연구 원문 3편과 공식 코드 검토 결과입니다. 추가 모델 실험은 진행하지 않았습니다.

**현재 설계에 동적 소속을 추가하는 방향은 추천하지 않습니다.** 시간에 따라 함께 학습할 cell을 바꾸는 발상은 가능하지만, 지금 확보한 근거로는 단순한 달력별 분할이나 같은 시간 정보를 받는 global 모델보다 나아질 이유가 분명하지 않습니다. TabICLv2의 직접 예측 성능이 좋았던 결과도 유지하되, 이를 RCTL의 모델 선택 효과로 확대하지 않았습니다.

## 무엇을 검토했는가

예를 들어 A와 B가 오전에는 함께 학습하기 좋고 오후에는 그렇지 않다면, 한 번 정한 cluster를 계속 사용하는 것이 불리할 수 있습니다. 이 가능성을 검토하기 위해 다음을 구분했습니다.

- **시간대별 clustering:** 오전과 오후의 cell 소속을 각각 정하고, 해당 자료로 RCTL을 학습합니다.
- **모델 배정:** 이미 학습한 RCTL 여러 개 중 현재 입력을 처리할 하나를 선택합니다.
- **소속 갱신과 재학습:** 새 자료를 반영해 cluster를 바꾸고 영향을 받은 RCTL을 다시 학습합니다.

세 방법은 필요한 자료와 계산 비용이 다릅니다. 특히 모델 배정은 cell의 고정 소속을 정하는 문제에서 sample별 모델 선택 문제로 바뀝니다. 어느 방법이든 예측할 때 아직 관측하지 못한 정답으로 소속을 결정해서는 안 됩니다.

## 원문과 코드에서 확인한 차이

| 선행연구 | 실제로 바꾸는 것 | 현재 연구에 적용할 때의 판단 |
|---|---|---|
| Dynamic clustering of time series data | 관측값과 cluster별 동적 선형모델의 관계를 이용해 시간별 소속을 추정 | 동적 소속과 소속의 급격한 변화를 억제하는 방식은 이미 있습니다. 전체 구간을 보고 추정한 과거 소속과 예측 당시 결정할 수 있는 소속을 구분해야 합니다. |
| DynaSTar, IJCAI 2026 | 도로 센서의 최근 입력에서 graph를 만들고 예측 과정에서 갱신 | 최근 상태에 따라 관계를 갱신할 수 있다는 근거입니다. 그러나 graph와 예측기를 함께 학습하므로, 독립적인 clustering 후 RCTL을 학습하는 설계의 개선 근거와는 구별해야 합니다. |
| Liu et al., Information Fusion 2024 | 통신 트래픽을 예측한 뒤 부하를 나눌 cell을 clustering | 예측→clustering→자원 조정 순서입니다. 예측모델이 함께 학습할 cell을 고르는 연구로 인용하면 목적이 달라집니다. |

첫 번째 논문의 공식 코드에서는 전체 구간의 정보를 이용한 backward 계산과 cluster 모델의 반복 적합을 확인했습니다. 이 계산을 학습 구간에서 사용하는 것은 가능합니다. 다만 미래 평가 구간의 소속까지 같은 방식으로 구한 뒤, 실제 예측 당시 사용할 수 있었던 배정이라고 평가할 수는 없습니다. [원문](https://arxiv.org/abs/2002.01890), [확인한 공식 코드](https://github.com/victhorio/dynmix/tree/bf866cefcd1f2754ee4b2ede31ff14aed79d0a7e).

DynaSTar는 graph를 갱신하면서도 전체 가중치를 매번 다시 학습하는 방식은 아닙니다. 대신 graph 생성과 최종 예측을 함께 학습합니다. sparse graph로 정보를 모으더라도 앞선 전체 node 쌍 관계 계산까지 없어지는 것은 아닙니다. 공식 논문에 제시된 저장소는 이번 접근에서 404였으므로 구현 재현으로 표시하지 않았습니다. [공식 원문](https://www.ijcai.org/proceedings/2026/0296.pdf).

통신망 논문은 부하·거리·이동 사용자 수로 small cell을 나눕니다. 논문의 개선이 연결되는 대상은 부하 분산과 자원 조정입니다. 공개 격자 트래픽과 별도 무선망 simulation도 구분해야 합니다. [기관 공개 원문](https://bimsa.net/doc/publication/3963.pdf).

## 지금 추가하면 해결되지 않는 문제

**시간대에 따라 값이 달라지는 현상과, 학습할 상대를 바꿔야 하는 현상은 다릅니다.** 시간·요일·최근 이력이 입력에 들어가면 하나의 모델도 오전과 오후의 다른 관계를 학습할 수 있습니다. 따라서 시간별 PCC가 변하거나 피크가 이동한다는 사실만으로 모델을 더 나눌 필요가 생기지는 않습니다.

이전 실제 확인에서도 최근 자료만 사용하는 전략의 일관된 우위는 없었고, 일부 증가 상태에서 나타난 grouping의 이득은 전체 손해를 상쇄하지 못했습니다. 이는 모든 동적 방법이 실패한다는 뜻이 아닙니다. 현재 후보를 뒷받침할 직접 근거가 아직 없다는 뜻입니다.

계산 부담도 구체적으로 달라집니다. S개 시간 조건마다 K개 RCTL을 만들면 최대 S×K개 모델을 보관해야 합니다. 각 sample을 한 조건에만 배정하면 학습 행 수 자체가 S배로 늘지는 않지만, 각 모델이 받는 자료는 줄어듭니다. 고정된 K개 모델 중 하나만 선택하는 방식은 이 부담을 줄일 수 있으나, 각 모델이 실제로 학습한 입력 범위와 배정 규칙을 맞춰야 합니다.

TabICLv2에서 상태별 예측을 계산할 수 있다는 사실만으로 이 문제가 해결되지는 않습니다. TabICLv2가 좋은 예측값을 내는 것, 학습할 cell을 올바르게 나누는 것, 나눈 자료로 RCTL이 더 잘 학습되는 것은 서로 연결해서 확인해야 합니다.

## 이번 판단을 다음 설계에 반영하는 방법

동적 소속을 새 모듈로 붙이지 않고, **동일한 시간·최근 입력을 받는 단순한 방법이 실제로 놓치는 학습 결정을 먼저 특정**하겠습니다. 그 결정에 TabICLv2가 제공하는 정보가 필요한지를 확인한 뒤 구조를 정해야 합니다. 이미 검토한 상태별 proxy에 갱신 기능만 붙이는 방식은 반복하지 않습니다.

이번 검토에서는 새 모델 학습·추론을 실행하지 않았고 누적 실행 상한도 유지했습니다. 최종 추천 연구 방향과 Word 문서는 아직 완성되지 않았습니다.
