# TabICLv2 재설계 진행 검토

2026년 9월 26일

이번에는 **“TabICL로 예측 관계를 더 정확하게 추정하면, 함께 학습할 cell을 고르는 판단도 좋아지는가?”**를 기존 16개 cell 자료로 확인했습니다. 결과는 분명합니다. TabICL의 직접 예측은 단순 회귀보다 좋았지만, 이번 clustering에서는 다른 소속을 만들지 못했습니다. 따라서 이 후보를 개선된 연구 방향으로 추천하지 않습니다.

## 1. 선행연구를 반영해 무엇을 바꾸었는가

검토의 출발점은 분산 학습입니다. 각 cell이 자기 자료로 학습한 결과를 cluster 안에서 합칠 때, 서로 다른 방향으로 학습하면 공유가 어려워질 수 있습니다. 이 문제를 최종 RCTL을 반복 학습하지 않고 파악하는 방향을 살펴보았습니다. 실제 사용자 환경에 자료 분산이나 개인정보 제약이 있다고 가정한 것은 아닙니다.

**FMCL은 이미 고정된 사전학습 모델로 clustering한 뒤 별도 모델을 학습합니다.** 그러므로 이 순서와 TabICL이라는 모델 이름 자체는 신규성이 아닙니다. FMCL은 분류의 class별 표현과 비율을 비교합니다. 현재 과제에서는 연속 트래픽의 어떤 관계를 비교할 것인지가 추가로 필요합니다. [FMCL 원문](https://arxiv.org/abs/2604.27510)

**EMD-CFL은 학습된 표현의 분포를 비교합니다.** 그러나 초기 local 모델 학습과 client 간 encoder 교환이 있으며, 전체 client 쌍을 계산합니다. 이를 그대로 RCTL에 적용하면 clustering에 RCTL의 학습 결과가 들어갑니다. 따라서 현재 독립성 조건에 맞춘 방법으로 바로 사용할 수 없습니다. [EMD-CFL 원문](https://arxiv.org/html/2506.07769v1)

최근 회귀 분석은 학습 방향의 차이에서 **참 예측 관계의 차이와 유한 sample의 잡음**을 구분합니다. 다만 매번 새 iid sample을 얻는 등의 가정이 있어 네트워크 시계열에 수렴 보장을 그대로 옮길 수 없습니다. 이 구분을 실제 데이터 진단의 질문으로 사용했습니다. [회귀 gradient 분석](https://arxiv.org/html/2609.25705v1)

통신 분야의 가까운 비교 대상인 FedCAP은 일별 profile로 cell을 묶은 뒤 cluster별 LSTM을 연합 학습합니다. 단순한 일별 profile 기준도 강한 대안으로 포함해야 합니다. 앞선 기록의 학술지명은 **Telecom**으로 정정합니다. 이 논문은 출판사 검색 본문과 서지를 확인했으며, PDF 전문 검토는 아직 하지 못했습니다. [FedCAP 출판사 페이지](https://www.mdpi.com/2673-4001/7/4/104)

## 2. 이번에 실제 확인한 알고리즘

각 cell의 과거 sample에서 최근 8시간, 하루·일주일 전 값, 최근 하루의 통계, 시간·요일을 입력으로 사용했습니다. 전체 흐름을 빼고 짧은 상승·하락만 비교한 실험이 아닙니다.

1. 기존 TabICL 출력으로 각 query의 이후 트래픽 평균을 근사했습니다. 새 TabICL 추론은 하지 않았습니다.
2. 각 cell에서 실제 관측된 **입력과 예측 평균의 쌍**을 만들었습니다. 다른 cell이 겪지 않은 공통 입력을 만들어 묻지 않았습니다.
3. 이 쌍들의 분포가 비슷한 cell을 묶었습니다. 비교 대상으로 입력만 사용한 방법, 실제 target을 붙인 방법, Ridge·HGB의 예측 평균을 붙인 방법, PCC를 두었습니다.
4. 각 방법의 소속을 먼저 고정했습니다. 모두 4개 cluster, cluster당 4개 cell입니다.
5. 이후 구간에서 고정된 RCTL의 MSE gradient를 계산해 같은 cluster 안에서 학습 방향이 얼마나 다른지 살폈습니다. RCTL 가중치는 바꾸지 않았고, 결과를 clustering에 되먹임하지 않았습니다.

이 설계는 입력 수준과 예측 관계를 함께 비교하면서 일시적인 target 변동의 영향을 줄이려는 시도입니다. 제곱손실에서는 기대 학습 방향이 조건부 평균과 연결되지만, 이 연결만으로 최종 예측 성능이 좋아진다고 결론낼 수는 없습니다.

## 3. 결과와 판단

| 직접 예측 방법 | 개발 query의 MSE | MAE |
|---|---:|---:|
| TabICL의 저장 분위수 평균 | 0.013043 | 0.077440 |
| Ridge | 0.015839 | 0.090011 |
| HGB | 0.015862 | 0.087740 |

cell별 평균으로 정규화한 단위의 값입니다. **TabICL의 직접 예측 이점은 확인되었습니다.** 다만 이 값은 실제 target에 대한 오차이며, 참 조건부 평균을 알고 측정한 추정 오차는 아닙니다.

더 중요한 결과는 **입력만 사용한 방법, 실제 target을 사용한 방법, TabICL·Ridge·HGB를 사용한 방법의 cell 소속이 완전히 같았다는 점**입니다. 이번 알고리즘에서 TabICL의 더 좋은 예측이 다른 clustering 판단으로 이어지지 않았습니다.

RCTL의 학습 방향 차이에서도 PCC보다 일관된 이점이 없었습니다. 아래 값은 같은 모델 상태의 단일 global 그룹을 기준으로 나눈 불일치 비율입니다. 같은 4개 cluster끼리 비교하며 작을수록 불일치가 작습니다.

| 고정 RCTL 상태와 뒤 7일 구간 | TabICL과 입력 기반의 동일 소속 | PCC 소속 |
|---|---:|---:|
| 초기 가중치 | 0.457 | 0.412 |
| 기존 global 모델 가중치 | 0.743 | 0.701 |

앞 3일에서는 TabICL 소속이 PCC보다 유리했지만 뒤 4일에서는 반대였습니다. 이를 근거로 안정적인 개선을 주장할 수 없습니다. 또한 이 확인은 가중치를 고정한 MSE gradient 진단입니다. 분산 RCTL의 실제 학습이나 최종 예측 성능을 검증한 결과가 아닙니다.

## 4. 후속 설계에 반영할 결론

앞으로 **“TabICL이 더 잘 예측한다”와 “TabICL이 더 좋은 cluster를 만든다”를 별개의 주장으로 다루어야 합니다.** 다음 후보는 단순 clustering이 실제로 잘못 묶는 상황을 먼저 특정하고, TabICL이 그 소속을 바꿀 정보를 제공한다는 근거를 갖춰야 합니다. 이번 거리의 가중치나 이름만 바꾸어 같은 데이터를 다시 확인하지 않습니다.

현재 최종 추천 방향과 교수님께 드릴 최종 Word 문서는 미완료입니다. 이번 후보의 결과를 성공한 설계로 문서화하지 않았습니다. 연구 방향 재설계는 계속 진행 중입니다.

이번 수치 확인의 측정 시간은 약 7.04초입니다. 새 TabICL 추론과 RCTL 학습은 없었고, 단순 회귀 적합 32회와 가중치를 고정한 RCTL 계산을 수행했습니다. 실행 전 계획, 고정한 소속, 코드, 전체 결과, 비용 원장은 아래에 보존했습니다.
