# 84 완료 조건과 실제 근거를 연결하는 검토 계획

2026-09-26. 직전 83단계는 새 원문과 비용 조건으로 후보 판정을 바꾼 progress다. 이번 단계에서 goal의 완료 조건이나 연구 범위를 바꾸지 않는다.

## 이번에 끝낼 작업

기존 기록을 단순히 합치는 대신 다음 세 가지를 명시적으로 확정한다.

1. TabICLv2 직접 예측, 소속 선택, 최종 RCTL 예측이라는 서로 다른 비교의 입력·대상·지표·시간 구간을 대조한다. 서로 다른 표의 숫자를 섞어 만든 우열은 배제한다.
2. 신규성, 개선 근거, 실행 가능성이라는 각 완료 조건에 현재 증거가 어디까지 도달했는지 대응한다. 미실행 비교를 실행된 사실과 분리한다.
3. 전체 쌍 비교와 처음부터 제한한 후보 검색의 호출·query 규모를 128·1,024·10,000 cell에 대해 계산한다. 이 산술 표는 최종 알고리즘이나 실행 시간의 증거가 아니다. 같은 context cache를 재사용해도 query 계산이 남는다는 점, 후보 개수 상한에 따른 비용을 구별한다.

## 실행 범위

새 모델, 새로운 데이터 진단, 기존 RCTL 설정 변경은 하지 않는다. 모델 예산은 byte 단위로 유지한다. 단순 정수 작업량 계산, 원본 JSON 값 검증, 문서 생성·렌더링만 수행한다. 이것을 모델 실험의 성공으로 기록하지 않는다.

비용 예시의 가정은 cell당 context M=256, cell당 query Q=64, 후보 k=16이다. 원래 4cell smoke와 연결하기 위한 설명용 숫자이며 최적값이 아니다. 전체 교차 query는 N(N-1)Q, own-query는 NQ, cell당 k개 방향 후보의 교차 query 상한은 NkQ다. 양방향 검사를 위해 선택한 무방향 edge를 양쪽으로 평가하면 query 상한은 2NkQ이며 중복을 제거한 실제 edge 수로 계산해야 한다. context의 내용이 변하는 교체·병합 검사는 N회 준비로 계산할 수 없다.

## 산출물

- 주장별 원자료 위치가 있는 한국어 근거 정리 보고서.
- 같은 내용의 교수님 검토용 Word 중간 검토본. 아직 추천 방향이 확정되지 않았음을 명시하며 최종 연구계획서로 표시하지 않는다. 기존 Word를 덮어쓰지 않는다.
- 작업량 계산과 문서 수치의 원자료 검증 기록, 모든 페이지의 렌더 검수 기록.

최종 추천 방향을 선택해야 한다는 원래 완료 조건은 그대로 남는다. 문서를 만들었다는 이유로 goal 완료를 선언하지 않는다. 실제 운영 제약에 대한 질문은 추가 문제 근거를 확인하기 위한 것이며 답변 전에는 그러한 제약이 있다고 가정하지 않는다.
