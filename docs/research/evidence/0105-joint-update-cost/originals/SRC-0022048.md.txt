# 83 정적 cluster의 갱신 비용을 줄이는 방향의 검토

2026-09-26. 계획을 먼저 고정하고 원문·기존 구현을 확인했다. 새 수치 실험과 모델 호출은 없다. 이 기록의 비용 식과 예시는 기호적 설명이며 실측 결과가 아니다.

## 판단

이번 후보는 **현재 추천안으로 채택하지 않는다.** 갱신이 필요한 cell을 함께 묶으면 공동 재학습의 중복 비용을 줄일 수 있다는 조건부 원리는 있다. 그러나 현재 자료에서는 어떤 cell이 언제 RCTL 갱신을 필요로 하는지, 이를 TabICLv2로 더 잘 판단할 수 있는지의 직접 근거가 없다. 비슷한 drift를 묶는 방법도 이미 존재한다. TabICLv2의 오차나 context 변화량을 이 기준에 넣는 것만으로 기존 연결 문제를 해결하지 못한다.

이 판단은 갱신 비용이라는 연구 문제가 무의미하거나 모든 drift clustering이 불가능하다는 결론은 아니다. 이번 후보의 실제 개선 근거가 아직 부족하다는 뜻이다. 상한 때문에 실험을 생략하고 통과시킨 것도 아니다.

## 기존 후보와 무엇이 달랐는가

17은 최근 자료와 누적 자료 중 무엇으로 예측할지, 77은 시간에 따라 cell 소속을 바꿀지를 살폈다. 이번에는 cell 소속을 고정한 채 **한 cell 때문에 같은 cluster 전체를 갱신하는 비용**을 줄이는 문제를 검토했다. 동적 clustering이나 모델 routing을 추가하지 않는다.

다음과 같은 조건이라면 계산상 이득이 가능하다. A·B는 첫 번째 시점에, C·D는 두 번째 시점에 모델 갱신이 꼭 필요하다고 가정하자. 두 cell을 다시 학습하는 비용을 2b라 하면, {A,B}/{C,D}는 총 4b가 들지만 {A,C}/{B,D}는 두 cluster를 두 번 갱신하므로 8b가 든다. 이는 **갱신 시점이 이미 알려져 있고, 어느 구성에서든 예측 품질이 허용되며, 같은 기간의 전체 cluster 자료로 다시 학습한다는 조건**의 산술 예다. 실제 자료에서 50%가 절감된 결과가 아니다.

일반적으로 cluster G의 갱신 시점 집합을 구성 cell의 필요한 갱신 시점 합집합으로 가정하면, 비용은 각 G에 대해 `한 번의 갱신 비용 × 합집합의 크기`를 더한 값이다. 고정 epoch·batch 크기에서 모든 cell의 같은 길이 자료를 사용한다면 한 번의 비용도 대체로 cluster 크기에 따라 늘어난다. 모델 수만 세거나 큰 cluster도 같은 비용이라고 가정하면 이 문제를 잘못 계산하게 된다.

따라서 핵심은 합집합을 최소화하는 이름이나 clustering 알고리즘이 아니다. **정확도를 해치지 않는 갱신 필요 시점을 어떤 관측 가능한 정보로 정하는가**가 먼저다.

## 가장 가까운 원문에서 확인한 내용

### A. Fed-PPBC: 변화 이후의 자료로 소속과 모델을 갱신하는 방법은 이미 있다

Hallak·Kem, *Adaptive federated learning framework for predicting EV charging stations occupancy*. DOI 10.1016/j.ijtst.2025.04.007. 저자 공개본은 2025-05-29 ResearchGate 업로드이며, 출판사 서지는 2026년 6월 22권 282–296쪽이다. [저자 공개 전문](https://www.researchgate.net/publication/391411282_Adaptive_Federated_Learning_Framework_for_Predicting_EV_Charging_Stations_Occupancy), [출판사 서지](https://www.sciencedirect.com/science/article/pii/S204604302500067X).

- §3.1·Algorithm 1: local 모델들을 먼저 학습하고 평균하여 global 모델을 만든다. cluster 중심과 관련 설정은 오프라인에 준비한다.
- §3.2.1·Algorithm 3: 최근 성능 지표의 변화와 임계값을 비교한다. 본문은 감지 window를 1로 설명한다. 이는 같은 입력에서의 참 조건부 관계 변화만을 검정하는 절차가 아니다.
- §3.2.3·Algorithm 5: 최근 점유율 벡터와 중심 간 Euclidean distance로 소속을 바꾼다. 과거 여러 갱신 시점의 합집합 비용을 최적화하는 방식과는 다르다.
- §3.2.2·Algorithm 4: 최근 n개 sample로 local 모델을 갱신하고 cluster 안에서 가중치를 평균한다. 현재의 독립 clustering과 동일하지 않다.
- §4.1, §4.5–4.7: 실제 EV 점유율 데이터 세 종류와 예측 오차 비교다. 설정별 결과를 통신 cell·RCTL의 유지 비용 절감으로 옮길 수 없다.

**반영:** ‘같이 변하는 대상을 묶어 갱신한다’는 발상은 신규성에서 제외했다. 새 후보가 다루는 정적 partition과 전체 운영 기간의 갱신 비용은 구별하되, 차이가 있다는 사실을 개선 근거로 취급하지 않았다.

접근 범위: 출판사 직접 요청은 403, HAL 공개 PDF는 확인 화면이었다. 우회하지 않았다. 저자가 올린 공개 전문의 지정 절과 알고리즘을 web 도구로 읽었으며, 원본 PDF·공식 코드 실행 검증은 하지 않았다. 본문과 표의 일부 수치·m 명칭이 일관되지 않아 성능 수치를 이번 판단 근거로 사용하지 않는다.

### B. FDA: 예측 오차의 동시·지연 변화를 비교하는 것도 기존 방법이다

Song et al., *A Fuzzy Drift Correlation Matrix for Multiple Data Stream Regression*, FUZZ-IEEE 2020. DOI 10.1109/FUZZ48607.2020.9177566. [저자 소속 기관 공개 PDF](https://opus.lib.uts.edu.au/bitstream/10453/147899/3/A%20Fuzzy%20Drift%20Correlation%20Matrix%20for%20Multiple%20Data%20Stream%20Regression.pdf).

§III 식1–8은 예측 오차를 정규화하고 구간 앞뒤 차이를 계산한 뒤 fuzzy 값으로 변환한다. 두 stream의 값 차이를 평균하여 동시 또는 지연된 drift 관계 행렬을 만든다. §IV는 실제 회귀기를 재학습한 비용 실험이 아니라 직접 생성한 일곱 개 오차 시계열이다. §IV.E는 지연 관계를 잘못 식별할 수 있음을 명시한다.

**반영:** TabICLv2 오차의 변화 시점을 비교하는 구조만으로 차별성을 주장하지 않는다. 식3은 정해진 구간에서 t 이후 자료도 쓰므로 과거 전체로 오프라인 partition을 정할 때와 실시간 감지를 구별한다. RCTL 오차로 행렬을 만들면 독립 조건에 맞지 않는다. Tab 오차로 대체하면 RCTL에 유효한 갱신 정보라는 추가 연결이 필요하다.

통계 규칙은 그대로 채택하지 않는다. 식6은 절댓값이므로 비음수인데 §III.D는 그 값의 기대값을 0, 분산은 미지수로 놓는다. 기대값이 정확히 0인 비음수 변수라면 거의 확실히 0이어야 한다. 또한 p3의 표준편차 기준과 p4의 lambda 표기에는 차이가 있다. p3·4를 렌더링하여 확인했다. 저자의 의도나 실제 코드 오류를 단정하지 않고, 이 식을 유효한 시계열 유의성 검정으로 사용하지 않는 근거로만 기록한다.

### C. 통신 장애 뒤 적응 문제는 실제 운영과 연결되지만, clustering 효과의 증거는 별도다

Ayoub et al., *Liquid Neural Network-based Adaptive Learning vs. Incremental Learning for Link Load Prediction amid Concept Drift due to Network Failures*, ONDM 2024, arXiv 2404.05304v1. [공식 학회 PDF](https://dl.ifip.org/db/conf/ondm2024/ondm2024/1570996339.pdf), [저자 원문 HTML](https://arxiv.org/html/2404.05304v1).

§III은 최근 세 관측값을 쓰는 link 부하 회귀다. §IV는 Euro28의 28 nodes·82 directed links, 정현파 기반 수요와 장애 후 경로 복구를 포함한 시뮬레이션이다. 실제 cell 트래픽에서 반복 관측한 갱신 기록은 아니다. §V는 추가 학습 없는 LNN과 5/20시점마다 갱신하는 MLP를 비교한다. Fig.3·Table I에서 유리한 방식은 변화 강도와 RMSE/MAPE에 따라 달라진다.

**반영:** 변화를 빨리 감지하고 자주 갱신하면 항상 좋아진다고 가정하지 않는다. 이 논문의 최종 예측기를 RCTL로 바꾸거나 TabICLv2를 추가하면 원문의 성능이 유지된다는 증거도 없다. 원문 p6의 Table I를 시각 대조했으며 코드 재현은 하지 않았다.

## 현재 실제 자료와의 연결

기존 `17_temporal_validity_findings.md`의 32 cell 진단을 재사용했다. Ridge·HGB 모두 최근 2주만 쓰는 방법보다 누적 자료를 쓰는 방법이 전체 평균에서 유리했다. 이전 한 주의 결과로 recent/expanding을 선택한 뒤 다음 세 주에 고정한 선택도 항상 expanding인 방법보다 불리했다. 이 결과는 갱신 비용 연구의 불가능성을 증명하지 않지만, 최근의 변화만 따라가야 한다는 근거로 사용할 수 없다.

기존 CESNET-TimeSeries24 원문 forecasting 예에서는 7일과 2일 예측 주기를 비교하며 매 예측 뒤 SARIMA를 다시 적합한다. horizon과 갱신 빈도가 함께 달라지므로 ‘같은 예측 문제에서 재학습만 자주 하면 이득’이라는 근거로 분리할 수 없다. 원문 R² 설명과 수치 방향에도 불일치가 있으므로 그 설명을 그대로 가져오지 않았다. 새로운 데이터 다운로드나 통계 계산은 없다.

## TabICLv2 역할에 남는 정확한 가정

가능한 계산은 오래된 context와 최근 context로 같은 query를 예측하고, 관계가 바뀌었을 가능성을 추정하는 것이다. 기본 API로 실행할 수 있다는 점은 이미 확인했다. 하지만 세 명제를 구별해야 한다.

1. context를 바꾸면 TabICLv2의 예측이 달라진다.
2. 그 차이가 관측 잡음·입력 분포·sample 구성 차이를 넘어선 예측 관계의 변화를 나타낸다.
3. 그 변화가 같은 cluster RCTL을 지금 다시 학습했을 때의 실익을 나타낸다.

1이 성립해도 2와 3은 자동으로 성립하지 않는다. RCTL 재학습이 불필요한 변화도 있고, 최근 sample 수가 적어 갱신 후 더 나빠지는 경우도 있다. 새로운 이름의 drift score는 이 구분을 대신하지 못한다.

선행연구 대비 남을 수 있는 질문은 ‘예측 품질을 유지하며 필요한 공동 갱신의 범위를 줄이는가’지만, 현재 증거로 추천안으로 확정할 수 없다. 정기 갱신, 기존 오차 감시, 최근 입력 변화 감시보다 좋은 행동을 정한다는 직접 근거가 필요하다. TabICLv2의 기존 직접 예측 우위를 이 근거로 대체하지 않는다.

## 보조 검토: 고정 RCTL의 출력 차원

`rctl_torch.py`의 출력층은 `Linear(steps*16, 1)`이고 마지막 sequence를 flatten한다. 따라서 L=8이면 최종 특징은 128차원이다. 마지막 channel 폭 16을 모델의 전체 출력 표현 한계로 쓰는 것은 잘못이다. 74의 rank1 출력 압축과 달리 자연스러운 용량 한계를 보려던 생각도, 최대 32 cell pilot에서 단순 출력 rank 논리로 필요성을 입증할 수 없다. 임의로 head를 줄여 제한을 만들지 않았다.
