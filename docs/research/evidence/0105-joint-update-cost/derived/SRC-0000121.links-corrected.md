# 공동 갱신 비용을 줄이는 clustering 방향의 검토

2026년 9월 26일

**현재는 이 방향을 추천안으로 채택하지 않습니다.** cell들을 함께 학습하면 모델 수를 줄일 수 있지만, 한 cell의 관계가 바뀔 때 같은 cluster 전체를 다시 학습해야 할 수 있습니다. 이 중복 비용을 줄이는 것은 검토할 만한 문제입니다. 다만 TabICLv2가 실제로 갱신이 필요한 cell과 시점을 더 잘 찾아준다는 근거는 아직 없습니다.

이번 검토에서는 새로운 모델 실험을 추가하지 않고, 선행연구의 계산 과정과 기존 실행 결과를 대조했습니다. 기존의 clustering → RCTL 구조와 RCTL 결과를 clustering에 사용하지 않는 조건을 유지했습니다.

## 검토한 아이디어

이번에는 시간에 따라 cell 소속을 계속 바꾸는 대신, **모델을 갱신해야 하는 시점이 비슷한 cell들을 처음부터 같은 cluster로 묶는 방향**을 살펴봤습니다.

예를 들어 A·B는 월요일에, C·D는 목요일에 갱신이 꼭 필요하다고 가정하겠습니다. {A,B}/{C,D}로 묶으면 각 모델을 한 번씩 갱신하면 됩니다. {A,C}/{B,D}로 묶으면 두 모델 모두 월요일과 목요일에 갱신해야 합니다. 같은 크기의 모델과 자료를 사용한다면 두 번째 구성에서 중복 작업이 생깁니다.

이는 원리를 설명하기 위한 가정입니다. 실제 자료에서 절감률을 측정한 결과는 아닙니다. 이 방향을 연구로 만들려면 **언제 갱신해야 정확도를 유지할 수 있는지**부터 알아야 합니다. 트래픽 값이 바뀌었다는 사실이나 TabICLv2의 예측이 달라졌다는 사실만으로는 충분하지 않습니다.

## 선행연구를 확인하면서 달라진 판단

| 연구 | 실제로 사용하는 정보와 결정 | 현재 연구에 주는 판단 |
|---|---|---|
| Fed-PPBC, Hallak·Kem, 2025 온라인 공개 / 2026 권호 | 성능 변화를 감시하고, 최근 점유율 벡터와 cluster 중심의 거리로 소속을 바꾼 뒤 local 모델을 갱신·평균 | 비슷한 변화 양상을 묶어 모델을 갱신하는 발상 자체는 기존 연구에 있음 |
| FDA, Song et al., FUZZ-IEEE 2020 | 예측 오차의 변화를 변환하여 여러 stream의 동시·지연 drift 관계를 계산 | TabICLv2 오차로 같은 작업을 한다는 설명만으로는 차별성이 부족함 |
| Ayoub et al., ONDM 2024 | 장애 후 link 부하 예측에서 추가 학습 없는 LNN과 주기적으로 갱신하는 MLP를 비교 | 갱신을 자주 할수록 항상 좋아지는 것은 아니며, 변화 강도와 평가 지표를 구별해야 함 |

[Fed-PPBC 저자 공개 전문](https://www.researchgate.net/publication/391411282_Adaptive_Federated_Learning_Framework_for_Predicting_EV_Charging_Stations_Occupancy)의 §3·Algorithm 3–5를 확인했습니다. 이 연구는 EV 점유율이며, 통신 cell의 고정 partition을 정하여 전체 운영 기간의 갱신 비용을 최소화하는 문제와 같지는 않습니다. 차이가 있다는 사실과 그 차이가 유용하다는 근거는 구별해야 합니다.

[FDA 원문](https://opus.lib.uts.edu.au/bitstream/10453/147899/3/A%20Fuzzy%20Drift%20Correlation%20Matrix%20for%20Multiple%20Data%20Stream%20Regression.pdf)의 §III은 예측 오차를 사용합니다. RCTL 오차를 사용하면 현재 독립 조건에 맞지 않고, TabICLv2 오차로 바꾸면 두 모델의 갱신 필요성이 연결된다는 추가 근거가 필요합니다. 이 논문의 실험은 생성한 오차 시계열이며 실제 통신 예측기의 재학습 비용 실험은 아닙니다.

[ONDM 2024 원문](https://arxiv.org/html/2404.05304v1)의 §IV–V는 통신 장애와 경로 복구를 포함한 시뮬레이션입니다. 변화에 적응하는 운영 문제를 보여주지만, 현재 cell 데이터에서 clustering으로 비용을 줄일 수 있음을 직접 검증한 결과는 아닙니다.

## 현재 증거로 확정할 수 있는 부분

다음 세 가지는 서로 다른 주장입니다.

1. **context가 달라지면 TabICLv2의 예측이 달라진다.** 모델의 작동 방식으로 확인된 내용입니다.
2. **그 차이가 실제 예측 관계의 변화를 뜻한다.** sample 수, 입력 분포, 잡음의 영향과 구별해야 합니다.
3. **그때 RCTL을 다시 학습하면 이득이 생긴다.** 모델 용량, 누적 자료, 새 자료의 양에 따라 달라집니다.

현재 확인된 1을 근거로 2와 3까지 성립한다고 제안할 수는 없습니다. 이를 해결하지 않고 drift 검사와 갱신 모듈을 추가하면 기존의 ‘TabICLv2에서 좋은 판단이 RCTL에도 좋은가’라는 문제가 다시 생깁니다.

기존 32 cell의 개발 진단에서는 Ridge와 HGB 모두 최근 2주만 사용하는 방법보다 과거를 함께 보존한 누적 방식이 평균적으로 유리했습니다. 이 결과가 모든 갱신 방식의 실패를 뜻하지는 않지만, 최근 변화만 따라가는 설계를 뒷받침하지도 않습니다. 새 후보를 유리하게 만들기 위해 이 기록을 제외하거나 재해석하지 않았습니다.

## 남겨둘 판단

이번 후보의 유효한 문제 정의는 **“같은 예측 품질을 유지하면서 불필요한 공동 재학습을 줄일 수 있는가”**입니다. 그러나 현재는 필요한 갱신 시점과 TabICLv2의 추가 판단 가치가 확인되지 않았으므로 추천안으로 확정하지 않습니다. 단순한 오차 감시·정기 갱신보다 나은 행동을 정하는 근거 없이 모듈을 추가하지 않는 것이 적절합니다.

이번 검토의 새 모델 호출과 수치 실험은 0회입니다. 누적 TabICLv2 69 context·39,360 query행, RCTL 29회 학습 기록과 상한을 유지했습니다. 최종 추천 방향과 교수님께 드릴 Word 문서는 아직 완료되지 않았습니다.

원문 위치, 비용 식의 가정, 접근하지 못한 자료, RCTL 출력 차원의 보조 검토는 [원83 상세 판단 보존본](../originals/SRC-0022048.md.txt)과 [팀용 정리](../../../records/0105-joint-update-cost.md)에 연결했습니다.
