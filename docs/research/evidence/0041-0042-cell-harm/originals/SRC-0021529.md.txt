# 41 평균에 가려진 cell별 손해의 범위 확인

2026-09-26. 새 clustering 규칙을 만들기 전에, 기존 결과의 전체 평균이 소수 cell에서의 지속적인 개선을 가리고 있는지 확인한다. 26–27의 입력 상태별 분석과 달리 이번 단위는 **cell 전체의 시간별 오차**다. 조건을 보고 cell을 선택하거나 소속을 바꾸지 않는다. 작성 중 날짜가 넘어갔으며 실행 전 이 날짜를 고정했다.

## 질문과 제한

1. 같은 primary seed의 다섯 K=4 분할은 각 cell에서 global RCTL보다 나은가? 그 방향은 개발 구간 앞·뒤 절반에서 유지되는가?
2. 모든 결과를 미리 알고 cell마다 가장 좋은 기존 예측을 고른 비실행 가능한 oracle의 이득은 어느 정도인가? 이는 관찰한 모델 집합의 진단이며, 새 clustering의 상한 또는 구현 가능한 결과가 아니다.
3. validation에서 cell마다 가장 좋았던 기존 예측 경로를 고르면 이후 개발 구간에서도 좋은가? 선택 편향과 시간 이동의 예시로만 계산한다. 이 경로는 RCTL 손실을 사용하므로 연구가 허용하는 clustering 방법이 아니다. 실제 partition, checkpoint, 파일을 변경하지 않는다.
4. 같은 입력의 단순 global Ridge/HGB는 cell별로 어느 범위에서 손해를 남기는가? 특정 cell을 제안 대상으로 사후 지정하지 않는다.

## 사전 고정한 계산

- 기존 16개 cell 전부, 기존 480개 시점 전부. 앞 240/뒤 240만 분리한다. 상태·기간·임계값 추가 탐색 없음.
- primary: global + TabICL risk / empirical risk / KNN risk / PCC / random의 seed 20260925. seed 20260926의 TabICL/empirical은 별도 표로만 보고하며 global 두 번째 seed가 없는 사실을 유지한다.
- per-cell MAE, global 대비 차이, 앞·뒤 절반 차이, 개선 cell 수, 두 절반 모두 개선 cell 수.
- 동일 primary 집합에서 cell별 사후 최소 MAE와 sample별 사후 최소 absolute error를 모두 계산하되 이름에 oracle을 명시한다. 후자는 매 시점 정답을 사용하는 더 비현실적인 기준임을 적는다.
- validation MAE로 고른 경로의 개발 MAE, validation에서 고른 경로가 global인 cell 수, 사후 cell oracle과의 차이. 동률은 global을 먼저 놓은 고정 방법 순서로 처리한다.
- global Ridge/HGB/persistence/daily/weekly의 per-cell 값은 이미 저장된 예측을 재집계한다. 재학습·새 추론 없음.

## 입력과 비용

- `results/rctl_pilot/all_predictions.npz`
- `results/frozen_fit_gap_34/summary.json`의 이미 계산한 validation per-cell MAE
- `results/observable_state_loss/arrays.npz`의 기존 단순 모델 예측
- 새 TabICL context 0, RCTL fit 0, RCTL forward 0, 저비용 모델 fit 0.
- wall 30초, RSS 1 GiB. 시작 marker·plan/code/input hash·결과·종료 marker를 저장하고 완료 실행을 반복하지 않는다. 누적 cheap 비용에 한 번만 합산한다.

## 결과가 바꿀 판단

‘평균만 나쁘고 여러 cell에서는 안정적으로 좋다’는 해석을 실제 범위로 좁힌다. 이 결과로 다른 소속·임계값을 만들지 않으며 TabICL의 이득으로 바꾸어 말하지 않는다. oracle 이득이 있더라도 TabICL로 그 선택을 구현할 수 있다는 뜻은 아니다. 목표는 분할 필요성의 증거를 분명하게 하는 것이며, oracle을 연구 추천안으로 채택하지 않는다.
