# 82. 간헐적 트래픽 후보와 선행연구 수치의 적용 범위

2026-09-26. `82_intermittence_scope_plan.md`에 따라 원문과 기존 데이터 진단을 확인했다. 새 모델 실행·수치 pilot·원자료 다운로드는 없다. 이 검토로 새 추천 방향을 확정하지 않았다.

이번에 검토한 결정은 ‘트래픽이 발생할 조건’과 ‘발생했을 때의 양’을 구별하여 함께 학습할 cell을 정하는 것이다. **현재 자료에서는 이 방향을 채택하지 않는다.** 희소 트래픽이라는 문제는 있지만, 그 증거가 현재의 Internet activity 자료와 같은 대상을 뜻하지 않으며, 발생 여부·크기를 나누는 예측과 공동 학습은 이미 구현된 방법이다. 아래는 그 판단의 근거다.

## 1. 희소성 수치를 옮기는 과정의 오류

ISP foundation model 논문 v2 §III.A는 10분 IP 자료의 99.94%, 1시간 자료의 99.21%를 gap이 있는 interval의 비율처럼 설명한다. 그러나 인용된 **CESNET-TimeSeries24 원 데이터 논문의 Table 6 제목은 ‘Percentage of time series with gaps’**이다. 분모가 전체 관측 시점이 아니라 시계열 수다. subnet의 86.31%·31.75%, institution의 77.81%·21.83%도 같은 구분이 필요하다.

원 데이터 논문은 Fig. 6 설명에서 관측된 시점의 평균 비율을 별도로 다룬다. 또한 2024-05-21 16:30부터 06-04 20:00 무렵까지 한 monitoring probe의 장애가 있었다고 명시한다. 따라서 빈 기록을 모두 실제 무통신으로 해석해서는 안 된다. ISP 논문의 zero filling은 저자들이 채택한 처리 방식이지, 누락 원인이 모두 동일하다는 확인이 아니다.

이번 기록에서는 **‘99.94%의 관측값이 0이다’라는 주장을 사용하지 않는다.** 앞선 자료를 통째로 부정하는 것도 아니다. 빈 구간이 널리 나타난다는 사실과, 각 시계열의 빈 구간 비중·원인은 다른 정보다.

출처: [ISP v2 §III.A–C](https://arxiv.org/html/2511.17529v2), [CESNET 원문 Technical Validation·Table 6](https://pmc.ncbi.nlm.nih.gov/articles/PMC11865510/). Sci. Data DOI `10.1038/s41597-025-04603-x`. 원문 HTML은 정상적인 공개 요청으로 확보했다. 이후 web 도구의 PMC 요청에는 확인 화면이 나타났고 이를 우회하지 않았다.

## 3. 이미 확보한 데이터가 보여 주는 범위

새 통계를 계산하지 않고 `results/population_scope_diagnostic.json`과 생성 코드를 다시 읽었다. 처음 35일의 **1시간 Internet activity, 10,000 grid 전체**에서 저장된 zero_fraction은 `0.0001975`, 즉 0.01975%다. 이 파일의 검사는 840시점 ×10,000 grid에 해당한다. 이전 10분 CSV의 세 cell도 확인한 첫 30일에는 0이 없었다.

이 자료로 ‘0이 대부분인 기존 cell의 예측’을 주된 문제로 삼을 직접 근거는 확보되지 않았다. 반대로 원시 10분 자료 전체나 실제 기지국 전반에 희소성이 없다는 뜻도 아니다. 시간 집계, 지리적 집계, 채널, 반올림, 누락 처리에 따라 관측 분포가 달라진다. STCNet README는 소수 셋째 자리 반올림과 SMS·통화 채널 결합을 명시한다. 이번에 원자료의 모든 누락 원인을 추적하거나 새로운 보간 여부를 확인하지는 않았다.

근거: `population_scope_diagnostic.py:20–22,88`, `results/population_scope_diagnostic.json`, `32_resolution_findings.md`, `sources/STCNet_README.txt`. 이 자료의 단위는 Internet activity이며 bytes 또는 Mbps로 바꾸어 쓰지 않는다. 앞선 51–55의 beam/cell 구별도 유지한다.

## 4. 새 알고리즘을 붙이기 전에 구별해야 하는 두 문제

다음은 원문 성능 결과가 아니라 비음수 target의 기본 성질을 적용한 논리 확인이다.

첫째, **분류 결과를 곱하는 것과 조건부 평균을 구하는 것은 다르다.** 다음 시점에 양의 트래픽이 발생할 확률을 p(x), 발생했을 때의 평균량을 a(x)라 하면 전체 평균은 p(x)a(x)다. 0/1로 먼저 결정한 값에 a(x)를 곱하면 일반적으로 이 평균과 다르다. 양의 시간만으로 a(x)를 학습한 것과 전체 시간의 y를 학습한 것도 구별해야 한다. beam 논문의 코드가 어떤 gradient 경로를 쓰는지 확인하지 않은 상태에서 구현 오류라고 단정하지 않는다.

둘째, **MAE와 MSE의 목표가 다르다.** 같은 입력 x에서 실제값이 90% 확률로 0, 10% 확률로 100이면 MAE에 맞는 중앙값은 0이고 MSE에 맞는 평균은 10이다. 모델이 0을 예측하는 현상만으로 학습 실패를 선언할 수 없다. 이는 설명을 위한 분포이며 실제 데이터 측정이 아니다. 데이터 전체의 0 비율을 입력별 발생 확률과 같다고 놓아서도 안 된다.

따라서 RCTL이 어떤 손실로 어떤 양을 예측하는지 유지한 채 clustering을 설계해야 한다. 발생/양의 크기 분포가 다르더라도 필요한 최적 예측값이 같으면 분리 이득이 없을 수 있다. 04·23–28에서 검토한 손실 목적의 구분을 다른 이름으로 다시 제안하지 않는다.

## 5. TabICLv2의 역할에 대한 판정

회귀 TabICLv2가 실제로 제공할 후보 정보는 같은 관측 이력에서의 트래픽량 예측이다. 그러나 많은 분위수를 출력한다는 사실만으로 실제 무통신의 확률이나 누락 원인을 정확히 추정했다고 볼 수 없다. 여러 cell의 발생/크기 관계로 소속을 정한다면, 그 결정이 계절별 발생 빈도·단순 회귀·기존 분리형 예측과 어떻게 다른지부터 보여야 한다.

현재는 그 결정과 개선 근거가 없다. 기존 Milan 진단에서 중요한 희소성 문제도 확인되지 않았다. 따라서 **간헐성 점수, 분류 head, 새로운 context 선택 모듈을 현재 연구에 추가하지 않는다.** 이는 간헐 시계열 연구 전체를 부정하는 판단이 아니라 현재 대상·정보·증거에서의 진입 판단이다.

재진입에는 다음 두 가지가 함께 필요하다. (1) 원래 관측 단위와 누락 원인을 구별할 수 있는 기존 cell 자료에서 반복적인 실제 무통신이 예측 손해를 만든다는 근거, (2) 이미 있는 발생/크기 공동 학습과 다른 유용한 공유 결정이다. 단순히 beam을 cell로 바꾸어 부르거나, 0을 임의로 늘리거나, 새 손실 이름을 붙여 이 조건을 대신하지 않는다.

- PDF 두 개, 합계 4,132,717 bytes·21쪽. Citywide p3, beam p9·12를 렌더링해 표·수식을 직접 확인했다. 논문 전체의 모든 실험을 재현했다고 주장하지 않는다.
- source HTML·PDF·추출문·hash를 `sources/intermittence_82/`에 저장했다. 통계는 기존 결과를 읽은 것이며 새 데이터 진단이 아니다.
- 새 TabICL context/query 0, 단순 모델 fit 0, RCTL fit/forward 0, 외부 코드 실행 0. 원장은 바꾸지 않았다. 남은 TabICL은 11 context·20,640 query행, 새 RCTL fit은 0회다.
