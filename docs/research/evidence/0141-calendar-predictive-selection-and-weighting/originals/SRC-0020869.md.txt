# 112 시각 보정 후보의 첫 예측 확인 결과

2026-09-26. 사전 계획 `112_calendar_predictive_comparison_plan.md`와 111의 고정 입력을 사용했다. 현재 보정 후보는 첫 예측 기준을 통과하지 못했으며 RCTL 확인으로 진행하지 않는다.

## 무엇을 비교했는가

앞 21일의 donor context 504개, 공통 입력 조건을 통과한 14개 방향과 대상 cell 11개를 사용했다. 세 이동량 모두 같은 query에서 비교했다. 앞 절반의 query로 이동량을 고르고 뒤 절반에서 평가했다. TabICLv2·Ridge·HGB의 입력과 정답은 같았다. 뒤 절반에 남은 방향별 query는 총 402개다. 각 방향 안에서 query를 평균하고, 각 cell 안에서 donor를 같은 비중으로 평균한 뒤 11개 cell을 같은 비중으로 평균했다.

이 기간은 이미 연구 설계에 사용된 개발 자료다. 독립 미래 평가나 대규모 성능 결과로 해석하지 않는다.

## 선택자와 평가 예측기를 분리한 결과

열은 실제 값을 예측한 모델이며, 행은 그 모델에 적용할 시각 이동량을 고른 방법이다. 작은 값이 좋다. 새 모델을 재호출하지 않고 저장된 예측을 교차 조회했다.

| 이동량 선택 방법 | TabICLv2 MAE | Ridge MAE | HGB MAE |
|---|---:|---:|---:|
| 보정 없음 | 0.124197 | 0.100080 | 0.100335 |
| 과거 평균 파형 | 0.125479 | 0.099738 | 0.101291 |
| TabICLv2 | 0.124745 | 0.101605 | 0.100851 |
| Ridge | 0.124977 | 0.100432 | 0.100790 |
| HGB | 0.122876 | 0.098535 | 0.102395 |

TabICLv2가 고른 보정량을 TabICLv2로 평가한 MAE는 무보정 대비 **0.000549 증가**했다. 평균 파형 선택보다는 작지만, 사전 계획은 무보정과 평균 파형보다 모두 작아야 다음 단계로 진행하도록 정했다. 따라서 `first_predictive_gate_passes=false`다. HGB가 고른 이동량도 HGB 자신의 뒤 구간에서는 악화하여 선택자와 예측기를 혼동하면 안 된다.

같은 방향별 query mask에서 자기 cell context를 사용한 MAE는 TabICLv2 0.080228, Ridge 0.092467, HGB 0.084306이었다. **자기 자료로 예측하는 능력과 다른 cell의 자료를 사용할 시각을 선택하는 능력은 다른 결과**다. 자기 자료와 다른 cell 자료만 쓰는 비교를 실제 혼합 context의 손해로 확대하지 않는다. 101의 혼합 context 직접 예측 결과도 그대로 유지한다.

## 집계 검증

저장된 선택이 앞 절반 정답만으로 재현되는지 확인했고, 독립적으로 펼친 query 가중치로 모든 교차 표를 재계산했다. 최대 차이는 2.78e-17이다. 입력·checkpoint hash, 14개 내부 predict 호출, 실제 사용량도 대조했다.

뒤 절반을 다시 둘로 나눈 결과를 각각 별도로 정규화하면 방향별 query 수 차이 때문에 전체 지표와 다른 가중치가 된다. 두 하위 구간 평균을 단순 평균하지 않는다. 원래 전체 지표의 가중치를 유지한 Tab 선택−무보정의 기여는 앞쪽 -0.000469, 뒤쪽 +0.001018이며 합계 +0.000549로 일치한다. 이 집계 문제를 이유로 사전 주 지표를 바꾸지 않았다.

## 판단과 비용

현재 세 이동량·고정 context·지원 범위에서 '평균 파형을 맞추면 예측 관계도 개선된다'는 진행 근거를 얻지 못했다. 모든 시각 보정 연구가 실패한다는 뜻은 아니며, 이 후보를 위한 이동 범위 확대·유리한 cell 선별·RCTL 학습은 하지 않는다.
