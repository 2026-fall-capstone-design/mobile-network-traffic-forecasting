# 시각 보정 실측 이후의 연구 판단

2026년 9월 26일. clustering → RCTL 구조를 유지하며 후보를 검토하고 있습니다. **이번 시각 보정 후보는 예측 비교를 통과하지 못해 후속 RCTL 학습을 진행하지 않습니다.** cluster 크기 제한을 없애는 변경과 입력 미분을 이용하는 변경도 현재 추천안으로 채택하지 않았습니다. 무엇이 실제로 확인됐는지 아래에 구별했습니다.

## 1. 하루 파형이 가까워진다고 다음 값 예측도 좋아지는 것은 아니었습니다

앞선 분석에서는 cell별 활동 시각을 맞추면 다음 주의 하루 평균 파형 차이가 약 9.2% 줄었습니다. 이번에는 실제 최근 트래픽값과 정답 시점을 그대로 두고, 모델에 제공하는 시각 표시만 보정했습니다. 과거 자료로 보정량을 고른 뒤 그 선택을 이후 구간에 고정했습니다.

같은 query를 사용한 TabICLv2의 결과는 다음과 같습니다. 작은 MAE가 좋습니다.

| 시각 보정량을 정한 방법 | 이후 확인 구간의 MAE |
|---|---:|
| 보정하지 않음 | 0.124197 |
| 과거 평균 파형으로 선택 | 0.125479 |
| TabICLv2의 예측 오차로 선택 | 0.124745 |

TabICLv2가 고른 보정량은 평균 파형 기준보다는 좋았지만 보정하지 않은 경우보다 오차가 컸습니다. 사전에 정한 진행 기준을 충족하지 않았습니다. 이 결과를 보고 이동 범위나 평가 cell을 바꾸어 이점을 찾지는 않았습니다.

한편 같은 확인 입력에서 자기 cell의 context를 사용하면 TabICLv2의 MAE는 0.080228로, Ridge 0.092467과 HGB 0.084306보다 작았습니다. 이 결과는 TabICLv2의 직접 예측 능력을 보여 줍니다. 그러나 **좋은 예측기라는 사실이 다른 cell을 함께 사용할 조건도 더 잘 선택한다는 뜻은 아닙니다.** 다른 cell의 자료만 쓰는 이번 비교를 실제 혼합 context의 손해와도 구별해야 합니다.

이번 확인은 14개 방향과 11개 대상 cell에서 수행했습니다. 전체 도시의 성능 평가가 아니며, 이미 설계에 사용한 개발 자료입니다. 수치는 저장 예측을 다시 계산해 검증했습니다.

## 2. cluster 크기를 자유롭게 해도 TabICL의 기여는 별도로 확인해야 합니다

기존 소규모 실험에서는 16개 cell을 네 cluster에 4개씩 배정했습니다. 원 UPC의 cluster 수 제한에는 이와 같은 동일 크기 조건이 없습니다. 따라서 모델 수를 네 개로 유지하면서 각 cluster의 크기는 달라도 되도록 비교했습니다.

제약을 없애면 소속이 바뀌고 일부 오차도 줄었습니다. 다만 동일한 예측 규칙으로 비교했을 때 TabICL 소속이 항상 좋지는 않았습니다. 어떤 규칙으로 최종 값을 계산하느냐에 따라 TabICL 소속과 단순 실제값 소속의 순위가 바뀌었습니다.

이 비교는 저장된 위험 추정값과 간단한 상태별 수정 예측을 사용했습니다. RCTL을 새로 학습한 결과는 아닙니다. **cluster 크기 제약을 없앤 것 자체는 기존 UPC를 넘어서는 신규성이 아니므로**, 이를 새 연구 방향으로 채택하지 않았습니다.

## 3. 입력 변화에 대한 반응을 비교하는 발상도 선행연구와 겹칩니다

입력이 증가할 때 예측도 증가하는지, 반대로 감소하는지를 이용해 관계를 구별하는 방향을 검토했습니다. SRDML(KDD 2022)은 이미 출력의 입력 미분으로 task 관계를 계산하고 이를 학습 규제에 사용합니다. 공개 코드에서도 미분의 부호를 유지한 채 차이를 비교합니다. 부호를 새로 반영한다는 설명만으로 차별점을 만들 수 없습니다. [논문과 서지](https://arxiv.org/abs/2207.01117), [공식 구현](https://github.com/BaiTheBest/SRDML/tree/b65d6da39a2f92491f0982790a9bd3a3e2d5b9bf)

현재 연구는 RCTL 학습 전에 cell 소속을 확정해야 합니다. 따라서 다른 모델에서 얻은 반응이 RCTL이 함께 학습하기 좋은 관계를 나타내는지 여전히 확인해야 합니다. TabICLv2의 예측값이 정확하다는 결과를 미분의 정확성이나 RCTL의 공동 학습 이점으로 바꾸어 설명하지 않겠습니다.

## 4. 함께 학습할 이득은 어떤 기준으로 측정해야 합니까

*Towards Principled Task Grouping for Multi-Task Learning*은 자기 task만 한 단계 학습한 경우와 다른 task를 함께 학습한 경우를 비교합니다. 출발 상태를 맞춘 뒤 손실 차이를 보는 방식입니다. 실제 모델과 optimizer를 갱신하므로, 고정 TabICLv2의 context를 바꾸는 비교와 측정 대상이 다릅니다. RCTL을 이 계산에 넣으면 현재 정한 clustering 독립 조건도 바뀝니다. [arXiv 원문](https://arxiv.org/abs/2402.15328v2), [공식 구현](https://github.com/LOGO-CUHKSZ/Principled-Task-Grouping/tree/3e783254a233b9ee109491b422db0d08836c0cf3)

이 논문에서 가져올 핵심은 **다른 자료의 도움을 판단할 때, 자기 자료만 사용했을 동일한 행동을 비교 기준으로 두어야 한다는 점**입니다. 그러나 그 계산기를 TabICLv2로 바꾸는 것만으로 RCTL의 공동 학습 이점을 알 수 있게 되지는 않습니다.

실험 구성도 구별했습니다. 논문은 여러 시계열을 공동 입력하고 출력별 decoder를 사용하며, 같은 task가 여러 group에 속할 수 있습니다. 현재는 각 cell을 한 cluster에 배정하고 그 안의 실제 sample로 scalar RCTL을 학습합니다. 두 구조의 grouping 효과를 동일하게 해석하지 않겠습니다. 또한 무작위 task 추출은 쌍 비교 비용을 줄여도 제곱 규모의 비용을 없애지는 않습니다.

TMLR 공식 목록에서 2026년 6월 출판과 공식 코드를 확인했습니다. 다만 최종 PDF는 접근 확인 화면 때문에 확보하지 못해, 실제 방법 분석은 2025년 5월 arXiv v2와 공개 코드에 근거했습니다. 두 버전이 완전히 같다고 표시하지 않았습니다. [공식 출판 목록](https://jmlr.org/tmlr/papers/)

## 5. 다음에는 무엇을 확인합니까

다음 질문은 **cell 사이의 관계가 실제로 다른 것인지, 자료가 한정돼 관계를 부정확하게 추정한 것인지 구별할 수 있는가**입니다. 관계 추정의 분산을 clustering에 반영한 선행연구의 구체적인 조건을 확인하겠습니다. TabICLv2가 출력하는 미래값의 분위수 폭을 곧바로 관계 추정의 불확실성으로 사용하지는 않겠습니다.

후보는 **기존 방법의 구체적인 오판 → TabICLv2가 추가로 추정하는 정보 → 달라지는 cell 소속 → 실제 RCTL 학습 자료의 변화**가 연결되어야 합니다. 이 연결을 바꾸지 않은 채 보정항이나 모델 모듈만 추가하지 않겠습니다.

이번 시각 보정에는 TabICL 14 context와 3,096개 query 행을 사용했습니다. 누적 사용량을 보존했고 추가 RCTL 학습은 하지 않았습니다. 현재 남은 허용량은 TabICL 18 context·13,288개 query 행과 RCTL 통합 적합 9회입니다. 최종 추천 방향과 최종 Word는 아직 미완료이며, 기존 문서는 보존하고 있습니다.
