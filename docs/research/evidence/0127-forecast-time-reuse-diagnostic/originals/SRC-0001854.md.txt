# 97. 저장된 RCTL 예측의 재사용 가능성 확인

2026-09-26. 새 수치 계산 전에 고정한다. 96은 파라미터 병합과 예측 관계의 차이를 확인한 제한적 진전이었다. 이번에는 95의 batch 비용을 기준으로 예측 실행 횟수를 줄일 여지가 있는지 확인한다. 후보 추천과 구별하는 문제 존재 진단이다.

## 바뀌는 질문과 선행 범위

83은 모델의 재학습 시점, 49는 다른 cell의 대표 출력으로 복원하는 문제였다. 이번에는 학습된 가중치와 cell partition을 그대로 두고, 같은 cell의 직전 RCTL 예측을 이후 시점에 재사용하는 serving 방식을 확인한다. 실제 자료를 숨기지 않고 모든 현재 관측값은 계속 이용 가능하게 둔다.

Skip RNN·Delta Networks 등에서 시간적으로 중복된 계산을 줄이는 발상은 이미 알려져 있다. 이번의 단순 주기적 재사용은 신규 알고리즘으로 주장하지 않는다. TabICLv2를 넣기 전에 효과의 크기와 강한 단순 대안을 확인하는 것이 목적이다. 저장된 RCTL 결과로 새 clustering이나 임계값을 정하지 않는다.

## 고정 조건

- 기존 16개 cell, 저장된 개발 구간 480시간. `all_predictions.npz`의 8개 방법을 모두 포함한다. 새 RCTL·TabICLv2 추론과 모델 학습은 없다.
- 이전 원시 관측값은 같은 정규화와 cell 순서를 확인한 기존 `design_data.npz`의 마지막 정답과 이후 관측값으로 구성한다. 시간 1008을 예측할 때 1007까지의 실제값만 사용할 수 있다. 첫 연결값 또는 시간 경계를 확인할 수 없으면 중단한다.
- 매시간 새로 계산한 기존 RCTL 예측과, RCTL 없이 직전 실제값을 사용하는 persistence를 기준으로 둔다.
- 재계산 간격 d는 결과를 보기 전에 {1,2,3,6}시간으로 고정한다. 시작 시점과 이후 d시간마다 새 예측을 사용한다. 처음 시작 위상은 0이며 유리한 위상을 찾지 않는다.
- 비교 A: 새 계산 전까지 마지막 RCTL 예측값을 유지한다.
- 비교 B: 마지막 RCTL 예측값에 ‘현재 실제값 − 그 예측을 계산할 당시의 최근 실제값’을 더한다. 즉 마지막 RCTL이 예측한 한 시간 증가량을 현재 실제값에 더한다. 관측값만으로 하는 산술 처리이며 재학습이나 새로운 예측 모델이 아니다. 이 방식은 현재 모델의 정확한 출력 재현을 보장하지 않는다.
- d=1에서는 두 방식 모두 저장된 RCTL 예측과 정확히 같아야 한다. 비교 B가 과거 예측을 사용하는 시점에는 현재 시점의 RCTL 값을 읽지 않아야 한다. 수식상의 시간 인덱스와 배열을 대조한다.

## 기록할 것과 판단

전체·앞 240시간·뒤 240시간의 cell 평균 정규화 MAE, cell별 MAE, 매시간 RCTL 대비 변화량을 모두 기록한다. 임의 허용 악화율을 정해 성공을 선언하거나 가장 유리한 d만 선택하지 않는다. 원래 강한 global K1도 같은 재사용 규칙을 적용하여 함께 비교한다.

예측 행 수는 `16×ceil(480/d)`, 같은 시각에 같은 모델의 cell을 batch로 처리하는 호출 수는 `K×ceil(480/d)`로 산출한다. 이는 실행 시간 측정이 아니다. 실제 관측 수집·입력 준비·cache 산술·모델 준비 비용을 없다고 간주하지 않는다. 새 wall-time 속도 향상을 주장하지 않는다.

오차 증가가 크거나 global·persistence 같은 단순 기준이 충분하면 복잡한 Tab 기반 재사용/clustering을 추가하지 않는다. 일부 절충이 나타나도 이를 새 소속의 유용성으로 확대하지 않는다. 다음 후보 진입에는 (1) 단순 주기/현재값 기준이 놓치는 실제 손해, (2) Tab이 바꾸는 자료 기반 결정, (3) 그 결정에서 clustering이 필요한 이유가 별도로 필요하다. 이번 계산만으로 추천 방향을 확정하지 않는다.
