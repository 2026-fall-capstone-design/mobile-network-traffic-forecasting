# 97. 예측 실행 주기를 줄이는 단순 대안의 실제 확인

2026-09-26. 사전 계획에 따라 저장된 RCTL 예측을 재생했다. 학습된 모델과 cell 소속은 변경하지 않았고, 새 모델을 호출하지 않았다. 이전에 확인한 16개 cell·480시간을 사용했으므로 개발 진단이다.

## 이번에 확인한 변화

**예측 계산을 줄이는 방향의 비교 기준에 ‘global RCTL의 단순한 시간 재사용’을 포함해야 한다.** 기존 예측값을 그대로 유지하면 오차가 크게 늘지만, 그 모델이 예측했던 증가량을 현재 실제값에 더하면 악화가 줄었다. 이 변경에는 TabICLv2나 새로운 clustering이 필요하지 않다.

이는 추천 연구 방향을 확보한 결과가 아니다. 새로운 clustering을 넣어야 하는 이유가 확인된 것도 아니다. 다만 계산 비용을 줄이려는 후속 후보가 넘어야 할 실제 기준을 확인했다. 95는 같은 시간의 여러 cell을 batch로 처리했으며, 이번에는 일부 시간의 모델 실행 자체를 생략하는 것을 다룬다.

## 어떤 값을 재사용했는가

시점 s에서 RCTL이 s+1의 트래픽을 110으로 예측했고, 그때 최근 실제값이 100이었다면 예측한 증가량은 10이다. 다음 시점의 실제값이 108일 때 새 RCTL 계산을 생략한다면 다음 두 방식을 비교할 수 있다.

- 출력 유지: 마지막 예측값 110을 계속 사용한다.
- 증가량 유지: 현재 실제값 108에 이전에 예측한 증가량 10을 더해 118을 사용한다.

두 번째 방식도 새로운 실제 관측값을 매시간 읽는다. 관측·통신 비용이 사라지는 방식이 아니다. 또한 그 시점에 RCTL을 새로 실행하면 나오는 값과 같다는 보장은 없다. 위 숫자는 동작 설명이며 결과 수치가 아니다.

재계산 간격은 결과를 보기 전에 1·2·3·6시간, 시작 위상은 0으로 고정했다. 모든 cell을 매시간 계속 예측하며, 생략하는 것은 RCTL의 새 계산이다. 확인할 미래 정답은 오차를 계산할 때만 사용했다.

행 수·호출 수는 해당 재사용 방식을 실행할 때 필요한 횟수의 산술값이다. 이번 진단에서는 이미 저장된 예측을 읽었으며 그 횟수만큼 신경망을 실행하지 않았다. 실제 지연시간 감소율을 측정한 표가 아니다.

Global의 2시간 증가량 재사용은 매시간 계산보다 MAE가 9.37% 크지만, 전체 20일 평균에서는 매시간 계산한 두 K4 방법보다 작았다. 이 9.37%를 허용 가능한 악화라고 정하지 않는다. 사용 목적에 따른 정확도·비용 절충의 한 점이다.

기간별로 보면 결과는 다르다.

| 비교 | 앞 10일 MAE | 뒤 10일 MAE |
|---|---:|---:|
| Global, 매시간 | 0.068523 | 0.073613 |
| Global, 2시간마다 증가량 재사용 | 0.078791 | 0.076659 |

따라서 global 재사용이 두 K4 방법보다 모든 기간에서 우월하다고 주장할 수 없다. 전체 비교의 이득은 뒤 구간의 차이에 영향을 받는다. Global 자체의 매시간 계산 대비 악화도 앞·뒤에서 각각 약 14.98%·4.14%로 달랐다.

RCTL 없이 현재 실제값을 다음 값으로 사용하는 persistence의 전체 MAE는 0.085135였다. Global의 2시간 증가량 재사용은 이보다 작지만 3시간 재사용은 이보다 컸다. 비용을 줄였다는 사실만으로 모델을 쓸 이유가 계속 유지되는 것은 아니다.

## 선행 원리와 혼동하지 않을 부분

[Delta Networks, ICML 2017](https://proceedings.mlr.press/v70/neil17a.html)의 §2 식 2–5는 고정 행렬에 대해 `W·x_t = W·(x_t−x_(t−1)) + W·x_(t−1)`로 계산을 재사용한다. 차이를 생략하지 않으면 정확한 등식이며, §3은 이를 GRU의 내부 연산에 적용한다. §4는 작은 변화량을 잘라낼 때 발생하는 근사 오차와 누적 문제를 구별한다.

이번의 출력 또는 증가량 유지에는 위 등식을 RCTL 전체에 적용하지 않았다. RCTL의 비선형 내부 연산을 생략한 결과가 동일하다는 주장도 하지 않는다. 표는 출력 수준의 근사를 실제 관측값과 대조한 결과다. Delta Networks의 음성·조향 실험 속도 수치를 통신 트래픽에 옮겨 쓰지 않는다.

[Skip RNN, ICLR 2018](https://arxiv.org/abs/1708.06834)은 학습한 gate로 recurrent state 갱신을 생략하는 직접 관련 연구다. 이번에는 서지·초록 범위만 확인했고 OpenReview 전문 URL은 확인 화면으로 연결되었으므로, 세부 알고리즘을 검증한 근거로 사용하지 않았다. 해당 논문을 재현한 실험이 아니다.

## TabICLv2와 clustering에 대한 판단

이번 비교는 TabICLv2를 사용하지 않았다. 새 계산이 필요한 시점을 Tab으로 추정하는 안을 검토하더라도 다음 두 질문이 남는다.

1. 최근 실제값, 시간대, 단순 주기 규칙보다 새로 계산할 시점을 더 잘 판단하는가. Tab 추론을 매시간 추가하면 절약하려던 RCTL 비용보다 커질 수 있으므로 준비·갱신 비용도 포함해야 한다.
2. cell마다 별도로 계산을 생략하거나 하나의 global RCTL에서 필요한 cell만 batch로 처리하는 방법보다, cell들을 다른 모델로 나누는 clustering이 어떤 이득을 주는가.

RCTL의 실제 예측 변화·오차를 읽어 cell 소속을 바꾸는 방식은 현재 독립성 조건에 맞지 않는다. 이번 사후 진단으로 새 partition이나 threshold를 선택하지 않았다. 기존 RCTL 출력으로 비용 절충을 살핀 것과 RCTL을 clustering의 결정에 넣는 것을 구별한다.

따라서 **단순한 예측 재사용 또는 거기에 Tab을 덧붙이는 방향은 아직 추천하지 않는다.** 후속 비용 후보에는 이번에 확인한 단순 global 재사용 기준을 포함한다. Tab의 예측 우위만으로 실행 시점 선택이나 cell 분리의 효용을 대신하지 않는다.

## 실행 기록

- 입력은 `all_predictions.npz`, `design_data.npz`, `evaluation_data.npz`, 기존 summary다. cell 순서·척도·시간 1007→1008 연결을 확인했다. 현재값 구성에 미래 target을 넣지 않았다.
- 기존 8개 방법 × 두 재사용 방식 × 네 주기 × 세 평가 구간, 총 192개 결과 행을 보존했다. 1시간 간격은 원 예측과 같고 새 계산 시점에는 원 예측값을 사용한다는 불변 조건을 확인했다.
- 첫 메타데이터 점검은 NPZ의 object 날짜 배열을 읽으려다 중단했다. 필요한 숫자 배열만 읽도록 했으며 pickle을 활성화하지 않았다. 첫 실행 시도는 bundled Python에 psutil이 없어 import에서 종료됐다. run marker와 수치 작업 전이었으며, 기존 모델용 runtime에서 진단을 한 번 정상 실행했다.
- 숫자 분석 0.0252162초, 자료 읽기·결과 저장을 포함한 기록 구간 0.2157690초를 cheap 예산에 한 번 반영했다. import·초기 hash·사전 메타데이터 읽기까지 포함한 end-to-end 시간은 아니다. 새 Tab/RCTL/기타 모델 fit·forward·gradient는 모두 0이다.
- 누적 기록 modeling 시간 1,998.2764094초, 새 원장 hash `807600a7666a6d6912c8db3014a033b5c3c7643527a02fc726da14cb8664d34f`. 잔여 Tab 11 context/20,640행, 추가 RCTL fit 0이다.

이번 확인은 비용 연구의 단순 비교 기준을 구체화한 진전이며 최종 추천 방향·최종 Word의 완료를 뜻하지 않는다.
