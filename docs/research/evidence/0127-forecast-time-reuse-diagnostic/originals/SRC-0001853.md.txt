# 예측을 매시간 새로 계산해야 하는가

2026년 9월 26일 · 연구 방향 재설계 중간 확인

**RCTL 계산을 줄이는 연구를 제안하려면, 새로운 clustering에 앞서 단순한 예측 재사용과 비교해야 합니다.** 저장된 16개 cell·20일 예측을 확인한 결과, 마지막 예측을 현재 관측값으로 보정하는 간단한 방법도 정확도와 계산 횟수 사이의 절충을 만들었습니다. 이 결과는 TabICLv2의 기여가 아닙니다.

## 확인한 방법

RCTL이 최근 실제값 100에서 다음 값을 110으로 예측했다면, 그 모델은 증가량 10을 예상한 것입니다. 다음 시점에 실제값 108이 관측되면 RCTL을 새로 계산하는 대신 `108+10=118`을 예측값으로 사용할 수 있습니다. 이 예시는 방법을 설명하기 위한 숫자입니다.

이 방식은 현재 실제값을 계속 관측하면서 이전 예측의 증가량만 재사용합니다. 데이터 수집을 생략하지 않으며, RCTL을 새로 계산한 결과와 같다는 보장도 없습니다. 오차가 얼마나 달라지는지를 실제 자료로 확인했습니다.

## 결과와 의미

| 방법 | 정규화 MAE | 새 예측 행 수 |
|---|---:|---:|
| Global RCTL, 매시간 계산 | 0.0711 | 7,680 |
| Global RCTL, 2시간마다 계산·사이 시점 증가량 재사용 | 0.0777 | 3,840 |
| 실제값 risk로 묶은 RCTL 4개, 매시간 계산 | 0.0816 | 7,680 |
| Tab risk로 묶은 RCTL 4개, 매시간 계산 | 0.0873 | 7,680 |
| RCTL 없이 최근 실제값 그대로 사용 | 0.0851 | 0 |

MAE는 작을수록 좋습니다. 예측 행 수는 해당 방식을 실행할 때 필요한 신경망 입력 행 수를 계산한 것이며, 이번에는 저장된 예측을 재생했습니다. 실제 실행 시간이 절반으로 줄었다는 측정 결과는 아닙니다.

Global RCTL의 2시간 재사용은 매시간 계산보다 오차가 약 9.37% 커졌습니다. 대신 신경망에서 새로 처리할 예측 행 수는 절반입니다. 이 정도의 오차 증가를 허용할지는 정하지 않았습니다.

전체 20일 평균에서는 이 단순한 방법이 기존 4개 cluster 모델을 매시간 계산하는 방법보다 오차가 작았습니다. 그러나 **앞 10일에는 4개 cluster의 매시간 계산이 더 정확했고, 뒤 10일에는 global 재사용이 더 정확했습니다.** 모든 기간에서 우월한 방식으로 해석하면 안 됩니다.

계산 재사용 자체는 기존 연구에도 있습니다. [Delta Networks](https://proceedings.mlr.press/v70/neil17a.html)는 신경망 내부의 변화량을 이용해 연산을 줄입니다. 이번 확인은 그 내부 알고리즘을 구현한 것이 아니라, 이미 계산한 최종 예측값을 재사용했을 때의 실제 오차를 살핀 것입니다.

## 현재 연구 방향에 반영할 판단

TabICLv2로 새 예측이 필요한 시점을 고르는 아이디어에는 여전히 두 가지 근거가 필요합니다. 첫째, 최근 실제값과 단순 주기만 쓰는 방법보다 좋은 시점을 골라야 합니다. 둘째, 하나의 global RCTL에서 필요한 cell만 계산하는 것보다 clustering으로 모델을 나누는 이유가 있어야 합니다.

이번 결과만으로 이 두 조건이 충족되지는 않습니다. 따라서 예측 재사용을 새 연구 방향으로 추천하지는 않았습니다. 다만 이후 비용 절감 후보를 평가할 때, 여기서 확인한 단순 대안을 빠뜨리지 않도록 비교 기준에 반영했습니다.

새로운 모델 학습·추론은 수행하지 않았습니다. 기존 소속과 가중치를 유지했으며, 최종 추천 방향은 아직 확정되지 않았습니다.
