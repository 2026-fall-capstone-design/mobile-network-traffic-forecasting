# 대표 입력 축약 실패에 대한 재설계 확인

첫 risk-table 후보의 설계 query에서 TabICL 직접 median MAE는 0.072614, 대표 입력에서 가져온 median은 0.140444였다. 약 두 배의 오차는 그대로 최종 모델에 연결하기 어려운 근거다. RCTL 학습은 진행하지 않는다. 서로 다른 clustering이 나왔다는 사실을 성공으로 사용하지 않는다.

이번 진단은 이미 저장한 예측만 사용한다. 새 TabICL/RCTL 실행은 없다. test target도 읽지 않는다.

1. 대표 입력과 실제 query의 최근값 차이를 복원하면 얼마나 달라지는지 계산한다: `prediction(x) = last(x) + median(anchor(x)) - last(anchor(x))`. 값의 기준을 옮기는 연산은 동일 anchor의 cell 간 상대 비교와 risk-table partition을 바꾸지 않는다. 이를 새 clustering 알고리즘이라고 부르지 않는다.
2. 원래의 공통 anchor 분포를 실제 query 위치로 복원했을 때, direct conditional quantile과의 평균 절대 차이(Wasserstein-1의 분위수 근사)를 계산한다. 복원 전후 오차를 비교하여 큰 손실의 원인이 수준 정보의 양자화인지 살핀다.
3. 이 진단만으로 통과를 선언하지 않는다. 본질적인 후속 후보는 각 cell의 실제 query 입력에서 얻은 conditional quantile을 유지하고, `Y-last(x)`의 예측 수정값별 손실 곡선을 같은 상태 안에서 합산하는 방식이다. 이 경우 계산하는 것은 명시적인 공통 함수군 `f_C(x)=last(x)+delta_C,state(x)`의 empirical expected MAE이다. 서로 다른 x를 동일 x라고 취급하거나, 다른 cell의 미관측 입력에 대한 분포를 요구하지 않는다.
4. 알려진 과거 query target으로 같은 손실 곡선을 직접 만드는 단순 대안도 있다. TabICL의 분포 기반 곡선이 그 대안보다 나아지는 근거가 없으면 TabICL 도입 이유가 부족하다. 양자화 수정 자체는 신규성이 아니다.
5. query를 같은 상태로 묶어 하나의 수정값을 공유하는 제한이 RCTL보다 강할 수 있다. 입력에 따른 수정값 차이·noise를 모두 task 차이로 해석하지 않으며, 이 제한의 오차를 별도로 확인한다. 실제 RCTL 결과를 보기 전에 이 후보를 명확히 고정해야 한다.

누적 비용: TabICL context 20개(최초 4 + 이번 16), query 17,664행(256 + 17,408), RCTL 학습 0회. 제한 예산을 유지한다.
