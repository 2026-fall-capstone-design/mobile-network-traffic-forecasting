# 손실 표의 계산 및 예측 의미 확인 — 추가 진단 전 고정

현재 후보의 partition은 이미 고정했고 RCTL 사후 검증이 진행 중이다. 이 진단은 partition, 하이퍼파라미터, 학습 대상을 바꾸지 않는다.

1. absolute-loss 표를 모든 action과 모든 quantile의 차이를 직접 계산하는 대신, 정렬한 quantile과 누적합으로 계산한다. 기존 표와 최대 차이 및 모든 pair score 차이를 확인한다. 같은 값이 나와야 하며 계산 속도 개선을 신규 수학이나 예측 향상으로 부르지 않는다.
2. 실제 입력·예측시점은 이전과 같다. clustering query 672~839로 만든 곡선과 고정된 action을 사용한다. 다음 주 840~1007에서, 두 cell을 따로 수정할 때와 공통 수정값으로 예측할 때의 실제 MAE 변화를 구한다. 120개 모든 pair를 이용한다. 후보별 예측된 손해와 관측된 손해의 순위 상관, 실제 손해가 양수인 비율을 기록한다.
3. 같은 계산을 실제 target, KNN, TabICL median, median/IQR 기준으로 비교한다. TabICL의 순위가 좋지 않으면 분포 평활화의 유효성에 대한 반증으로 기록한다. 이것은 RCTL 검증이나 독립 최종 성능이 아니며, 설계 구간의 surrogate 진단이다.
4. 128/1024/10000 cell 비용은 M=504,Q=168,S=129,B=64,G=257,k=16,repeat=1로 산술 산출한다. 현재 measured fit+predict 시간을 선형 확장한 값은 추정으로 표시한다. 후보 검색/병합은 구현하지 않은 대규모 속도를 측정값으로 쓰지 않는다.
5. 새 TabICL 호출, 새 RCTL fit은 하지 않는다. 기존 전체 numeric CPU 10분 상한 중 60초 이하를 사용한다. RCTL과 병행한 벤치마크는 CPU 경합 가능성을 명시한다.
