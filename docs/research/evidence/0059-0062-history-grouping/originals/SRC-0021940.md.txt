# 60: grouping × 최근 입력 길이의 작은 확인

2026-09-26. 결과 확인 전에 작성한다. 새로운 추천 알고리즘의 성능 검증이 아니라, grouping에 따라 필요한 이력이 달라진다는 중간 현상을 확인한다.

## 고정 조건

- 기존 첫 smoke의 4 cell: 3737, 3765, 6137, 6165. 다른 cell을 결과에 맞춰 추가·교체하지 않는다.
- 기존 시간 단위별 Milan 인터넷 활동량. bytes나 Mbps로 해석하지 않는다. 모든 기간은 이전 작업에서 접근한 개발 자료이며 독립 test가 아니다.
- 과거 context target 시점: index168..839를 균등 간격으로 256개 선택하고 모든 cell/조건에서 고정한다. query: index 기준 day43,47,51,55의 각 날짜에서 0..23시를 균등 간격으로16개, cell당64개. 날짜는 0-based index로 저장하며 실제 timestamp도 저장한다.
- 정규화: cell별 처음672시간 평균으로 나눈다. 이후 구간을 이용해 척도를 바꾸지 않는다.
- target은 다음 한 시점의 실제값이다. t의 입력은 t-1까지의 최근2개 또는8개 값이다. 두 조건 모두 t-24, t-168, t-24..t-1 평균·표준편차, target 시간/요일 sin·cos를 제공한다. 따라서 전체 과거를2시간으로 줄이는 검사가 아니라 **주기·요약 정보를 고정한 채 연속 입력 길이만** 비교한다.
- K1(global), 고정된 공간 K2({3737,3765},{6137,6165}), K4(local). 각 cell의256개 row를 합쳐 cluster context를 만든다. 총 고유 row수는 각 조건에서1024로 동일하고 context당 크기는1024/512/256으로 다르다. M이 고정된 기존 공통context 검사와 다르며 데이터 공유량의 차이를 포함한다.
- 별도 단순 대안: global에 cell one-hot4열을 추가한다. grouping 대신 입력으로 cell을 구분하는 방법이다. 두 길이에 모두 적용한다.
- query의 정답은 fit에 제공하지 않는다. context와 query의 최근8시점 입력이 겹치지 않는 시간 경계를 확인한다.

## 모델과 비용

TabICLv2 공식 고정 checkpoint, ensemble1, median, CPU4 threads, seed20260925. Ridge(StandardScaler,alpha1), HGB(absolute_error,100iter,15leaf,min20,l2=1,early_stopping=False,동일seed). 모든 예측은 음수를0으로 clip한다. 튜닝0.

각 길이에서 1+2+4+1=8 contexts, 두 길이 합16 contexts. 각 partition당256 query행이므로 총2×4×256=2,048행이다. 단순 모델32 fits. RCTL fit/forward0. Tab240초, simple30초, 전체300초, call 사이 관측RSS8GiB를 상한으로 둔다. 시작 전 누적 잔여31 contexts/24,032행을 확인한다. 완료/실패 호출을 모두 기록하고 ledger에 한 번만 반영한다.

## 결과와 해석

모델별 각 조건의 전체·cell별·날짜블록별·전후반 MAE와 원 활동량 MAE를 보존한다. I_K=(global2−global8)−(K2시점−K8시점)를 계산한다. I>0이면 이 확인 자료에서 grouping이 긴 연속 이력의 필요성을 줄인 방향이며, 인과 효과나 참 조건부 정보량 추정치로 부르지 않는다.

다음 판단을 사전에 정한다.

1. 분할 후 2시점 설정이 global2(또는 global one-hot2)보다 전체와 양쪽 시간 절반에서 모두 나쁘면, 이 범위에서 복잡한 grouping으로 연산을 줄일 근거가 없다.
2. I의 부호가 양쪽 시간 절반에서 달라지거나 Tab과 두 단순 추정기의 방향이 모두 다르면, 안정적인 데이터 특성으로 확정하지 않는다.
3. 같은 grouping/길이에서 Tab이 강한 단순 추정기보다 나쁘면 그것만으로 모든 Tab 선택 규칙이 반박되는 것은 아니다. 그러나 이번 결과로 Tab의 우월성을 주장하지 않는다. 같은 선택을 더 저렴하게 얻는다면 Tab 도입의 근거가 부족하다.
4. 여러 조건 중 나은 한 수치만 선택해 추천하지 않는다. 결과를 보고 새 cell/입력/정규화/threshold를 추가하지 않는다. 이번 자료의 차이와 변동을 보고하는 단계이며 임의의 허용 MAE를 설정하지 않는다.
5. 구조적 비용은 별도 계산한다. L2는 L8보다 core conv/LSTM MAC이 대략1/4이지만 실제 지연·학습시간을 측정한 것은 아니다. 모델 수 증가의 메모리 비용을 함께 적는다. 짧은 RCTL의 새 학습이 없으므로 RCTL 성능 통과로 처리하지 않는다.

결과가 지지하면 한 번에 대규모 연구를 권하지 않고 source 비교와 구현 가능한 결정 규칙을 먼저 정리한다. 지지하지 않으면 이번 후보의 실패 원인을 기록하고 남은 예산을 보존한다.
