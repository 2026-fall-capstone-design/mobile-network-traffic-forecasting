# 101 실제 pooled context 판단의 제한된 진단 — 실행 전 고정

2026-09-26. 이 계획 작성 시 새 모델 실행은 시작하지 않았다.

## 확인할 질문

B2는 cell별 TabICL 분포로 제한된 함수 `f0(x)+상태별 수정값`의 위험을 합산했다. 여러 cell의 실제 sample을 한 context에 넣은 예측은 아니었다. 14·19의 pooled context 실험은 cell ID와 입력 정보의 효과를 확인했으며 아래 세 partition의 직접 비교를 하지 않았다. 두 연산을 동일시하여 실제 context 공유까지 실패했다고 결론 내릴 수 없다.

이번에는 이미 고정된 세 partition에서 실제 pooled-context TabICLv2가 어떤 예측 결과를 내는지, 같은 실제 자료를 준 단순 회귀와 다른 판단을 하는지 확인한다. 새로운 clustering 알고리즘의 성능 검증이나 독립 test가 아니다. 과거 RCTL 결과는 이미 알려져 있으므로 사후 진단임을 명시한다. 결과를 보고 partition·입력·시간·규칙을 수정하지 않는다.

## 고정된 비교와 자료

- 04에서 RCTL 실행 전에 고정한 16 cell과 partition을 재사용한다: global K=1, TabICL-risk K=4, empirical-target-risk K=4. 첫 비교는 무분할 기준, 뒤의 두 비교는 원래 제안과 동일 알고리즘의 실제 정답 대안이다. 새 RCTL 결과에 맞춘 탐색이나 5개 방법 중 좋은 pair 선택을 하지 않는다.
- context target 시간은 168–839, cell당 672개다. 원래 RCTL의 학습 시간 및 실제 target과 같다. 원래 B2 context 504개보다 길다는 차이를 명시하므로, B2와 달라진 결과를 계산식 제거 하나의 인과 효과로 해석하지 않는다.
- query target 시간은 1008–1343의 연속 14일, cell당 336개로 고정한다. 기존 최종 20일의 첫 14일이며 두 주의 모든 시각을 포함한다. 이미 열람한 자료로서 개발 구간이다. RCTL이 early stopping에 사용한 840–1007은 query에서 제외한다. 이는 독립 미래 성능을 새로 입증하는 설정이 아니다.
- feature는 원래 16열 그대로다: 최근 8시간, 24시간 전·168시간 전, 최근 24시간 평균·표준편차, 예측 시점의 시각·요일 sin/cos. 처음 28일의 cell별 평균 정규화 척도를 고정한다. 미래 실제값을 feature 또는 전처리에 사용하지 않는다.
- cluster의 모든 실제 context 행을 cell 번호·시간순으로 합친다. query도 같은 순서다. global context 10,752행, K4의 context 각각 2,688행이다. 같은 cell은 모든 partition에서 같은 672개 실제 학습 행을 제공한다. context 100개로 인위적으로 잘라내지 않는다.
- 각 query의 유일한 target은 해당 cell의 실제 다음 시점 값이다. 모든 방법과 partition의 query·실제값은 같다. cell ID를 새로 넣지 않는다.

## 실행과 판정

1. 입력·소속·계획·실행 코드·모델 checkpoint·원장 hash를 저장한다. 라이브러리 버전과 실제 thread 수를 기록한다.
2. global 1개, Tab-risk 4개, empirical-risk 4개의 순서로 총 9 context에서 TabICLv2를 실행한다. 기존 공식 회귀 checkpoint, ensemble=1, CPU 4 threads, seed=20260925, batch_size=1, kv_cache=False, AMP/FA3/offload=False. 각 context마다 fit 1회와 전체 query median predict 1회만 허용한다. 내부 추론 횟수 및 전처리 설정도 저장한다. 가중치 재학습은 하지 않는다.
3. 같은 context와 query에서 StandardScaler+Ridge(alpha=1), HGB(absolute_error, max_iter=100, lr=.1, max_leaf_nodes=15, min_samples_leaf=20, l2=1, early_stopping=False, seed 동일)를 비교한다. 각각 9 fit, 총 18 fit이다. 튜닝하지 않는다. Ridge 자체는 제곱손실 학습이며 평가만 MAE라는 차이를 명시한다.
4. cell에 같은 비중을 둔 정규화 MAE를 primary로 한다. cell별·날짜별·앞/뒤 7일을 모두 기록한다. group 크기가 같은 K4끼리의 Tab-risk minus empirical-risk와 각 K4 minus global을 비교한다. 한 cell이나 날짜를 빼고 성공으로 바꾸지 않는다. 14일 묶음 자체를 유의성 또는 외부 일반화 증명으로 쓰지 않는다.
5. 새 예측·점수·순위를 파일로 고정한 뒤 저장된 RCTL 예측을 같은 query에서 읽어 사후 대조한다. 기존 primary seed의 세 partition, secondary seed의 두 K4를 모두 기재한다. RCTL 새 fit/forward/gradient/BN 갱신은 0이다. Tab과 RCTL의 함수군·학습 절차·validation 사용이 다르므로 순위 일치가 보장이 되지 않는다.
6. 단순 회귀도 같은 유용한 순위를 내면 Tab의 별도 결정 기여를 확인한 것으로 간주하지 않는다. 직접 Tab 예측이 좋아도 partition 선택 또는 결정 비용이 개선되지 않으면 새 clustering 기여로 승격하지 않는다. 순위가 다르면 어떤 비교에서 다른지 범위를 한정한다. 세 partition의 비교만으로 새로운 알고리즘이나 광범위한 rank 신뢰성을 주장하지 않는다.

## 산출물과 해석 범위

실행 코드·설정·호출별 비용·원본 예측 배열·요약·원장 갱신 기록을 남긴다. 이번 결과는 기존 surrogate 기각의 범위를 정하고, 실제 sample pooling이 유용한 판단을 주는지 직접 확인하는 근거다. 실제 context 공유라는 발상 자체를 신규성으로 쓰지 않으며, 최종 추천의 다른 조건이 충족되지 않으면 연구 목표를 완료 처리하지 않는다.
