# 실제 context를 공유하면 RCTL에 적합한 cluster를 고를 수 있는가

2026년 9월 26일 추가 확인 결과

**실제 sample을 함께 넣어도 TabICLv2와 RCTL이 선호하는 cluster 구성이 달랐습니다.** 반면 TabICLv2 자체의 트래픽 예측은 단순 회귀보다 정확했습니다. ‘예측을 잘하는 모델’과 ‘다른 예측기에 적합한 cluster를 고르는 모델’은 구분해야 한다는 직접 근거를 얻었습니다.

## 무엇을 확인했는가

앞선 검토에서는 cell별 TabICLv2의 예측 분포를 계산식으로 합쳐 공유 손해를 추정했습니다. 실제 sample을 하나의 context에 넣는 것과는 다른 방식입니다. 이번에는 이 차이를 직접 확인하기 위해 기존에 고정한 세 구성을 비교했습니다.

- **K1:** 16개 cell의 자료를 모두 함께 사용합니다.
- **Tab-risk K4:** 기존 TabICLv2 기반 규칙으로 만든 4개 cluster를 사용합니다.
- **실제 정답 기반 K4:** 같은 규칙에서 Tab의 예측 분포 대신 실제 확인용 정답을 사용해 만든 4개 cluster입니다.

모든 구성에서 cell당 같은 과거 sample 672개와 같은 확인용 query 336개를 사용했습니다. 최근 트래픽, 전날·전주 값, 시각·요일 정보도 같았습니다. cluster당 context를 100개로 제한하지 않고 실제 학습 자료를 모두 사용했습니다.

TabICLv2와 단순 회귀모델은 이번에 실행했습니다. RCTL은 새로 학습하지 않고, 과거에 이 세 구성으로 학습해 저장한 예측을 같은 날짜·시점에서 대조했습니다. 확인한 14일은 이미 열람한 개발 자료이므로 새로운 독립 test 성능은 아닙니다.

## 핵심 결과

아래 값은 정규화한 MAE이며 작을수록 좋습니다.

| 예측기 | K1 | Tab-risk K4 | 실제 정답 기반 K4 |
|---|---:|---:|---:|
| 실제 pooled-context TabICLv2 | **0.06618** | 0.07325 | 0.07541 |
| Ridge | **0.07923** | 0.08679 | 0.08244 |
| HGB | **0.07157** | 0.09170 | 0.08460 |
| 저장된 RCTL, 첫 seed | **0.07287** | 0.08600 | 0.07986 |
| 저장된 RCTL, 두 번째 seed | 미실행 | 0.08810 | **0.08367** |

**첫째, TabICLv2의 직접 예측 능력은 확인했습니다.** K1에서 HGB보다 오차가 7.53%, Ridge보다 16.46% 작았습니다. 앞·뒤 7일을 나누어도 이 우열은 같았습니다.

**둘째, 두 가지 K4 구성의 판단은 RCTL과 반대였습니다.** TabICLv2에서는 Tab-risk 구성이 더 좋았지만, 두 RCTL seed에서는 실제 정답 기반 구성이 더 좋았습니다. 이번 비교에서는 Ridge와 HGB도 RCTL과 같은 순위를 냈습니다. 더 정확하게 예측한다는 사실만으로 RCTL의 cluster 선택도 더 잘 대리한다고 볼 수 없습니다.

**셋째, K1을 선택하는 판단은 TabICLv2만의 이점이 아니었습니다.** 모든 비교 예측기에서 14일 전체의 K1 오차가 가장 작았습니다. 따라서 이번 결과로 TabICLv2가 유용한 cluster 수 선택을 새로 가능하게 했다고 주장하지 않습니다.

TabICLv2의 K4 선호는 앞·뒤 주 사이에서도 달라졌습니다. RCTL은 두 seed 모두 두 주에서 실제 정답 기반 K4를 선호했습니다. 전체 평균만으로 모든 cell과 모든 시간대의 결과를 설명하지 않도록 세부 결과도 보존했습니다.

## 연구 방향에 반영할 판단

이제 남은 문제는 단순히 context를 실제 sample로 구성하는 방법이 아닙니다. **TabICLv2가 측정하는 공유 효과 중 어떤 부분이 RCTL의 학습에도 유효한지를 구체적으로 연결해야 합니다.** 같은 실제 자료를 사용해도 두 모델의 사전학습, 함수 구조, 학습 절차는 다르기 때문입니다.

따라서 기존 공통 context 검사를 다시 붙이는 것만으로 연구 방향이 개선되었다고 판단하지 않습니다. Tab과 단순 회귀의 점수를 섞거나 모듈을 늘리는 방안도 이번 결과만으로 추천하지 않습니다. 최종 RCTL에 유용한 판단이 무엇인지, 그 판단에서 TabICLv2가 단순한 방법보다 어떤 역할을 하는지가 먼저 필요합니다.

이번 검사는 TabICLv2의 사용 자체를 부정하는 결과가 아닙니다. 좋은 직접 예측이라는 장점은 남아 있습니다. 다만 현재의 clustering → RCTL 목적에서는 그 장점이 유용한 cell 소속 결정으로 이어진 근거가 부족하다는 점이 더 분명해졌습니다.

실제 추가 실행은 TabICLv2 9 context·16,128 query행으로 약 138.26초, 단순 모델 18 fit으로 약 1.00초였습니다. RCTL 추가 학습은 없었습니다. 원래 예산 안에서 수행했으며 원본 예측과 상세 비교를 보존했습니다.
