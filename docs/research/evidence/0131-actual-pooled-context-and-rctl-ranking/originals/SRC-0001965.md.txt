# 101. 실제 context 공유와 RCTL 판단의 직접 대조

2026-09-26. 실행 전 계획: `101_pooled_context_diagnostic_plan.md`. 9개 TabICLv2 context와 동일 자료의 단순 회귀 18 fit을 실제 실행했다. 새 RCTL 학습·추론·gradient 계산은 모두 0이다.

## 새로 확인한 판단

**실제 sample을 한 context에 함께 넣는 방식으로 바꾸어도, TabICLv2의 cluster 선호가 RCTL과 일치하지 않았다.** TabICLv2 자체는 같은 자료를 받은 Ridge·HGB보다 예측 오차가 작았다. 그러나 두 4-cluster 구성 사이에서는 RCTL과 반대 순위를 냈다. 따라서 좋은 직접 예측 성능을 좋은 RCTL clustering의 근거로 사용하는 연결이 여전히 성립하지 않는다.

이번 결과는 단순한 문헌상의 우려가 아니다. 원래 RCTL을 학습하기 전에 고정했던 세 partition에 실제 pooled context를 구성하고, 저장된 RCTL 예측과 같은 cell·시점에서 대조한 관찰이다. 다만 이미 열람한 개발 구간의 세 구성 비교이므로 모든 자료·모든 partition에 대한 불가능성 결론으로 확대하지 않는다.

## 이전 검사와 무엇이 다른가

04의 B2는 cell별 TabICL 예측 분포로 `공통 Ridge 예측 + 상태별 수정값`의 손해를 계산했다. 이 곡선들을 합산하여 cluster를 정했으며, 실제 sample을 합친 context로 TabICL을 다시 실행하지 않았다. 그 결과를 실제 context 공유의 결과와 같다고 보면 안 된다.

14·19에서는 여러 cell의 자료를 한 context에 넣었지만 cell 식별 정보·입력 정보의 효과를 검사했다. 이번처럼 원래 global·Tab-risk K4·empirical-risk K4를 같은 확인 구간에서 직접 비교한 것은 아니다.

101은 이 미확인 부분을 검사했다. context는 RCTL의 원래 학습 target 시간 168–839이며 cell당 672개다. 입력은 기존 16열, 정규화는 기존 최초 28일 평균을 유지했다. 두 4-cluster 구성은 cluster당 2,688개, global은 10,752개의 실제 sample을 참고했다. 어느 구성에서도 cell의 학습 자료를 임의로 삭제하거나 정답을 합성하지 않았다.

query는 시간 1008–1343의 연속 14일, cell당 336개다. RCTL의 early stopping 구간 840–1007과 분리했다. 최종 20일의 첫 14일이며 이미 과거 작업에서 열람한 기간이므로 새 독립 test는 아니다. Tab 예측과 그 점수를 먼저 저장한 다음 저장 RCTL 예측을 읽었다. RCTL 결과에 맞추어 소속이나 설정을 바꾸지 않았다.

B2의 context 504개와 이번 672개는 다르다. 따라서 B2와 다른 결과가 나오더라도 그 원인을 계산식 제거 하나로 분리하지 않는다. 이번 핵심 비교는 같은 672개 실제 학습 자료를 사용한 세 구성의 상대 판단이다.

## 실제 결과

표의 값은 cell별 고정 척도로 정규화한 MAE다. 작을수록 좋으며, 모든 cell의 비중은 같다. Tab-risk와 empirical-risk는 동일한 K=4·cluster 크기 4이며, 소속을 만드는 오차 곡선의 정보만 달랐던 기존 두 구성이다.

| 예측기 | 모든 cell을 공유한 K1 | Tab-risk K4 | 실제 정답 기반 risk K4 | K4 중 작은 오차 |
|---|---:|---:|---:|---|
| 실제 pooled-context TabICLv2 | 0.06618315 | 0.07324503 | 0.07540668 | Tab-risk |
| 동일 자료 Ridge | 0.07922794 | 0.08678670 | 0.08244128 | 실제 정답 기반 |
| 동일 자료 HGB | 0.07157078 | 0.09170042 | 0.08459679 | 실제 정답 기반 |
| 저장 RCTL, seed 20260925 | 0.07287361 | 0.08600222 | 0.07986498 | 실제 정답 기반 |
| 저장 RCTL, seed 20260926 | 미실행 | 0.08809589 | 0.08367167 | 실제 정답 기반 |

이 표에서 구분할 사실은 세 가지다.

1. **TabICLv2의 직접 예측 능력은 유용했다.** global 조건에서 HGB보다 MAE가 7.53%, Ridge보다 16.46% 작았다. 앞·뒤 7일에서도 우열은 같았다. 사전학습 회귀가 이 자료에서 아무 역할도 못 한다는 결론은 맞지 않는다.
2. **같은 K에서 어떤 소속이 좋은지 판단하는 능력은 별개였다.** Tab은 Tab-risk K4를 선호했지만 두 RCTL seed는 실제 정답 기반 K4를 선호했다. Ridge·HGB도 이번 비교에서는 RCTL과 같은 방향이었다. 직접 예측이 더 정확한 평가기가 partition의 상대 우열도 더 잘 대리한다고 주장할 수 없다.
3. **global을 선택하는 판단은 Tab만의 기여가 아니었다.** 14일 전체에서는 Tab·Ridge·HGB·primary RCTL 모두 K1의 오차가 가장 작았다. 따라서 이번 결과로 Tab이 더 유용한 K 선택을 만들었다고 할 수 없다. 16개 cell의 이 결과를 원 논문 전체나 다른 규모에서도 K1이 최적이라는 주장으로 확대하지 않는다.

### 시간 구간을 나누면

다음 값은 Tab-risk K4의 MAE에서 실제 정답 기반 K4의 MAE를 뺀 것이다. 양수이면 실제 정답 기반 구성이 유리하다.

| 판단에 사용한 예측기 | 전체 14일 | 앞 7일 | 뒤 7일 |
|---|---:|---:|---:|
| pooled-context TabICLv2 | −0.00216165 | +0.00016346 | −0.00448675 |
| Ridge | +0.00434542 | +0.00040833 | +0.00828251 |
| HGB | +0.00710363 | +0.00296595 | +0.01124130 |
| RCTL seed 20260925 | +0.00613725 | +0.00313680 | +0.00913769 |
| RCTL seed 20260926 | +0.00442422 | +0.00133309 | +0.00751534 |

Tab의 두 K4 선호는 앞·뒤 주에서 달랐다. 전체에서 Tab-risk가 더 좋았던 날은 14일 중 10일이지만, cell별 평균으로는 16개 중 6개였다. 평균 개선을 모든 cell의 개선으로 표현하지 않는다. 반대로 RCTL 두 seed는 앞·뒤 주 모두 실제 정답 기반 구성이 유리했다. 이 요약은 독립 반복 실험이나 유의성 검정이 아니다.

## 연구 설계에서 바뀌는 결론

기존 판단은 ‘분포를 합치는 대리 계산이 부정확해서 RCTL과 연결되지 않았을 수 있다’는 여지를 남겼다. 이번에는 실제 finite context의 학습 효과를 직접 평가했지만 같은 K의 순위 차이가 남았다. 따라서 **공통 context 검사를 다시 붙이는 것만으로 기존 방향을 복구하지 않는다.**

Tab과 RCTL은 실제 target·cell 소속·입력 정보를 공유해도 다른 사전학습·함수군·학습 절차를 사용한다. RCTL은 과거 validation으로 early stopping을 했고, Tab은 고정 pretrained 모델로 context 추론을 했다. 이 차이가 구체적으로 어느 정도 순위 반전을 일으켰는지는 분해하지 않았다. 결과가 보여 주는 것은 ‘같은 실제 자료를 넣었으니 공유 효용도 같을 것’이라는 추론을 그대로 사용할 수 없다는 점이다.

clustering을 RCTL 호출 없이 실행하는 독립성은 유지할 수 있다. 그러나 독립적으로 실행된다는 사실은 그 판단이 RCTL에 적합하다는 증거가 아니다. 후속 방향은 이 둘을 구별해야 한다.

이번 결과만으로 단순 회귀를 새 clustering 알고리즘으로 추천하지도 않는다. 세 구성에서의 순위 일치는 발견 범위가 좁고, 그 원리는 새로운 것이 아니다. Tab·단순 회귀의 점수를 섞거나 agreement 규칙을 추가하면 해결된다고 주장하지 않는다. Tab의 추가 역할과 실제로 바뀌는 유용한 결정을 따로 설명해야 한다.

K4가 Tab 실행에서는 더 빨랐지만, 이것은 Tab의 context 크기에 따른 작업량이다. 최종 RCTL은 소속 확정 뒤 별도로 학습·실행하므로 이 수치를 RCTL 운영 속도 향상으로 바꾸어 설명하지 않는다. 95에서 확인한 RCTL의 묶음 처리 비용과도 구분한다. 16개 cell의 CPU 실행을 10,000개 cell로 선형 외삽하지 않는다.

누적 Tab 사용량은 78 context·55,488 query행·389.079522초다. 남은 상한은 2 context·4,512행이며 새 RCTL fit은 여전히 0이다. 원장은 `60b589e806c4d1bc8b37d9130e1215d5e15de1d186980ca7de5d2bf4d0a1a43a`로 갱신했다. 예산을 초기화하지 않았다.

## 확인 가능한 근거와 남은 일

- 원본 설정·실행 전 hash: `results/pooled_context_101/settings.json`.
- 실제 호출별 sample·query 수와 시간: `calls.json`, `simple_calls.json`.
- 입력·정답·예측 배열: `inputs.npz`, `predictions.npz`.
- MAE 및 cell·일·시간 절반별 차이: `summary.json`.
- 새 예측 점수의 사후 RCTL 대조 전 저장본: `new_scores_frozen.json`.
- 실행 종료와 비용 반영: `run_finished.json`, `budget_update.json`.

설치 TabICL의 `TabICL.predict_stats` 경로는 기본 `embed_with_test=False`이며, ICL layer에서 key/value는 context 행으로 제한된다. sklearn target scaler와 입력 변환은 context에 fit한다. 이번 query target은 `fit`·`predict` 인자에 넣지 않았다. 정적으로 확인한 실행 경로에 대한 설명이며 모든 설정의 보장은 아니다.

실제 sample pooling 검사와 기존 B2 검사의 구분을 보완했고, 순위 반전과 비용을 직접 확인했다. 최종 추천 방향·최종 Word의 완료 조건은 아직 충족하지 않았다. 좋은 직접 예측이라는 긍정 근거는 유지하되, 이것만으로 새로운 RCTL clustering 주제를 채택하지 않는다.
