# 110 새 후보: 하루 주기 위치를 맞춘 뒤의 예측 관계 비교

2026-09-26. 이 문서는 최종 추천안이 아니라 실행 가능한 후보와 첫 진입 검사를 고정한다. 109에서 상한 절단이나 로그 불일치로 기존 결과를 무효화할 근거를 찾지 못했다. 기존 후보를 더 학습하는 대신, UPC가 중요하게 사용하는 피크 시각과 실제 공유할 예측 관계를 구별할 수 있는지를 살핀다.

## 바꾸려는 결정과 RCTL에 전달되는 것

cell A는 오전 8시, B는 오전 10시에 비슷한 일과를 시작할 수 있다. 이 차이 때문에 피크와 동시 PCC가 달라도, 각 cell의 일과에서 같은 위치에 있을 때 최근 입력과 이후 값의 관계는 같을 가능성이 있다. 반대로 피크만 옮겨 파형을 맞춰도 그 이후 변화 규칙이 다를 수 있다.

후보는 `어떤 cell을 묶는가`와 `그 cell의 하루 주기 위치를 어떻게 표시하는가`를 함께 출력한다. 각 cell의 고정 이동량 phi를 정하고 입력의 hour를 `(hour - phi) mod 24`로 표시한다. 최근 lag, 일주일 전 실제값, 정답 시점과 실제 관측 순서는 움직이지 않는다. 미래의 다른 cell 값을 가져오는 정렬이 아니다. 이동량은 clustering에 사용한 과거에서만 정하고 이후에는 고정한다. 요일·휴일은 실제 달력 정보로 유지한다.

clustering이 확정되면 같은 이동량을 실제 RCTL의 훈련·예측 입력에도 적용한다. 이는 TabICL 점수로 소속만 정하고 끝나는 기존안과 다른 전달 경로다. RCTL의 TCN·LSTM·이중 잔차와 실제 정답 학습은 유지한다. RCTL 학습 결과를 이동량이나 소속 선택에 사용하지 않는다.

## TabICLv2가 맡을 수 있는 판단

단순 파형 정렬로 몇 개의 이동량 후보를 만든 다음, 해당 주기 위치에서 실제 최근 입력을 가진 query의 다음 값을 다른 cell의 context로 예측할 수 있는지 비교한다. 예를 들어 A의 오전 8시가 B의 오전 10시와 대응한다면, B의 context에 A query를 제시할 때 달력 좌표만 B의 오전 10시로 대응시킨다. query의 실제 최근 관측값은 그대로 둔다.

이 검사는 파형 정렬이 아니라 **시간 좌표를 바꾼 조건에서 예측 관계도 대응하는가**를 확인하려는 것이다. 회귀 TabICLv2의 고정 가중치를 재사용할 수 있다. 입력 지원 밖의 query에서 나온 결과는 공유 근거로 쓰지 않는다. 모든 비교의 query 정답은 과거 확인 구간의 실제값이며, 최종 미래 정답을 쓰지 않는다.

각 cell 쌍의 최적 이동량을 따로 받아들이면 A–B, B–C, A–C의 이동량이 서로 모순될 수 있다. 하나의 cluster에서 cell마다 고정된 phi를 부여할 수 있어야 한다. 다만 정렬과 clustering의 공동 최적화, 이동량의 일관성 자체도 기존 문제이므로 신규성이라고 부르지 않는다.

## 가까운 연구와의 구별이 필요한 지점

- TROUT, Weylandt·Michailidis, arXiv:2012.04756v2, §2–4: spectral registration과 clustering을 공동으로 다룬다. 식 (1)의 모든 Fourier 성분에 같은 복소 회전을 곱하는 연산과, 주파수마다 다른 위상 변화가 생기는 실제 시간 이동을 구별한다. 파형 정렬 자체는 기존 방법이다.
- CAPS, arXiv:2602.02729v1, §3.1–3.3: RoPE와 세 attention 경로를 최종 예측 모델 안에서 학습한다. 이번 후보의 고정 cell별 달력 좌표와 독립 clustering과는 학습 위치가 다르다. 상대 시각을 쓰는 것 자체는 신규성이 아니다.
- Adaptive Oscillatory-State Alignment, arXiv:2606.06010v1: 본문을 추가 확인하여 입력 window별 진동 상태 정렬과 cell별 고정 좌표를 구별해야 한다. 초록만으로 차이를 확정하지 않는다.
- 동시 alignment/classification, heterogeneous multireference alignment 계열도 근접 연구다. 비용을 예측오차로 바꾼 것이 기존 일반 목적식의 추정기 교체에 그치는지 확인해야 한다.

최종 차별점의 후보는 `피크 시간 차이와 예측 관계 차이를 분리하고, 확인한 변환을 실제 공유 학습 입력까지 전달한다`는 판단 단위다. 이 문장만으로 신규성·성능·TabICL의 필요성을 확보했다고 선언하지 않는다. 같은 좌표 보정과 같은 예산에서 cross-correlation 또는 단순 회귀만으로 충분하면 TabICL을 넣은 연구로 추천하지 않는다.

## 먼저 실행할 검사: 시각 차이의 존재와 재현성

아직 이동량별 TabICL 추론이나 새 RCTL 학습을 시작하지 않는다. 현재 16개 cell 전체의 저장된 훈련 target 168~839를 사용한다. 앞 21일(168~671)을 구성 구간, 다음 7일(672~839)을 확인 구간으로 고정한다. 유리한 cell이나 확인 날짜를 골라내지 않는다.

1. 앞 21일의 cell별 평균·표준편차로 파형 비교 단위만 맞춘다. 원래 target·RCTL 입력 파일은 변경하지 않는다.
2. 전체 앞 21일, 그 안의 첫 14일/마지막 7일, 뒤의 확인 7일 각각에서 24시간 평균 profile을 구한다. 연속 시간을 임의 재배열하거나 미래로 채우지 않는다.
3. 각 cell 쌍 120개에 대해 앞 21일 profile의 제곱차를 최소화하는 정수 시각 이동을 0, +1, -1, ..., +11, -11, +12 중 정한다. 동점은 이 순서로 정한다. 전후 level과 amplitude는 앞 21일에서 정한 척도를 유지한다.
4. 선택한 이동량을 확인 7일 profile 비교에 그대로 적용한다. 이동하지 않은 경우와 절대차·제곱차를 비교한다. 이는 일별 파형 재현 진단이며 다음 시점 예측 성능으로 부르지 않는다.
5. 앞 14일과 다음 7일에서 따로 정한 이동량의 원형 차이, 실제 peak 시각 차이, 21일 이동량이 0인 쌍 수를 모두 기록한다. profile을 움직였을 때 훈련 오차가 줄었다는 사실만으로 유용성을 판단하지 않는다.
6. 120개 개별 최적 이동량이 560개 삼각형에서 일관되는지도 기술 통계로 기록한다. 이 불일치를 새로운 synchronization 문제의 발견이나 RCTL 손해의 증거로 확대하지 않는다.

이동량이 확인 구간에 재현되지 않거나 대부분 0이면 현 자료에서 이 방향에 추가 Tab/RCTL 예산을 쓰지 않는다. 안정된 비영 이동과 확인 파형의 개선이 함께 관찰되면, 그때만 원문 대조와 예측 관계 검사의 세부 실행 명세로 진행한다. 이번 파형 검사만으로 clustering의 예측 이득을 판정하지 않는다.

후속 명세로 넘어갈 기술적 기준은 실행 전에 다음으로 정한다. 비영 이동이 120쌍의 절반을 초과하고, 그 쌍들 중 절반을 초과하는 수가 앞14일/다음7일에서 원형 차이1시간 이내이며, 선택 이동을 고정한 확인 profile의 평균 절대차가 무이동보다 작아야 한다. 이는 큰 모델 실행을 피하기 위한 첫 존재·반복성 검사이며 통계적 유의성 기준이나 최종 연구 채택 기준이 아니다. 통과해도 새 모델 실행은 별도 명세가 필요하다.

## 비용 및 다음 단계의 현실성

첫 검사는 120쌍×24이동×24시간의 작은 배열 연산이며 모델 호출0이다. 10초·RSS1GiB 상한, 한 번 실행하고 설정·코드·입력 hash·모든 결과를 보존한다. 기존 모델 상한은 늘리지 않는다.

후속 예측 검사를 실행할 경우에는 모든 cell 쌍과 모든 이동량을 무제한 추론하지 않는다. 16 cell, cell별 최대2개 후보와 후보당3개 이동, 방향별 query64개로 제한하는 명세라면 교차 query는 최대6,144행, 자기 비교1,024행으로 총7,168행이다. 16개 context 준비와 기존 구간의 target 사용을 모두 포함한다. 이 수치는 가능한 계산량 명세이며 아직 실행 예산을 예약한 것은 아니다. 대규모에서는 N·d·P·q에 비례하는 최초 추론량과 후보 검색 비용까지 포함해야 한다.

모든 phi와 소속을 고정한 뒤 필요한 RCTL 비교만 별도 계획으로 시작한다. 현재 남은 모델 적합9회를 자동으로 모두 사용하지 않는다. 같은 K·같은 이동 입력을 준 단순 clustering 기준과 비교해야 한다. 보정되지 않은 기준과의 비교만으로 TabICL 기여를 주장하지 않는다.
