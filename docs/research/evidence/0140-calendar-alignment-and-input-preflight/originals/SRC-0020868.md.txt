# 112 고정 시각 보정이 실제 예측 관계를 개선하는지 확인

2026-09-26. 111의 입력 준비 결과를 받은 뒤 작성했으며 새로운 예측값을 계산하기 전의 계획이다. 아직 예산 활성화·모델 실행·cluster 선택을 하지 않았다.

## 확인할 가정

하루 평균 파형을 맞추는 이동량과 다음 트래픽값 예측에 유용한 이동량은 다를 수 있다. TabICLv2가 실제 최근 관측값을 유지한 상태에서 더 유용한 이동량을 선택하는지 확인한다. 이 단계를 통과해도 cell 소속과 고정 좌표의 일관성, 같은 K의 RCTL 성능 확인은 별도로 남는다.

## 고정 자료와 비교 단위

111에서 통과한 방향 14개·대상 cell 11개·세 이동량·공통 query mask를 그대로 사용한다. 후보 검색이나 지원 반경을 다시 계산하지 않는다. 고정 archive의 hash를 실행 설정에 넣는다. context는 각 donor의 168~671 실제 입력·target 504개다. query는 672~839에서 선택한 시점이며 세 이동 모두 같은 실제 target으로 평가한다. 모든 시점은 개발 자료다.

원래 cell 정규화 척도는 `data_and_smoke.py`에서 raw 시점0~671의 평균으로 정했다. query 시작672 이후 target으로 새 척도를 맞추지 않는다. context의 최근 이력에 필요한 앞부분까지 포함한 과거 척도를 유지하며, 모델별 추가 scaler는 해당 context만으로 적합한다.

앞 32개 query 위치 중 mask가 남긴 시점에서 이동량을 고르고, 뒤 32개 중 남긴 시점에서 선택을 고정하여 평가한다. 동점은 무이동, 이후 사전에 정한 이동 순서로 정한다. 정답을 예측 모델의 context나 입력 매칭에 넣지 않는다. 선택 단계가 과거 확인 정답을 사용한다는 사실을 zero-shot label-free clustering으로 포장하지 않는다.

## 동일한 자료를 받는 세 회귀 모델

1. TabICLv2: 현재 설치된 회귀 구현과 로컬 `tabicl-regressor-v2-20260212.ckpt`. n_estimators=1, batch_size=1, kv_cache=False, CPU 4 thread, AMP/FA3/offload/auto-download 비활성, seed 20260925. point 출력은 median으로 고정한다. 최종 RCTL의 loss는 바꾸지 않는다.
2. StandardScaler+Ridge(alpha=1): scaler와 회귀 모두 해당 donor context만으로 적합한다.
3. HGB: loss=absolute_error, max_iter=100, learning_rate=0.1, max_leaf_nodes=15, min_samples_leaf=20, l2_regularization=1, early_stopping=False, random_state=20260925. 101과 동일한 설정이다.

동일 cell의 context는 한 번 준비한다. 그 context를 사용하는 교차 query와 자기 기준 query를 한 요청에 묶는다. 같은 query를 세 이동에서 예측한 행은 각각 추론 행으로 계산한다. 캐시가 모든 비용을 없앤다고 가정하지 않는다.

## 선택의 효과와 모델 자체의 성능을 분리한다

먼저 각 모델에서 다음 세 값의 뒤 절반 MAE를 구한다: 무이동, 앞 21일 profile만으로 고른 이동, 해당 모델의 앞 절반 오차로 고른 이동. 모든 방법은 같은 query에서 평가한다.

이어서 선택자 5개(무이동/profile/Tab/Ridge/HGB)와 평가 예측기 3개(Tab/Ridge/HGB)의 표를 만든다. 예를 들어 Tab이 선택한 이동량과 Ridge가 선택한 이동량을 **똑같이 HGB의 저장 예측**에서 평가한다. 이 계산은 이미 얻은 예측을 조회하므로 새 모델 호출이 없다. Tab 모델의 낮은 기본 오차와 Tab의 더 나은 이동량 선택을 혼동하지 않기 위한 진단이다. HGB에 유리한 선택이 RCTL에도 유리하다는 보장은 아니다.

주 지표는 뒤 절반의 cell 평균 MAE다. 각 cell에서 donor별 MAE를 먼저 같은 비중으로 평균하고, 대상 cell 11개를 같은 비중으로 평균한다. 앞 절반 선택 MAE, 뒤 절반을 시간순으로 다시 나눈 두 구간, 방향별 결과, 비영 이동 선택 수와 자기 cell context 기준도 모두 기록한다. query 수가 많은 방향에 자동으로 더 큰 비중을 주지 않는다. 통계적 유의성을 선언하지 않으며 작은 값에 맞춰 뒤늦게 허용 폭을 정하지 않는다.

## 이 확인으로 내릴 판단

- Tab이 고른 이동의 뒤 절반 평균 MAE가 무이동과 profile 이동보다 모두 작지 않으면, 현재 후보의 첫 예측 관계 가정이 지지되지 않은 것으로 기록한다. 단지 하루 파형이 맞는다는 이유로 RCTL 학습을 시작하지 않는다.
- Tab 안에서만 이득이 있고 같은 예측기에 대한 다른 선택자와 비교했을 때 선택의 이점이 없으면, Tab의 직접 예측 능력과 유용한 좌표 선택을 분리하여 후자는 미확인으로 둔다. 유리한 cell·이동만 골라 기준을 바꾸지 않는다.
- 개선이 양쪽 뒤 절반 구간에서도 같은 방향이며 단순 선택보다 유용한 변화가 있으면, 그 구체적 방향과 비용을 근거로 cluster 단위의 고정 좌표 명세를 작성한다. 자동으로 신규성을 확보하거나 RCTL 검증으로 진입했다는 뜻은 아니다.
- 모든 선택자가 비슷하면 단순 이동 보정의 근거로 기록한다. 이를 TabICL 고유 신규성으로 사용하지 않는다. 근접 문헌과의 일반 목적식 중복은 결과가 좋아도 남는다.

## 실행 한도와 예산 적용 순서

실행 코드를 완성하고 static 검토를 한 뒤 목표 제9.1절의 이미 허용된 단 한 회차에서 TabICL 부분을 활성화한다. 활성화 전 원장을 보관하고 과거 누적 78 context·55,488행·389.0795223초를 보존한다. 새 누적 context/행 상한은 110/71,872이며 기존 미사용 2 context·4,512행을 별도로 더하지 않는다. 이 추가 회차의 Tab 시간 상한은 600초다.

이번112가 예약하는 최대치는 Tab 14 context·3,096행·180초, 단순 회귀 28 fit와 준비·정산 전 배열 연산 30초, 전체 단계 210초다. memory 4GiB·CPU thread 4개 이내, RCTL fit/forward/gradient/통계 적합은 모두0이다. 남은 RCTL 적합9회는 유지한다. 다른 유효 사용량과 전체 누적 상한도 함께 확인한다.

attempted context와 attempted query 행을 호출 전에 저장하고 완료마다 부분 예측과 시간을 보존한다. 실패·강제 중단 비용도 정산하며 자동 재시작하지 않는다. 실행 결과를 확보한 뒤 원장을 한 번 갱신한다. 아직 호출하지 않은 예약분은 실사용과 분리한다.

이번 확인은 처음111의 최대 7,168행 가정보다 좁혀진 실제 3,096행만 사용한다. 1만 cell로 확대할 때의 전수 후보 검색 비용은 별도로 남으며 현재 16 cell 결과로 대규모 효율을 주장하지 않는다.
