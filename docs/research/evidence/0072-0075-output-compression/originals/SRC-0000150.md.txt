# TabICLv2의 예측력과 clustering 역할을 구분한 추가 검토

2026년9월26일. 이번에는 **여러 cell의 미래값을 소수의 공통 출력으로 표현하고, cluster별 RCTL이 그 출력만 예측하도록 하는 방향**을 검토했습니다. 현재 결과로는 이 방향을 추천하기 어렵습니다. TabICLv2 자체의 예측은 좋았지만, 그 정보를 출력 압축에 사용했을 때의 추가 이득은 확인되지 않았습니다.

## 1. 무엇을 해결하려고 했는가

기존처럼 여러 cell이 같은 RCTL 가중치를 공유해도 각 cell의 입력을 따로 처리하면 예측 실행 수는 cell 수만큼 남습니다. 여러 cell을 몇 개의 공통 움직임으로 표현할 수 있다면 실행 수를 줄일 여지가 있습니다. 여기서 중요한 선택은 변동이 큰 움직임이 아니라 **과거 정보로 미리 예측할 수 있는 움직임을 남기는 것**입니다.

이 발상 전체가 새롭지는 않습니다. [ForeCA(ICML2013)](https://proceedings.mlr.press/v28/goerg13.html)는 주파수 구조를 이용해 예측 가능한 성분을 찾고, [response dimension reduction](https://doi.org/10.1016/j.csda.2008.07.029)은 조건부 평균을 보존하는 출력 공간을 다룹니다. [TMLR2025의 GNN clustering](https://openreview.net/forum?id=MHQXfiXsr3)은 pooling한 출력의 예측과 cell별 복원을 공동학습합니다. 따라서 이번 검토는 압축이라는 이름 자체보다, RCTL을 호출하지 않고 TabICLv2로 더 나은 압축 결정을 할 수 있는지에 초점을 두었습니다.

Tab 예측만으로 만든 기준과, 별도 시점의 실제 target으로 예측 오류의 영향을 보정한 기준을 비교했습니다. 이 보정도 추정 오류를 완전히 없애지는 않습니다. 공식 코드·원문을 읽은 범위와 접근하지 못한 본문은 [상세 출처 기록](<C:/Users/jungj/OneDrive/Desktop/연구실/Tab-ICL/tmp/redesign_20260925/72_73_source_findings.md>)에 구분했습니다.

## 2. 작은 실제 데이터 확인

기존에 사용한 Milan4cell을 그대로 사용했습니다. 네 cell의 최근 관측·전일·전주·하루 요약·시간대·요일을 동일한 입력으로 제공하고, 한 시간 뒤의 연속값을 예측했습니다. cell당 context256개, 별도의 이후7일에서168개 시점을 확인했습니다. 모든 기간은 개발자료이며 독립 최종 test는 아닙니다.

| 회귀기 | 정규화 MSE | 정규화 MAE |
|---|---:|---:|
| Ridge | 0.014360 | 0.089565 |
| HGB | 0.011925 | 0.078400 |
| TabICLv2 | **0.009580** | **0.066828** |

TabICLv2의 MSE는 두 시간 절반과7개 일별 구간 모두에서 두 단순 회귀기보다 작았습니다. **작은 context로 최근 관측과 이후 값의 관계를 추정하는 능력은 확인했습니다.** 이 비교만으로 모든 cell·기간에서의 우월성이나 공간 입력의 효과까지 확인한 것은 아닙니다.

다음으로4cell을2cluster로 묶고, 각cluster에 출력 하나를 남겼습니다. Tab 기준과 전체 실제자료 PCA, Ridge 기준은 모두 같은 cell 소속을 골랐습니다. 실제 관측값을 압축한 target으로 별도 HGB를 학습한 결과는 다음과 같습니다. 이 모델은 RCTL을 대신 검증하기 위한 것이 아니라 출력 표현 자체를 확인하기 위한 중간 비교입니다.

| 출력 표현 | 개발 MSE |
|---|---:|
| 비압축 기준 | **0.012446** |
| 실제자료 PCA | 0.019871 |
| Tab 예측만 사용한 압축 | 0.019799 |
| 실제 target으로 보정한 Tab 압축 | 0.020054 |

Tab 예측만 사용한 압축에는 PCA 대비 작은 차이가 있었지만, 보정한 기준의 이득은 나타나지 않았습니다. 압축 방법 전체가 비압축 기준보다 불리했습니다. 추가 비용을 정당화할 clustering 개선으로 평가하기 어렵습니다.

## 3. 계산비용에서도 바뀐 판단

같은 입력을 사용하는 RCTL 구조의 연산 수를 계산하면, 큰 절감은 출력 차원을 줄이는 데서가 아니라 core 실행 횟수를 줄이는 데서 나옵니다. 같은 두 cluster에서 출력 차원을 그대로 둔 head와 압축한 head의 계산량은 거의 같았습니다. 따라서 단순한 다중 출력 RCTL을 비교에서 제외하고 압축의 속도 이득을 주장할 수 없습니다. 이 확인은 정적인 연산량 계산이며 실제 속도 측정은 아닙니다.

현재 후보에는 추가 구조를 붙이지 않겠습니다. **TabICLv2의 좋은 직접 예측 결과는 유지하되, 이것을 RCTL clustering의 이득으로 해석하지 않겠습니다.** 이후 후보도 Tab이 계산한 정보가 어떤 실제 결정을 바꾸고, 그 결정에서 단순 대안보다 무엇이 좋아지는지를 기준으로 판단합니다.

이번 실행은 Tab4contexts·1,344query행, 단순 회귀26회였고 새 RCTL 학습은 없었습니다. 정해 둔 누적 상한을 유지했습니다. [전체 수치·설정·판정](<C:/Users/jungj/OneDrive/Desktop/연구실/Tab-ICL/tmp/redesign_20260925/74_output_compression_findings.md>)에 긍정적 결과와 한계를 함께 기록했습니다. 전체 재설계의 최종 추천 방향과 Word 문서는 아직 완료되지 않았습니다.
