# 88 조건부 sample 비교의 신규성·가정·비용 검토

2026-09-26. 사전 범위는 `88_conditional_reference_scope_plan.md`이다. 네 원문과 TabPFN+CRT의 공식 코드 경로를 확인하였다. 새 모델 실행과 수치 pilot은 없다.

## 판단

**회귀형 foundation model의 분위수를 조건부 sample 생성에 사용하는 방향은 이미 구현되어 있다. 이를 TabICLv2로 교체하는 것만으로는 새로운 clustering 방법이 되지 않는다.** 87에서 발견한 무조건 shuffle의 문제도 조건부 MI 및 permutation 연구가 이미 명시적으로 다루었다. 보정항이나 근접 매칭만 추가하는 안은 추천하지 않는다.

이번 분석은 조건부 검사가 쓸모없다는 결론이 아니다. 그 검사가 답하는 질문과 현재 clustering이 바꾸는 학습 행동을 정확히 구별하게 되었다. ‘다른 cell의 입력이 추가 정보를 제공하는가’는 ‘두 cell의 sample을 같은 scalar RCTL로 학습하면 좋은가’와 다르다. 입력 공유를 실제로 추가하더라도 이미 검토한 47·81과 비교하여 새로운 이득이 있어야 한다.

## 2. TabPFN+CRT의 실제 구현까지 확인한 내용

공식 저장소 `msalem7777/tabpfn-crt`의 commit `c495edac3125ba2d0f104fcb7c11d3d9012bab13`을 고정하였다. 공개 파일 네 개를 저장하였고 실행하지 않았다.

1. `tabpfn_crt/crt.py:49`에서 무작위 train/evaluation 분할을 한다. 시계열의 연대순 분할은 아니다.
2. 62–68행에서 V2 target 모델을 `fit_with_cache`로 준비한다. 이어서 입력 열 j를 제외한 나머지 열로 j를 예측하는 모델을 91–97행에서 준비한다.
3. 103–114행에서 조건부 분위수 표를 한 번 계산한다. 135–164행의 각 반복에서는 이 표에서 값을 뽑고 target 모델을 다시 예측한다. 학습 파라미터가 고정되어도 반복 추론 비용은 발생한다.
4. `utils.py:27–51`은 회귀 full output의 criterion과 logits으로 log predictive density를 계산한다. 회귀 평균만을 비교하는 검사가 아니다.
5. 173행은 `(1 + null 통계량이 관측 통계량 이상인 횟수)/(B+1)`을 반환한다. 이 수식만으로 잘못 추정한 conditional sampler나 시간 의존성을 보정하지는 않는다.

본문 실험은 B=1000, 분위수 K=200, 반복5회라고 설명한다. 저장소 함수 기본값은 B=200/K=100이며, 공개 demo는 B=1000/K=1000/반복25회다. 본문의 표를 현재 코드 설정으로 재현했다고 주장하지 않는다. requirements는 패키지 버전을 고정하지 않으며 코드는 명시적으로 TabPFN V2를 선택한다. 최신 모든 TabPFN 버전의 실험이라고 확대하지 않는다.

연속 분포를 유한한 분위수 값 중 하나로만 추출하면, 조건부 생성 분포는 유한한 원자들에 질량을 둔다. 참 분포가 절대연속이라면 두 분포의 total variation 거리는 1일 수 있다. 따라서 ‘분위수가 촘촘하니 CPT 정리4의 오차항도 작다’는 주장은 성립하지 않는다. 연속 보간·smoothed sampling이나 특정 통계량에 대한 근사 분석은 다른 가정이 필요하다. 이 관찰은 실제 p-value가 반드시 나쁘다는 주장이 아니다.

## 3. 조건부 정보와 clustering 목적을 연결할 때 남는 차이

### 입력 정보의 추가 여부와 sample 공유의 효과

각자 독립인 두 cell이 같은 자기 이력→다음 값 관계를 가진다면, 다른 cell의 같은 시각 입력이 추가 정보를 주지 않아도 유한 자료에서 동일 관계를 공동 학습할 수 있다. 반대로 B의 현재값이 A의 다음 값에 유용해도, A의 입력에 B의 현재값을 넣지 않고 B의 과거 sample 행만 추가해서는 그 정보가 전달되지 않는다. 47의 핵심 구분이 그대로 남는다.

공동 입력·다중 출력으로 바꾸면 정보 전달은 가능하지만, 이는 81에서 이미 검토한 다른 학습 단위다. DGCformer·DUET·CCM·집합 변수 clustering보다 어떤 입력 경계를 더 잘 선택하는지 확인해야 한다. CRT의 p-value가 작다는 사실만으로 그 경계의 예측 손해나 연산 이득이 정해지지 않는다.

### 분포 관계의 발견과 점 예측 오차의 감소

분산만 다른 조건부 분포는 서로 의존하더라도 최적 평균이나 중앙값이 같을 수 있다. 따라서 log density/CMI 기준의 유용성과 RCTL의 MAE/MSE 개선은 같은 목적이 아니다. 여러 회귀 출력 분위수, 조건부 검정의 정확성, 좋은 point forecast를 같은 증거로 합치지 않는다.

### 시계열 조건의 보존

시간·요일·자기 이력은 입력 열로 제공해야 한다. 그러나 연속한 query의 각 값을 독립적으로 재생성하면 원래 시계열의 joint dependence까지 보존되는 것은 아니다. 시간 블록을 사용한다는 설명만으로 CRT의 교환가능성 조건이 자동 성립하지도 않는다. 블록 생성 분포, 조건부 독립 또는 근사 오차 가정을 별도로 정해야 한다.

위 구분은 새로운 검정법의 제안이 아니라, 이 분야의 결과를 현재 연구에 옮길 때 필요한 조건이다.

## 4. 실제 호출 구조로 정리한 비용

한 target, 검사할 입력 p개, 각 evaluation Q행, null 반복 B회를 생각한다. 저장소 함수를 열마다 그대로 호출하면 target context도 매번 다시 준비하므로 context 준비는 2p회다. 분위수 모델의 원래 Q행 추론과 target 모델의 원자료·B개 교체자료 추론을 합한 외부 query 처리량은 `p(B+2)Q`행이다. ensemble 내부 작업은 추가로 세어야 한다.

같은 target 모델과 원자료 예측을 재사용하도록 바꾸면 context 준비는 `p+1`회, query 행 수는 `(pB+p+1)Q`가 된다. 분위수 표를 cache해도 target 모델의 `pBQ`행 재예측은 남는다. 이는 코드에서 얻은 산술 작업량이며 새 wall-time 측정이 아니다. 저자의 복잡도 표기를 그대로 cell 수에 대입하지 않는다.

검사하려는 것이 cell 쌍이라면 후보 cell 수·lag 수에 따라 p 또는 target 수가 추가로 커진다. 따라서 이 검사를 모든 쌍에 붙인 뒤 상위 후보만 남기는 방식으로 계산량을 줄였다고 주장할 수 없다. 현 단계에서는 비용이 큰 새 CRT pilot을 실행하지 않는다.

## 5. 이번 단계의 구체적인 결정

| 검토한 후보 | 새로 확인한 근거 | 결정 |
|---|---|---|
| Tab 분위수로 조건부 sample 생성 | TabPFN+CRT 본문과 공식 구현에 같은 역할이 있음 | 모델 교체만으로 추천하지 않음 |
| 조건이 비슷한 시간 구간으로 shuffle 제한 | CMIknn·CCMI가 이미 원리와 방법을 제시 | 기본 비교 방법으로 유지 |
| 생성 모델 오차를 보정해 조건부 정보 계산 | CCMI의 KL 편향 소거와 CPT의 오차 분석이 있음 | 보정항 추가만으로 추천하지 않음 |

남는 질문은 새로운 shuffle 이름이 아니라, 현재 traffic에서 단순한 입력/공유 방식이 만드는 어떤 실제 손해를 줄일 것인지다. 조건부 정보 검사를 더 복잡하게 만드는 단계로 진행하지 않는다. 새로운 후보는 위 인덱스와 다른 결정이거나, 기존에 확인된 실패 원인을 직접 바꾸는 근거가 필요하다.

이번 단계는 원문·코드·기호 분석이다. 새 Tab/RCTL 실행 및 수치 진단 0회, 원장 불변, 추가 RCTL fit0을 유지한다. 추천 방향과 최종 Word는 아직 미완료다. 네 논문 전체의 실험이나 모든 증명을 검증한 것으로 표시하지 않는다.
