# 51–54 검토 결과: 공개 데이터의 범위와 관측 비용 후보

검토일: 2026-09-26. 새 추천안과 최종 Word는 아직 확정하지 않았다. 기존 보고서·실험은 수정하거나 재실행하지 않았다.

## 이번에 바뀐 판단

관측하는 cell 수를 줄이는 문제는 실제 선행연구가 다루는 구체적인 비용 문제다. 그러나 입력 복원 오차로 관측 대상을 고르는 원리는 이미 알려져 있다. TabICLv2를 복원기로 바꾸는 방향은 4개 cell의 작은 확인에서 단순 회귀보다 추가 이득을 보이지 않았다. 이 후보를 더 큰 clustering 실험으로 확대하지 않는다.

이는 전체 연구 중단이나 모든 데이터에서 TabICL이 불필요하다는 결론이 아니다. 이번에는 **문제의 존재**, **방법의 신규성**, **TabICL의 추가 기여**를 각각 확인했고, 마지막 두 항목을 충족하지 못했다. 다른 예측기의 복원 오차가 좋다는 사실만으로 RCTL의 공동 학습 이득을 주장하지 않는다.

## 2. 전체 오차 개선과 운영 목적의 개선을 구분

GOTSF는 요청한 **target 값의 범위**에 초점을 맞추는 예측이다. 여기서 interval은 context의 시간 구간이 아니다. AAAI2026 출판본9쪽과 arXiv2504.17493v3(2025-08-14)14쪽, 공식 코드 commit `31b17e55a0cb6f41bfe25230db3f81567efd58f3`을 대조했다. 입력에 범위의 경계를 넣거나, 범위와의 거리에 따라 회귀 손실을 가중하고 분류 head로 범위 소속 가능성을 추정한다. 기존 구조에 추가 head와 학습 목적 변경이 필요하다.

Table1의 여러 범위 평균은 일반적인 전체 시점 MAE와 다르다. active entrypoint가 호출하는 `exp_long_term_forecasting_discrete.py`와 `script_stats.py`는 범위 밖 target/prediction을0으로 만든 후 전체 원소 수로 MAE를 나눈다. 따라서 같은 예측값에 대한 이 값은 ‘범위 내 조건부 MAE × 해당 범위의 빈도’다. 서로 다른 interval 조건으로 만든 예측들을 평균한 표를, 하나의 전체 예측기의 MAE가 동일 비율로 개선됐다고 읽지 않는다. 출판본 식5와 active code의 가중 방식도 완전히 같지 않다. code에서는 회귀 항을 원소별 가중하고 BCE를 더한다.

arXiv 에너지 예는 DLPRB 부하를 용량·on/off 전력 가정에 넣은 simulation이다. 실제 전력 절감 측정이나 cell clustering 효과가 아니다. 이를 반영해 운영 목적을 별도로 정의할 수는 있지만, 단순한 가중 loss나 요청 구간 도입을 새 clustering 기여로 세지 않는다. [GOTSF 출판본](https://ojs.aaai.org/index.php/AAAI/article/view/39249), [v3](https://arxiv.org/abs/2504.17493v3), [공식 구현](https://github.com/netop-team/gotsf).

ITU Journal2025 beam forecasting 논문은 짧은 horizon의 lag·rolling feature와 먼 horizon의 달력·집계 특징을 나눈다. §5.2.3의 CV는 base-station 기준10fold이며 엄격한 순방향 시간 검증과 구별해야 한다. 달력·lag를 강한 단순 기준에 포함해야 한다는 근거로 사용한다. 새로운 cell clustering 검증으로 사용하지 않는다. [ITU 원문](https://www.itu.int/dms_pub/itu-s/opb/jnl/S-JNL-VOL6.ISSUE4-2025-A27-PDF-E.pdf).

## 4. 54: 실제로 수행한 가장 작은 확인

검사 전에 `54_partial_observation_pilot_plan.md`를 고정했다. 기존 중앙지역16개 중 공간상 네 모서리를 관측 지점으로 고정하고, 고정된 네 내부 cell의 관측을16시간씩 생략했다. 네 query 블록은 서로 떨어진 날이다. 모든 방법은 같은 마지막 보고값·전날/지난주값·동시 probe 네 값·시간/요일·보고 경과시간을 받는다. cell당 context256행, query64행이다.

| 방법 | 정규화 MAE | 이 숫자의 의미 |
|---|---:|---|
| 마지막 보고값 유지 |0.278152|16시간 내내 오래된 값을 쓰는 기준|
| 전날 같은 시각 |0.108815|주기성을 이용하는 강한 무학습 기준|
| 지난주 같은 시각 |0.175410|주간 lag 기준|

TabICL은 Ridge보다4개 cell 모두 전체 오차가 컸다. HGB보다 좋은 cell은1개였지만 같은 cell에서 Ridge가 더 좋았다. 앞쪽 두 블록에서는 TabICL0.069936, Ridge0.086665, HGB0.078469로 TabICL이 좋았다. 뒤쪽 두 블록에서는 TabICL0.147138, Ridge0.099261, HGB0.119203으로 순위가 바뀌었다. 긍정적인 앞 구간을 삭제하지 않으며, 전체 이득이 재현되었다고 하지 않는다.

원래 단위 결과도 파일에 보존했다. 이 단위는 해당 공개 자료의 Internet activity이며 bytes/Mbps가 아니다. 자료는 원래 관측됐고, 생략은 실험에서 모사했다. 실제 장애 빈도나 operator의 보고 정책을 측정한 결과가 아니다. 네 중앙지역 cell과 네 블록, ensemble1의 동작 확인 범위이며 TabICL 전체의 성능 순위를 확정하지 않는다.

TabICL은4contexts·256query행·2.543409초, 두 단순 학습기는 합계8fits·0.416225초였다. stage3.257689초이며 데이터·코드hash 계산 전 준비시간까지 포함한 전체 시스템 latency는 아니다. memory는 호출 사이 RSS 관측최대480,579,584bytes로 연속측정 peak가 아니다. 이전부터 보고된 source 다운로드/초기 전처리의 미계측 시간도 이번 수치에 포함했다고 주장하지 않는다.

최초 실행은 모델 호출 전에 historical context의 시각도 공동 결측으로 취급한 assert에서 중단했다. context는 당시 완전 관측 자료이고, query만 운영상 생략을 모사하므로 검사 범위를 수정했다. 원래 코드·오류·수정 기록을 보존했다. 데이터 선택·seed·판정 규칙은 그대로이며 첫 실패에서 나온 예측 결과는 없다. 최초 process wall4.163165초도 보수적으로 누적 비용에 포함했다. 실제 모델 실행은 한 번 완료했고 재실행하지 않는다.

## 5. 알고리즘으로 확대하지 않는 이유

검토했던 흐름은 ‘관측 지점 선택 및 grouping → TabICL로 생략된 현재 이력 복원 → cluster별 RCTL로 이후 실제 트래픽 예측’이었다. 이것은 처음 제안했던 ‘TabICL의 미래 오차로 어느 cell을 함께 학습할지 고르기’와 목적이 다르다. 그러나 관측 선택·복원 원리는 이미 존재하고, 현재 확인에서 TabICL의 추가 이득도 없었다. 좋은 복원이 RCTL에 좋을 것이라는 주장만 남긴 채 모듈을 추가하지 않는다.

복원기가 per-cell로 필요하다면, 직접 관측m개를 제외한 N−m개 각각에 context/cache와 온라인 추론이 필요하다. 관측 지점 선택에서 k개 대안을 각 cell마다 검사하면 최소Nk회 context 구성이 추가될 수 있다. model training0이 곧 구축/운영비0인 것은 아니다. 이번4contexts의 측정값을10,000cell의 실제 latency로 선형 환산해 확정하지 않는다. 단순 회귀의 저장/복원 비용도 포함한 비교가 필요하다.

가장 가까운 선행연구는 최종 예측모델의 LRP를 사용하지만, 이를 TabICL 점수로 교체했다는 차이만으로 신규성이 충분해지지 않는다. 주된 비용을 줄이는 분명한 원리 또는 단순 방법이 놓치는 정보가 실제로 확인되어야 한다. 지금 확인은 그 진입 조건을 통과하지 못했다.
