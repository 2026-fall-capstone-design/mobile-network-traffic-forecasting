# 52. 공개 Beijing 원자료의 사용 가능성 확인

2026-09-26. 성능 확인이나 추천 후보 채택이 아니라, MobiGPT가 인용한 STK-Diff의 실제 공개 범위를 확인한다.

- 출처: `tsinghua-fib-lab/STK-Diff`, commit `e1faed12aa7abb33d801fe9483026769ffaeeed3`.
- 확인한 파일: `traffic_data/beijing.npz`, Git tree에 기록된 크기 1,413,636 bytes. README의 `bs_beijing.npz`와 실제 경로가 다르며, loader는 실제 경로를 사용한다.
- 내려받기 상한: 위 파일 하나, 1,500,000 bytes. NPZ 전체가 약1.4MB로, 외부 인접행렬(각 약7.4MB)을 함께 받지 않는다. 완료 후 Git blob hash와 크기를 확인한다.
- 파싱은 `numpy.load(..., allow_pickle=False)`로 수행한다. 외부 Python 코드를 실행하거나 의존성을 설치하지 않는다.
- 확인할 정보: 배열 이름·형태·dtype·유한값·음수/0의 비율, 시간 길이, station 식별자·시간표·단위 설명의 존재 여부. 다운로드한 값만 보고 GB 단위나 날짜·cell 수를 추정하지 않는다.
- README는 기지국의 집계 트래픽이라고 설명한다. 물리 cell별 측정이라고 바꾸어 쓰지 않는다. 공개 부분집합을 MobiGPT 전체 데이터라고 하지 않는다.
- 모델 fit/forward는 모두0이며, 자료 진단 계산만 cheap diagnostic 예산에 한 번 반영한다. 계산 상한10초, 메모리128MB 이하의 배열을 처리한다. 기존 비용을 초기화하지 않는다.
- 시간 길이·식별자·정규화 정보가 연구의 시간 분할과 단위 정의에 부족하면, 이 자료로 새로운 도시에서의 성능을 검증했다고 하지 않는다. 가능한 범위와 부족한 범위를 구분한다.

이번 확인이 성공해도 알고리즘 신규성이나 RCTL 개선은 확인되지 않는다. 공개 원자료의 적합성이 확인된 경우에만, 그 자료를 쓰는 별도 최소 실험 계획을 작성한다.
