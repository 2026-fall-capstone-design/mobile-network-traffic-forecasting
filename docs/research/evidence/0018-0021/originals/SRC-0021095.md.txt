# 추가 진단의 결과와 설계 판단

2026-09-25. 16·18·19·20의 실행 전 계획과 실제 결과를 종합했다. 기존 파일은 보존했다. 모두 개발용 확인이며 독립 최종 검증이 아니다. 기존 중앙부 16개와 최초 28일 활동량 사분위별로 무작위 선택한 16개를 합친 고정 32 cell을 사용했다. 어려운 cell을 사후 제외하지 않았다.

## 현재 판단

추가한 네 가지 진단은 복잡한 clustering 모듈을 바로 도입할 근거를 주지 않았다. 가장 명확한 관찰은 **예측기의 외삽 오류를 cell 간 공유의 어려움으로 해석할 위험**이다. 그러나 아직 이 오류 때문에 실제 병합 결정이 잘못되었다는 인과관계나 이를 고친 clustering의 이득까지 확인한 것은 아니다. 단순 변화량 예측을 새 연구의 신규성으로 제시하지 않는다.

## 1. 오래된 자료를 버려야 하는가

Ridge/HGB에 최근 8시간, 일·주간 lag, 하루 평균·변동, 시각·요일을 동일하게 제공했다. 4개 주간 구간에서 과거 2주 고정, 최근 2주, 누적 자료를 비교했다. 정규화 MAE는 아래와 같다.

| 예측기 | 과거 2주 고정 | 최근 2주 | 누적 자료 |
|---|---:|---:|---:|
| Ridge | 0.132091 | 0.126735 | 0.115344 |
| HGB | 0.180521 | 0.162980 | 0.149347 |

누적 자료는 sample 수가 더 많다. 따라서 자료의 최신성과 자료량의 효과를 동일한 효과로 부르지 않는다. 첫 확인 주에서 cell별로 recent/expanding을 고르는 단순 선택도 이후 세 주에서 항상 expanding보다 나빴다. 이 자료로 adaptive forgetting이나 drift 기반 재배정의 필요성을 주장하지 않는다. 세부 결과는 `17_temporal_validity_findings.md`와 `results/temporal_validity/`에 있다.

## 2. 이웃 정보를 더하면 별도 구조가 필요한가

동일한 자기 입력에 이웃 8개 평균, 학습 구간 PCC가 가장 높은 이웃 하나, 8개 이웃 각각의 최근 이력을 추가했다. 시간 분할은 동일하다.

| 예측기 | 자기 입력 | 이웃 평균 | PCC 이웃 하나 | 이웃 8개 개별 입력 |
|---|---:|---:|---:|---:|
| Ridge | 0.141232 | 0.150974 | 0.155292 | 0.167896 |
| HGB | 0.238204 | 0.238173 | 0.238492 | 0.240117 |

일부 cell의 개선이 전체 이득으로 이어지지 않았다. 공간 정보의 정렬·attention·별도 clustering을 추가할 직접 근거는 확보되지 않았다. 공개 가공 자료의 보간·반올림 영향이 있을 수 있으므로 이 결과를 공간적 원인의 부재라고 해석하지 않는다.

## 3. cell 식별 정보를 주면 공유 예측이 좋아지는가

32 cell 각각에서 과거 context 64개, 뒤 구간 query 64개를 고정했다. pooled context와 query는 각각 2,048행이다. TabICLv2의 checkpoint·seed·ensemble 1을 유지하고 입력만 비교했다.

| 입력 | TabICLv2 MAE | Ridge MAE | HGB MAE |
|---|---:|---:|---:|
| cell ID 없음 | 0.240992 | 0.164979 | 0.255205 |
| one-hot cell ID | 0.242169 | 0.178096 | 0.255064 |
| 과거 cell 요약값 | 0.244203 | 0.164547 | 0.257802 |

ID 열 순서를 바꾼 TabICLv2 결과는 0.242254다. 이 설정에서 식별 정보의 뚜렷한 이득을 확인하지 못했다. 다만 유한한 pooled 모델의 결과이므로 이를 모든 clustering 이득의 상한이나 cell 간 관계가 동일하다는 증명으로 사용하지 않는다.

## 4. 평균 오차를 좌우한 현상

cell 7524가 ID 없는 TabICLv2 전체 absolute loss의 60.45%를 차지했다. context target은 정규화 기준 최대 3.256이었지만 뒤 구간 실제값은 최대 30.196이었다. 예측 시점에 이미 알 수 있는 최근 입력도 최대 29.250에 도달했는데, raw target 모델은 높은 실제값에 약 3.2 수준의 예측을 반환했다. 일부 예측이 context 최대값을 조금 넘으므로 출력의 수학적 상한으로 설명하지 않는다. 관측치의 물리적 원인도 추정하지 않았다.

같은 입력·context·query를 그대로 두고 `다음 값 − 최근 입력값`을 예측한 뒤 최근값을 더하는 기본 대안을 확인했다. RCTL의 target이나 구조는 바꾸지 않았다.

| 예측기 | 원래 target | 변화량 target | 개선된 cell 수 |
|---|---:|---:|---:|
| TabICLv2 | 0.240992 | 0.132710 | 4 / 32 |
| Ridge | 0.164979 | 0.164741 | 32 / 32, 차이는 작음 |
| HGB | 0.255205 | 0.155597 | 1 / 32 |

TabICLv2 평균은 44.93% 감소했지만 28개 cell의 오차는 증가했다. 기존 중앙부 16개 평균도 0.096572에서 0.101476으로 증가했다. cell 7524의 오차가 4.661670에서 1.045719로 감소한 영향이 크다. 이 사실을 빠뜨린 채 일반적인 44.93% 개선으로 보고하지 않는다. 최근 관측값을 그대로 예측하는 기준의 전체 MAE는 0.155334다.

## 5. 선행연구를 반영한 해석

- MGSTC의 loss buffer와 갱신, PID 방식의 이전 오차 보정은 실제 최종 예측기의 결과를 사용한다. 이를 RCTL 결과 없이 수행하는 clustering과 동일하게 설명할 수 없다. MGSTC Milan 실험은 중앙 30×30 grid의 다섯 활동 합계·10분 자료로, 현재의 시간별 internet activity와 단위·범위가 다르다. [원문 §4.3·§5.1](https://arxiv.org/html/2508.08281v1)
- QoS 공동 clustering은 배정과 모델 학습을 번갈아 최적화한다. 현재의 독립 clustering과 제약이 다르며, 적응적 재배정과 모델 수 절충만으로 새 기여를 주장할 수 없다. [원문 §3·§4](https://arxiv.org/html/2604.12903v1)
- Feature to Dynamics는 전역 추세·주기와 국소 특징으로 작은 AR 예측기의 계수를 생성한다. 원문의 개념적 ARMA 설정과 실제 결정적 AR rollout을 구분해야 한다. 같은 source에서 처음부터 학습한 축소 모델 비교를 공개 대형 checkpoint에 대한 우위로 확대하지 않는다. [원문 §4·§5](https://arxiv.org/html/2606.01289v1)
- 공식 TabICL forecasting의 `_seasonality.py`에서 확인한 detrending은 주기 탐색 전 신호 처리다. 이것을 변화량 target을 회귀하는 공식 기능이라고 부르지 않는다. 직접 확인한 설치 버전은 2.2다. [공식 forecasting 안내](https://tabicl.readthedocs.io/en/latest/tutorials/time_series_forecasting.html)

## 6. 다음 판단에서 구분할 사항

raw 예측기의 큰 오차, 다른 context로 교체했을 때의 손해, 실제 여러 cell을 함께 학습한 RCTL의 손해는 서로 다르다. 현재 결과는 첫 현상을 확인했다. 두 번째·세 번째를 확인한 것처럼 서술하지 않는다. 다음 후보를 검토한다면 **예측 관계의 차이와 추정기의 유효 범위를 분리했을 때 기존 기준보다 어떤 병합 판단이 정확해지는가**부터 좁혀야 한다. 잔차 처리나 지원 범위 필터를 단순히 붙인 것은 이미 알려진 대안이므로 독립적인 신규성으로 채택하지 않는다.

## 비용과 재현 자료

추가 TabICLv2 실행은 6 contexts, 12,288 query rows, fit/predict 59.672초다. 누적은 45 contexts, 35,712 query rows, 223.887초다. 추가 RCTL 학습은 없으며 누적 29 fits 상한을 유지했다. 이번 작은 회귀 진단의 시간은 각 summary JSON에 보존했다. 전처리까지 포함한 전체 wall time을 모델 시간과 혼동하지 않는다.

실행 계획·코드·결과는 번호 16·18·19·20 및 `results/`의 같은 이름 폴더에 있다. `summarize_error_concentration.py`는 저장된 예측만 읽어 집중도를 재계산하며 새 모델을 호출하지 않는다. 추천안과 최종 Word는 아직 완성되지 않았다.
