# 109 같은 K4의 저장된 학습 경로 확인

2026-09-26. 108에서 사후 BN 통계 재계산이 두 K4의 오차 차이를 해소하지 못했다. 다음 확인은 학습을 다시 하는 것이 아니라, 아직 최종 checkpoint 비교에 반영하지 않은 epoch별 로그를 읽는 것이다.

## 확인할 주장과 대상

- TabICL risk와 empirical risk의 K4, seed 20260925·20260926, 각 4개 모델의 원래 `*_history.json` 16개를 읽는다. global 및 나머지 12개 로그는 중단 규칙의 전체 일관성 확인에만 사용하며 같은 K의 핵심 비교와 섞지 않는다.
- 기존 34는 최종 가중치의 train/validation 예측, 106은 최종 예측의 cell별 전이, 108은 같은 가중치의 BN 통계 변경이었다. 이번에는 epoch별 validation 경로와 실제 중단 조건을 확인한다.
- 최적화 전역 수렴, 학습량의 인과적 효과, 새 clustering의 성능을 이 로그만으로 증명하지 않는다.

## 고정할 계산

1. 원본 학습 코드와 frozen settings에서 epoch 상한, patience, 개선 판정, batch 처리 규칙을 읽는다. history의 길이·best epoch·최저 validation·종료 이유가 fit_results와 일치하는지 확인한다.
2. 각 모델의 실제 첫/최선/마지막 validation, 최선 이전 개선 폭, 마지막 10개 epoch의 변화, 최대 epoch 도달 여부를 기록한다. 단조 수렴을 가정하지 않는다.
3. 동일 seed의 두 K4가 모두 기록을 가진 epoch까지만 4개 모델의 동일 cell 비중 평균 validation을 나란히 계산한다. 종료 후 값을 보간하거나 마지막 값으로 채우지 않는다. 전체 공통 구간의 차이 배열을 남기고 유리한 epoch 하나를 골라 새 성능으로 쓰지 않는다.
4. 훈련 중 train_mae는 가중치가 계속 달라지고 dropout·BN이 훈련 모드인 값이다. 평가 모드 validation과의 차이를 과적합 크기로 직접 해석하지 않는다. 두 분할의 train 곡선은 보조 기술 통계로만 기록한다.
5. 첫 seed의 global과 K4는 model당 sample/update 수가 다르므로 같은 epoch를 같은 최적화 작업량으로 표현하지 않는다. 핵심 판정은 같은 K4에서 한다.

## 결과별 행동

특정 분할의 여러 모델이 상한까지 꾸준히 개선 중인데 끝난 경우에는 '기존 학습 조건 아래의 비교'와 '충분한 학습 뒤의 비교'를 구별한다. 이것만으로 추가 학습을 승인하거나 원래 결과를 삭제하지 않는다. 동일 조건을 어떻게 통제할지 명세가 먼저다.

상한 절단 또는 기록 불일치의 근거가 없으면 조기 종료 설정을 바꿔 기존 후보를 반복 학습하지 않는다. 같은 sample 수의 두 분할에서 공유 상대가 바뀐 효과를 설명하는 새 소속 결정 명세에 남은 모델 예산을 보존한다. RCTL loss를 cell 소속·clustering threshold에 입력하지 않는다.

새 모델 fit·forward·Tab 호출은 0이다. JSON/배열 계산 상한은 10초, RSS 1GiB다. 설정·코드·입력 hash와 결과를 저장하고 측정한 계산만 누적 원장에 추가한다. 실패 시도도 기록하며 완료 분석을 재실행하지 않는다.
