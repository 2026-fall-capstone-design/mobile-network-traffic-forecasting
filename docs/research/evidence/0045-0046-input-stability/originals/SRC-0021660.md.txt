# 47 입력 공유 검토 결과

2026-09-26. 상태: 추가 검토 완료, 추천 방향 미확정. 45 계획 뒤 46 진단을 한 번 실행했다. 기존 연구·예산을 이어갔으며 새 goal을 만들지 않았다.

## 1. 무엇을 새로 구별했는가

`B의 sample을 A와 함께 학습한다`와 `B의 과거 관측값을 A의 입력 열에 추가한다`는 서로 다른 행동이다. 전자는 같은 함수를 추정하는 데 쓸 자료를 바꾸고, 후자는 예측 시점에 관측하는 정보를 바꾼다. 다른 cell의 자료를 사용한다는 말로 둘을 합치면 clustering → RCTL의 연결을 설명할 수 없다.

원 GECOS의 보존된 공개 코드 `sources/GECOS_main.txt`는 `Input(shape=(self.steps, 1))`와 `Dense(1)`을 사용한다. 소스 tree는 `a7519dde9d6f5deb3006689df047d99ea0dac7b7`이다. 원문 IV.A는 cell별 sliding sequence를 설명한다. 따라서 같은 cluster가 됐다는 사실만으로 여러 cell이 입력 채널로 들어간다고 해석하지 않는다. 공개 코드는 전체 데이터 로더를 포함하지 않으므로 실제 논문의 모든 전처리를 재현했다고 주장하지 않는다.

입력 공유를 새 경로로 다루려면 cluster별로 **어느 cell의 어떤 시각 값을 어느 열에 놓는지** 정해야 한다. 모든 구성원의 이력을 연결하면 cluster 크기에 따라 입력 폭과 첫 층의 parameter 수가 달라진다. 고정된 상대 위치의 이웃을 넣는다면 비인접 cell끼리 같은 cluster가 되어도 그 이웃은 각기 다른 cell이다. 두 구현을 같은 공유 구조로 취급하지 않는다. 이번에는 RCTL 입력이나 학습을 변경하지 않았다.

## 3. 원문에서 확인한 구체적 차이

### DIC-ST, Remote Sensing 2022

원문: https://doi.org/10.3390/rs14061439

§3.1–3.2, Algorithms 1–2, §4.3/Table 2를 읽었다. 22개 실제 기지국의 시간별 downlink GB이며 §3.1은 100일 자료를 설명한다. Algorithm 1의 clustering 대상은 cell이 아니라 EMD의 IMF다. entropy·스펙트럼 피크 수로 세 성분을 구성한다. 성분별 transfer entropy로 graph를 만든 뒤 T×22 입력을 2층 GCN에 주고 세 예측을 합한다. Table 2의 세 기지국에서 graph를 쓴 조건의 RMSE가 더 작다. 이는 공간 입력 활용의 선행 근거이며 UPC식 cell partition의 성능 증거는 아니다.

재현 시 해소할 부분도 확인했다. 식 11은 Ci를 예측하면서 Cj의 과거를 추가하지만 화살표는 Ci→Cj로 쓴다. 식 13의 양방향 비율과 Algorithm 2의 절대값 `≥1` 표기도 다르다. 시간 분할은 §4.3에서 3:1·10일 예측으로 적으며 EMD/graph 추정의 정확한 절단 시점은 명료하지 않다. 미래 누출이 있었다고 확정하지 않는다. full-series EMD를 현재 예측 입력에 그대로 쓰지 않는 것이 이번 설계 기준이다. Data Availability는 ‘Not applicable’이며 공개 원자료·코드 링크는 본문에서 확인하지 못했다.

**반영:** ‘시계열 분해 + 예측 관계 graph’ 자체를 새 기여로 삼지 않는다. Algorithm 2는 cell 쌍 계산에 더해 세 겹 순회를 포함하므로 대규모 실행 비용을 생략하지 않는다. 원문 표기만 고치는 것을 연구 신규성으로 내세우지 않는다.

### Markov boundary for tabular prediction, 2605.29411v2

원문: https://arxiv.org/html/2605.29411v2

2026-08-19 v2, CIKM 2026 accepted 표기. §2–7, Theorem 2.2, Propositions 3.2/5.1/5.2, Table 2를 읽었다. 3,450개 합성 SCM task와 6개 회귀기를 비교한다. 참 boundary를 알 때와 실제 추정한 입력 집합을 구분한다. Table 2에서 F=200의 Grow-Shrink 입력은 Ridge 98.9%, TabPFN 37.4%의 task에서 전체 입력보다 좋다. 같은 입력 선택의 효과도 회귀기에 따라 다르다.

Theorem 2.2는 Markov·faithfulness·product support·동일 graph·각 boundary 변수의 조건부 평균 영향 가정 아래 MSE 충분성을 말한다. Proposition 3.2의 유한 자료 비용은 정규 선형 OLS 예다. 이를 RCTL/MAE의 보장으로 옮기지 않는다. §7의 boundary head 사전학습과 예측 손실의 결합은 후속 방향 제안이며 공개 TabICLv2 checkpoint의 기능이 아니다. 이번에 원문으로 exact TabICL checkpoint/API·세부 학습 예산까지 확정하지는 않았다.

**반영:** TabICL이 고른 입력을 RCTL의 최적 입력으로 간주하지 않는다. 필요한 신호의 누락과 불필요한 열의 추가를 따로 확인한다. ‘boundary를 찾는다’는 말만으로 신규성·실용성을 주장하지 않는다.

## 4. 입력 공유를 병합 점수로 곧바로 바꿀 수 없는 이유

다음은 실제 트래픽 결과가 아닌 논리 확인이다. 입력을 가장 최근 한 시점으로 한정한다. 두 cell의 중심화한 변동 a,b가 `a_next=0.5b+εa`, `b_next=−0.5a+εb`를 따르고, noise는 같은 양의 분산을 가진 독립 정규분포라고 하자. 안정된 정상분포에서 두 좌표의 분산은 같고 서로 독립이다.

- A를 예측할 때 B의 최근 값은 유용하다. B를 예측할 때 A의 최근 값도 유용하다.
- 각 cell의 입력을 `[자기 값, 상대 값]` 순서로 통일하면, A의 조건부 중앙값은 `+0.5×상대 값`, B는 `−0.5×상대 값`이다.
- 입력 분포는 같아도 필요한 함수가 다르다. cell 구분 없이 같은 함수 하나를 쓰는 구조에서는 두 함수를 동시에 재현할 수 없다.

따라서 강한 양방향 입력 의존성은 같은 RCTL 함수를 공유하기 적합하다는 충분조건이 아니다. 반대로 cell ID·입력 역할을 구별하는 구조라면 이 반례의 충돌을 해소할 수 있다. 그런 변경을 명시하고 유한 자료의 추정 비용까지 확인해야 한다. 이 예는 모든 multivariate RCTL이 실패한다는 주장이 아니다.

또한 정적인 전체 graph의 Markov boundary에는 target의 자식이 포함될 수 있다. 시계열의 미래 target 뒤에 발생하는 관측값은 현재 입력으로 쓸 수 없다. 예측 시점까지 관측 가능한 열만 먼저 고정하고 그 안에서 정보를 비교해야 한다. 정적 표의 이론을 시간 전개된 전체 graph에 그대로 적용해 미래 열을 가져오지 않는다.

## 5. 이 방향에서 TabICLv2가 담당할 수 있는 계산과 비용

가능한 역할은 동일한 context 행·target·query 시간에서 입력 열만 바꾸어, 다른 cell의 과거가 추가 예측 정보를 주는지 추정하는 것이다. 기존 sample 교체 검사와 역할이 다르다. 아직 이 계산을 실행하거나 추천한 것은 아니다.

단순하게 cell마다 자기 입력과 후보 k개의 이웃 입력을 하나씩 비교하면 최소 한 차례에 `N(k+1)`개의 context 구성이 생긴다. k=8, context 256행, query 64행, ensemble 1인 가정에서:

| cell 수 N | context 구성 수 | query 예측 행 수 |
|---:|---:|---:|
| 128 | 1,152 | 73,728 |
| 1,024 | 9,216 | 589,824 |
| 10,000 | 90,000 | 5,760,000 |

이는 작업량의 산술 계산이며 시간 측정치가 아니다. 시간 블록 반복·조합 효과 검사·cluster 갱신 비용은 아직 더하지 않았다. 입력 열과 전처리가 달라지는 여러 context를 하나의 동일 cache로 처리한다고 가정하지 않는다. 후보를 싸게 찾는 비용도 별도다. 2N개의 자기/모든 이웃 비교로 줄일 수 있지만, 이때 답하는 질문은 개별 cell 선택이 아니라 이웃 묶음 전체의 효용이다.

## 6. 이번 판단과 다음 진입 조건

‘TabICLv2로 예측 의존 graph를 구한 뒤 연결된 cell을 같은 RCTL로 묶기’를 현 상태에서 추천하지 않는다. 원인이 세 가지로 분명해졌다.

1. 공간 입력의 이득이 있더라도 sample pooling의 이득과 다른 문제다.
2. 기존 통신 연구가 이미 성분별 예측 의존 graph를 사용한다. 이름 변경만으로 차별점이 생기지 않는다.
3. 실제 개발 자료에는 일부 공간 입력 이득이 있으나, 회귀기 간 일치가 제한적이고 앞 주 선택이 뒷 주 평균 이득으로 이어지는 정도도 작거나 반대다. 현재 관찰만으로 TabICL 추정 비용을 추가할 근거가 부족하다.

이 경로를 다시 열려면 **어떤 관측 정보의 손실을 어떤 입력 구성으로 회복하며, 그 구성으로 결정한 cell 소속이 RCTL의 학습 단위와 왜 맞는지**를 먼저 답해야 한다. 기존 입력 교체·sample 교체·정보 이론 점수에 이름을 추가하는 것으로 대신하지 않는다. 새 실험이 필요하다는 말만 남기지 않도록 이번에는 두 행동의 비동등성, 선행 구조, 실제 긍정·부정 범위, 규모 비용을 확정했다.

새로운 전체 연구 방향·최종 Word는 아직 완성되지 않았다. 이번 결과는 다음 후보의 설계 제약으로 사용한다. 현재 목표 범위와 RCTL fit 상한을 유지한다.
