# 45 입력 정보 공유와 sample 공유의 구분

2026-09-26. 이전 cell별 진단(42)은 같은 자료를 함께 학습하는 분할의 이득을 다뤘다. 이번 검토는 **다른 cell의 과거 관측값을 추가 입력으로 제공하는 행동**을 별도로 살핀다. 아직 추천안이 아니며 기존 실패를 새 이름으로 바꾸지 않는다.

## 먼저 확인할 원문

- DIC-ST: A Hybrid Prediction Framework Based on Causal Structure Learning for Cellular Traffic and Its Application in Urban Computing, Remote Sensing 2022, DOI 10.3390/rs14061439. 실제 통신 트래픽에서 사용하는 분해, clustering 단위, transfer entropy, 공간 입력, 예측 모델을 확인한다. 제목의 causal이라는 말을 관찰 자료만으로 인과가 입증됐다는 뜻으로 옮기지 않는다.
- The Good, the Bad, and the Ugly of Markov Boundary for Tabular Prediction, arXiv:2605.29411의 최신 버전. 참 조건부 독립 구조를 아는 경우와 구조를 추정하는 경우의 차이, 특징 누락과 불필요한 특징 추가의 손해, 계산 예산, 논문의 제안과 실제 수행 결과를 구분한다.
- 원 UPC·RCTL의 입력 설명을 다시 대조한다. cluster별 모델을 둔다는 사실만으로 다른 cell의 과거 값이 입력 열로 추가된다고 추론하지 않는다.

검색으로 발견한 CLPREM, temporal causal PFN은 위 경로와의 관련성부터 판단한다. 문헌 수를 채우려고 검토 범위를 늘리지 않는다. 공개 원문 접근 제한은 우회하지 않는다.

## 실제로 달라지는 질문

- sample 공유: B의 `(입력, 실제 target)` 행을 A와 함께 학습해도 되는가?
- 입력 공유: A의 최근 입력만 사용할 때보다 같은 시각에 관측 가능한 B의 과거 값을 더 주면 A의 미래 예측에 정보가 생기는가?

후자는 방향이 있으며, B의 과거가 A에 유용해도 A와 B가 같은 예측 규칙을 공유한다는 뜻은 아니다. 따라서 이를 곧바로 기존 sample pooling의 병합 점수로 쓰지 않는다. multivariate 입력을 실제 RCTL에 전달하는 설계와 비용이 동반되어야 한다.

## 46: 이미 저장된 공간 입력 진단의 추가 확인

새 모델을 실행하기 전에 `results/spatial_information/predictions.npz`만 읽는다. 원래 18에서 비교한 32 cell, 2개 모델(Ridge/HGB), 자기 입력·이웃 평균·PCC 이웃·8방향 이웃, 같은 336시간을 모두 유지한다. 결과를 본 뒤 cell을 제외하지 않는다.

확인할 주장 하나: **평균에서는 약했던 공간 입력 이득이, 특정 cell에서 앞·뒤 168시간 모두 재현되는가?**

각 입력 대안에 대해 전체 및 두 주별 MAE 차이, 두 주 모두 개선된 cell 수, 두 회귀기 모두에서 두 주 모두 개선된 cell 수를 계산한다. 작은 수치 반올림으로 부호를 바꾸지 않는다. 전체/첫16/나머지16 결과를 구분한다. 개별 cell 목록은 탐색 결과이며 새 독립 검증으로 부르지 않는다.

추가로 첫 168시간에서 고른 입력 대안을 다음 168시간에 적용하는 규칙을 계산한다. 선택 단위는 cell별·회귀기별이고 대안은 기존 네 가지 모두다. 다음 주의 실제 target으로 대안을 고르지 않는다. 정답을 아는 사후 최적 선택도 별도 계산하되 실행 가능한 방법으로 제안하지 않는다. 이 진단의 선택 결과를 RCTL의 cluster 배정에 사용하지 않는다.

가능한 결과와 행동:

1. 반복되는 이득이 거의 없거나 첫 주 선택이 다음 주 손해를 키우면, 공간 입력이 현행 문제를 해결한다는 주장을 하지 않는다. TabICL 호출로 확대하지 않는다.
2. 일부 cell에서만 이득이 보이면, 해당 비율과 비용을 보고하고 일관된 메커니즘·입력 가용성·가장 가까운 기존 연구와의 차이를 먼저 확인한다. 그 cell만 골라 성공률을 보고하지 않는다.
3. 여러 cell에서 유지되는 이득이 있어도 이것은 simple 모델의 입력 진단이다. TabICLv2 및 cluster별 RCTL 성능 확인을 대신하지 않는다.

새 RCTL fit/forward, 새 Tab context/query, 새 simple fit은 모두 0. 저장된 배열의 계산만 최대 10초·RSS 1 GiB로 제한한다. 실제 시간을 누적 cheap budget에 한 번만 더한다. 기존 RCTL 29 fits 상한은 유지한다. 입력 hash, 계획 hash, 시작/완료 marker와 결과를 남기며 재실행하지 않는다.

## 후보 판단 기준

다른 cell의 입력이 유용하다는 사실, 그 입력을 찾는 방법의 신규성, 그 cell을 같은 RCTL로 묶는 이득은 서로 다른 주장이다. 세 연결을 확인하지 않고 graph·인과·고차 상호작용이라는 표현을 추가하지 않는다. 두 원문에 이미 있는 구조는 새 기여로 세지 않는다.
