# 94. 예측 horizon 때문에 아직 정답이 없는 최근 입력의 활용 가능성

2026-09-26. 93은 실제 기록 감사와 탐색 진입 기준 수정으로 다음 설계를 바꾸었으므로 progress다. snapshot35와 비용 원장을 확인했다. 새 후보를 합격시키거나 기존안의 기각을 뒤집은 것은 아니다.

## 기존 검토와 달라질 수 있는 점

09의 prediction-powered 보정은 정답이 이미 있는 동일한 과거 자료에 예측을 더하고 빼면 empirical로 환원될 수 있다는 점과, 실제 대량 unlabeled 자료의 필요성을 지적했다. 여기서는 인위적으로 label을 가리지 않고, 예측 시점과 horizon의 정의상 아직 실제 결과가 관측되지 않은 최근 입력이 있는지 확인한다. 17·77·83의 drift 감시·동적 재배정과 같은 원리라면 새 후보로 포장하지 않는다.

현재 시각 t에서 입력 X_s는 시각 s까지의 관측으로 구성하고 정답은 y_(s+h)라 둔다. 완전히 관측된 target은 s+h≤t인 행에만 있다. 경계 근처 입력의 가용성과 그 입력이 지금 추천하려는 미래 예측 문제의 분포를 대표하는지는 별도다. h=1에서 생기는 한 행을 대량의 새로운 독립 자료라고 부르지 않는다. 더 큰 h를 검토한다면 실제 연구 목적·선행연구와의 연결이 먼저 필요하며 유리한 지연을 만들기 위해 임의로 변경하지 않는다.

## 이번에 확인할 것

1. 관련 primary 연구 최대3편의 실제 추정식·의존성/분포 변화 가정·delay 처리·검증 대상을 읽는다. prediction-powered inference, 지연 label의 시계열 예측, TFM의 streaming/context 갱신을 중심으로 가장 가까운 방법을 찾는다.
2. 과거 labeled 입력과 최근 unlabeled 입력의 분포가 다르면 어떤 보정이 필요한지 확인한다. 현재 unlabeled 입력만으로 conditional drift까지 알아낼 수 있다고 주장하지 않는다.
3. 예측·분포 모니터링과 cell 소속 선택은 다르다. 마지막에는 실제로 바뀌는 clustering 결정, RCTL 학습 자료의 변경, 필요한 갱신 비용을 특정할 수 있는지 판단한다.
4. 데이터가 모두 기록된 뒤 수행하는 오프라인 clustering에 굳이 지연 문제를 만들어 넣지 않는다. 실제 사용할 예측 시점에서 필요한 조건을 확인한다. 이미 끝난 실험의 test는 계속 개발자료다.
5. 새로운 문제라면 TabICLv2의 context 기반 조건부 회귀가 단순한 최근값/달력/Ridge와 달리 기여할 이유를 적는다. 이미 알려진 delayed-feedback 적응이나 pseudo-labeling에 이름만 바꾼 조합이면 실행하지 않는다.

이번 범위는 문헌·코드·시간 가용성의 기호 검토다. 새 데이터 수치·Tab 추론·RCTL fit0. 잔여 Tab11context/20640query, 추가 RCTLfit0 유지. 이후 작은 실행이 필요하면 별도 사전 계획에서 질문·비교·비용을 고정한다.
