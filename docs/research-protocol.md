# 공통 실험 규약

모델을 비교할 때 데이터, 예측 시점, 평가 표본을 동일하게 맞추기 위한 기준입니다.
입력 준비는 [데이터 안내](../data/README.md), 결과 파일 작성은
[웹 데이터 규약](web-data-contract.md)을 참고합니다.

## 비교 대상

현재 기준 모델은 다음 두 가지입니다.

| 모델 ID | 예측 방법 | 역할 |
|---|---|---|
| `last-value` | 예측 대상 시각의 1시간 전 관측값 사용 | 직전 상태를 유지했을 때의 오차 확인 |
| `seasonal-24h` | 예측 대상 시각의 24시간 전 관측값 사용 | 하루 주기를 사용했을 때의 오차 확인 |

연구 방향은 TabICLv2 직접 예측과 TabICLv2 기반 군집화 후 RCTL 예측을 검토합니다.
선택한 모델은 위 기준 모델과 같은 테스트 표본에서 비교합니다.

## 실험 전에 정할 조건

| 조건 | 기록할 내용 |
|---|---|
| 데이터 | 데이터 버전, 대상 셀, 관측 단위, 전체 기간 |
| 시간 분할 | 학습 또는 컨텍스트·검증·테스트의 시작과 끝 |
| 입력 | 과거 관측 길이, 추가 특징, 결측 처리 |
| 예측 | 예측 간격, 한 번에 예측할 시점 수, 실제 관측값 갱신 시점 |
| 모델 | 구현·가중치 버전, 변경할 설정, 고정할 설정 |
| 비교 | 기준 모델, 지표, 제외 표본과 사유 |
| 실행 | 설정 파일, 명령, 시드, 환경, 결과 경로 |

같은 실험에서 달라지는 조건을 먼저 정합니다.
예를 들어 입력 이력 길이를 비교한다면 데이터·테스트 구간·나머지 설정은 고정합니다.

## 시간 분할과 정보 사용

학습·검증·테스트는 시간 순서로 나눕니다.
모델 선택과 하이퍼파라미터 조정은 검증 구간에서 수행하고,
테스트 구간은 최종 비교에 사용합니다.

정규화 통계, 결측 보정 규칙, 특징 선택과 군집화도 해당 예측 시점에 이용할 수 있는
데이터로 계산합니다. 각 변환을 어느 구간에서 학습하고 어느 구간에 적용했는지 기록합니다.

### 예측 기준 시점과 대상 시점

| 필드 | 의미 | 예시 |
|---|---|---|
| `origin_time` | 입력 정보를 사용할 수 있는 예측 기준 시점 | 01:00 UTC |
| `timestamp` | 예측하려는 관측 시점 | 02:00 UTC |

현재 웹 데이터 규약은 **1시간 뒤 한 시점 예측**을 지원합니다.
실제 관측값의 수집 지연이 있다면 입력으로 사용할 수 있는 마지막 시점도 그만큼 조정합니다.

합성 예제는 매 시간 새 관측값을 받은 뒤 다음 1시간을 예측합니다.
따라서 앞선 테스트 시점의 실제값을 다음 예측에 사용할 수 있습니다.
이는 테스트 시작 시점에 이후 24시간을 한 번에 예측하는 조건과 다르므로,
비교 모델 모두 같은 관측값 갱신 조건을 적용합니다.

## 평가 표본 맞추기

비교 단위는 `(cell_id, origin_time, timestamp)`입니다.
모델마다 이 조합과 실제 관측값이 일치해야 합니다.

- 셀 목록과 테스트 시작·종료 시각을 고정합니다.
- 입력 이력이 부족한 구간은 모든 모델에 동일하게 적용할 평가 범위를 먼저 정합니다.
- 결측이나 오류로 표본을 제외할 경우 개수와 사유를 기록합니다.
- 현재 웹 출력에는 선언한 테스트 구간을 셀마다 빠짐없이 1시간 간격으로 포함합니다.

## 평가 지표

오차는 `예측값 - 실제값`으로 계산합니다.

| 표시 이름 | JSON 필드 | 계산 | 해석 |
|---|---|---|---|
| MAE | `mae` | 전체 표본의 절대오차 평균 | 평균적으로 얼마나 차이 나는지 확인 |
| RMSE | `rmse` | 전체 표본의 제곱오차 평균에 제곱근 적용 | 큰 오차에 더 민감한 전체 오차 |
| Macro RMSE | `macro_rmse` | 셀별 RMSE를 구한 뒤 셀마다 같은 가중치로 평균 | 셀 단위 성능을 균등하게 반영 |
| 표본 수 | `n_points` | 평가한 예측값 개수 | 비교 범위 확인 |
| 셀 수 | `n_cells` | 평가에 포함한 셀 개수 | 비교 범위 확인 |

RMSE는 전체 표본을 한꺼번에 계산한 pooled RMSE입니다.
Macro RMSE는 셀별 RMSE의 평균이므로 두 값은 구분해서 보고합니다.
오차 지표는 관측값과 같은 단위를 사용하며, 값이 작을수록 예측 오차가 작습니다.

지표 계산은 [evaluation 모듈](../src/traffic_forecasting/evaluation/__init__.py)로 통일합니다.
현재 구현은 소수점 6자리까지 저장합니다.
웹의 셀·표시 구간 필터는 차트만 바꾸며, 지표는 전체 테스트 표본 기준을 유지합니다.

## 연구 모델 연결 순서

1. 입력 데이터를 셀·시각·관측값 형식으로 정리하고 전처리 조건을 기록합니다.
2. 동일한 테스트 표본에 대해 기준 모델과 연구 모델의 예측값을 생성합니다.
3. 각 예측값을 [Prediction](../src/traffic_forecasting/forecasting/__init__.py)의
   `cell_id`, `origin_time`, `timestamp`, `actual`, `predicted`로 표현합니다.
4. `evaluation.summarize()`로 모델별 지표를 계산합니다.
5. 예측·지표 JSON을 작성하고 `manifest.json`에 모델과 파일 경로를 등록합니다.
6. `check-data`를 통과한 결과를 웹에서 확인하고 실험 기록에 해석을 남깁니다.

현재 `demo` 명령은 합성 예제 전용입니다.
연구 모델을 추가할 때는 모델 실행과 결과 내보내기를 연결하는 코드를 함께 구현합니다.
다중 예측 구간이나 군집 결과를 웹에 표시하려면 스키마와 검증·화면도 함께 확장합니다.

## 결과 보관과 해석

실행마다 구별할 수 있는 `run_id`를 사용하고,
명령·설정·코드 버전·데이터 버전·결과 위치를 함께 보관합니다.
GPU를 사용하는 실험은 장치와 관련 라이브러리 버전도 기록합니다.

결과에는 지표와 함께 어떤 조건에서 차이가 났는지, 실패한 사례는 무엇인지,
다음 실험에서 무엇을 확인할지를 적습니다.
확률적인 모델을 여러 번 실행했다면 시드별 결과와 집계 방법도 남깁니다.
기록 양식은 [진행 기록 안내](progress/README.md)에 있습니다.
